# Round 1171 audit plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round closes the residual recorded by `#41001`: protected metadata names
were still joined with a host `filepath.Join` and compared with
`sandboxpath.PathWithin`, so a write rule nested below `<root>/.git` lifted the
whole `.git` protection and the comparison ignored Rust's URI resolution.

## Rust behaviour

`codex-rs/protocol/src/permissions.rs:2526-2549`
`protected_metadata_names_for_writable_root` keeps a metadata name protected
unless the local matcher's `can_write_path` accepts that exact metadata path:

```rust
let mut metadata_paths = vec![root.join(*metadata_name)];
metadata_paths.extend(raw_writable_roots.iter().map(|raw_root| raw_root.join(*metadata_name)));
if metadata_paths.iter().all(|metadata_path| {
    !matching.can_write_path(&PathUri::from_abs_path(metadata_path)).unwrap_or(false)
}) {
    protected_names.push((*metadata_name).to_string());
}
```

`can_write_path` (permissions.rs:1051-1086) only lifts the metadata denial when
some write entry covers the metadata path itself
(`p.starts_with(root) && root.starts_with(&protected)`), so a broader writable
root above the metadata path does not help and a nested rule below it does not
either. The path that has no `PathUri` representation fails closed and stays
protected.

## Go gap

`sandbox/integrity/policy.go::protectedMetadataNames` tested
`PathWithin(resolvedEntry, metadataPath)`, i.e. "entry at or below the metadata
path", so a grant such as `<root>/.git/objects` un-protected all of `.git`, and
the containment used host `filepath` semantics instead of URI identity.

## Change

- `protectedMetadataNames` now resolves one candidate per writable root
  (`filepath.Join(root, name)`, matching Go's 1:1 root/raw-path model) and asks
  `metadataPathWriteGranted`.
- `metadataPathWriteGranted` mirrors `can_write_path`: the policy access for the
  metadata path must resolve to write (`sandbox.ResolveFileSystemEntryAccess`),
  and some non-glob write entry must name that exact path. The comparison is
  URI-native (`utils.InferredPathURI` + `PathURI.Equal`, so Windows case and
  separator spellings fold and POSIX stays byte-exact); unresolvable paths stay
  protected.
- Test `sandbox/integrity/protected_metadata_roots_like_rust_test.go` covers the
  no-grant case (all roots protect `.git`), a grant scoped to one root (only that
  root loses protection), and the nested `<root>/.git/objects` grant (stays
  protected).
