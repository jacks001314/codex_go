### #38893 Restore thread timestamp maxima independently

`codex-rs/state/src/runtime.rs` fixes the thread timestamp-maxima restoration
query during state initialization:

- Before: `SELECT MAX(updated_at_ms), MAX(recency_at_ms) FROM threads` - SQLite
  evaluates the two-argument `MAX(a), MAX(b)` as the multi-argument scalar
  `max()` (same-row maximum / NULL-on-any-NULL semantics) rather than two
  independent column aggregates, so when the updated_at and recency_at maxima
  belong to different threads one counter was silently corrupted on reopen.
- After: `SELECT (SELECT MAX(updated_at_ms) FROM threads), (SELECT
  MAX(recency_at_ms) FROM threads)` - each counter is restored independently
  from its own column.
- Rust regression test `init_restores_independent_thread_timestamp_maxima`
  seeds two threads (updated 3000/recency 1000 and updated 1000/recency 4000),
  closes, reopens, and asserts both counters restore to (3000, 4000).

Go had the exact pre-fix query in `state/runtime.go` `loadThreadTimestamps`.
Aligned to the independent scalar subqueries and pinned the regression with
`TestStateRuntimeRestoresIndependentThreadTimestampMaxima` (same two-thread
scenario, close + reopen, both counters verified).
