## Findings

- Rust #43462 removes the legacy Guardian approval-review entrypoints and the
  deleted contributor hooks. Go never had those hooks, so their removal has no
  runtime counterpart.
- The actionable Go gap was the request-scoped review trigger introduced with
  the shared synchronous review path. Rust records `GuardianReviewReason` on
  `GuardianAssessmentEvent` and uses the same value for the route metric.
- Rust's app-server emits `autoApprovalReview/strictReviewRequired` only while
  a review is in progress and its reason is one of `elevated_risk`,
  `stale_score`, `incompatible_compaction`, `scoring_failure`, or
  `authorization_changed`.

## Changes

- `state/guardian.go`: add the Rust-compatible `GuardianReviewReason` values,
  unknown-value fallback, `Event.ReviewReason`, and `ReviewStore.StartWithReason`
  so the reason survives every terminal transition.
- `appserver/guardian_reviewer.go`: derive `policy`, `fresh_required`,
  `scoring_failure`, `elevated_risk`, or `authorization_changed` from the real
  Go synchronous-review route, reuse it for the route metric, and emit the
  strict-review notification for the Rust strict-reason set while in progress.
- Tests: `state/guardian_test.go` pins enum serialization, unknown handling and
  reason retention; `appserver/guardian_review_reason_like_rust_test.go` pins
  route reasons, route metrics and strict-notification conditions; the existing
  oversized-serving-assessment test now also requires `scoring_failure`.
