上游自带用例（可逐字对照）：`restricted_read_only_uses_scoped_read_roots_instead_of_erroring`（`bwrap.rs:2420-2445`，断言 **`args.args[0..4] == ["--tmpfs","/","--dev","/dev"]`** 且存在 `--ro-bind <readable> <readable>`）、`restricted_read_only_with_platform_defaults_includes_usr_when_present`（`:2447-2470`）。

**挂载顺序（本批的第二个坑，实测确认）**：上游把文件系统挂载排在 `--proc /proc` **之前**（`:337-381`）。Go 现状把 `--proc /proc` 排在最前（`linux.go:988-990`）。实测两条原始实验：

```
$ bwrap --proc /proc --tmpfs / --dev /dev --ro-bind /usr /usr ... -- /bin/sh -c 'ls /proc'
ls: cannot access '/proc': No such file or directory          ← Go 现状顺序 + tmpfs ⇒ 沙箱内完全没有 /proc
$ bwrap --tmpfs / --dev /dev --ro-bind /usr /usr ... --proc /proc -- /bin/sh -c 'ls /proc; grep " /proc " /proc/mounts'
dr-xr-xr-x 428 nobody nogroup 0 ...                            ← 上游顺序 ⇒ 新 procfs 正常
proc /proc proc rw,nosuid,nodev,noexec,relatime 0 0
```
（同一实验对 `--ro-bind / /` 布局两序都正常，所以既有 R1/R2 布局不需要动。）

结论：R3 若照 Go 现状顺序实现会**额外缩小语义**（丢 /proc），因此本批在 tmpfs 之后**重发** `--proc /proc`，使 R3 布局与上游语义一致；R1/R2/full-write 布局**一个字节都不改**。

## 3. 实现（生产 argv 变更，最小面）

`sandbox/linuxsandbox/linux.go`：
1. 新增 `linuxPlatformDefaultReadRoots`（Rust `LINUX_PLATFORM_DEFAULT_READ_ROOTS` 逐条同序）、`(*linuxFilesystemPolicy).includePlatformDefaults()`、`(*linuxFilesystemPolicy).readableRoots(cwd)`（= Rust `get_readable_roots_with_cwd` + 平台默认增补，排序去重）。
2. `execBubblewrap` 的 restricted 分支拆两条：
