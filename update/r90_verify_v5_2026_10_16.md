## 2. 【新反例】交付来源（delivery provenance）：Go 按“已组装”记账，Rust 按“已提交”记账

一次性探针 `appserver/zz_probe_guardian_delivery_test.go`（跑完已删）原文：
```
review#1 (agent fails) err=<nil> requests=1
  review#1 prompt has 'first evidence'=false imageItems=1
review#2 (agent ok) err=<nil> requests=2
  review#2 prompt has 'first evidence'=false imageItems=0
```
探针做的唯一事情：`modelGuardianReviewer` 的 `agent` 在第一次 `Review` 时返回 `errors.New("probe: first review fails")`，第二次正常；`nodeReplEvidence` 指向同一份 `NodeReplReviewEvidence`（`RecordMultimodal(..., []string{"first evidence"}, []string{"data:image/png;base64,AAAA"})`），不追加新证据。

观察：
1. 第一次 review 的 agent 调用失败（`Review()` 仍返回 `nil`，走内置回退判定），但 `appserver/guardian_reviewer.go` 的 `ledger.Admit(newImages...)` 与 `r.noteGuardianReviewedEvidence(threadID, nodeReplEvidence.Sequence())` **都在请求发出之前**执行；
2. 因此第二次 review 的请求 `imageItems=0`，且首轮文本 `first evidence` 也不再出现 ⇒ 该证据对同一 thread **永久不再送达任何一次成功的 review**。

Rust 侧对照（`C:\rw\codex-rs`）：
- `guardian-context/src/images.rs:29` 注释即契约：“Only admitted history proves delivery; images kept here are not committed yet.”
- `guardian-context/src/images.rs:30-59 retain_new_images(history, prepare)`：`history` 是**已提交的 reviewer 会话历史**（`ResponseItem::Message` 的 `ContentItem::InputImage`），只丢“已提交过”的图；失败的请求不会进入 history ⇒ 下一轮仍会 retain 该图。
- 结论：Rust = 结果导向（已提交才算送达）；Go = 决策导向（已组装即算送达）。**存在差异**。
- 最小复现输入：同一 thread，第一次 guardian review 的 agent 调用返回 error（或中途取消/超时），然后再次 review 同一份证据。
- 影响：guardian 会永久少看一次图像证据（且该段文本证据也不重放）。
- 建议（仅建议，我不改码）：把 `Admit` 与游标推进放到“请求成功”之后，或至少在失败/取消路径上不推进。
