### 0.1 gofmt 门禁的环境事实（重要，影响所有车道）

本 worktree 由 `git worktree add` 新建，而本机 Git **系统级** 配置 `core.autocrlf=true`

所以 **原始 `gofmt -l .` 在本 worktree 输出 3479 行（= 每个 .go 文件），这是换行符产物，不是格式化缺陷**。

证据（把 worktree 的 `.go` 全部按 CRLF→LF 归一化到临时镜像后跑 gofmt）：

```

```

## 7.2 C8 收尾结论：**无载体（Go 无 remote/executor stdio MCP 启动路径）**；Go 唯一 stdio 载体 **aligned**

三选一结论 = **无载体**（对 Rust 被改的那个函数而言）＋ Go 实际存在的载体已对齐。

### 31.7 未覆盖 / drift（如实）

1. **Listing/Runtime 双模式无载体（drift）**：Rust 用 `DiscoveryMode::{Runtime,Listing}` 把“发现”和“执行”分开——Listing 期算指纹并把 `current_hash` 报成 `declaration/content`，Runtime 期 **不算**指纹、只把 `plugin_trust` 挂到 handler 上，改内容在**执行**时以 `trust_error` 报错；Go 只有一条 `Discover()` 通路（`hooks/list` 与执行用的是同一批 `HookMetadata`）。因此 Go 落成「发现期即绑定（Listing 语义）+ 执行期复验（Runtime 语义）」的合成形态，**没有** `DiscoveryMode` 枚举本身。后果：Go 侧“内容变了”表现为 `trustStatus=modified`（handler 在执行门 `hookTrustAllowsExecution` 被跳过），而 Rust Runtime 会照跑 handler 再以 `trust_error` 失败。行为上都是“未重新批准则不生效”，但错误呈现不同。
2. **`hook.command_outcome="trust_error"` 无载体（drift）**：Rust 在 `finish_command_run` 里把 outcome 记进 tracing span 字段（`command_runner.rs:219-241`）。Go 没有 span/`command_outcome` 指标面（只有 `emitHookRunMetrics`），故只落地 `hookOutputEntries` 里的 `HookOutputError` 文本，未新增指标标签。
3. **config 写盘拆分改成读侧拆分（Go 适配，申报）**：Rust 在 `app-server/src/config_manager_service.rs:364-392` 把合并批准拆开落盘；Go 没有 `config_manager_service` 对应物，客户端（`tui/hooks_rpc.go:45` `BuildHookTrustValue`）直接把 `hook.CurrentHash`（改后即 `declaration/content`）写进 `hooks.state.<key>.trusted_hash`。若不做处理，客户端自身写的批准会永远 `modified`（回归）。故在 `pluginHookTrustForSource` 读回时按 Rust 的同一规则 `split_once('/')` 拆分（`hooks_discovery.go:1449`）。这是 Go 侧的**读侧等价实现**，语义等价于上游的写侧拆分；Rust 对合并形式本身会返回 false，Go 更宽松。
4. **`LegacyPath` 的来源**：Rust 从 `ConfigLayerStack` 里找 `ConfigLayerSource::User{file}`；Go 用 `HookDiscoveryService.CodexHome` 下的 `config.toml`（与 `appendUserHooks` 同一约定），`CodexHome==""` 时等价于 Rust 的 `None`。若将来 Go 支持多用户图层/profile 覆盖，这里需要改成走 `Config.Read(IncludeLayers)`。
5. **未验证项**：`plugin_trust.rs::verify()` 的取消传播（`oneshot` receiver closed ⇒ `Interrupted`）在 Go 侧没有对外可观察面（`pluginContentHashWithCancel` 有 cancel 缝，但 runner 只在超时后放弃等待，不注入取消），故只做“超时预算共用”，未验证取消语义；`app-server` 的 `hooks_list`/`plugin_list` fixture 测试（Rust 侧）未在 Go 侧搬（Go 的对应契约面在 `appserver/hooks_discovery_test.go`，本批未改其断言）。
6. **临时文件**：`%TEMP%\r90c7\{gen.py,gen.py.txt,rc1.py,rc2.py,rc3.py,patch*.py,mirror*/,**/bundle}` 与 `appserver/*.rcbak` 全部用完即删（`git status` 已无残留）。
