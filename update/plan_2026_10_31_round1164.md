# Round 1164 audit plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round ports the `codex exec` half of Rust #43069: a forked session with
`--worktree` now branches from the source conversation's latest turn cwd, and an
explicitly untrusted source is refused before anything is allocated.

## Fork source resolution (`exec/worktree_fork_source.go`)

Rust's `exec/src/worktree.rs::fork_source` starts a temporary in-process
app-server, resolves the fork target to a thread id, reads the thread, and uses
`latest_thread_cwd` (the newest persisted `turn_context.cwd`, falling back to the
thread's cwd). Go already resolves the fork target through the session store and
rollout import in `resolveExecResumeRecordForMethod`, so the new helper reuses
that lookup and then:

- streams the source thread's rollout and keeps the last `turn_context` cwd,
  accepting both the Rust `payload` wire shape and the legacy Go sibling key;
- falls back to the thread record's cwd when the rollout has no turn context or
  cannot be read (Rust's scanner fallback);
- maps a missing target to Rust's `Session not found: <id>`.

`RunContext` resolves this before the checkout exists, keeps `--cd` when the
user supplied it, and passes the resolved cwd to `WorktreeManager.Create`.

## Source trust gate

Rust builds a source config with `ignore_project_config` and refuses
`active_project.is_untrusted()` with
`--worktree requires a source that is not explicitly untrusted`. Go now applies
the same gate through `ProjectTrustLevelForTarget` on the resolved source cwd
before allocating the checkout, for plain `--worktree` and for forks.

## Tests

`exec/worktree_fork_source_like_rust_test.go` covers the newest turn-context
cwd (including a malformed line and the legacy sibling key), the thread-cwd
fallback, the untrusted-source rejection (with no worktree allocated), fork
checkout creation from the source repo when `--cd` is absent, and the explicit
`--cd` override. Verified with `go test ./exec -count=1`.

## Residual

The interactive startup half of #43069 (`tui/src/worktree_startup.rs`:
`ManagedTuiWorktree::prepare`, the destination-auth `check_source_policy`
re-check that keeps an unused checkout, and `StartupRecovery` reporting) has no
Go counterpart yet: `codex --worktree` and interactive `codex fork --worktree`
do not allocate a checkout at launch. That half lives in the TUI/startup stream
and is recorded as the remaining gap for this entry.

## Step model on tool telemetry (#44242 residual)

Rust's step-scoped `SessionTelemetry` carries the issuing step's model as a
metric metadata tag. Go's dispatcher now stamps that model into every tool
execution's telemetry tags (`invocation.StepAttribution.Model`), so
`codex.tool.call` and its duration histogram are attributed to the step that
issued the call rather than the turn's first model. `EmitMCPCallMetricsForExecution`
copies the tag onto the MCP counter, duration and error counter (sanitized like
Rust's metric tag values).

Tests: `TestToolDispatcherTagsStepModelOnTelemetryLikeRust`,
`TestEmitMCPCallMetricsTagsStepModelLikeRust`; verified with
`go test ./turn ./telemetry -count=1` and the appserver MCP/tool metric subset.

Residual for #44242: artifact-operation metrics still take their tags from the
turn-scoped sink (that emission lives in `appserver/turn_runtime.go`), and the
model-visible tool list is still built once at turn start, so a mid-turn switch
to a text-only model keeps advertising `view_image` and relies on the call-time
rejection.
