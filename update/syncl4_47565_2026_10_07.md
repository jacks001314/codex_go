## 4. 任务 B（只读）：`#39935` 是否翻案 —— **成立（Go 侧漏洞面存在）**

### 4.1 裁定问题与答案

> Go 的 MCP OAuth 流程里，`#39935` 所保护的「面向多 authorization-server / 端点来源绑定」的面，本身是否存在？

**存在。** Go 明确**按受保护资源元数据列举并逐个尝试多个 authorization server**：

```
$ git grep -n "AuthorizationServers\|authorization_servers" -- mcp/
mcp/oauth_discovery.go:54:	AuthorizationServers []string `json:"authorization_servers"`
mcp/oauth_discovery.go:82:	for _, authorizationServer := range resourceMetadata.AuthorizationServers {
mcp/oauth_discovery.go:503:	metadata.AuthorizationServers = uniqueNonEmptyStrings(metadata.AuthorizationServers)
```

`DiscoverStreamableHTTPOAuth`（`mcp/oauth_discovery.go:57`）在 PRM 未直接给出可用 AS 时，遍历 `resourceMetadata.AuthorizationServers`，**取第一个能解析出元数据的候选**并返回（`:82-95`）。

而解析出的元数据**从不与其 issuer 做来源绑定校验**：

```
mcp/oauth_discovery.go:540  func discoveryFromMCPOAuthAuthorizationMetadata(serverURL string, metadata *oauthAuthorizationServerMetadata) *StreamableHTTPOAuthDiscovery {
        ... Issuer: authorizationServer, AuthorizationEndpoint: strings.TrimSpace(metadata.AuthorizationEndpoint),
            TokenEndpoint: strings.TrimSpace(metadata.TokenEndpoint), ...
```

全仓唯一相关的 `errors.Is`/origin 比较只有：

```
$ git grep -n -i "does not match the authorization" -- '**/*.go'
mcp/oauth_login.go:313:	return errors.New("MCP OAuth callback issuer does not match the authorization server metadata")
```

这是 **RFC 9207 callback `iss` 校验（#40691）**，即「回调里带回来的 `iss` 必须等于元数据 issuer」；它**不能**替代 `#39935` 的「授权端点 origin 必须等于 issuer/token origin」——后者在**发起授权前**就挡住跨源授权端点。

### 4.2 Rust 在何处做该绑定（对照）

```
codex-rs/rmcp-client/src/oauth_client_registration.rs:49   validate_authorization_server_endpoints(&metadata)?;
codex-rs/rmcp-client/src/perform_oauth_login.rs:876         validate_authorization_server_endpoints(&metadata)?;
codex-rs/rmcp-client/src/oauth/issuer_binding.rs:11         pub(crate) fn validate_authorization_server_endpoints(...)
```

即：Rust 在 `resolve_metadata()`（同一「多 AS 解析」入口）之后**立刻**校验端点 origin；Go 的对应入口 `DiscoverStreamableHTTPOAuth` 之后无此步骤。

### 4.3 Go 现状（对照 Rust 该函数的四段语义）

| Rust `validate_authorization_server_endpoints` 语义 | Go 现状 |
|---|---|
| ① 非 http/https scheme ⇒ 拒 | **已有**：`mcp/oauth_discovery.go:476 mcpOAuthWebEndpoint`（#47326） |
| ② `issuer-bound callbacks` 广告 ⇒ 需有 issuer，直接放行 | 部分：`mcp/oauth_callback_mode.go:45 MCPOAuthCallbackModeForDiscovery`（#40691） |
| ③ 无 issuer-bound ⇒ `authorization_endpoint.origin() == issuer.origin()` 或 `== token_endpoint.origin()`，否则拒 | **缺失**（Go 无任何 origin 比对） |
| ④ 两条窄例外（`mcp.mercadopago.com/mcp` / `agent.robinhood.com/mcp/trading`） | **缺失**（无例外表；`#50189` 因此在 Go 无载体） |
