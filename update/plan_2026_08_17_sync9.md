## Gap: Vim normal mode not dispatched

Rust's composer supports a full Vim mode (bottom_pane/chat_composer.rs): when
Vim is enabled the composer starts in NORMAL mode, normal-mode keys dispatch
Vim actions (motions, insert-entering, edits, operators, text objects), and
insert mode types normally until Esc. Go registered the actions but never
dispatched them.

Implemented in the tea Model (`tui/tea/vim_mode.go`):

- Normal/insert state machine (`m.vimInsert`; `/vim` starts normal, Esc from
  insert returns to normal).
- Normal-mode dispatch through the resolved keymap: insert-entering
  (i/a/A/I/o/O/s/C), motions (h/l/k/j/w/b/e/0/$ - word motion computes
  boundaries over the current line via LineInfo + SetCursor), edits (x/D),
  line yank (Y) + paste (p), and the dd/yy line-operator repeats via a
  pending-operator state. The full operator + motion/text-object engine
  (dw/diw/ciw/...) remains a tracked follow-up.
- Insert mode types normally; the #38907 queued-message history-up gate now
  requires real NORMAL mode (`!m.vimInsert`), matching Rust's VimNormal
  context.

The existing long-tail slash test was updated to enter insert mode before
typing after `/vim` - correct Vim semantics (letters dispatch actions in
normal mode), surfaced by the dynamic tests.
