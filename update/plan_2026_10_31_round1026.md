## Findings

- #42082 is implemented in Go:
  - `mcp/invocation_registry.go` plus `mcp/tool_executor.go`
    (`RegisterToolInvocation`) retain invocation metadata for every MCP
    `tools/call`, including Node REPL-backed servers.
  - `appserver/mcp_elicitation.go` reads the nested `callId`
    (`mcpElicitationLiveCallID`), resolves it through
    `service.LiveToolInvocation(serverName, callID)`, and uses it as the review
    target only when the live invocation belongs to the same server. Missing,
    unknown, other-server, and released ids fall back to the
    elicitation-specific target, and the nested action keeps its own identity.
  - Coverage existed only for the Codex Apps/Browser path; this round adds the
    Node REPL matrix.
- #42086 is implemented in Go: `appserver/guardian_review_metrics.go` adds a
  sanitized `tool` tag to the review counter only for `codex_apps` MCP calls,
  and existing `guardian_review_metrics_test.go` coverage asserts that custom
  MCP actions and the duration/token histograms never carry it.
- #49411 is Rust-only eval-order hygiene: the commit binds a temporary
  `app_server_time_provider(...)` value to a local before passing it. Go
  evaluates the argument directly and has no equivalent borrow or aliasing
  requirement, so no carrier exists.
