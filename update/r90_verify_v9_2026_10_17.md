### 1.2 三处「旧断言改写」判定（V-b7 §1 重点）

### 1.3 `content_item_metadata` 一层（真实结构缺口，非改弱）

- Go 全仓 `git grep -n "content_item_metadata"`（非文档）= **0**；`ContentItemProvenance|ContentItemNamespace` = **0**（命中仅在 `update/*.md` 自述）。

### 2.2 A-b5 行为等价申报（image-only ⇒ 逐字节等价）：**rejected**

以 Go 自己产出的 image 三元组（`appserver/turn_runtime.go:11514-11527`：`<image name=[Image #N] path="…">` / `input_image` / `</image>`）做探针：

```
PROBE compact triplet(withText=false) text="<image name=[Image #1] path=\"C:\\shot.png\">\n</image>" content=[{"Type":"input_text","Text":"<image name=...>\n</image>",...}] kinds=[unknown]
PROBE compact triplet(withText=true)  text="look at this" content=[{"Type":"input_text","Text":"look at this",...}] kinds=[user.text]
```

Rust 等价输入（`compact.rs:757-788`）：`user_input_parts` 跳过三个标签、`filter_map(InputText)` 得空 ⇒ `parts.is_empty()` ⇒ push `InputText{text:""}`（`compact.rs:779-787`）⇒ 压缩后该消息文本是 **`""`**。
Go 同输入：`compactedUserTextParts` 同样得空 parts ⇒ 走「safety net」`parts = [{input_text, ItemText(&item)}]`，而 `ItemText` 对三元组返回**两个标签的拼接**（`compact.go:802-824`）⇒ 文本为 `<image …>\n</image>`。

- 即：**仅含 image 的用户消息，压缩后 Go 的文本与 Rust 不同**（部件数=1、kind=`unknown` 两侧一致；差别只在文本内容）。用户仅发一张图（无文字）即命中。
- 该偏差**先于本提交**（RC-1 台面实测旧 `compact.go`：`text="<image name=[Image #1] path=\"C:\\a.png\">" content=nil`，同样非空）。本提交把容器从 `Content=nil` 改成 `[1 个文本部件]`（更接近 Rust），但 `compact.go:1166-1171` 的注释「an item that carries text without content parts … Rust's message always carries content, so only Go needs this shape」**低估了该分支的可达性**，据此申报的「逐字节等价」不成立。
- 最小修法（不属我职责，仅记录）：`parts` 为空时用空文本 + `unknown`（与 Rust 一致），仅在 `Content` 全空且 `item.Text` 非空的「扁平化 rollout 项」才回落到 `ItemText`。
