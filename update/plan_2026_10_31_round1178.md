# Round 1178: shutdown watchdog lifetime, async test budgets and a code-mode transport wakeup (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

## Gap

`go test ./...` failed on `main` in four places that never failed when each package ran alone.

- `codex_go/app` ended at ~45s with `app-server shutdown timed out; exiting`
  and no `--- FAIL` line. `ServeWithShutdown` arms a 45s `time.AfterFunc` that
  calls `os.Exit(1)`, but nothing stopped the timer once teardown completed.
  `TestRunAppServerAcceptsConfiguredEnvironmentsLikeRust` cancels the stdio
  server after 300ms and the test binary keeps running later tests; the leftover
  deadline killed the process even though shutdown had succeeded. Reproduced
  deterministically with `-count=60`: the run died at 46.7s without any
  assertion, and reached 79.8s with the fix.
- `codex_go/appserver` failed 7 of 45 runs of
  `TestRuntimeRouterAdditionalContextToolOutputTruncationLikeRust`,
  `TestSkillInstructionsSelectAppsTheyMentionLikeRust` and
  `TestPendingInjectionInterruptsWaitAgentLikeRust` while the rest of the suite
  was running. Every failure was one of the package's 2 second async deadlines
  (`waitForRuntimeAgentRequest`, `waitForTurnCompletedStatus`,
  `waitForBlockingAgentStart`); the routers themselves complete in
  milliseconds when idle, but `./appserver` takes 400s under full-suite load.
- `codex_go/codemode` hung until the 10 minute test timeout in
  `TestRemoteSessionNegotiatesServerOutputTruncationLikeRust`.
  `scriptedHandshakeTransport.Read` checked its queue once and then blocked on
  `<-ctx.Done()` with a background context, so a `session/ready` response queued
  by `Write` afterwards never woke the reader and
  `remoteConnection.requestWithYield` (`remote_provider.go:828`) waited forever.
- `codex_go/mcp` failed 2 of 100 runs of
  `TestMCPDiscoverLocalStdioHandshakeRecoveryLikeRust` with
  `Call() error = write |1: The pipe is being closed`. That is Windows
  `ERROR_NO_DATA`/`ERROR_BROKEN_PIPE` from writing to a helper that already
  exited. Rust's `should_restart_legacy`
  (`rmcp-client/src/stdio_handshake.rs`) restarts a fresh legacy helper when the
  in-place fallback initialize fails with `BrokenPipe` or `ConnectionReset`;
  Go only recognised `io.ErrClosedPipe`, so it surfaced the write error instead.

## Evidence

- `appserver/stdio.go`: `stdioShutdownWatchdog` keeps its timer behind a mutex
  and gains `disarm`, which `ServeWithShutdown` defers. `arm` keeps the
  first-EOF-wins rule (the timer is only created once) and ignores later signals.
  `appserver/stdio_test.go` pins both directions:
  `TestStdioShutdownWatchdogArmsOnce` still fires once, and
  `TestStdioShutdownWatchdogDisarmsAfterShutdown` proves a disarmed watchdog
  never fires.
- `appserver/runtime_router_test.go` declares `asyncTestWaitTimeout = 10s`;
  `waitForRuntimeAgentRequest`, `waitForBlockingReviewRuntimeAgentRequest`,
  `waitForBlockingAgentStart` and `waitForTurnCompletedStatus` use it, as do the
  analytics event waits in `appserver/app_analytics_test.go` and
  `waitForAbortLifecycleStart` in `appserver/abort_lifecycle_like_rust_test.go`.
  Assertions are unchanged; only the budget moved.
- `codemode/output_truncation_negotiation_like_rust_test.go`: the scripted
  transport keeps a 1-slot `readable` channel that `Write` signals and `Read`
  selects on alongside `ctx.Done()`, so a frame queued after a read wakeup is
  still delivered.
- `mcp/closed_transport_windows.go` / `mcp/closed_transport_other.go` add
  `isMCPClosedTransportError` (EPIPE plus `ERROR_BROKEN_PIPE`,
  `ERROR_NO_DATA`, `WSAECONNRESET` on Windows; EPIPE and ECONNRESET elsewhere),
  and `shouldRestartLegacyHandshake` uses it. A new
  `TestShouldRestartLegacyHandshakeOnClosedTransportLikeRust` pins that a
  wrapped broken-pipe write restarts the helper while an unrelated write error
  does not.

## Note

A parallel agent owns the in-flight `cli` clap-diagnostic refactor. Its
uncommitted `clapRepeatedValueOptionError` scan passed the whole root argv to
the leaf parser, so `codex --profile work sandbox --profile local -- ...`
