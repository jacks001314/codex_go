## Goal

Let delegated subagents surface MCP elicitation prompts and wait for the
client's answer, while keeping legacy `request_user_input` tool approvals
restricted to the root thread.

## Findings

- Rust removed the root-only MCP elicitation guard and the
  `allow_user_interaction` plumbing from `ElicitationAuthority`,
  `ElicitationRequestManager`, and `Session::request_mcp_server_elicitation`.
  Explicit elicitations can now be surfaced by root and non-root agents under
  the existing approval policy and automatic review rules.
- Rust kept `request_user_input` tool approvals root-only and introduced the
  message `MCP tool approval via request_user_input requires the root thread.`
- Connector authentication no longer returns a `Result` from the elicitation
  request: acceptance returns retry guidance (Go already did), and a declined
  response preserves the connector's original failure (Go already did).
- Go still published `AllowUserInteraction` on both MCP elicitation paths and
  rejected subagent prompts with `MCPElicitationHandoffMessage`.

## Implementation

- `appserver/mcp_elicitation.go`, `appserver/runtime_router.go`: remove the
  authority field, the subagent guard, and its classification helper.
- `appserver/mcp_tool_approval.go`: replace `allowUserInteraction` with
  `nonRootAgent`; only the legacy `request_user_input` branch denies subagents,
  using `mcp.MCPToolApprovalUserInputRootThreadMessage`.
- `mcp/tool_approval.go`: replace `MCPElicitationHandoffMessage` with the new
  root-thread message for the legacy approval path.
- Tests: subagent elicitations now reach the client (form, browser-auth, URL,
  OpenAI form), subagent tool approvals prompt through elicitation, and the
  legacy path still denies with the new guidance.
