## Goal

Audit #41909 (executor-context-aware permission transforms) and close any
observable gap in Go's additional-permission normalization/intersection.

## Findings

- Go has two lanes for additional permissions. The legacy appserver lane stores
  read/write path lists (`sandbox.AdditionalPermissionProfile`), while the
  request-approval broker lane uses `sandbox.RequestPermissionProfile` entries
  that can carry glob and special paths.
- The follow-up Rust #41928 work is already ported to
  `sandbox/policy_transforms.go` and wired through
  `appserver/server_request_broker.go`: executor-convention normalization,
  materialization, intersection, deny retention, symbolic `slash_tmp`/`tmpdir`
  fail-closed handling, and convention-aware overlap checks.
- One observable gap remained from #41909: home-relative glob entries were
  joined against the working directory instead of the user home. A requested
  `~/secrets/**` deny therefore never overlapped a home grant, and
  `retainConstrainingPermissionDenies` silently dropped the deny constraint,
  widening the effective grant.
- Upstream resolves `~`, `~/...`, and (under the Windows convention) `~\...`
  from the executor context's `user_home_dir` in
  `materialize_cwd_dependent_entry`.

## Implementation

- `sandbox/policy_transforms.go` now expands home-relative permission globs
  before any cwd join:
  - `materializePermissionGlob` and
    `materializePermissionGlobForConvention` both resolve `~` and `~/...`, with
    `~\...` only under `utils.ConventionWindows`.
  - `materializeHomeRelativePermissionGlob` and
    `homeRelativePermissionGlobSuffix` keep the convention spelling (Windows
    separators, POSIX cleanup) and fall back to the previous cwd-relative
    behaviour when the host home directory is unavailable.
- The expansion feeds both matching (`resolveRequestedPermissionAccess...`) and
  deny retention, so a home-relative deny now stays attached to accepted grants.

## Residuals

- Home expansion uses the host `os.UserHomeDir()` because executor-provided
  `userHomeDir` metadata is not plumbed into policy transforms; a remote
  executor with a different home still falls back to the host value.
- `NormalizeRequestPermissionProfilePathsForConvention` rejects foreign
  conventions for `file:` URIs but passes plain non-URI paths through. The
  intersection remains convention-aware and drops mismatched grants, but the
  broker does not surface upstream's explicit normalization error for them.
