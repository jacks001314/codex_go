## Goal

Mirror #41385: every Guardian classification is its own inference turn, the
reviewed turn is the classification's parent, and the parent's trusted causal
root travels with the classification when it is known.

## Implementation

- `appserver/guardian_reviewer.go`: mint a UUIDv7 `classificationTurnID` before
  the review attempt loop so retries keep one reviewer turn
  (`guardianClassificationTurnID`, `(*modelGuardianReviewer).classificationTurnID`).
  The review request's `TurnID` and client metadata `turn_id` use that identity;
  `parent_turn_id` stays the reviewed turn, and `root_turn_id` is the reviewed
  turn's recorded root or omitted when it has none.
- `appserver/guardian_isolated_assessment.go`: isolated assessments follow the
  same rule, with the captured action's turn as parent.
- `appserver/agent_runtime.go`: `guardianTrustedRootTurnIDForTurn` reads the
  active turn's recorded lineage (explicit `TurnParams.RootTurnID`, or a
  non-self captured run-config root), keeping the Rust
  `TurnMetadataState::root_turn_id()` semantics.
- `codexapi/client_context.go`: `ClientMetadata()` also emits the top-level
  `root_turn_id` next to `parent_turn_id`, matching Rust's
  `CodexResponsesMetadata::to_client_metadata` (the key was previously only in
  `x-codex-turn-metadata`).

## Residuals

- Rust's tool-lifecycle `root_turn_id` input is part of the extension
  contributor registry; the Go port has no extension registry, so the equivalent
  root propagation is implemented where Go consumes it (Guardian request
  metadata).
- Rust's async scorer/Luna sampler path does not exist in Go; the synchronous
  reviewer and isolated assessment carry the same identity rules.
