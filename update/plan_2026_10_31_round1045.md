## Goal

Gate computer-use-only Guardian scoring and fast approval decisions on the
active model's REPL auto-review requirement, including model switches in a live
thread, and invalidate stale scores when scoring is skipped.

## Findings

- Rust #42422 changes `ext/guardian-v2/src/async_scorer/extension.rs`: the
  asynchronous classifier and its cached-score fast path run only for
  computer-use-only threads whose active model requires REPL review. Skipping
  advances `latest_failed_tool_call`, so an older or in-flight score cannot be
  revived after switching back to a reviewed model.
- Go deliberately has no Guardian V2 asynchronous risk-scoring subsystem. The
  synchronous reviewer in `appserver/guardian_reviewer.go` returns the full
  structured assessment; there is no sampler, score cache, or cached-score
  approval path to gate or invalidate.
- `guardianScoreProgress` only enforces the synchronous `max_tool_call_lag`
  bound. It does not retain scores that could be replayed by a later model.
- Model-provided `guardian.computer_use` policy is already honored by
  `ModelInfo.ComputerUseReviewRequired` for node-REPL evidence, but that does
  not create the upstream asynchronous scoring behavior.
- The sibling async-scorer commits #40013, #40393, #40431 and #40480 are
  recorded `not_applicable` for the same architectural reason.
