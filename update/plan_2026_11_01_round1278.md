## Advanced this round

A server-truncated Code Mode session dropped the `Script error:` block from its
observations. Rust's runtime keeps a completed failure as one logical text item
that starts with the label, charged to the observation's own budget
(`code-mode-runtime/src/output/output_collection.rs::BoundedOutput::push_error`),
and the client deliberately does not append it again
(`core/src/tools/code_mode/mod.rs`, Go mirror `tool/code_mode_exec.go`
`remoteResponseOutput`/#58125). Go only pushed the bare diagnostic.

## What changed

- `codemode/output_collection.go` adds `boundedOutput.pushError`: the error and
  its label become a single text item, only the head and tail spans an
  observation could still select are materialized, and the skipped middle is
  charged to that item's own gap — the same accounting an ordinary write of the
  labeled text produces. `outputCollector.collectError` routes server-mode
  diagnostics through it and still returns the independently bounded (64 KiB)
  copy for logging.
- `codemode/output_render.go` now owns `renderSessionObservation`, the single
  implementation of a session's per-observation policy.
  `SessionRuntime.renderObservation` and `stdioHostSession.observeResponse`
  both call it, so the stdio host no longer renders the items and bounds the
  diagnostic in two separate places (the second copy also never labeled the
  error).
- `codemode/sobek_engine.go` reports a script failure as the exception's own
  text — a thrown string verbatim, an `Error` as `Name: message` — instead of
  `javascript execution failed: …`, matching Rust's V8 exception formatting.
- `codemode/stdio_host.go`: the session field no longer claims server
  truncation "is not implemented yet".

## Why it matters

Rust pins the exact bytes in
`code-mode-host/src/grpc/service_tests.rs::server_output_budgets_follow_exec_wait_and_terminate_over_grpc`:

```
Warning: truncated output (original token count: 24)
Total output lines: 2

Script error:
…17 tokens truncated…67890123456789
```

Go produced `Warning: truncated output (original token count: 20)` with no
label, so the model-visible item lost the failure block and the header
reported a different token count.
