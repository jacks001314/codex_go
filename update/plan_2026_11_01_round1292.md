## Advanced this round

Two gaps made the text a model reads differ from Rust.

### 1. exec/wait descriptions were a Go paraphrase

Rust composes the model-visible text in
`codex-rs/code-mode-protocol/src/description.rs` (`EXEC_DESCRIPTION_TEMPLATE`,
`LEGACY_IMAGE_HELPER_DESCRIPTION`, `UNIFIED_IMAGE_HELPER_DESCRIPTION`,
`WAIT_DESCRIPTION_TEMPLATE`, `TOOL_SEARCH_GUIDANCE`) and, for wait,
`core/src/tools/code_mode/wait_spec.rs`. Go carried its own rewrite:

- it dropped `fresh V8 isolate`, the `tools.exec_command(...)` /
  `tools.mcp__ologs__get_profile(...)` examples, the `ALL_TOOLS` entry and the
  full helper signatures;
- it added a Go-only "Enabled nested command tool:" block with a serialized
  input schema and an example command, plus "There is no nested tools.exec
  method";
- its `image(...)` helper line was a single sentence instead of Rust's
  `ImageDetailVisibility::Visible` / `Hidden` variants, so the unified image
  budget could not hide image detail;
- `wait` documented nothing per parameter, used `integer` instead of Rust's
  `number`, and shipped only one sentence instead of the headline plus
  `WAIT_DESCRIPTION_TEMPLATE`.

### 2. the response header was not a body item

Rust's `CodeModeToolOutput::new` inserts
`"{status}\nWall time X seconds\nOutput:\n"` as `body[0]`
(`core/src/tools/code_mode/output.rs`), then appends the script's content
items. Go only prepended the header to `Output.Body`, and the dispatcher's
`outputBody` prefers `Data["content_items"]`, so a model never saw
`Script completed` / `Script running with cell ID ...` — which also made
Rust's wait guidance ("Use `wait` only after `exec` returns `Script running
with cell ID ...`") unusable. Two `turn` tests
(`TestAgentLoopInstantInterruptYieldsCellAndDeliversQueuedInput`,
`TestInstantInterruptYieldsCodeModeExecOnQueuedUserInput`) were red on this.

## What changed

- `tool/code_mode_descriptions.go` (new): the Rust templates extracted
  verbatim, with `{{ default_exec_yield_time_ms }}` / `{{ image_helper }}`
  placeholders preserved.
- `tool/code_mode_exec.go`: `codeModeExecDescription` renders that template
  and the shared discovery guidance, appends `TOOL_SEARCH_GUIDANCE` when a
  ranked `tool_search` is registered (Rust
  `DeferredToolDiscovery::RankedSearch`), and no longer synthesizes the
  command-tool section. The wait spec renders the headline plus
  `WAIT_DESCRIPTION_TEMPLATE` and documents `cell_id`, `yield_time_ms`
  (`number`), `max_tokens` (`number`) and `terminate` like
  `create_wait_tool`.
- `tool/code_mode_exec.go`: `applyCodeModeHeader` also records the rendered
  header under `CodeModeResponseHeaderDataKey`, and
  `turn/tool_dispatcher.go` prepends it as the body's first content item, so
  the model-visible body is header + script items.
- `codemode/codemode.go`: `BuildExecToolDescriptionWithVisibility` selects the
  legacy or unified image helper; `BuildWaitToolDescription` and
  `WaitToolInputSchema` return the Rust template/schema.
- `turn/runtime.go`, `appserver/runtime_router.go`: carry
  `CodeModeImageDetailHidden` / `CodeModeImageDetailHiddenForModel` from
  `unified_image_budget_enabled` (feature `unified_image_budget` and
  `use_responses_lite || can_request_original_image_detail`), refreshed on a
  mid-turn model switch.
