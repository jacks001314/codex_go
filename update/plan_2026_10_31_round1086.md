## Goal

Keep rollout search running when one compressed rollout cannot be read, and
confirm the attachments data model matches the renamed Rust state schema.

## Findings

- `appserver/router.go` builds the searchable record set from the session
  store plus `rollout.ListThreads`/`rollout.RecordFromPath`. Any per-file read
  or decode error (including a damaged `.jsonl.zst`) is skipped with
  `continue`, and a failed directory listing is skipped, so one unsearchable
  compressed rollout does not abort `thread/search` - the Rust #44226
  outcome.
- Go persists thread attachments through the thread record's
  `thread_attachments` Extra key (`appserver/thread_attachments.go`) instead of
  the Rust SQLite table, with the same bounded record fields and wire contract
  (`attachmentType`, `identityKey`, payload, createdAt). The Rust #43927 change
  only renames `thread_artifacts`/`artifact_type` to
  `thread_attachments`/`attachment_type` in the state migrations; Go has no
  `thread_artifacts` storage to rename.
