## Findings

- #45672 consolidates Guardian reviewer lifecycle ownership in three places:
  - `ReviewerPool` ties reusable trunks and temporary forks to cancellation
    guards, replaces a cancelled trunk before reuse, and a dropped review cannot
    leave a reusable agent behind.
  - `ReviewerTasks` is shared between the pool and `ThreadManager`; pool
    shutdown cancels the runtime and awaits tracked cleanup, and the separate
    session shutdown protocol is deleted.
  - Denial cleanup moves from core task handling into Guardian's turn start,
    stop and abort hooks, and `install` registers the thread and turn lifecycle
    contributors together.
- Go's reviewer is host-owned and replay-based instead of pool-owned: every
  review request carries the parent transcript, and the only reusable state is
  the response cursor in `guardianSessionRunner` (`previous`/`seeded`,
  `priorReview`, `completedReviews`). The turn-hook part landed earlier
  (`beginGuardianTurn`/`endGuardianTurn` -> `CircuitBreaker.ClearTurn`).
- Two ownership gaps remained: `markThreadUnloaded` dropped the thread's other
  Guardian state (review history, blocking, catalog refresh, permission grants)
  but never the reusable reviewer, so a closed runtime kept its response chain,
  prior-review cursor and completed count; and the history/compaction resets
  called `sessionFor`, which *created* a reviewer session for threads that had
  never reviewed.

## Changes

- `appserver/guardian_reviewer.go`: new `existingSessionFor` lookup (never
  creates state) and `DropThreadSession`, the Go form of the thread-store pool
  teardown; an explicitly supplied shared session runner is left untouched.
  `forgetGuardianReviewerSession` routes the router's thread-unload hook to any
  reviewer that owns per-thread sessions.
- `appserver/runtime_router.go`: `markThreadUnloaded` now calls
  `forgetGuardianReviewerSession` next to the other per-thread Guardian
  cleanups, so the reviewer's lifetime ends with the thread runtime.
- `resetGuardianAfterParentCompaction` and
  `resetGuardianAfterParentHistoryReset` use `existingSessionFor`, so lifecycle
  resets only touch reviewer state that already exists.

## Residual

- Rust's `ReviewerPool`/`ReviewerTasks`, trunk cancellation guards and fork
  snapshots have no Go counterpart by construction: Go runs one in-process
  reviewer, replays the transcript per review, and reuses only the last
  committed response cursor. A cancelled or timed-out attempt rolls the
  checkpoint back (`finishAborted`/`finishTimedOut`), so it never becomes the
  reuse base, and in-flight reviews run on the turn context that
  `RuntimeRouter.Close` cancels and joins through `WaitForTurnWorkers` instead
  of a separate reviewer task tracker.
- The full `appserver` run still reports the known baseline failures
  (`TestRustAppServerV2SuiteManifestCoversRustModules`,
  `TestRuntimeRouterTurnCompletedEmitsAcceptedLineFingerprintsLikeRust`,
  `TestRuntimeRouterFileChange*`, `TestPrecomputedExportArtifactsMatchTargetRustCommit`,
  `TestStdioServerHandlesConcurrentTurnStarts`,
  `TestRuntimeRouterExecutorCatalogUsesExtensionByteBudgetWithoutCoreWarningLikeRust`).
