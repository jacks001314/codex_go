## Scope

Align VS Code/app-server integration and the local TUI with Rust for version reporting,
token usage, context-window compaction, and reconnect status.

## Root causes

- Provider SSE usage was present, but the local exec/TUI path never emitted
  `thread.token_usage.updated`, so `/status` remained at zero.
- Local sessions did not persist Rust-shaped total usage, last usage, or the effective model
  context window, so resumed threads could not restore status or make a valid compact decision.
- The old whitespace token estimate counted a long unbroken Chinese message as one token.
- Context-window overflow ended the turn without marking the resumed thread for Rust's next-turn
  pre-turn compaction flow.
- Retry notifications used a warning instead of Rust's app-server `error` notification with
  `willRetry: true`, which made VS Code clients consume the wrong state shape.
- Retry and compaction status were not represented as animated, transient Activity rows.
- TUI headers and the remote TUI initialize request reported hard-coded `dev` / `0.0.0`
  instead of the build version.

## Implementation

- Propagate and persist total/last token usage plus the effective context window.
- Restore usage on resume and estimate legacy session history when stored usage is absent.
- Compact before a resumed turn when the Rust threshold is reached; persist overflow as a
  next-turn compaction requirement.
- Use Unicode-aware estimates for CJK and conservative estimates/truncation for long unbroken text.
- Emit animated `Reconnecting...` and `Compacting context...` Activity rows and update them in place.
- Match Rust's 200 ms exponential retry backoff with 0.9-1.1 jitter.
- Emit retryable app-server errors with `willRetry: true`, stream-disconnect metadata, and details.
- Use the injected build version in local/remote TUI headers and remote initialize client info.

## Verification

- Local TUI usage reaches `/status` with real totals and effective context window.
- Usage survives session persistence and resume.
- Long resumed contexts compact before model sampling.
- Overflow marks the next turn for pre-turn compaction.
- Retryable app-server errors do not fail the active turn in the remote TUI.
- Focused tests cover CJK estimation, compact event ordering, retry Activity, protocol shape,
  version propagation, and usage restoration.
