### 8.4 已知偏差与既有失败（如实记录）

- 路径绝对性校验走 Go `utils.LegacyAppPathString.ToPathURI`，错误文案复刻 Rust
  （`provide an absolute POSIX|Windows file path for environment <id>`），但不含 serde 的
  `at line 1 column N` 尾缀；缺字段文案为 ``missing field `x` ``（沿用 `agentboard/tools.go` 既有约定）。
- `localEnvironmentFileSystem.WriteFileStream` 会创建缺失父目录（既有 Go 设计，见
  `tool/environment_filesystem_stream_test.go`）；exec-server（remote）目标不创建父目录，与 Rust 一致。
  因此"缺父目录 → entity not found"只在 remote 目标上断言。
- exec-server 线缆把 PermissionDenied 与 InvalidInput 都编码为 -32600（`fsOperationFailure`），
  远端目录错误在 Go 侧统一回 `permission denied`；本地路径保持 Rust 的 `invalid input parameter`。
- Rust 的 `strict: false` 由 Go 的 Responses 序列化层统一输出（`model/responses_tools.go`），
  `tool.Spec` 不单列该字段。
- 既有失败（非本次引入）：pristine worktree `D:\qax\reagent\dev\codex_go_pristine`（HEAD `084ec624`）
  同样失败 —— `TestUnifiedExecRestoresExecutorPathDirsForLoginShellLikeRust` /
  `TestLocalShellLaunchRestoresExecutorPathDirsLikeRust`（login-shell PATH）、
  `TestDriveLetterPathsAreNotReparseRejectedAndJunctionsStayBlocked`（Windows junction）、
  `TestWindowsSandboxPowerShellFallbackWithoutCompatibleShellLikeRust`（PowerShell 回退）。
