## 6. 方法论（必须遵守）

**队长门禁 6 步（每笔交付都做）**：`git cherry-pick -n <sha>` → lane/staged `git patch-id --stable` 判等 → `gofmt -l` 空 → `go build ./...`（涉及 Windows 加 `GOOS=windows`）→ `go vet` → 受影响包**整包**测试对基线 → **队长自跑反向对照** → `git commit` → `git push` → `ls-remote`。

**反向对照模板（必带 assert，否则假绿）**：
```bash
cp <file> /tmp/x.bak
python3 - <<'PY'
p='<file>'; s=open(p).read(); old="..."; new="... // LEADER REVERSE CONTROL"
assert s.count(old)==1, s.count(old); open(p,'w').write(s.replace(old,new,1))
PY
gofmt -l <file>; go test ./<pkg>/ -run '<Test>' -count=1   # 期望 FAIL（值级/行为级，非 build failed）
cp /tmp/x.bak <file>; go test ./<pkg>/ -run '<Test>' -count=1   # 期望 ok
```
只 commit 子路径时**不要**用 `git commit -- <paths>` 切分原 commit（会造成 patch-id 不匹配）；要么整笔提交，要么按 commit 逐笔 cherry-pick 后整笔 commit。

**回收前比对（本会话新增流程）**：`agent_admin_remove` 之前，对该车道分支跑 `git log --oneline main..<branch>` 与逐 commit `git patch-id` 比对；不匹配时再按 PR 号复核（`git log --oneline main --grep="#<PR>" -F`），因为**冲突解决会让同一改动产生不同 patch-id**。本会话全量普查 17 个分支头 → 唯一真实孤儿是 `#49100`（已由 sync578 补收），其余均已在 main 或属在飞提交。

**已知 flaky（不计新增失败、勿修）**：`appserver` 的 `TestStdioTransportPushesOrderedProcessNotificationsLikeRust`、`TestStdioServerGoalSetResponsePrecedesGoalNotification`、`TestOtelProviderReloadsAfterAccountChange`、`TestRuntimeRouterExecutorSkillProviderCatalogReadAndResourceAccessLikeRust`（并发跑偶发）。

**基线失败集（保持原样）**：`appserver` 4（GatewayOAuth / Otel / PluginList per-repo / TurnStartFileChangeApplyFailure）· `model` 2 · `execserver` 3 · `tool` 3 · `config` 4 · `applypatch` 1 · `mcp` 1 · `tui` 1（`TestSelectStartupTooltipMatchesRustPlanBranches`）· `tui/tea` 1 · `sandbox/windowssandbox/{elevated,bin/setup_main/win}` 各 1（Windows 语义在 Linux）· `app` 需 `TERM=xterm-256color`。

**其它陷阱**：台账 sha 列有错（自行 `git log --grep` 解析）；**不要跑 `go test ./...`**（无输出、耗时长）；`gofmt -l .` 有 33 个基线噪声文件；A2A 用 `type=request|response|message` + `mode=async`，发 request 后**结束本轮**等自动投递，不轮询/不 sleep。
