# Round 1228: Retained cleanup logons and the registered cleanup transaction (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42375,
`package_lifecycle/registered.rs`; #45550).

## Context

The uninstall transaction must keep only the trusted runtime finalizer's
private logins alive while it stops every other sandbox process and logon,
then prepare the exact managed accounts, prepare native cleanup, save the
retirement fence, retry teardown inside the live invocation, and commit the
removal only after the guard succeeded.

## Retained cleanup logons

`sandbox/windowssandbox/uninstall_cleanup_windows.go` ports
`uninstall_windows::retained_logons`:

- `captureRetainedLogons` refuses more than two tokens, duplicates each one
  so its logon session cannot be recycled, requires a distinct managed
  sandbox account SID, and records the token's `AuthenticationId`.
- The logon-session drain skips only those exact LUIDs; every other sandbox
  logon still blocks cleanup.
- `PrepareSandboxCleanupWithRetainedTokens` threads the guard through
  account disable, process stop and the setup lock, restoring the original
  flags if preparation fails; `Release` drops the duplicated tokens with the
  lock.

## Registered cleanup transaction

`windowsandboxservice/registered_uninstall_windows.go` adds
`CleanUpRegisteredRuntime`, porting `package_lifecycle::registered::clean_up`:

- refuses another package family, an unfinished retirement, an owner that
  still has the app installed, or an installation whose owner/home no longer
  matches the record;
- validates the record with `PrepareRuntimeCleanup`, prepares managed logons
  with `PrepareRuntimeRemoval`, and prepares native cleanup with the removal's
  retained tokens;
- re-checks `owner_allows_cleanup` so a reinstall before the boundary cancels
  without retiring resources, saves the retirement fence, and retries
  `CleanUpResources` inside the live invocation;
- commits the removal only after teardown succeeded and aborts it on every
  other path.
