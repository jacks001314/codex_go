### sync151: the environments.toml provider and the stdio client transport

The executor environment configuration layer now exists in Go, mirroring
Rust's `environment_toml.rs` / `environment_provider.rs`:

- `execserver.ParseEnvironmentsTOML` / `LoadEnvironmentsTOML` decode
  `environments.toml` (top-level `default` and `include_local`, one

  never echo configuration values in failures — syntax errors report a line and
  column, unknown fields report the field name.
- `NewEnvironmentProviderSnapshot` reproduces Rust's validation messages
  verbatim: reserved/whitespace/invalid-character/overlong ids, duplicate ids,
  `must set exactly one of url or program`, empty program, `args/env/cwd
  require program`, `auth_bearer_token requires url`, `connect_timeout_sec
  requires url`, non-websocket and malformed urls, config-dir-relative stdio
  cwd resolution, `default = "none"` disabling the default, and a local default
  rejected when local is disabled.
- `DefaultEnvironmentProviderSnapshot` mirrors the `CODEX_EXEC_SERVER_URL`
  fallback (`remote` environment, or `none` disabling the provider), and
  `EnvironmentProviderFromCodexHome` selects the file when present.
- The stdio transport is implemented: `execserver.DialClientOptions.StdioCommand`
  spawns the configured program and speaks line-delimited JSON-RPC over its
  stdin/stdout (reusing the shared initialize/session machinery). Mirroring
  Rust, a stdio connection registers no reconnect strategy, so a dropped
  connection fails instead of resuming a session the child cannot know about,

manager still learns about environments only from RPC registrations, so the

### sync152: the app-server serves the configured executor environments

- `EnvironmentManager.ApplyProviderSnapshot` pre-registers a provider snapshot:
  remote entries become records with their URL, bearer headers and connect
  timeout, stdio entries become records carrying the program command, and the
  provider's default selection is retained. The local environment stays
  implicit.
- The app-server startup loads the provider from CODEX_HOME, so a malformed

Remaining for full fidelity: Rust builds the same environment manager from

### sync155: the protocol agent path (#15313/#18353)

`codex_protocol::AgentPath` now exists as the Go `agent.AgentPath` protocol
layer (`agent/path.go`), mirroring `codex-rs/protocol/src/agent_path.rs`:

- `AgentPathRoot`/`AgentPathMorpheus` plus their string values, `String`,
  `IsRoot` and `AgentName` (the last segment, or `root`).
- `NewAgentPath`/`ValidateAgentPath` mirror `validate_absolute_path` exactly,
  including the `morpheus` early return, the `/root` prefix requirement, the
  trailing-slash rejection and per-segment name validation. The unreachable
  "absolute agent path must not be empty" branch is not reproduced, because
  Rust's `split('/')` can never yield zero segments: `/` reports the
  "must start with `/root` or be `/morpheus`" error in both languages.
- `ValidateAgentName` mirrors `validate_agent_name` (empty, reserved `root`,
  reserved `.`/`..`, embedded `/`, then the lowercase/digit/underscore charset).
- `Join` and `ResolvePath` mirror `join`/`resolve`: `/root` is special-cased,
  a `/`-prefixed reference is an absolute path, a relative reference is
  validated (`validate_relative_reference`) and then appended, and an **empty
  reference is rejected** with Rust's "agent path must not be empty". (The
  first draft of this file returned the caller's own path for an empty
  reference; Rust has no such rule and the message-board tools never use one,
  so it was corrected before landing.)
- `agent.rootAgentPath` is now an alias of `AgentPathRoot` so the spawn
  reservation key and the protocol validator cannot drift.

Behaviour is pinned by `agent/path_test.go`, which replays every Rust
`agent_path.rs` test plus the `/`, empty-relative-reference, `a/b`, morpheus

### sync156: the message-board collaboration tools

The second slice of the message-board program is the model-facing tool layer,
`codex_go/agentboard/tools.go`, porting `tools.rs`, `tools/spec.rs` and
`tools/arguments.rs`:

- `NewMessageBoardTools`/`NewMessageBoardToolsWithOverrides` build the nine
  tools (`create_channel`, `get_channels`, `list_threads`, `search_posts`,
  `read_thread`, `read_post`, `subscribe`, `unsubscribe`, `post`) bound to one
  caller and its `agent.AgentPath`. The host supplies the namespace and its
  description; an empty namespace publishes plain function tools, matching
  Rust's `Option<&str>`. Only the five read tools declare parallel support.
- The parameter schemas are transcribed from `spec.rs`, including the bundled
  descriptions, the `minimum` bounds, the `sort` enum, the notify-recipient
  array and the `additionalProperties: false` envelope. A catalog description
  override replaces only the description, because Rust keeps the bundled
  parameters for these tools (Go ignores a catalog parameter override, as
  Rust warns and does).
- Arguments decode with `deny_unknown_fields` semantics through the new
  `tool.Invocation.DecodeStrictArguments` (Rust's `tools/arguments.rs` structs
  all deny unknown fields). Rust's `NonZeroU32`, `u32`, `Uuid` and enum fields
  are validated after decoding, and Rust's non-`Option` fields are pointers so
  a missing field is rejected. Behaviour (reject) matches serde; the message
  text is Go's, like every other `DecodeArguments` failure in this port.
- The executors mirror `tools.rs`: the requested read is tried first and the
  page/preview limits halve only when the serialized result exceeds the
  response budget (`bounded_read`), mutations reserve 2048 bytes plus the
  caller and target paths before writing (`check_mutation_budget`), the request
  ID is `turn:call` for direct calls and `turn:cell:runtime_call` for Code Mode
  calls, and every model error is truncated to 512 characters.
- `tool.Invocation.ResponseByteBudget` ports `ToolCall::response_byte_budget`
  with `codex_utils_output_truncation::with_serialization_allowance` (new on
  `utils.TruncationPolicy`): a direct call is bounded by
  `min(max_response_bytes, policy * 1.2)` and a Code Mode call only by the
  tool's own limit. The policy is threaded end to end -
  `turn.RuntimeOptions.TruncationPolicyForModel` resolves it from the effective
  model, `Runtime.Run` puts it on `ToolDispatcherOptions.Truncation`, and
  `addInvocationContext` stamps it onto every `tool.Invocation`; the app-server
  builds the resolver from `modelInfoForRuntimeWithConfig`.

Tests: `agentboard/tools_test.go` pins every schema literally, runs the
channel/thread/search/read/subscribe scenarios over the in-memory board,
replays the strict-argument and mutation-budget rejections, and proves the
request-ID and bounded-read behaviour (including that a rejected mutation
leaves the board unchanged). `tool/response_budget_test.go` pins the allowance
rounding and the direct/Code Mode budget matrix.

### sync157: the SQLite (local) message-board backend

The third slice of the message-board program is `codex_go/agentboard/local.go`,
porting `local.rs` plus `local/{queries,paging,lifecycle}.rs`:

- The schema is copied verbatim, and the process keeps one SQLite pool per
  canonical database path with reference counts so live handles cannot open
  duplicate or stale pools (Rust's `POOLS` plus `Weak<SqlitePool>`; Go's
  `state.SqliteConfig.OpenReadWrite` already supplies the host's connection and
  journal policy).
- Every write runs in a `BEGIN IMMEDIATE` transaction that first checks the
  `deleted_boards` tombstone, so a permanently deleted board's root cannot be
  resurrected. `DeleteLocalBoards` writes the tombstone, deletes the board's
  subscriptions, opt-outs, posts and channels, and recovers an unopenable
  corrupt database by backing it up and recreating it
  (`state.IsSQLiteCorruptionError` + `state.BackupDBFilesForFreshStart`).
- `create_channel`, `post`, `set_subscription`, `read_post`, `list_channels`,
  `list_threads`, `search_posts` and `read_thread` mirror Rust's SQL, including
  the `request_id = "<caller>:<request id>"` idempotency column, the
  `subscription_opt_outs` rule that keeps an explicit unsubscribe until the
  agent subscribes again, the `instr(<folded search>, <folded query>)>0`
  matching, the `MATERIALIZED` page CTE for activity-sorted threads, and the
  per-query preview budgets (`MAX_READ_CHARS / (2 * n)`, `/(n + 1)`).
- Posts are written on `context.WithoutCancel`, mirroring Rust's detached
  `tokio::spawn(...).await` so a cancelled tool caller cannot abort an accepted
  write and its one-shot fanout; a failed notice never fails the commit.

The stored format is byte-compatible with Rust's serde shapes, which
`TestLocalBoardStoresRustCompatibleJSON` pins directly against the database: the
`payload` column holds `{"metadata":...,"text":...}` (with chrono's serde
`...Z` timestamp), the `request` column holds `serde_json`'s `PostRequest`
(`{"request_id":...,"destination":{"Channel":"work"},...}`), subscription target
keys hold serde's externally tagged `SubscriptionTarget`
(`{"Channel":"work"}` / `{"Thread":"<uuid>"}`), and `channels.created_at` holds
`chrono::DateTime::to_rfc3339`'s numeric-offset form (`+00:00`, which Go needs
the `-07:00` layout to emit).

Shared with the in-memory arm in the same pass: `validateChannelName`,
`newBoardPostID` (now `uuid.NewV7`, matching Rust's `Uuid::now_v7`; the
in-memory arm used v4), and the cursor/paging helpers
(`boardWindow`/`finishBoardPage`/`decodePageCursor`/`base64PageCursor`) factored
out of `pageItems` so both backends page identically.

Tests: `agentboard/local_test.go` proves persistence across handle
close/reopen, request-id idempotency after reopen, the channel/thread/author/
after search filters, cursor paging with invalid-cursor rejection, channel and
thread subscription opt-outs (including that posting again does not undo a
thread unsubscribe), permanent deletion with a surviving tombstone and an
untouched sibling board, and the collaboration tools running over the SQLite
board.

Remaining for this program: the runtime registration behind the
`agent_message_board` + `multi_agent_v2` gates (the host-supplied `delegation`
namespace and `MULTI_AGENT_V2_NAMESPACE_DESCRIPTION`, the
`multi_agent_v2.message_board_in_memory` switch, and the `LocalBoardHost`
adapter, which needs the `AgentControl::resolve` seam and a running-turn
notification injection), plus the `contains_external_context` marker.
