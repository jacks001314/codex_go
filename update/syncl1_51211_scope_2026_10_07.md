## 1. Rust 语义（逐 hunk）
### 生产 hunk
1. `codex-rs/sandboxing/src/bwrap.rs`
   - `system_bwrap_warning(permission_profile, sandbox_policy_cwd)`：**新增 policy cwd 参数**，把 **effective** filesystem policy + policy cwd 交给查找（原为无参数版本）。
   - `find_system_bwrap_in_path(file_system_policy, sandbox_policy_cwd)` → 转调新通用函数 `find_pre_sandbox_executable_in_path(program, policy, cwd)`。
   - `find_executable_in_search_paths(program, search_paths, cwd, policy, policy_cwd)`（核心过滤）：
     - 计算 `full_disk_write = policy.has_full_disk_write_access()`；`writable_roots = policy.get_writable_roots_with_cwd_inheriting_root_metadata(policy_cwd)`，并对 root canonicalize、把 read-only subpath 重锚到 canonical root 下。
     - `policy_can_write(p) = full_disk_write || ∃root. is_path_writable(p)`。
     - 遍历 `which::which_in_all`（每个候选先 canonicalize），**拒绝**（跳过、继续下一个）当满足任一：
       a. `!cwd_is_root && path.starts_with(cwd)`（保留原行为：命令 cwd 下的候选不可信）；
       b. `policy_can_write(path) && current_user_can_modify(path)`（候选本身可被策略写入且当前用户可改/可替换）；
       c. 存在祖先：对某个 `component` 的 `parent`，`policy_can_write(parent) && !is_read_only_mount(component) && current_user_can_modify(parent)`（可重命名/删除的父目录能重定向安装路径；read-only carveout 是 bind mount 不能自身被改名，故继续向上走）。
   - `current_user_can_modify(path)`：metadata 读失败⇒true（未验证不得信任）；`uid == geteuid()`⇒true（owner 可先 chmod 再写）；`faccessat2(AT_FDCWD, W_OK, AT_EACCESS)==0`⇒true（内核检查含 POSIX ACL）；否则**仅当 errno ∈ {EACCES, EROFS} 才返回 false**，其它错误一律视为可修改（⇒拒绝）。
   - **拒绝后行为**：跳过该候选、继续 PATH 下一个；PATH 全部不合格⇒回退 bundled bubblewrap；两者皆无⇒`Unavailable`（硬失败）。
2. `codex-rs/sandboxing/src/lib.rs`：`#[cfg(target_os="linux")]` 导出 `find_pre_sandbox_executable_in_path`；非 Linux 的 `system_bwrap_warning` 补 `_sandbox_policy_cwd` 形参。
3. `codex-rs/linux-sandbox/src/launcher.rs`：`preferred_bwrap_launcher()` 拆为 **`initialize_bwrap_launcher(policy, cwd)`**（`OnceLock` 一次性初始化）+ `preferred_bwrap_launcher() -> &'static`（未初始化则 panic）。
4. `codex-rs/linux-sandbox/src/linux_run_main.rs`：在 `run_bwrap_with_proc_fallback` **顶部、proc-mount preflight 之前**调用 `initialize_bwrap_launcher(file_system_sandbox_policy, sandbox_policy_cwd)`（注释：preflight 用「无 writable roots 的合成 policy」，故必须提前按真实 policy 选 launcher）。
5. 调用点改用 **effective** profile + `config.cwd`：`exec/src/lib.rs`、`app-server/src/lib.rs`、`tui/src/app/startup_prompts.rs`（原来传 `config.permissions.permission_profile()`）。
