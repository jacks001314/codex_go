## 0（覆盖缺口）`executorCredentialFromHeaders` 的「恰好 1 个头」分支

- Rust 依据：`codex-rs/exec-server/src/remote.rs:321`（`let token = (headers.len() == 1).then(|| headers.get(AUTHORIZATION)).flatten()`，`resolve_auth:309`）。Rust 的 `HeaderMap` 在插入时规范化 key，所以「len==1」与「按 AUTHORIZATION 查得到」是同一个头；Go 的 `http.Header` **字面量不规范化 key**（只有 `Set`/`Add` 会），所以上一批的实现只取 map 最后一个 key，理论上存在「`Authorization` + `authorization` 两个拼写各带一个合法 Bearer」漏过 count 门的隐患。
- Go 落点：
  - `execserver/remote_credential.go:107-127`：信头门改为顺序无关——遍历所有 key，任一 key 非 `EqualFold("Authorization")` 即拒；再用唯一 values 判 `len(values) != 1`。
  - `execserver/remote_credential_test.go:118-155`：链式用例新增 `two_authorization_spellings`、`non_authorization_header`。
  - `execserver/remote_credential_test.go:157-232`：新增 `TestExecutorCredentialHeaderCountGateLikeRust`，6 个子例（各由**唯一一个**门拒绝：两条 Authorization 拼写 / Authorization+无关头 / 单头两值 / 非 Authorization 头携带合法 Bearer / 空头 / 对照单 Bearer 接受），并断言非法头 registry 命中数 = 0。

- RC 原文（两条门分别撤，分别翻转，证明上一批「只撤 count 门不翻转」的原因是旧用例被其它门兜住）：
