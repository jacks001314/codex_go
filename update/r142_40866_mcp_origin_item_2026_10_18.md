# Rust #40866: originating item IDs in MCP request metadata

Upstream commit: `f5420174dafba153913a3e697f89002c338dfd7e`

## Result

Equivalent implementation was already present.

- MCP request metadata is built from the current thread, session, context window,
  and the invocation's originating Responses item ID.
- Existing meta objects are cloned and current values replace stale thread,
  session, window, or item IDs. Non-object metadata passes through unchanged.
- Direct calls use the item ID captured when the tool call was dispatched.
- Nested Code Mode calls clone the originating invocation context, so they keep
  the original exec item ID even after the cell resumes through a later wait.
- Calls without a known origin omit `itemId`, matching Rust.
