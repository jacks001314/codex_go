## Findings

- Rust #42391 authorizes `apply_patch` in the executor path context. The
  actionable bug in Go was ordering: an out-of-root target was refused before
  the approval callback could run, while Rust asks the user and then derives a
  parent-directory write grant for the approved patch.
- Rust `write_permissions_for_paths` filters already-writable targets, grants
  the target parent, and normalizes the grant under the executor path
  convention. Go previously had no equivalent per-patch grant.
- Rust treats an executor-managed sandbox as always available, so a patch
  constrained to writable paths skips approval there. `Disabled` and
  `External` profiles also auto-approve because they intentionally run without
  an outer sandbox. Go can mirror that for executor filesystems and for those
  profiles.
- Go still has no in-process filesystem sandbox around local `apply_patch`.
  A constrained local workspace-write patch therefore remains on the
  conservative approval path instead of claiming Rust's platform-sandbox
  auto-approval.

## Changes

- `tool/apply_patch_executor.go`: verify the patch and compute its changes
  before deciding that a path is outside the workspace; request approval for
  an out-of-root patch; add `applyPatchWritePermissionsForPaths`,

  grant and recheck executor-convention parent roots; add
  `applyPatchRunsWithoutOuterSandbox` and shared `requestPatchApproval`

  conventions, parent grants, and auto-approved decision reporting.
