# Round 1246: config-server sign-in for CLI login, logout and doctor (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6.

## Why

#57175 was still a plan-only N/A, but Go loaded the managed bundle only from
the app-server, exec and sandbox startup paths. The CLI never signed into a
customer-hosted configuration server, logout never cleared that grant, and
doctor reported effective settings without the required policy.

## What changed

- `app/config_server_login.go`: `newConfigServerAuthManager` (no manager unless
  the server declares OAuth), `ensureConfigServerLogin` (reuse the stored grant,
  sign in only on `auth.ErrGatewayLoginRequired`), `logoutConfigServer`, and
  `loadManagedLoginConfig` (reload with the config-server bundle applied). The
  bundle loader now builds its manager through the same helper.
- `app/app.go`: `login` with a required config server signs into that server
  instead of ChatGPT for the browser and device-code flows, and signs in before
  storing an API key or access token; `login status` never signs in. `logout`
  clears the config-server grant and reports success when either credential set
  was removed.
- `doctor/doctor.go`: `Options.ManagedConfigLoader` plus the new managed branch
  of `loadEffectiveConfigForDoctor` make `config.load` fail when a required
  config server has no applied bundle or when the applied server differs from
  the requirement; `app` injects the loader at the doctor call site.

## Tests

- `app/config_server_login_like_rust_test.go`: manager requires OAuth, the grant
  is reused until logout and the next sign-in only happens afterwards, and an
  absent server is a no-op.
- `doctor/config_server_like_rust_test.go`: the required server's bundle is
  applied and reported, a bundle from another server fails `config.load`, and a
  missing loader fails with `config.ErrConfigServerMismatch`.
- `go test ./app ./doctor ./config` passes.

## Residual

Rust signs into the config server during interactive TUI startup
(`tui/src/startup_orchestration.rs`) and preserves the app-server's
config-server settings and refresh worker across OpenAI login/logout
(`app-server/src/config_manager.rs`). The TUI slice belongs to the parallel TUI
agent, and Go's app-server applies the bundle once per run with no refresh
worker.
