### Implemented this cycle

1. `657bd889ae` #39316 "Support Edu Plus and Edu Pro account plans"
   - Rust recognizes `edu_plus`/`edu_pro` as distinct education workspace plans
     across auth parsing (`protocol/auth.rs`), workspace classification
     (`is_education_like`/`is_workspace_account`), backend rate-limit mapping,
     cloud-config eligibility, usage-limit messages, and TUI display names.
   - Go gap: `auth/account.go` and `chatgptapi/backend_models.go` lack the two
     variants; `accountPlanTypeFromBackend` maps them to unknown;
     `sandboxCloudConfigEligibleAuth` and `PlanTypeDisplayName` lack education-like
     handling.
2. `1bfabb21fe` #39594 "Raise the MCP tool name limit to 128 bytes"
   - Rust `MAX_TOOL_NAME_LENGTH` 64 -> 128 so model-visible names survive to the
     Responses API 128-byte boundary.
   - Go gap: `mcp/tool_runtime.go` `runtimeMCPToolNameMaxLength` is still 64.
3. `fdc23b93b8` #39637 "Treat `invalid_grant` refresh failures as permanent"
   - Rust classifies `400` + `invalid_grant` (RFC 6749 string form, plus the
     legacy object form) as a permanent refresh failure that is cached, while
     other 400s stay transient/retryable.
   - Go gap: `auth/oauth.go` only treats 401/legacy subtypes as permanent, and
     `auth/refresh_failure.go` `extractRefreshTokenErrorCode` cannot see the
     plain-string `{"error":"invalid_grant"}` shape.
4. `186b449bc2` #39607 "Resolve model-provided shells by type"
   - Rust uses a model-provided path only to select the shell type, then resolves
     the executable through normal discovery/fallback (`get_shell(shell_type)`),
     keeping the packaged zsh fork when configured and present.
   - Go gap: `shell/command.go` `GetShellByModelProvidedPath` returns the
     provided path verbatim; no `GetShell(shellType)` discovery exists.
5. `f277e313f1` #39700 "Fail closed on unsafe config and sed parsing"
   - Rust adds `sed_has_in_place_flag` (`-i`, `--in-place`, combined short flags,
     backup suffixes, `--` boundary) so in-place `sed` stays an unknown/mutating
     action instead of a read; app-server config loads propagate the unsupported
     untrusted-policy error instead of falling back.
   - Go gap: `shell/command.go` `sedReadPath` does not detect `-i`/`--in-place`
     and can classify an in-place `sed` as a file read. The app-server config
     part is equivalent: Go config loads already propagate errors (no
     default-config fallback in the Go daemon startup path).
6. `14a8ac89af` #39385 "Prefer the most recent session when queueing by name"
   - Rust resolves duplicate exact-name queue targets to the most recent session
     instead of rejecting them as ambiguous, and prefers state-db matches before
     rollout scanning.
   - Go gap: `app/session.go` `sessionIDByUniqueActiveName` /
     `lookupRemoteSessionUniqueByName` reject duplicates with an ambiguity error.
7. `f5e9d66851` #39157 "Notify clients when Guardian requires strict review"
   - Rust adds `autoApprovalReview/strictReviewRequired` with
     `StrictReviewRequiredNotification {threadId, turnId, startedAtMs}`.
   - Go gap: `appserver` had no such notification method/type; the generated
     protocol schema did not match the Rust fixture.
