## Ported changes

### #58751 live paginated history

- `appserver/runtime_router.go`: `paginatedRunningResumeInitialTurnsPage` now
  gates the active turn on `resumeActiveTurnBelongsInInitialPage`. A descending
  page still leads with the live turn; an ascending page only carries it when
  the prepared page already holds it or is the final, underfilled page. The
  unconditional Asc append is gone.
- `state/thread_history_query.go`: `threadHistoryItemsPageQuery` forces
  `sqlite_autoindex_thread_items_1` for item-id reads, taking precedence over
  the turn-page hint (Rust's `page_item_rows` change).
- Eviction and `restore_evicted_agent_text` have no Go counterpart: Go projects
  the active turn from session items on demand instead of retaining a live
  `ThreadHistoryBuilder`, so full resumes already carry every agent message.
  The user-visible contract (summary vs full parity) is covered by the existing
  `thread_items_*`/`attached_thread_*` suites.

### #58720 pending approvals in the subagent picker

- `tui/tea/modal.go`: `ApprovalRequestMsg` carries `ThreadID` and the approval
  modal remembers it. `openNextThreadApproval` only surfaces the active
  thread's requests; another thread's request stays queued.
- `tui/tea/thread_approvals.go` (new): `routeApprovalRequest` queues requests
  addressed to an inactive thread, `pendingApprovalThreadIDs` derives the
  waiting set from that queue plus the open modal, `threadLabel` mirrors
  Rust's `thread_label` (agent path first for non-primary threads,
  `Main [default]` for the primary thread, UUID-tail suffixes for anonymous
  agents), `openPendingApprovalForThread` replays a waiting request when its
  thread is selected, and `dropStaleThreadApprovals` forgets requests whose
  connection is gone.
- `tui/tea/agent.go`: picker rows put waiting threads first (stable order),
  suffix their label with `(needs approval)`, select the first waiting row when
  the picker has no remembered selection, keep the selected thread across
  reorders, and add a row for a thread whose approval arrived before its
  metadata.
- `tui/tea/model.go`: approval dispatch routes through `routeApprovalRequest`,
  a disconnect drops stale requests, thread switches replay waiting approvals,
  and `renderBottomPane` paints the notice above the pending-input preview.
- `tui/bottom_pane/pending_thread_approvals.go`: hint is now
  "/subagents to review requests".
- `app/remote_tui.go`: approval requests carry `params.ThreadID`
  (`ConversationID` for the legacy params), writes are serialized, and
  operator-facing requests are answered from their own goroutine so a request
  waiting on an inactive thread cannot stall notifications.
- `app/interactive.go`: the embedded turn stamps its approval with the thread
  id (`shellApprovalFuncForThread`).

### #58718 inset conversation rendering

- `tui/tea/conversation_inset.go` (new) + `Options.ConversationInset`:
  `ConversationRect{X,Y,Width,Height}` renders the conversation inside the
  supplied rectangle. The transcript and composer reflow to the inset width,
  rows outside the rect stay blank for the host's own content, cursor and
  selectable rows are translated into viewport coordinates, and full-screen
  surfaces (pager, dashboard, session picker, centered dialogs) keep the whole
  viewport, matching Rust's centered-dialog behaviour.
- `tui/tea/model.go`: `resize` split into `applyLayoutSize` (layout only) plus
  the telemetry/reflow tail, so a one-frame inset render does not record a
  bogus terminal-size observation.

### #58722 backend session helpers — not applicable

- Rust's `BackendSessions::displayed_name`, `first_listening_backend` and
  `next_listening_backend` read a multi-backend registry that the commit itself
  marks `dead_code` ("used by the next stack stage"). Go binds one app-server
  backend per TUI process (`Options.BackendID`, `codextui.ProcessBackendID`)
  and has no registration-order list of listening sessions, so there is no
  equivalent state to name or cycle. Porting the helpers would require
  introducing the whole backend registry first.

### The CSP finding

The independent security review of the new inline-visualization runtime found a
real defect the lane's own string assertions could not see: the outer shell CSP
was `default-src 'none'; style-src 'unsafe-inline'; frame-src 'self'`, and a
`srcdoc` frame inherits it, so every injected script — the new tabs, carousel
and tooltip runtime included — was blocked by the browser. Chrome 149 confirmed
the regression.

`bfb82dab` now mirrors Rust's `viewer.rs` relationship (shell = frame CSP with
`frame-src 'self'`), replaces the bare `https:` wildcard with the seven
explicit CDN hosts, keeps `default-src 'none'` and `sandbox="allow-scripts"`,
and adds a viewer-cache symlink check. The new tests extract the real script
body from the shell's `srcdoc` and execute it under a DOM shim, so a future CSP
regression fails immediately.
