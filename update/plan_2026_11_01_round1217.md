# Round 1217: Managed provisioning policy and the accept loop (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342, crate
windows-sandbox-service; `machine_policy.rs` and `ipc::run`).

## Context

Round 1216 persisted the authenticated owner, but nothing enforced managed
policy and nothing drove the pipe: `HandleRequest` needed a `PolicyValidator`
that did not exist, and `RunService` had no production broker. This round adds
both.

## Managed policy

`windowsandboxservice/machine_policy.go` ports
`machine_policy::validate_requirements`: managed policy must permit the elevated
Windows sandbox (a present allow-list that omits it fails closed), a disabled
network rejects any proxy port or local binding, `allow_local_binding = false`
rejects local binding, `http_port`/`socks_port` admit only listeners on the
required port, and every proxy port must be classified by a listener or by the
required ports so omitting listener identities cannot bypass the restriction.

`LoadManagedRequirements` ports the configuration load: bootstrap the owner's
configuration with the managed layer, resolve cloud configuration
authentication, build the ChatGPT bundle loader (default endpoint, host network
policy, no cache namespace), reload with the bundle and return the merged
requirements. Non-enterprise identities contribute only on-disk requirements.

`machine_policy_windows.go` adds `ValidateProvisioningRequest` and
`MachinePolicyValidator`: a registered-Core refresh keeps the existing sandbox
and never starts the configuration runtime, every other request loads the policy
while impersonating the owner, and an impersonation or load failure fails closed.

## Accept loop

`windowsandboxservice/broker_windows.go` ports `ipc::run`: open the listener,
publish readiness, refresh the recorded owner before blocking and again after
each accept, skip disconnected wakeups, authorize the client process before
dispatching, run `HandleRequest` with the policy and handler, write one framed
response and refresh the listener. `NewProvisioningBroker` assembles the SCM
broker: readiness reports `SERVICE_RUNNING` and logs `EVENT_SERVICE_STARTED`,
requests run `RunProvisioning` with the lifecycle as owner registrar, and the
managed-policy validator is enforced before provisioning.

## Known gaps

Owner-aware cleanup between sessions (`runtime_lifecycle::run`'s restore and
`PackageLifecycle::clean_up`), `provisioning/registered.rs` refresh, package
uninstall observation and the cleanup journal, `ServiceStopReason` diagnostics,
WTS session restore, retained-handle setup launch, the registered-runtime
transactions and the service binary itself remain open.
