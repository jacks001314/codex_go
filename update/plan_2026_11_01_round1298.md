## The gap

Rust's `PreparedEnvironmentManager::prepare_from_codex_home` and
`prepare_from_env` consult `noise_environment_config_from_env()` first: when
`CODEX_EXEC_SERVER_NOISE_REGISTRY_URL`, `..._ENVIRONMENT_ID` and `..._AUTH_TOKEN`
are all set the registry executor becomes the single remote default (no local
environment); a partial configuration is an error. Go parsed the registry
configuration (`RegistryNoiseRendezvousConnectProviderFromEnv`) but no host used
it, and `parity.json` still recorded the in-process hosts as running locally.

## What changed

- `execserver/environments_toml.go`: `EnvironmentTransportNoise` transport kind
  carrying a `NoiseRendezvousConnectProvider`, `NoiseEnvironmentProviderSnapshot`,
  and the `PrepareEnvironmentProviderFromCodexHome` / `PrepareEnvironmentProviderFromEnv`
  bootstrap with Rust's noise-first precedence.
- `tool/unified_exec_environments.go`: the provider default installs the
  registry transport on unified exec as `NoiseProvider`.
- `app/app.go`, `app/local_environments.go`, `exec/exec.go`: app-server startup,
  `codex exec`/`codex review`, the TUI in-process runner and `--worktree` all use
  the prepared provider, so `--worktree` rejects a registry default too.
- `parity.json`: `executor-environment-toml-provider` moved to `done`.
