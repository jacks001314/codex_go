## 42375: desktop uninstall ownership

Rust records desktop uninstall ownership from `initialize_processor` whenever a
`Codex Desktop` client connects over stdio:

- the registration is a bounded, awaited attempt before the response, so a
  background registration cannot race an uninstall;
- a failure is a warning, never an initialize error;
- ownership must not depend on account sign-in or sandbox setup.

`appserver/windows_sandbox_runtime.go` now ports that call:
`registerDesktopUninstallOwnership` runs only on Windows, only for the `stdio`
transport and the exact `Codex Desktop` client name, and calls the service
through `registerDesktopWindowsUninstallOwnership`
(`provisionservice.Client.RegisterDesktopInstallation`, Round 1206). A failure
logs `could not register desktop uninstall ownership` and leaves the response
intact.

## 58380 follow-up: stale vendored export pins

`appserver`'s precomputed-export gate compared the vendored
`app-server-exports-{stable,experimental}.json.zst` artifacts against SHA-256
pins from the previous re-vendor. Round 1195 copied the artifacts from the
current 67f0994b tree byte-for-byte but left the pins behind, so
`TestPrecomputedExportArtifactsMatchTargetRustCommit` failed for the whole
package.

The two artifacts were re-hashed and checked against the pinned Rust checkout
(`app-server-protocol/schema/precomputed/`): the vendored bytes are identical
(`5a93be76...` stable, `72216e63...` experimental), so the pins are corrected
rather than the artifacts.

## Known gaps, deliberately not faked

Go ships no `windows-sandbox-service` binary, so the registration reaches only
an installed service and fails closed with a warning otherwise. The service-side
desktop-installation record write, package-lifecycle cleanup and uninstall
policy execution remain unimplemented (Round 1207 carries the record and policy
code they will run).

## Coverage

`appserver/windows_sandbox_desktop_registration_like_rust_test.go` pins the
stdio/`Codex Desktop` gate (other clients and transports never register), the
recorded Codex home, and that a failed registration still answers initialize

Verified with `go build ./...`, `go test ./appserver -count=1`,
`go test ./sandbox/... -count=1` and `go test ./execserver -count=1`.
