## Context

Guardian review threads reuse synthetic approval prompts as user messages.
Deriving thread titles and previews from those prompts makes listings show
large, useless summaries. Rust #47302 keeps the prompts out of display
metadata and defaults Guardian threads to `Guardian review` / `Approval review`.

## Implementation

- `session/source.go` owns `GuardianThreadTitle` and `GuardianThreadPreview`
  next to `IsGuardianReviewSource`, the Go mirror of
  `codex_state::is_guardian_review_source`.
- `state/backfill.go` adds `metadataIsGuardianReview` and
  `applyGuardianDisplayDefaults`. Guardian projections skip `user_message`,
  the `item_completed` user-message arm and `thread_goal_updated`, so
  `title`, `preview` and `first_user_message` come from the compact defaults.
  `upsertRolloutThread` keeps an explicit title already stored for the thread
  instead of overwriting it with the Guardian default.
- `rollout/rollout.go` `BuildThreadItem` reports `Approval review` and an
  empty `FirstUserMessage` when the session meta source is a Guardian review,
  matching Rust's `read_head_summary` short circuit.

## Re-audit

`#47275` (enable Guardian thread context by default) is a strict predecessor of

`threadContext = true` in `appserver/guardian_reviewer.go` and registers
`guardianv2.thread_context` as a removed compatibility no-op, so the default-on
behaviour and the in-flight invalidation contract are both present.
