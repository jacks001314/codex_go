# `#45779` Use native process identities for PID-managed daemons

Rust 依据：`c0316291ca477b8355c0c4f20784f4863ee30f5a`。

## 落地内容

- `PIDRecord` 新增 `processIdentity`，wire shape 与 Rust untagged
  `ProcessIdentity` 对齐：`bootId + startTicks`、`startSeconds +
  startMicroseconds`。
- Linux：
  - 直接解析 `/proc/<pid>/stat`，以最后一个 `)` 之后的字段定位 state 与
    starttime，避免 comm 中的空格/括号干扰；
  - 记录 `/proc/sys/kernel/random/boot_id` + kernel start ticks；
  - 匹配时先校验 boot id，再比较 start ticks，不再依赖 `ps` 的
    locale/timezone 文本；
  - zombie 仍按 start ticks 匹配后 reap。
- macOS：
  - 使用 `x/sys/unix.SysctlKinfoProc("kern.proc.pid", pid)` 读取 native
    `kinfo_proc.P_starttime`，记录秒/微秒与 zombie 状态，不再依赖
    `ps -o lstart` 文本。
- 启动路径：新进程在记录 legacy `processStartTime` 的同时写入 native
  identity；identity 读取失败会终止刚启动的子进程并报错。
- updater 启动后调用 `PromoteLegacyIdentity`：仅当 legacy 记录仍匹配、且前后
  两次 native identity 一致时，原子重写 PID 记录补上 identity。
- Windows 保持 `processStartTime`，并继续把访问受限 PID 的
  `OpenProcess` 错误向上传播，而不是当作 stale。

## 剩余差异

Rust 的 macOS `MacOsUnique` 还读取 `proc_pidinfo` flavor 17 的
`unique_id` 与 `kern.bootsessionuuid`，用于跨用户身份校验。Go 标准库和
`x/sys/unix` 只暴露 `kinfo_proc`，没有 `proc_pidinfo`；在不引入 cgo 的前提下
无法读取该 unique ID。因此 Go 使用 Rust 同样支持的 timestamp-only
`MacOs` 形态（native start time），但缺少 macOS 的 boot-id/unique-id 双重
校验。该限制记录为 partial，而不是静默跳过。
