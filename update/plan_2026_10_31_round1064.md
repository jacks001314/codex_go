## Goal

Carry host-trusted HTTP headers on remote exec-server WebSocket handshakes and
reconnects, with loopback-only DNS resolution for plain `ws://` destinations.

## Findings

- Rust #42606 adds `RemoteEnvironmentOptions`/`upsert_environment_with_options`,
  validates headers (invalid, duplicate, and connection-controlled names),
  requires `wss://` or a loopback destination, and connects header-bearing
  `ws://` loopback targets directly with DNS results restricted to loopback.
- Go already normalized and redacted headers in
  `execserver/connection_headers.go` and reused them across reconnects, but it
  dialed through the default HTTP transport without restricting DNS answers to
  loopback or bypassing configured proxies.
- Go's host plumbing uses `DialClientOptions.HTTPHeaders` and
  `tool.UnifiedExecEnvironment.ExecServerHTTPHeaders` instead of a separate
  environment registry options struct.

## Implementation

- `execserver/connection_headers.go`: added `loopbackWebSocketAddresses` and
  `loopbackDirectWebSocketClient`, which dials only resolved loopback addresses
  without a proxy and fails when none of the answers is loopback.
- `execserver/client.go`: header-bearing `ws://` dials now use the direct
  loopback client for the initial connection and for every reconnect.
- `execserver/connection_headers_loopback_test.go`: covers filtering mixed DNS
  answers, rejecting non-loopback resolution, the proxy bypass, and a real
  header-bearing handshake over `ws://localhost`.
