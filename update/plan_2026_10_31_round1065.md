## Goal

Withdraw pending network policy reviews when a remote process finishes without
turning the completed command into a review failure, while keeping explicit
denials as the reported call outcome.

## Findings

- Rust adds `NetworkRequestCancellation`/`NetworkRequestCancellationReason`,
  records `ProcessFinished`, `ProcessCancelled`, `ConnectionClosed`, and
  `TimedOut` at the exec-server session level, and skips the failure outcome
  when the reason is `ProcessFinished`.
- Go's exec-server client already withdraws a pending review when the process
  session closes: `clientProcessSession.cancelNetworkPolicy` closes
  `policyDone`, `handleInboundRequest` then answers deny, cancels the decider,
  and never writes a failure outcome. `TestClientNetworkPolicySubscriptionClose
  CancelsPendingWithoutLateWriteLikeRust` and
  `TestClientNetworkPolicyTimeoutFailsClosedLikeRust` pin this behavior.
- Go's appserver network approval recorded a user denial only after
  `persistNetworkPolicyAmendment` returned, so a process finishing during the
  execpolicy write could observe an empty outcome and report the command as an
  unqualified success (Rust #42746 stores `rejected by user` first).

## Implementation

- `appserver/network_approval.go`: the network approval service now owns an
  injectable `persistAmendment` function, and a deny network-policy amendment
  records `rejected by user` before waiting for persistence.
- `appserver/network_approval_denial_before_persist_like_rust_test.go` holds
  persistence open, finishes the call, and asserts the denial outcome survives.
