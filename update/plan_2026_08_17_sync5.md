## Gap: delegate sessions must run with approval policy `never` (#38205)

Rust semantics (codex_delegate.rs + mcp_tool_call.rs + mcp_skill_dependencies.rs):

1. Delegated sessions always run with `AskForApproval::Never`; `run_codex_thread_interactive`
   rejects delegate creation with any prompt-capable policy and pins the config
   with `Constrained::allow_only(Never)`.
2. Approval-requiring commands and MCP tool calls are denied within the delegate
   (never -> `Decision::Forbidden` / `ReviewDecision::denied("MCP tool call
   requires approval, but approval policy is never")`), not forwarded to the
   parent session.
3. Missing skill-MCP dependency prompts are skipped with never (already aligned
   in Go: turn_runtime.go `maybePromptAndInstallSkillMCPDependencies`).

Go previously let subagent (delegate) turns inherit the parent's approval
policy, so approval-requiring actions could reach the parent. Implemented the
central enforcement:

- `appserver/runtime_router.go`: `runtimeRecordIsSubagent` (subAgentThreadSpawn /
  Originator=subagent / subagent review-compact-other / memory consolidation
  sources) + `prepareTurnStartParams` pins `params.ApprovalPolicy = never` for
  every subagent turn (spawn, send-input, resume).
- With never, the existing deny paths apply inside the delegate: shell
  escalation reject (tool/shell.go), MCP elicitation auto-decline
  (mcp_elicitation.go), network no-prompt (network_approval.go), skill-MCP
  dependency skip (turn_runtime.go) - previously only reachable when the whole
  session configured never.
