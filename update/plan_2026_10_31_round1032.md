## Goal

Audit #42113 (apply remote platform semantics to exec safety checks) and
implement the parts that have a faithful Go code path.

## Findings

- Rust threads `DangerousCommandPlatform` through command parsing, executable
  identity, dangerous-command classification, and unmatched-command approval
  heuristics. It derives the target from
  `turn_environment.executor_platform_os`: `linux`/`macos` use POSIX,
  `windows` and every other reported value use Windows rules conservatively,
  and an absent value falls back to the host.
- Go has the `DangerousCommandPlatform` type and executable lookup key, but no
  `dangerous_command_match`/`dangerous_powershell_words_match` classifier and
  no exec-policy unmatched-command heuristics. Approval in Go comes from the
  sandbox override and approval policy, so there is no equivalent call site to
  receive a target platform. Porting only the platform parameter would be dead
  code and would not change behavior.
- Go's own Windows shell safety validation keys off the resolved shell type and
  its path checks use host path semantics; it is not a replacement for Rust's
  classifier and does not implement remote-platform dangerous-command rules.
- The non-classifier parts of #42113 are applicable:
  - Rust normalizes executable identities using the target platform (basename,
    Windows drive prefix, case folding, `.exe`/`.cmd`/`.bat`/`.com` suffix).
  - A failed `exec_command` reports a model-facing message bounded to 900
    retained bytes with middle truncation, does not prepend the rejected
    command, and keeps deterministic process IDs reserved after release.

## Implementation

- `execpolicy/execpolicy.go`: `executableLookupKeyForPlatform` now strips the
  target platform's directory syntax, removes a Windows drive prefix, lowercases
  Windows names, and strips executable suffixes. POSIX keeps case and suffix,
  but takes the basename after `/`.
- `tool/shell_executor.go`: launch/execution failures return
  `exec_command failed: <error>` through `RespondToModel`, with middle
  truncation at 900 retained bytes. Cancellation and deadline errors stay
  unwrapped so `errors.Is` and the exec span still classify them.
- Unified-exec process IDs were already monotonic (`nextID` only advances), so
  no production change was needed there; a regression test now proves a
  released ID is not reused.
