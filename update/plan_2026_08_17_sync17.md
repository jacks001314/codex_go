1. `772e88c8ae` #38916 "Honor legacy `:project_roots` permission entries"
   - Rust `parse_special_path` now treats `:project_roots` as an alias for
     `:workspace_roots` (deny rules + read-only subpath carveouts in legacy
     profiles must not fail open).
   - Go `config/permissions.go` `specialFilesystemPath` already maps
     `:project_roots` -> `project_roots` kind (pre-existing alias). Gap =
     no Go test proving the legacy profile behavior (deny + carveout).
2. `c8ddb210d2` #38918 "Improve `codex doctor` network diagnostics"
   - Rust probes the configured Responses inference endpoint through the
     route-aware HTTP client (proxy + custom CA), classifies TLS / proxy-auth /
     invalid-proxy / proxy-resolution / timeout / unsupported-proxy-scheme /
     resolver / connect failures into actionable diagnostics, reports
     privacy-safe macOS system proxy state, and suggests enabling
     `respect_system_proxy` when a configured proxy is otherwise unused.
   - Go `doctor` has `network.env` (proxy env vars + custom CA file checks) and
     `network.provider_reachability` (HEAD/GET probe + /models route probe) but
     the probe uses a bare `http.Client` and `classifyHTTPProbeError` only
     distinguishes timeout vs connect-failed. Gap = failure classification +
     route-aware (system proxy + custom CA) probe client + respect_system_proxy
     / managed-proxy config detail.
3. `935b1c4e3d` #38919 "Reject obsolete app-server permission profile fields"
   - Rust rejects `permissionProfile` with invalid_params (-32602) on
     `thread/start`, `thread/resume`, `thread/fork`, `turn/start` and directs
     clients to `permissions` with a named profile; unrelated unknown fields
     stay accepted.
   - Go `appserver/protocol.go` `Request.Validate()` currently rejects nothing
     extra and all Validate errors surface as -32600. Gap = rejection + -32602
     classification on the four methods + unknown-field acceptance tests.
4. `1f41cc5d92` #38921 "Compact successful command activity in the TUI"
   - Rust `ExecCell` groups consecutive successful Agent / UnifiedExecStartup
     commands into a compact `Ran N commands` entry (full transcript preserved),
     flushes at interaction boundaries / after failures / after 32 commands,
     and applies the same rules on replay.
   - Go `tui/exec_cell` already mirrors the pre-change Rust model (exploring
     cells, complete/flush) but has no groupable sources, no 32-command cap,
     no compact group display, and the tea model renders every command
     execution as its own message. Gap = exec_cell grouping model + compact
     render + tea model accumulation with flush points.

## Gap implementation

### G1 (#38916) legacy `:project_roots` alias - test-only

- `config/permissions_test.go`:
  `TestLegacyProjectRootsRestrictionsDoNotFailOpenLikeRust` mirrors Rust's
  `legacy_project_roots_restrictions_do_not_fail_open`: read_deny/write_deny
  with `":project_roots" = "none"` deny at the cwd, write_read with
  `":project_roots" = { docs = "read" }` resolves docs to read-only.

### G2 (#38918) doctor network diagnostics

- `doctor/doctor.go`:
  - `classifyHTTPProbeError` extended to classify TLS handshake/cert errors,
    proxy authentication (HTTP 407 + proxyconnect), invalid proxy config,
    system proxy configuration unavailable, unsupported proxy scheme, proxy
    resolution failure, timeouts, connect failures - mirroring Rust
    `RouteAwareRequestError::failure_class` messages.
  - `providerHTTPClient` upgraded to a route-aware client: system proxy
    respected (per config) and custom CA env (CODEX_CA_CERTIFICATE /
    SSL_CERT_FILE) loaded, matching Rust's route-aware pool behavior.
  - `network.env` check gains "respect system proxy: enabled/disabled" and
    "managed proxy: configured/not configured" details from the effective
    config (Rust `check()`); macOS system proxy reporting is platform-gated
    (N/A on Windows host, documented).
- `doctor/doctor_test.go`: classifier unit tests + route-aware client tests.

### G3 (#38919) reject obsolete `permissionProfile`

- `appserver/protocol.go`:
  - New `ErrInvalidParams` sentinel + `obsoletePermissionProfileError`.
  - `Request.Validate()` rejects `permissionProfile` on the four methods with
    the Rust message (`permissionProfile is no longer supported for <method>;
    use permissions with a named profile id instead`).
- `appserver/router.go` / `runtime_router.go` / `stdio.go`: the three request
  entry points classify `ErrInvalidParams` as -32602 (invalid params) while
  keeping -32600 for generic validation errors.
- `appserver/protocol_test.go`: rejection on all four methods, unknown-field
  acceptance, connection stays usable.

### G4 (#38921) TUI compact command activity

- `tui/exec_cell/model.go`: `ExecSourceUnifiedExecStartup`,
  `isGroupableSource`, `MAX_GROUPED_COMMANDS = 32`, reworked `WithAddedCall`
  (continues exploration / continues compact group), reworked `ShouldFlush`
  (flush at 32, on failure, on non-groupable source when inactive; keep
  compact groups un-flushed while all calls are groupable/successful).
- `tui/exec_cell/render.go`: `compactGroupDisplayLines` ("Ran N commands" +
  remaining calls) and `commandCallDisplayLines` extraction.
- `tui/tea/model.go`: active compact-group tracking (message index + cell),
  `renderCommandExecutionItem` accumulates consecutive successful
  Agent/UnifiedExecStartup completions into the compact group (source read from
  item metadata), flushes on failures / non-groupable sources / interaction
  boundaries (submit, slash, approval, MCP elicitation, request-user-input,
  turn completed/interrupted, other non-command items).
