# Round 1294 — view_image hides detail under the unified image budget

Rust target: `67f0994b532b8740f14b5b738af7b7b2a915b1d6` (anchor worktree
`D:\qax\reagent\dev\git\codex-anchor-67f0994b`, hash `67f0994b`).

## The gap

Rust's `unified_image_budget_enabled`
(`core/src/image_preparation.rs`) turns on image-detail hiding when the feature
is enabled and the model either uses Responses Lite or accepts original detail.
`view_image_spec.rs` then

- omits the `detail` input property
  (`options.can_request_original_image_detail && !options.unified_image_budget`), and
- omits the output `detail` property, leaving `required: ["image_url"]`;

`view_image.rs` keeps `ImageDetail::Original` for every call
(`use_original_detail = options.unified_image_budget || ...original`) and
`ViewImageOutput::code_mode_result` returns only `{ "image_url": ... }`.

Go always advertised `detail`, returned the requested hint, and exposed it to
Code Mode, so a unified-budget model kept seeing a detail surface Rust hides.

## What changed

- `tool/view_image.go`: `ViewImageOptions.UnifiedImageBudget` and
  `ViewImageStepSettings.UnifiedImageBudget`; the spec drops the input and output
  `detail` fields (required becomes `image_url`); `Execute` resolves
  `imageDetail` as Rust does (original whenever the budget hides detail) and
  leaves `detail` out of the result/Data, while the content item still carries
  `original`.
- `appserver/runtime_router.go`: `unifiedImageBudgetEnabled(cfg, info)` mirrors
  the Rust predicate and feeds the turn options, the per-step surface refresh and
  the call-time `StepSettings`.
- `exec/exec.go`: the CLI view_image options resolve the same flag from the
  turn's feature settings and model info.

## Also fixed

Round 1292 removed Go's embedded "Enabled nested command tool" block, and three
`appserver` tests had read the shell selector (or the tool-catalog size) out of
it:

- `stable_environment_tools_like_rust_test.go` and
  `runtime_router_test.go` (unified exec remote environment) now read the
  registered nested `exec_command` spec, because Rust renders nested schemas
  only in `code_mode_only`. Coverage is unchanged.
- `post_turn_compact_test.go` asserted that a zero post-turn threshold means the
  compact runner never runs. The now-longer bundled tool surface can legitimately
  trip a pre-turn `contextWindowExceeded` compaction, so the test asserts only
  that no `PostTurn` compaction ran — the Rust gate it covers.
