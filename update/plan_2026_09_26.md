## Why the model lives in its own package

Go's `history` package is the counterpart of Rust's **`message-history`** crate
(the append-only global `history.jsonl`: `history.go` / `message_history.go`
mirror `message-history/src/lib.rs`). Rust's **`codex-history`** crate
(`history/src/lib.rs` and its `retained_context` / `retained_source` /
`retained_assistant_messages` / `sender_user_messages` / `heartbeat` /
`reconciled_retained_context` modules) had no Go counterpart at all, so the port
lands as `codex_go/retainedctx` and the Go top-level directory inventory is
re-pinned (`parity/rust_inventory_test.go`).

Go also has no typed `CodexHarnessMetadata` (persisted items carry
`Metadata map[string]any`), so the package takes the typed view it needs
(`retainedctx.HarnessMetadata`: `user_input_order`, `inherited_user_message`,
`sender_user_messages`). Wiring the rollout/compacted-item wire to the typed
metadata is recorded below as the follow-up.

## sync215: the retained-context model (`codex-history`)

`retainedctx` ports the bounded, host-owned evidence families that live outside
the model's compaction contract, with Rust's admission rules intact:

- **`heartbeat.go`** - `HEARTBEAT_CONTENT_KIND`, `UserInputOrigin`
  (`FromTurnTrigger`, `FromMessage`, `IsUser`), and `Heartbeat`
  (`ParseHeartbeat`, `HeartbeatFromMessage`). `ParseHeartbeat` reproduces Rust's
  byte-budget guard (`len + lines*6 + 64 > 3600` with `str::lines()` counting),
  the single-trailing-newline strip, the exact envelope prefix/suffix, and the
  automation-id/timestamp byte-class limits. The Go zero value is normalized
  onto `User` so an unset origin never round-trips into a different stored value.
- **`retained_source.go`** - `ResponseItemID` (`NewResponseItemID("retained")`,
  UUIDv7), `RetainedSourceRole`, `RetainedSourceID`, `RetainedSource`, plus
  `RestoreSourceRevision` and `Source` (delivery proof requires both a message id
  and a recorded revision).
- **`retained_context.go`** - `VerifiedQuestionAnswer`, `VerifiedAnswer`,
  `RetainedUserMessage` (skips the ordinary-user origin on the wire, defaults it
  on decode), `RetainedInputSource` (`Local(order)` / `Inherited`),
  `RetainedContextOrder` (inherited prefixes order before local acceptance
  order), `RetainedContextEntry` / `OrderedEntry`, `RetainedContextEvent`
  (internally tagged `verified_answer`), and `RetainedContext` itself with
  Rust's serde layout: `verified_answers` + `incomplete`,
  `user_messages` + `user_messages_incomplete` (legacy default **true**),
  `assistant_messages` + `assistant_messages_incomplete`, `next_order`, and the
  empty-skipped `sender_deliveries`. Storage limits are `MAX_FAMILY_RECORDS = 8`,
  `MAX_RECORD_BYTES = 16_384`, `MAX_FAMILY_BYTES = 65_536`; `boundFamily` sorts
  by acceptance order (not persistence order) and evicts the oldest, marking the
  family incomplete; `RetainedUserMessage.bound` clears text/incompleteness and
  truncates ids at a char boundary; `RetainedContextEvent.Bound` clears an
  oversized answer's questions and truncates its ids.
- **`retained_messages.go`** - `RecordUserMessage` (heartbeat coalescing that
  compares only the latest version of the same automation, id-based replacement,
  inherited prefix order via `next_inherited_order`, revision minting,
  `verified_answers_incomplete |= inherited`), `RecoverUserMessageExcerpts`,
  `Record`, `Restore` (deep copy, re-bound every family, repair pre-adoption
  checkpoints, re-derive `next_order` from surviving item metadata), and
  `Rollback` (boundary by acceptance order or first removed message id; the
  legacy fallback by turn id, with inherited/local scoping).
- **`retained_assistant_messages.go`** - `RecordAssistantMessage`, including
  #48158's rules: an unsequenced `Local(None)` source is left to legacy
  transcript selection; a **complete, empty** assistant message is neither
  recorded nor a dedup hit (an id collision removes the stale record instead);
  an incomplete message keeps its omission notice; `HasOmittedAssistantMessages`
  reports storage loss or an undeliverable record.
- **`reconciled_retained_context.go`** - `LiveUserMessage`,
  `NewReconciledRetainedContext` (source-identity matching before ordering,
  conflicting/absent orders mark the result incomplete, latest ordered user turn
  tracking), `OrderedEntries` (with heartbeat-version coalescing after ordering,
  scoped per inherited/local prefix), and `UnmatchedUserMessages`.

Tests mirror Rust's suites: `retained_context_tests.rs` (order through recovery,
checkpoint and rollback; family storage limits without changing snapshots;

### sync216: unique exec-server process IDs for every request (#48168)

Rust previously suffixed a fresh UUID onto the exec-server process id only when
the request carried sandbox or shell-snapshot settings; a thread sharing an
executor, or a sandbox retry, could reuse a public handle while the executor
still retained its previous process. The suffix is now unconditional.

Go's unified-exec remote start built `remoteID` as the bare stringified public
process id, i.e. exactly the pre-#48168 "no suffix" branch, so it had the same
collision window.

- **`tool/unified_exec.go`**: `remoteID` is now
  `"<public id>-<uuid v4>"`. The public id keeps addressing the session
  (`unifiedExecProcess.id`, the tool's process list, writes and signals), while
  the suffixed value is what the executor is addressed with: process-event
  subscription, network-policy controller registration, `ExecParams.ProcessID`
  and every later read/write/signal/terminate against that process. The trace
  event still reports the public id separately from the executor key.
- **`tool/unified_exec_spans_test.go`**: the process-start event's executor key
  is now asserted to be the public id plus a parseable UUID suffix, mirroring
  Rust's request-parameter test (`assert_regex_match` on the suffixed format and
  `assert_ne!` across repeated calls).

### sync217: usage-limit windows in turn and compaction analytics (#48174)

Rust preserves an optional `limit_window_minutes` from usage-limit error
responses on `UsageLimitReachedError`, accepting unsigned integers that fit in
`u16` and treating missing/null/malformed/out-of-range values as unknown, and
reports it as `usage_limit_window_minutes` in turn and compaction analytics
(`null` for every other error kind).

Go had no home for the value at all: its HTTP 429 with `error.type ==
"usage_limit_reached"` fell through to a plain `ResponsesAPIError`, so no
usage-limit classification (and therefore no window) reached the app-server.
This pass lands the classification together with the window.

- **`codexapi/error.go`**: `APIError` (and `APIErrorDetails`) gained
  `UsageLimitWindowMinutes *uint16`. `Details()` and `NewAPIErrorWithDetails`
  carry it on both the literal and the details-backed construction paths.
- **`model/responses_agent.go`**: `responsesAgentAPIErrorBody` gained the
  untyped `limit_window_minutes` member; `responsesHTTPError` classifies an HTTP
  429 whose `error.type` is `usage_limit_reached` as `ErrorRateLimit` (Rust's
  `CodexErr::UsageLimitReached`, checked before the quota codes as in
  `api_bridge.rs`) and attaches the window through
  `usageLimitWindowMinutesFromValue` (unsigned integers that fit in `u16` only).
  The wrapped-WebSocket `error` event path gained `websocketUsageLimitError`,
  which requires a numeric status and a `usage_limit_reached` error type before
  producing the same classified error with its window, mirroring Rust's
  `parse_wrapped_websocket_error_event` / `map_wrapped_websocket_error_event`
  followed by `map_api_error`.
- **`appserver/turn_runtime.go`**: `turnAnalyticsErrorFields` gained
  `UsageLimitWindowMinutes`, populated only for `codexapi.ErrorRateLimit`, and
  the value is threaded through `turnCompletionAnalyticsContext` into
  `emitCodexTurnAnalyticsEvent`. A status-only 429 (`ErrorAPI` /
  `ErrorRetryable`) keeps reporting `null`, as Rust does for other error kinds.
- **`appserver/compaction_analytics.go`**: the compaction event carries the same
  field from its error classification, so local and remote compaction failures
  report the window.
- **`telemetry/turn_event.go` / `telemetry/compaction_event.go`**: the turn and
  compaction event params gained `usage_limit_window_minutes *uint16` (always
  serialized, `null` when unknown) and the constructors copy it from the input.

Tests: the HTTP window matrix (five-hour 300, weekly 10080, missing, null,
malformed, out-of-range 70000), the unchanged quota classification without a
window, the wrapped-WebSocket mapping with and without a status, the
app-server analytics field matrix (usage limit with and without a window, and
another error kind that must report null), the turn and compaction event JSON
nullability, and the exec-server process-id suffix and uniqueness.

Recorded as remaining from #48174's lane: Rust's `UsageErrorBody` also models
`plan_type` and `resets_at`, and its 429 branch classifies `usage_not_included`
as `CodexErr::UsageNotIncluded`; Go's HTTP path still does not model those, so
the window is the only usage-limit detail Go currently preserves on the HTTP
error. Rust's `analytics` crate also folds the value through
`TurnCodexError`/reducer aggregation, which has no Go counterpart (Go's
telemetry events are the wire shape only).
