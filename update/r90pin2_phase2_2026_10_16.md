## 5. 真缺口清单（不弱化断言）

### 5.1 项 #2 —— 不是丢生命周期，是 **ID 分配器串号**

实测（`-v` 失败 dump 里 persisted `session.Item` ID 全集）：
`user-turn-1 / permissions-instructions-turn-1 / outer-exec-nested-2 / tool-call-turn-1-outer-exec / tool-output-turn-1-outer-exec / msg-final`，
其中**恰有 1 条** `Type:"commandExecution"`，ID = **`outer-exec-nested-2`**，`Text:"weather\r\n"`（`unified_exec_evented=true`，pending drain 为空）。
测试断言的是精确 ID `outer-exec-nested-1`（`appserver/runtime_router_test.go:9770`）。

因果链（上游依据齐全）：
1. `instant_interrupt` default true 是**正确的**：Rust `codex-rs/features/src/lib.rs:1210-1214` = `{key:"instant_interrupt", stage:UnderDevelopment, default_enabled:true}`；`with_defaults()`（`lib.rs:555-566`）按 `default_enabled` 无条件入集；`features/src/tests.rs:122-135` 的 `default_enabled_features_are_stable` **专门为 InstantInterrupt 开了例外**（注释：*Instant interrupts are enabled by default while retaining their development stage*）。
2. 该 feature 打开后，code-mode exec 走"可观察 cell"分支：`tool/code_mode_exec.go:655` 的 `preempt == nil` 快路径被跳过（preempt 由 `turn/tool_dispatcher.go:355-361 BeginStepPreempt` 经 `tool_dispatcher.go:571-577` 注入；Rust 对应 `core/src/session/mod.rs:4026-4031`）。
3. 该分支用**同一个** `e.nextID`（`tool/code_mode_exec.go:56 atomic.Uint64`）既发 cell id（`:671 cell-%d`）又发嵌套调用 id（`:1265 %s-nested-%d`）。cell 先取走 1 个号 ⇒ 嵌套命令变成 `-nested-2`。
4. Rust 侧语义：cell 只有在**用户真的插话**时才让出观察窗，cell 继续跑且结果照常进 rollout（`core/tests/suite/pending_input.rs:1514` `steers_yield_exec_and_wait_without_stopping_the_cell`，同文件 1584/1626 分 instant_interrupt on/off 两态）。
5. 结论：嵌套调用 ID 不应取决于"调用方有没有挂 preempt" ⇒ **Go 侧分配器缺陷**，落点 `tool/code_mode_exec.go:671`（cell id 不该占用嵌套序号）或 `:1265`。修完 `outer-exec-nested-1` 自然回来，测试无需改。**`tool/**` 不在我的授权写入面 ⇒ 标 blocked，请另开车道或授权。**
6. 附带发现（同一处，未改动）：`tool/code_mode_exec.go:25 CodeModeDefaultExecYieldTime = 30 * time.Second`，Rust `codex-rs/code-mode-protocol/src/runtime.rs:15 DEFAULT_EXEC_YIELD_TIME_MS = 10_000` ⇒ **30s vs 10s 漂移**，建议同车道一并裁决。
