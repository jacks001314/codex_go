## 1. `#44060` Raise Guardian's action review limit to 200,000 bytes

Rust 依据：`3d3df0a0ca`。

- `state.GuardianMaxActionBytes = 50_000 * 4`（200,000 字节），
  `state.GuardianMaxActionStringTokens = 16_000`。
- 新增 `state.FormatGuardianActionPretty`，先按 Rust
  `truncate_guardian_action_value` 递归截断每个字符串（复用
  `context.GuardianTruncateText` 的 prefix + `<truncated
  omitted_approx_tokens="N" />` + suffix 形式），再序列化并检查总字节数；
  超限返回 Rust 原文 `Guardian action exceeds the 200000-byte review limit`。
- 序列化改用 `json.Encoder` + `SetEscapeHTML(false)`：serde_json 不转义
  `<`、`>`、`&`，此前 `json.MarshalIndent` 会把截断标记写成 `\u003c...`，
  导致审阅者看到的文本与 Rust 不一致。
- Guardian prompt 构建（`joinPlannedAction` → `marshalGuardianPromptAction`）
  走同一格式化器，超限动作在 app-server 侧按既有
  `prompt_build_error` 路径 fail-closed 拒绝。
- stdin 审批（`appserver.writeStdinApproval`）新增
  `maxStdinApprovalBytes = 8_000`：序列化动作 + reason 超过上限、或动作被
  截断时，在 hooks / Guardian / 用户审批之前返回 Rust 原文
  `terminal input and permission details are too large to review safely; use
  a smaller input or start a new terminal with fewer grants`。
- 记录 `codex.unified_exec.stdin_review.size_check` 计数器，标签
  `result`（`within_limit` / `formatter_truncated` / `over_limit`）与
  `input_kind`（`text` / `control`）；格式化失败时不打点，与 Rust 的 `?`
  提前返回一致。

验证：

- `go test ./state -run Guardian` 通过（含 `TestGuardianActionReviewLimit*`）。
- `go test ./appserver -run Guardian`、`go test ./context`、`go test ./app` 通过。
- `go test ./appserver -run TestGuardianStdinReviewSizeLimitLikeRust` 通过。
- `go vet ./state ./appserver ./context`、`go build ./...` 通过。
- `go test ./state` 的 `TestOpenRuntimeDBValidatesBeforeMigrateLikeRust`
  在 detached `85858439` 上同样失败（`validation attempts after reopen = 1,
  want 2`），为既有基线，与本轮无关。

## 2. `#45579` Copy current thread attachments into non-ephemeral forks（审计）

Rust 依据：`19286b8819`。

Go 已有等价载体 `applyThreadForkAttachments`（`appserver/thread_attachments_runtime.go`）：

- 非 ephemeral fork 复制源线程“当前”附件成员关系，使用新 UUIDv7 id 和统一
  `now` 时间戳，保留 `attachmentType`、`identityKey`、`payload`；
- ephemeral fork 不继承附件；
- 复制失败记录日志并允许 fork 在无附件状态下成功；
- 复制发生在 fork record 保存/发布之前，早期 turn 的 fork 仍复制当前成员；
- 附件成员关系之后可独立增删。

`TestThreadForkCopiesAttachmentsLikeRust` 覆盖复制、新 id、独立删除；
`go test ./appserver -run TestThreadForkCopiesAttachmentsLikeRust` 通过。
该行此前是符号名不匹配造成的 `implementation_pending` 假阴性，已改判
`complete`。
