## Goal

Accept the optional `account/rateLimits/read` usage capabilities, forward Luna
Reserve only for eligible ChatGPT sessions, keep lightweight polls off the
separate reset-credit detail request, and expose `ordinaryUsageAllowed` only for
the active account.

## Findings

- Rust #42358 adds `GetAccountRateLimitsParams { supports_luna_reserve,
  exclude_reset_credit_details }` behind `Option`, preserving omitted and `null`
  params. The handler forwards `x-openai-codex-luna-reserve: 1` only when the
  client opts in, the auth mode is `Chatgpt`, and the account is not FedRAMP.
  `exclude_reset_credit_details` skips the parallel detailed reset-credit
  lookup, falling back to the usage response summary. `ordinary_usage_allowed`
  is only returned when the backend account/user identity matches the active
  session.
- Go already extracted `ordinaryUsageAllowedFromPayload`, exposed it on
  `auth.GetAccountRateLimitsResponse`, and filtered it (plus the upsell banner)
  through `accountBoundRateLimitExtras`, re-resolving the login after the
  backend read. That behavior is unchanged and newly covered end to end.
- Go's handler decoded params into an empty struct, so the capabilities were
  rejected-looking-but-ignored: any opt-in was dropped and no Luna header was
  ever sent. `auth` had no params type and `chatgptapi` had no opt-in entry
  point.
- Go never performs the separate reset-credit detail request: the usage
  payload's `rate_limit_reset_credits.available_count` is the only credit
  summary it returns. Accepting the flag therefore already matches Rust's
  skipped-detail response.

## Implementation

- `auth/account.go`: added `GetAccountRateLimitsParams` and the
  `NullableGetAccountRateLimitsParams` alias.
- `chatgptapi/cloud_tasks.go`: added `GetRateLimitsWithLunaReserve` and a shared
  `getRateLimitsForUsage`; the usage GET layers
  `x-openai-codex-luna-reserve: 1` over the client headers through the new
  `doJSONWithHeaders`.
- `appserver/runtime_router.go`: decodes `account/rateLimits/read` params into
  the nullable type, selects the Luna Reserve read only when
  `rateLimitsSupportsLunaReserve` (opt-in, `chatgpt` mode, non-FedRAMP), and
  documents that `excludeResetCreditDetails` needs no extra skip because no
  detail request exists.
- `appserver/rate_limits_capabilities_like_rust_test.go`: covers opt-in,
  omitted, null, opt-out, lightweight-poll, `chatgptAuthTokens`, and FedRAMP
  cases against a real HTTP backend, plus the identity filter and a
  non-boolean capability rejection.
