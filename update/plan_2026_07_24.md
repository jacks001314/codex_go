## 本轮实施记录

- 新增 Browser Use managed requirement 的 TOML 解析和 app-server v2 JSON 协议输出。
- 新增 `guardianv2` 功能注册，默认关闭。
- 新增 `tools.update_plan.enabled` 和 `features.multi_agent_v2.wait_agent_enabled`，
  默认保持启用；显式关闭时从每轮模型工具面移除对应工具。
- tool-router 复用条件已包含两个开关，避免关闭配置错误复用默认工具集。
- `non_prefixed_mcp_tool_names = true` 现在对所有 MCP server 省略 legacy `mcp__`
  前缀；配置对象可用 `server_names` 仅选择指定 server，关闭 feature 时全部保留前缀。
- MCP 工具的前缀策略会跨 exposure、排序和重复名称归一化保留。
- MCP Streamable HTTP、OAuth discovery、registration、code exchange 和 token refresh
  请求默认发送 `codex-mcp-client/<version>`；静态或环境配置的 User-Agent 优先。
- 构建脚本通过 ldflags 向 MCP client 注入发布版本；开发构建使用 `0.0.0`。
- app-server standalone image generation 在 auth snapshot 明确为 Free plan 时不再注册；
  hosted image generation 继续由 Responses runner 的现有 Free-plan 检查过滤。
- standalone installer mirror 变更经审计不适用于 Go；保留 Go updater 自有 release
  endpoint。
- thread start 将 model、model reasoning effort、Plan-mode reasoning effort、service
  tier 和 personality 写入持久化线程 config 快照；后续 batch writes 只影响新线程。
- Plan mode 使用 `plan_mode_reasoning_effort`，显式 turn effort 仍具有最高优先级。
- 新增外部完成 import history 记录 RPC；常规和外部导入历史均保留 provider ID。
- 外部 session importer 扫描 external-agent `projects/**/*.jsonl`，解析 user/assistant 消息并生成 Codex thread/rollout；`created_at` 取最早有效源时间，`updated_at` 和 `recency_at` 取最晚有效源时间，无有效时间时回退导入时刻。
- MCP runtime 配置更新按连接身份复用健康 HTTP/stdio 客户端；工具过滤、审批、
  timeout 等视图配置变化不触发重连，身份变化、移除或已关闭连接会被替换并关闭。
- runtime reconciliation 保留复用连接已发布的工具、资源与 Apps catalog，避免无关
  配置刷新回退远程插件安装后的 Apps 工具。
- 新增可信插件脚本归因解析器，仅接受已安装、非 local 且带远程身份元数据的
  `openai-curated-remote` 缓存；复杂 shell、缺失文件、路径逃逸和不安全 wire path
  均 fail closed。
- 普通 shell 与 unified-exec 的 started/completed command item 传播 `pluginId` 和
  `scriptPath`，审批后的 declined completion 会重新解析并保留归因；exec/SDK 使用
  snake_case，app-server 使用 camelCase，analytics 写入前再次校验相对路径。
- 新增 `APIErrorDetails` 与独立 retry delay metadata；保留旧 `APIError` 字段和
  struct literal 兼容。HTTP `Retry-After` 在 Responses 错误映射时保存，stream 与
  client retry 统一从 wrapped error 读取延迟，app-server 仅按 details 分类错误。
- paginated 线程 start、resume 和 fork 通过跨平台文件锁持有单写者 ownership；
  competing resume 返回 JSON-RPC `-32600`，Router shutdown 后 ownership 可转移。
- archive/delete 在修改任何父子线程前按稳定顺序预占完整子树；任一线程由其他
  app-server 持有时整批拒绝，成功归档或删除后释放本进程保留的 ownership。
- rollout replay 对同一 `(turnId, itemId)` 的后续快照原位刷新，保留首次创建时间
  和 creation ordinal，并单独推进 latest update ordinal。
- session thread store 支持 exclusive update watermark、creation/update ordinal
  排序、分页与 turn 过滤；两类游标不可混用，forked rollout lineage 拒绝增量读取。
  旧记录缺少 ordinal 时按现有 creation order 合成，app-server wire shape 保持不变。
- exec-server 使用最终配置解析出的 `respect_system_proxy` HTTP client；delegated
  `http/request`、remote registry、普通 environment WebSocket 和 Noise rendezvous
  初连/重连共享该 transport。per-request timeout、redirect policy 与 custom CA 保留。
- app-server environment discovery 不发起连接；final ConfigService 读取完成后再注入
  HTTP policy，已发现但未连接的 environment records 同步更新。
- TUI 增加 `toggle_side_conversation`（默认 `ctrl-/`，兼容 `ctrl-7`），父线程与 side thread 的 transcript、状态和 composer placeholder 可往返保存；Ctrl+C 继续关闭 side。
- thread event store 跟踪 pending interrupt turn，重复请求可合并，turn completion 或 thread close 自动清理；实际 app-server interrupt 已由现有 Bubble Tea command 异步执行。
- Windows sandbox proxy settings mode 已加入 exec-server sandbox wire context，并贯穿
  local/remote unified exec。普通 session 与 fs helper 默认 `reconcile`；Guardian
  originator 或 `x-openai-subagent=guardian` 的 turn 使用 `preserve`，复用已有 marker
  中的 proxy ports，避免缺少父 session proxy env 时清空持久设置。
