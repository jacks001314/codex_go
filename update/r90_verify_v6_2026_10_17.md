## 2. 【重要新发现】#54047 的恢复逻辑在生产路径没有任何生产者 ⇒ 死代码

`resetTaskTimerFromReplayedStart` 的两个入参在**非测试代码里永远不会非 nil**：

1. **turn/started 通知**：`app/remote_tui.go:4075-4090`（`case appserver.NotificationTurnStarted`）手里就有 `payload.Turn.StartedAt`（秒），但构造事件时用的是 `protocol.TurnStartedWithID(payload.Turn.ID)`（`:4084` thread-scoped 分支、`:4089` 主分支），**`StartedAtMS` 被丢弃**。全仓非测试代码里，`StartedAtMS` 唯一的写入点是 `protocol/exec_events.go:565` 的 `ItemStartedAt(...)`（只服务 `item.started`，唯一调用点 `app/remote_tui.go:4248`）⇒ `event.StartedAtMS` 对 turn.started 恒为 nil。
2. **resume**：`SessionResumeResponse.WorkingTurnStartedAtMS`（`tui/tea/model.go:200-203`）**全仓无任何生产者**——4 个 `SessionResumeResponse{}` 构造点（`app/interactive.go:204`、`app/interactive.go:3270`、`app/prompt_edit.go`、`app/remote_tui.go:1656`）都不填它；`app/remote_tui.go:1656 remoteTUIResumeResponseFromThread` 明明拿到了含 turns 的 `*appserver.Thread`，且同一函数里已填了 `WorkingStatusHeader` / `WorkingReasoningTurnID` / `WorkingReasoningItemID` / `CompletedTurns`，却唯独没填这个。
3. 复现判据（可复跑）：`git grep -n 'StartedAtMS' -- '*.go' | 过滤 _test.go` ⇒ `protocol/` 内只有 `exec_events.go:24/27/565`；`git grep -rn 'WorkingTurnStartedAtMS' -- '*.go'` ⇒ 只有 `tui/tea/model.go:200,203`、`tui/tea/session_picker.go:432`、以及测试文件。

⇒ 结论：两条用例都绿，但它们直接手工构造了带 `StartedAtMS` 的事件/响应；**应用路径下 `applyThreadEvent("turn.started")` 与 `applyResumeResponse` 都拿到 nil，计时器恢复从未生效**。Rust 侧不是这样：`chatwidget/protocol.rs:105-109` 用 `notification.turn.started_at`、`chatwidget/replay.rs:146-149` 用重放回合的 `started_at`，两处都有真实数据源。
**建议（仅建议，我不改码）**：`app/remote_tui.go:4084/4089` 改用携带时间戳的构造（如按 `payload.Turn.StartedAt` 秒 → 毫秒填入 `StartedAtMS`），并在 `remoteTUIResumeResponseFromThread` 里从进行中回合的 `StartedAt` 填 `WorkingTurnStartedAtMS`；另补一条**桥接层**回归测试（直接断言 `handleNotification` 产出的 ThreadEvent 带 StartedAtMS），否则这类「模型绿、桥接断」的缺口仍会漏网。

## 4. TUI T1 的上游边界语义（与 Go 逐条对照）

Rust `tui/src/chatwidget/turn_runtime.rs:117-124`：
```rust
pub(super) fn on_replayed_task_started(&mut self, started_at: Option<i64>) {
    self.on_task_started();
    if let Some(started_at) = started_at {
        let elapsed_secs = chrono::Utc::now().timestamp().saturating_sub(started_at);
        self.bottom_pane.reset_status_timer(Duration::from_secs(elapsed_secs.try_into().unwrap_or_default()));
    }
}
```
| 输入 | Rust | Go | 判定 |
| --- | --- | --- | --- |
| 缺时间戳 | 只跑 `on_task_started()`，计时从零 | `startedAtMS == nil` ⇒ 早返回，`syncTaskRunningTimer` 置 now ⇒ 从零 | 等价 |
| 未来时间戳 | `saturating_sub` ⇒ 0 秒 | `started.After(now)` ⇒ 夹到 now ⇒ 0 秒 | 等价 |
| 等于当前时刻 | 0 秒 | 0 秒 | 等价 |
| **`started_at == 0`** | `Some(0)` ⇒ `elapsed = now`（≈1.79e9 秒）⇒ 计时器显示约 56 年 | `*startedAtMS <= 0` ⇒ 早返回 ⇒ 从零 | **存在差异（低危：服务端恒发真实 epoch 秒，0/负值不可达；建议只登记，不必修）** |
| **负值** | `Some(-n)` ⇒ `elapsed = now + n`（更大） | 早返回 ⇒ 从零 | 同上 |
单位：Rust 的 `started_at` 是**秒**（`v2/thread_data.rs:386` 字段注释 “Unix timestamp (in seconds)”，`#[serde(rename_all="camelCase")]` ⇒ 线上键 `startedAt`）；Go 的线上 `appserver.Turn.StartedAt`（`appserver/protocol.go:859`）也是秒（写入点 `appserver/runtime_router.go:13657-13676` 用 `time.UnixMilli(active.StartedAtMS).UTC().Unix()` 转换）⇒ **线上单位一致，无 1000× 偏差**；Go 内部 `ThreadEvent.StartedAtMS` 是毫秒（`protocol/exec_events.go:24-27` 注释），属设计差异，但如上所述 turn.started 根本没人填它。
