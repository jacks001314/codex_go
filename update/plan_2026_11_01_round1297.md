# Round 1297 — reject remote-default worktrees before allocation

Rust target: `67f0994b532b8740f14b5b738af7b7b2a915b1d6` (anchor worktree
`D:\qax\reagent\dev\git\codex-anchor-67f0994b`, hash `67f0994b`).

## The gap

Rust's exec bootstrap checks the prepared environment manager before it loads
config or allocates a checkout:

```rust
if worktree
    && EnvironmentManager::prepare_from_codex_home(&codex_home)
        .await?
        .default_environment_is_remote()
{
    anyhow::bail!("--worktree requires local execution");
}
```

Go only rejected an explicit `--remote` flag, so an `environments.toml` default
naming a configured executor (or a CODEX_EXEC_SERVER_URL default) still created
a managed worktree and ran the turn against a remote executor.

## What changed

- `execserver/environments_toml.go`: `EnvironmentProviderSnapshot.DefaultEnvironmentIsRemote`
  mirrors `PreparedEnvironmentManager::default_environment_is_remote` — true only
  when the selected default names one of the configured environments (the
  implicit local environment is never listed; a disabled default is local).
- `exec/exec.go`: `rejectRemoteWorktreeDefault` reads the provider snapshot from
  the runner's codex home before config load/worktree creation and returns
  `--worktree requires local execution`.
