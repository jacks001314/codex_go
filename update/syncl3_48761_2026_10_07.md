## 5. Rust 依据 + ⚠️ parity 校正（**请裁示**）

**Rust `#48761`（`e75b6b1e0c`，12 文件）的实际改动面**：
- `transcript_view/layout.rs::activity_layout(..., shortcut: Option<ShortcutHint>)`：把 compact activity 的通用披露标签 `"+ Show details"` 换成 `"+ {count} {noun}"`，并在
  `if Line::from(format!("{label}{hint}")).width() + indent <= usize::from(width)` 成立时才拼 `hint = format!(" ({} to expand)", shortcut.display_label())`，`indent = min(width/4, 4)`；`shortcut: None`（未绑定）⇒ 不拼。
- `transcript_view.rs:287-296`：`shortcut = keymap.primary_hint(KeymapContext::Global, "open_transcript")`。
- `exec_cell/compact.rs`：`ActivityDisclosure::OutputLines(hidden)`（**保留但被预览裁掉**的行数，排除存储丢弃），与 `Generic` 区分。

**⚠️ 校正（本题的关键事实）**：Go 现有 3 个渲染点对应的 **不是** 上面这个 `layout.rs` 面，而是 Rust 的 **`ui_consts::transcript_hint()`** 面：

```
codex-rs/tui/src/ui_consts.rs:12-17   pub(crate) fn transcript_hint() -> String {
                                          format!("{} to view transcript", ctrl(Char('t')).display_label()) }   // 仍硬编码 ctrl+t
codex-rs/tui/src/tool_output.rs:119   format!("+{omitted} {unit} ({})", transcript_hint())  → truncate_line_with_ellipsis_if_overflow(..., self.width)
codex-rs/tui/src/exec_cell/render.rs:306  format!("… +{omitted} {noun} ({})", transcript_hint())
codex-rs/tui/src/tool_output_tests.rs:102 ["", "", "", "+99997 lines (⌃t to view transcript)"]  # 默认宽度下仍带 hint
```

即：**Rust 在 pin `5b0b253035` 上，该 marker 面仍是「硬编码 ctrl+t + 超宽时按 ellipsis 截断」**；配置化 + 「放不下则省略」是 `layout.rs` 那个**另一面**（后缀 `to expand`，Go 无 `transcript_view` 载体）的规则。

因此本补丁 = **把 `#48761` 的「配置化 + 未绑定/放不下则省略」规则搬到 Go 现有的 marker 载体**（队长 r88b §3 / r88e ④ 明确指定的方案 1）：
- 默认配置（`open_transcript = ctrl+t`）下输出与 Rust 逐字节一致（`TranscriptHint` = `"ctrl+t to view transcript"`；`displayKeyBinding("ctrl-t")=="ctrl+t"`）。
- 仅在**两个边角**与 Rust marker 面不同：① 用户 remap `open_transcript` ⇒ Go 跟随（Rust marker 仍 `ctrl+t`）；② 宽度不足 ⇒ Go 省括号保 count（Rust marker 会 `truncate…ellipsis`）。

**佐证「配置化」在 Go 侧不是空穴来风**：Go 的生产 footer 本身就是「配置化绑定 + ` to view transcript`」这条式子 —— `tui/bottom_pane/footer.go:242` 拼 `props.KeyHints.ShowTranscript + " to view transcript"`（默认值 `footer.go:89 ShowTranscript:"ctrl+t"`，但 `git grep -n 'KeyHints:' -- '*.go'` 生产 0 命中 ⇒ 没有按 keymap 灌值的点 = 另一处未接线）。本补丁让 marker 与 footer 用**同一个句式、同一个配置源**，即把 `#48761` 的规则接到 Go 已有的「配置化披露提示」面上。

**请队长裁示**（我按「已批准方案 1」交付，不擅自改口径）：
- 认可「规则搬家」⇒ 直接落 main（默认配置零差异，边角更贴近 Rust 的**配置化**面）；或
- 要求 marker 面与 Rust `ui_consts::transcript_hint()` 逐字节一致 ⇒ 我立刻出第二版：**只做配置化、保留 `TruncateWithEllipsis` 截断**（撤回宽度省略半条 + 还原 `tui/tool_output_preview_test.go:82` 原断言），1 轮内可交；或
