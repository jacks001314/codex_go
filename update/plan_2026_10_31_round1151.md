## Findings

- Rust #41924 moves realtime history ownership into Core: the reducer's
  segmentation, session boundaries, and backing-agent promotions are persisted
  as canonical `realtime_item` rollout records in event order, and hosts only
  translate the resulting `HistoryItemStarted` / `HistoryTranscriptDelta` /
  `HistoryItemCompleted` events into notifications.
- Ephemeral sessions record no history and emit no history lifecycle events.
- Typed user input seals the live transcript before the user message enters the
  timeline; realtime handoff delegations are excluded.
- Go already had the shared reducer and the typed notifications, and the state
  DB already carried the `thread_realtime_items` projection table, but nothing
  wrote `realtime_item` rollout records, nothing projected them, and
  `thread/timeline/list` was registered without a handler.

## Changes

  codec plus `SealUserInputForPrompt`, which skips realtime handoff
  delegations.

  `HistoryItemSink` and `HistoryEnabled` hooks and one
  `publishHistoryEffects` path that emits the live transcript stream, persists
  the durable items, then publishes their lifecycle notifications.

- `state/thread_history_projection.go`: project canonical realtime items into

- `state/thread_timeline.go`: implement paginated canonical timeline reads:
  turn boundaries, ordinary items, and realtime items merged by
  `(rollout ordinal, kind, id)`, plus the realtime session that was open before
  the page.
- `appserver/`: implement `thread/timeline/list` (params, tagged entries,
  runtime forwarding, paginated-history error mapping), persist reducer items
  through the rollout recorder in event order, suppress history for ephemeral
  threads, and seal live segments before typed turn starts and accepted steers.

  persistence order, ephemeral suppression, delegation exclusion, timeline
