## Gap: macOS/Linux process hardening

Rust hardens the process pre-main (ctor): Linux/Android
prctl(PR_SET_DUMPABLE, 0) + setrlimit(RLIMIT_CORE, 0) + clear LD_*; macOS
ptrace(PT_DENY_ATTACH) + setrlimit + clear DYLD_*; FreeBSD/OpenBSD setrlimit +
LD_*; fail-closed exit codes 5-7; Windows is a TODO no-op.

Implemented:

- New `processhardening` package (platform-split by build tags): linux/android
  (unix.PrctlRetInt PR_SET_DUMPABLE), darwin (syscall.SYS_PTRACE +
  PT_DENY_ATTACH), freebsd/openbsd, other-unix no-op, non-unix no-op
  (matching Rust's Windows TODO); shared env-prefix filtering operating on raw
  string bytes (non-UTF8 keys like Rust's byte-based helper).
- Wired at `cmd/codex/main.go` start (mirroring Rust's pre-main ctor).

## Pre-existing darwin cross-compile fixes (surfaced by the gate)

The full-tree `CGO_ENABLED=0 GOOS=darwin go build ./...` failed before this
cycle's change in two places (both introduced in the 2026-08-16 batch):

- `doctor/disk_unix.go` used `Statfs_t.Frsize`, which does not exist on darwin
  (darwin uses `Bsize`); split into `disk_unix.go` (unix && !darwin, Frsize)
  + `disk_darwin.go` (Bsize).
- `doctor/doctor.go` referenced `windowsDevDriveCheck` inside a runtime.GOOS
  guard, but the identifier was defined only in the windows-only file; added a
  non-Windows stub (`dev_drive_other.go`).
