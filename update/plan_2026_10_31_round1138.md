## Findings

- #43939 adds executor-context filesystem permission helpers to the protocol
  crate: `DenyReadValidator`/`DenyReadViolation`, `ReadDenyMatcher::
  try_new_with_context`, `can_read_path`, `get_unreadable_globs_with_context`,
  `has_context_read_denials`, a strict `validate_context_paths`, and
  `PathUri`-based workspace-write constructors. Core configuration now shares
  the required-entry and readable-path checks through the validator instead of
  an inline local matcher.
- Behavioural deltas: malformed or unresolvable denials (missing executor home
  for `~` globs, foreign path convention, unavailable `:tmpdir` metadata) fail
  closed when the context matcher is built, `:slash_tmp` denials only apply on
  POSIX executors, and a concrete readable grant that reopens a managed denial
  is still reported as a conflict.

## Implementation

- `sandbox/deny_read_target.go`: `DenyReadContext`, `DenyReadViolation`,
  `PreparedReadDenials` (`NewPreparedReadDenials`), `DenyReadValidator`,
  `ValidateManagedDenyRead`, `HasContextReadDenials`,
  `CanReadPathWithContext`, `ReadDenyGlobsWithContext`. Globs expand `~`
  against the executor home, `:tmpdir`/`project_roots`/`:slash_tmp` materialize
  from context facts, reversed character classes are rejected, and
  foreign-convention candidates are denied.
- `appserver/command_exec.go`: `mergeManagedDenyRead` now runs the shared
  validator over the selected profile's explicit writable roots plus the
  managed denials, returning Rust's shadowed-denial message before appending.
- Tests: `sandbox/deny_read_target_like_rust_test.go` (POSIX/Windows/UNC
  matrix, `/tmp` convention, tmpdir metadata, project-root materialization,
  violation precedence, fail-closed globs) and the new
  `appserver/command_exec_deny_read_test.go` conflict case.

## Assessment

- The `PathUri`-typed constructors (`workspace_write_with_path_uris`,
  `with_materialized_project_roots_for_path_uris`) need no separate Go
  carrier: permission materialization already lives in
  `config.permissionProfileBuilder.materializedEntriesForWorkspaceRoots`
  over `ConfigPathContext` URI facts, mirroring Rust's
  `materialize_project_roots_with_path_uris`.
- The Windows glob component split matches `PathConvention::Windows
  .path_segments`: `sandbox/windows_deny_read_glob.go` already splits on both
  separators and drops empty components.
