## Goal

Attribute exec-server process lifecycle and network-policy telemetry to the
launching tool call and executor.

## Findings

- Rust #42373 adds optional `ExecMetadata` (`thread_id`, `tool_call_id`) to
  `ExecParams`, propagates it from unified exec, and records four bounded
  OpenTelemetry events from the executor: `codex.exec_server.process_start`,
  `process_spawn_failed`, `sandbox_denied` and `process_exit`. Each event
  carries the launch trace/span id captured at launch, conversation id, tool
  call id, registry-issued executor identity, sandbox type, and (on exit) the
  exit code and termination flag; payloads, paths, env values, output and error
  text are excluded. Launch attribution survives reconnects, network-policy
  audit events reuse it, and invalid trace headers no longer inherit an
  unrelated active span.
- Go already carries the protocol half: `execserver.ExecMetadata` is optional on
  `ExecParams` and is filled by `tool/unified_exec.go` (`unifiedExecWireMetadata`
  sends threadId/toolCallId), so metadata serialization and propagation match.
- Go also opens the launch spans (`codex.exec_server.process_start`,
  `process_prepare_sandbox`, `process_prepare_shell_snapshot`,
  `codex.process.spawn`) and forwards JSDP request/response trace events, so the
  launch trace relationship exists.
- The lifecycle events themselves are missing: the exec-server never emits
  `process_spawn_failed`, `sandbox_denied` or `process_exit`, the
  `process_start` span carries only `process.id`, and the tracehook span
  interface exposes no trace/span ids to stamp onto a bounded event.
- The network-policy audit event (`emitNetworkPolicyDecisionAudit`) records only
  `execution.id`; it has no conversation/tool-call or executor attribution, and
  no executor registration identity is retained with a launched process.
- The invalid-trace-header hardening has no Go counterpart to fix: Go parses its
  own `traceId;spanId` carrier and does not fall back to ambient active spans.

## Implementation

- No product code this round: the missing lifecycle events need a telemetry
  record bound to each exec-server process (attribution captured at launch and
  reused on exit/reconnect) plus a trace-id accessor on the tracehook span
  surface; that is a cross-cutting change, not a local patch.
