## What changed

Rust #58404 tracks the history boundary covered by the last usable usage report
(`History::last_server_reported_usage_item_count`), advances it only on a
report, and estimates everything recorded after it. Go already carried the
boundary-aware `compact`/`context` helpers but never fed them a live boundary,
so retained output from failed or usage-less responses fell out of the context
estimate and compaction ran late.

- `persistCompactTokenStatus` now writes `token_usage_boundary` with the usage
  it persists: the thread's item count at the report, which is Rust's
  `max(last model output item, request input item count)`.
- `compactTokenStatusForTurnWithPolicy` estimates through
  `compact.EstimateActiveContextTokensWithUsageBoundary` with that boundary, so
  covered items are never re-charged; a usage record written before the
  boundary keeps the restored-history approximation.
- `midTurnSamplingCompaction` no longer reports an empty context when the
  response carries no usable usage: `midTurnActiveContextTokensLikeRust`
  starts from the last usable report in the turn (identified by its item IDs in
  the merged history), falls back to the persisted report, and otherwise
  estimates the whole history.
