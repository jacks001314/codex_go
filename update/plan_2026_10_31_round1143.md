## Findings

- #44138 moves writer-lock coordination from `thread-store` into `rollout` so the
  background compressor and the local thread store share one namespace. Cold
  rollouts can still have a live writer, so compression must skip busy threads
  and must recheck the source under coordination between verification and
  publication.
- Rust also stops two other races: `materialize_rollout_for_append` keeps the
  caller's writer guard while a compressed rollout is restored, and
  `update_thread_metadata` takes writer ownership before any store or SQLite
  write when a legacy memory-mode or git-info patch appends a `SessionMeta`.
- Go already had `Store.AcquireWriter`/`AcquireWriters`, a bounded coordination
  wait, and a compressor that skipped active writers. It still acquired the
  thread lock before metadata/verification ran, never held coordination across
  publication, could create a lock file while probing, and updated memory-mode
  and git-info metadata without ownership or the paginated early return.

## Changes

- `session/writer_lock.go`: new `PublicationLock` plus
  `Store.TryAcquireForPublication`. It takes the bounded coordination lock,
  probes the thread lock without `O_CREATE` (missing file = idle, matching
  Rust), returns `ErrConflict` for a live writer, and keeps coordination locked
  until `Release`, which never deletes the probed lock file.
- `rollout/compression.go`: metadata, verification, and the pre-publication
  state check now run without the writer lock; the lock is taken only for the
  final state recheck, no-clobber rename, post-rename recheck, and source
  removal, with a busy thread reported as `SkippedBusy`.
- `rollout/rollout.go`: `ResumeWithWriter` is the Go form of
  `open_rollout_for_append(path, writer_lock)` /
  `RolloutRecorder::new_with_writer_lock`: compressed-rollout materialization and
  the plain-file open happen under the caller's guard.
- `appserver/router.go`: memory-mode and git-info patches acquire writer
  ownership through `acquireMetadataRolloutWriter` before the store or SQLite
  write, reuse a live paginated thread's writer instead of self-conflicting, and
  stop before the legacy `SessionMeta` append for paginated threads, matching
  Rust's paginated early return.

## Verification

- `session/writer_lock_test.go`: publication skips a live writer, holds
  coordination until `Release` (a competing `AcquireWriter` times out), treats an
  existing unlocked lock file as idle, and never creates a lock file for a thread
  that never had a writer.
- `rollout/compression_active_writer_like_rust_test.go`:
  `TestRolloutCompressionPublicationLeavesNoWriterLockLikeRust` compresses cold
  rollouts without leaving `thread-writer-locks/<id>.lock` and still compresses a

- `appserver/router_test.go`: memory-mode and git-info patches against a thread
  owned by another store are rejected with `already has an active writer` while
  neither the session store nor the Rust state SQLite row changes; releasing the
  owner lets the memory-mode patch succeed.

## Residual

- Rust's `RolloutRecorder` keeps writer ownership across a background writer
  task and stops queued work through `discard()`/`wait_for_exit()` before
  deletion. Go's recorder writes inline under its mutex and `Close` syncs, so
  there is no deferred queue to discard; ownership is held for the synchronous
  append instead. This is a structural difference, not a missing contract.
- The full `appserver` run still reports the known baseline failures
  (`TestRustAppServerV2SuiteManifestCoversRustModules`,

  `TestRuntimeRouterFileChange*`, `TestPrecomputedExportArtifactsMatchTargetRustCommit`,
  `TestStdioServerHandlesConcurrentTurnStarts`) plus
  `TestRuntimeRouterExecutorCatalogUsesExtensionByteBudgetWithoutCoreWarningLikeRust`,
  which fails because the working tree carries an extra untracked skill under
