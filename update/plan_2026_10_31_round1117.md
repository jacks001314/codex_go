## Findings

- #47114 was a real gap. Go already had migration
  `0007_thread_item_lifecycle_timestamps.sql` and read `started_at_ms` /
  `completed_at_ms` from `thread_items`, but the projection only wrote
  `created_at_ms`. The projection now inserts both columns and keeps existing
  non-null values with `COALESCE` on conflict, matching Rust. `ThreadItemEntry`
  gained nullable `startedAtMs` / `completedAtMs`, populated from the stored row
  in both `thread/items/list` and `thread/items/read`, with the legacy rollout
  path falling back to the item payload.
- #49032's database half is already implemented: `initializeDatabaseSettings`
  sets incremental auto-vacuum only for schema-empty databases before WAL,
  preserves existing vacuum/journal modes without taking the writer lock, and
  keeps the pool's per-connection pragmas. The stderr span half is Rust
  tracing-specific; Go logs through slog without span entry/exit records.
- #47094 applies `DescriptorPolicy::StdioOnly` to Rust's Unix stdio launcher.
  Go launches MCP stdio servers through `os/exec` with only stdio wired, no
  `ExtraFiles`, and close-on-exec descriptors created by the runtime; `os/exec`
  has no pre-exec hook for descriptors inherited by the Go process itself.
- #47088 prunes Cargo/Bazel default dependency features; Go modules have no
  feature graph.
- #47089 centralizes Rust JSON-RPC result serialization through the payload
  enum without changing wire shapes. Go marshals typed response structs once at
  the transport boundary and has no per-variant serialization match.
