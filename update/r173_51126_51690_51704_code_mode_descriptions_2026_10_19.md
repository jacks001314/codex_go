# Round 730: Code Mode settlement helpers and description ordering

## `#51126` promise settlement streaming helpers

Rust 依据：`28a264fbc766a59f2b550b8318f88e4a4b8dffe1`。

Go 的 Sobek runtime 已安装 `as_settled` / `stream_settled`：

- iterable 输入使用位置索引，Map 输入保留 key；
- settlement 顺序在 consumer 忙碌期间仍按完成顺序排队；
- 支持 Promise、thenable 与 plain value；
- `stream_settled` 逐个 await callback，并传播 callback error；
- early `return()` 丢弃后续结果；不可 settle 的 cell 可由终止流程清理。

验证：

- `go test ./codemode -run Settled -count=1`

## `#51690` / `#51704` tool-description-first ordering

Rust 依据：

- `95ec468619386ebb93506ac2091a48e5a558d25c`
- `0a2a64e94200b03af3901bad4cd918030739c697`

实现：

- `code_mode_tool_description_first` 是 default-off under-development feature；
  `Config.CodeModeToolDescriptionFirst` 读取该值。
- app-server 与 exec 将设置传入 `CodeModeRuntime.SetToolDescriptionFirst`。
- remote `EnabledTools`、本地 `ALL_TOOLS` 和 tool-search result 会合并 tool 与
  namespace 描述：
  - 默认：namespace text 在前；
  - 开启：tool text 在前；
  - `exec tool declaration` 始终位于最后。
- `CodeModeToolSpecs` 仍保留分离的 tool/namespace 描述，供 exec prompt 单独渲染，
  避免重复 guidance；indirect prefix 在合并后只应用一次。

验证：

- `go test ./config -run TestCodeModeToolDescriptionFirstLikeRust -count=1`
- `go test ./tool -run TestCodeModeToolDescriptionOrderLikeRust -count=1`
- `go test ./turn -run TestBuildToolRegistryOrdersCodeModeToolDescriptionsLikeRust -count=1`
- `go test ./turn -count=1`
- `go test ./config -count=1`
- `go vet ./config ./turn ./tool ./appserver`
- `go build ./...`
- `go test ./parity -count=1`

`go test ./tool -count=1` 仍有两个既有的 login-shell PATH 基线失败；本轮新增的
Code Mode 定向测试全部通过。
