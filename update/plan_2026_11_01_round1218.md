# Round 1218: Owner session restore and cleanup retry (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342/#42375,
crate windows-sandbox-service; `package_lifecycle.rs` restore paths and
`service/runtime_lifecycle.rs`).

## Context

Round 1217 served the pipe but left the session-change hook empty, so an owner
whose session ID changed while the service was stopped was never restored, and
the teardown retry policy that keeps uninstall cleanup alive inside the SCM wait
hint did not exist.

## Session restore

`windowsandboxservice/lifecycle_windows.go` adds:

- `RestoreAuthenticatedUser`: a retained installation needs no work, a record
  with a registered runtime owned by another package family is skipped, the
  logged-in user's token is opened for the session, its SID must equal the
  recorded owner, and the token is then registered through
  `RegisterOwner` with the new session ID so the home is pinned again.
- `RestoreRecordedOwner`: retries the recorded session first, then every other
  current session, because session IDs can change while the service is stopped;
  the recorded failure is reported when no session matches.

WTS enumeration `WTSEnumerateSessionsW` (freed with `WTSFreeMemory`) and
`WTSQueryUserToken` are reached through seams so the fallback order is testable.

## Cleanup retry

`windowsandboxservice/runtime_lifecycle_windows.go` ports
`runtime_lifecycle::retry_cleanup`: the current teardown step is retried, never
a phase recovered from stored intent; an SCM stop gets five one-second
attempts inside the 10 s wait hint, while a non-stop failure backs off 30
one-second waits and returns once shutdown begins. Deferred failures are logged
once per distinct message so retries cannot flood the event log.

`NewProvisioningBroker` now restores the recorded owner on every session change
and logs, but does not fail the listener, when restoration fails — the same
fallback contract as `runtime_lifecycle::run`'s `restore_owner`.

## Known gaps

Native packaged sandbox cleanup (`prepare_packaged_windows_sandbox_cleanup`),
the uninstall observation (`PackageCatalog` + `PackageUninstalling`),
`PackageLifecycle::clean_up` with the cleanup journal, registered-runtime
metadata removal, `restore_disabled_accounts`/`runtime_owner_removed`,
`provisioning/registered.rs` refresh, `ServiceStopReason`, retained-handle setup
launch and the service binary remain open.

## Coverage

`lifecycle_restore_windows_test.go` (no record, retained installation, recorded
owner registered with the new session and a pinned home, a different logged-in
user refused, another package family skipped, fallback to a changed session ID,
and the recorded failure reported) and `runtime_lifecycle_windows_test.go` (immediate
success, transient failure retried with two full backoffs, five stop-requested
attempts, shutdown during backoff, and no service state).
