### 4.2 桶边界独立复算（自建探针 `metrics/zz_probe_test.go`，跑完已删）
```
PROBE len 511 b0 0 b1 1 b2 1.0276099259939215 b509 1.0204027554383544e+06 b510 1.048576e+06
PROBE value 0 -> bucket 0             PROBE value 1048575 -> bucket 510
PROBE value 1 -> bucket 1             PROBE value 1048576 -> bucket 510
PROBE value 510 -> bucket 230         PROBE value 1048577 -> bucket 511
PROBE value 511 -> bucket 230         PROBE value 2097152 -> bucket 511
PROBE value 512 -> bucket 231         PROBE value 1023 -> bucket 256
```
与解析推导一致：`boundaries[i]=2^(20(i-1)/509)`、`boundaries[510]=2^20`；`511` 落在 230（`2^8.99803=511.29>=511` 的最小 i 是 230）、`512` 落在 231（`2^9.037=525.3`），`2^20` 恰为 `boundaries[510]` 而同桶，`2^20+1` 溢出到第 512 桶（index 511）。与 shipped 探针测试（`appserver/incremental_tools_metrics_test.go:237`）声明值逐一吻合。

### 4.3 ⑤ 的结论 + 最小反例
- 自陈「本机 rustc(MSVC) 的 `pow` 非正确舍入，不能作钉值来源」**成立**，且**不削弱** Go 守卫，理由三条：(a) 上游语义是 libm 的正确舍入 `pow`，Go 的 `roundedPowerOfTwo` 以 256 bit 精度求值后一次舍入 ⇒ 复现的就是正确舍入值；(b) 守卫是漂移探测器，RC-3 已证明其有区分力；(c) digest 取自既有 telemetry 已对 Rust 钉过的同族算法。
- 最小反例（同一探针输出）：`maxExp=20` 家族 **81/510** 个边界与 `math.Pow` 差 1 ULP，首个在 index 8：`math.Pow=1.2100352836332537 (0x3ff35c4df5235fe2)` vs `exact=1.210035283633254 (0x3ff35c4df5235fe3)`；`maxExp=17` 家族 **72/510** 个（与 Go 注释宣称的 72 一致，首个 index 5：`0x3ff18d6931c639eb` vs `0x3ff18d6931c639ec`）。⇒ 若缺精确求值，钉值必然漂移，注释里的 72 是真实计数而非估计。

### 4.4 ⑥ `state/` 与 `rollout/` 取消门是否同一语义
- 同一语义、单一实现点：`state` 只把 `ctx.Err() != nil` 作为谓词交给 `rollout.ReadProjectionStepsCancellable`（`state/thread_history_projection.go:135-141`），实际取消点全在 `rollout`（开文件前 `readProjectionSuffix`、解压/限长读 64 KiB 的 `cancellableRolloutReader`、记录之间 `readProjectionStepsData` 每条一次），与 Rust `rollout/src/seekable_reader.rs:74-118`（`open_rollout_seekable_reader` 入口检查 + 包装解码器与临时文件 + `min(len,64*1024)` + read 前后各查一次）逐点对应；错误值也一致（Rust `io::Error::other("rollout read cancelled")` ↔ `ErrRolloutReadCancelled`）。
- 唯一「只改一侧」风险点已实测：`state` 侧只多一层 `errors.Is(err, ErrRolloutReadCancelled) && ctx.Err()!=nil` 的**错误包装**（`:116-120`），不是写入门；即使有人单独撤掉 state 门（保留 rollout 门）也不会漏写 checkpoint。
