## 2. 缺口分析

Go 的 Guardian transcript 由 `guardianReviewTranscript` 生成 `[]string`，
每条是 `role: text`，作者信息只存在于文本前缀里。Rust 的 JSON 模式要求
host 元数据（author/index/label）与文本分离，避免消息内容伪造角色或
transcript 边界。`#49038`（保留加密 agent message）也依赖同一套结构化记录。

## 3. 本轮落地

1. `state/guardian_transcript.go`
   - `GuardianTranscriptEntry{Author, Index, Label, LineRole, RetainedSourceOrder, Text}`；
   - `Render`：line 模式保持原有 `role: text`；json 模式输出
     `{"author","index","label?","retained_source_order?","text"}`，
     文本作为 JSON 字符串转义，`<`/`>`/`&` 与 serde_json 一样保持字面量；
   - `GuardianTranscriptJSONInstructions`（Rust `TRANSCRIPT_JSON_INSTRUCTIONS`
     原文）与 `ApplyGuardianTranscriptInstructions`。
2. `config.Config.GuardianV2TranscriptFormat()`
   - 读取 `[features.guardianv2].transcript_mode`，默认 `line`，仅 `json`
     选择 JSON（大小写/空白容忍）。
3. `appserver/guardian_reviewer.go`
   - `guardianReviewTranscriptEntries` 在收集条目时写入 host 归属：消息角色、
     tool 名称（JSON label）、顺序 index；`guardianReviewTranscript` 按线程
     配置渲染 line/json；
   - line 输出逐字保持不变，既有测试无需改写。
4. `appserver/agent_runtime.go`
   - `guardianReviewInstructions` 在 JSON 模式下把 provenance 指令放在
     policy 指令之前（Rust 语义：配置的 policy 不能移除 provenance 约束）。

## 144. Round 284 negotiated WebSocket zstd compression

### `#54930` Add negotiated zstd compression to app-server WebSockets
