### 3.1 生产改动 `network/proxy_server.go`（+66/−9）

1. **DNS seam**（`:1802`）：
   ```go
   var proxyLookupIPAddr = func(ctx context.Context, host string) ([]net.IPAddr, error) {
       return net.DefaultResolver.LookupIPAddr(ctx, host)
   }
   ```
   `proxyHostResolvesToNonPublicIP`(`:1812`) 与 `dialCheckedTarget`(`:1538`) 改走它 —— 这是让
   「未获批主机**零次 DNS**」成为**可回归值级断言**的先决条件（对齐 Rust
   `NetworkProxyState::host_blocked_with_lookup` 注入面）。
2. **R1 gate**（`:1623`）：旧 `if/else if` 结构替换为
   `if baselineLocalBindingReason(request, allowlist, allowed) != "" { deny(NotAllowedLocal) }`。
3. **R2 复查**（`:1643`，decider 返回 Allow 之后）：
   ```go
   if !settings.AllowLocalBinding && approvedLocalBindingReason(request, allowlist) != "" {
   ```

## 6) 对第 (3) 条裁定的正面回应（参数化而非「只认 allowlist」）

队长转述 syncl1 的硬约束：**不可**把 DNS 门收窄成「只有 `allowed`（allowlist 命中）才查 DNS」，否则会打断
「decider 一次性批准主机」的内层检查。本实现**不是**那种收窄，而是 Rust 同款**参数化**，只是用两个调用点表达：

| Rust | Go 对应 | DNS 条件 |
|---|---|---|
| `host_blocked_with_local_binding(…, HostAuthorization::RequireAllowlist)` | `baselineLocalBindingReason(request, allowlist, allowed)`（`:1667`） | 仅当 `allowlisted` ⇒ 等价「未授权不得触碰 DNS」 |
| `host_blocked_with_local_binding(…, HostAuthorization::Approved)` | `approvedLocalBindingReason(request, allowlist)`（`:1683`） | 无条件查 DNS ⇒ 等价 `Approved`（授权后必查） |

- 审批路径 `:1635-1653`：`decider != nil → Decide → Allow → approvedLocalBindingReason`，**先审批再查 DNS**，
  命中 private ⇒ 拒绝；这正是 (3) 的内层语义来源。
- 内层 MITM 路径确实**重入**完整策略（`serveMITMHTTP:1396` 只写 `proxyMITMContextKey` ⇒
  `handleHTTPRequest` 的 `policyChecked=false`（`:1059`）⇒ `blockReasonFor → evaluateProxyPolicy`），
  于是 R1+R2 对「无 allowlist 条目 + 有 decider」的主机同样生效：**decider 批准 → 复查 → 403 not_allowed_local**。
- 与 syncl1 探针的**唯一口径差异**：baseline 下该探针 `deciderCalls=0`（因 DNS 抢跑），本补丁下
  `deciderCalls=1`（审批后才查 DNS）。**结果等价（403 + not_allowed_local）、调用顺序不同**，
  而顺序变化正是 R1 要修的缺陷本身（syncl1 的 `deciderCalls=0` 是旧 bug 的副产品，不是待保留行为）。
  RC1 的 FAIL 行 `inner MITM decider calls = 0, want 1` 即为该差异的机器判据。
