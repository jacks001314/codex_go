## Goal

Keep collaborator tool analytics events correlatable when the tool completes
before its sampling response arrives.

## Findings

- Rust #42752 emits `CollabAgentToolCall` items with
  `ToolEventEmission::AwaitResponse` instead of
  `ImmediateUnlessCorrelated`, so the reducer holds the event until a sampling
  response can attach the originating id; the next response becomes the
  subsequent id.
- Go already had `pendingToolEvents`, `releasePendingToolEvents`, and both
  response-id fields, but `emitToolEvent` only buffered events that were
  already correlated. A fast collaborator completion was therefore emitted
  immediately with no response ids.
- Go's existing `TestRuntimeRouterCollabAndImageToolAnalyticsLikeRust` expected
  immediate delivery; Rust's turn-close flush is now the equivalent path.

## Implementation

- `appserver/tool_event_origin.go`: added `toolEventEmission` with
  `toolEventEmissionAwaitResponse` and `emitToolEventWithEmission`, keeping
  `emitToolEvent` as the immediate-unless-correlated wrapper.
- `appserver/remaining_tool_item_analytics.go`: collaborator events now use the
  await-response emission.
- `appserver/collab_agent_tool_response_ids_like_rust_test.go`: covers both
  orderings (completion first and response first) and asserts
  `originating_response_id=response-1` and
  `subsequent_response_id=response-2`.
