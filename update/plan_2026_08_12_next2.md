       (reject incomplete/conflicting/unsupported combos); thread a
       process-scoped session so resolve and refresh reuse the same
       `WorkloadIdentityExchange`.

       authenticated subject.
     - Retry classification + concurrent-refresh invalidation semantics from

   portable piece implemented:
   - `auth.AuthsEqualForRefresh` for `chatgptAuthTokens` now compares token

     Regular `chatgpt` mode keeps full auth JSON equivalence.
   - Tests: token-data equality, chatgpt-mode distinction, nil handling.
   - Architectural delta (documented, not ported): the Configured vs Runtime
     `ExternalAuthSource` slot, host-owned immutability (no replace/clear/
     logout), process-local credentials, and provider `classify_error` require
     a Rust-style `ExternalAuth` provider layer in the Go auth manager; Go's
     external auth is the host-driven `chatgptAuthTokens` mode with no host
     surface to install a configured provider. The workload-identity consumer

   implemented:

     removal); remote apply_patch commands now flow to the executor and run
     under the executor's process sandbox.
   - `sandbox/violation.go`: added `IsLikelyExecutorManagedSandboxDenied`
     (keyword-based, no backend requirement) mirroring Rust
     `is_likely_executor_managed_sandbox_denied`.
   - `tool/unified_exec.go`: added `executorWindowsSandboxLevel` (Disabled +
     Windows-convention cwd -> the restricted-token/unelevated baseline) and
     applied it in `NewFileSystemSandboxContext`, mirroring Rust
     `executor_windows_sandbox_level`.
   - Tests: executor level selection, path convention, sandbox-context
     upgrade, denial keywords.
   - Tracked delta: executor-side fs-helper fail-closed on Disabled
     (`SandboxablePreference::Require` semantics in `execserver/fs_helper.go`,

     executor to fail closed on Disabled would alter skill-read behavior
     without a Windows-only test matrix here.
