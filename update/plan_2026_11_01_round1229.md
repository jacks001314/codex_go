# Round 1229: Package uninstall observation (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42375,
`package_lifecycle.rs` catalog subscription and
`package_lifecycle/registered.rs::on_package_uninstalling`).

## Context

The service must retire the managed sandbox only when the authenticated owner's
package is really gone. An update removes an old version first, so the decision
is taken from the whole package family and only after the notification reports
completion; a service that cannot watch its own uninstall must refuse the
registration instead of cleaning up blind.

## Package catalog surface

`windowsandboxservice/winrt_catalog_windows.go` adds the WinRT surface the
subscription needs:

- `RoGetActivationFactory` for `Windows.ApplicationModel.PackageCatalog`
  (`IPackageCatalogStatics`), `OpenForCurrentUser`, and the
  `PackageUninstalling` / `RemovePackageUninstalling` pair;
- `IPackageUninstallingEventArgs.Package` and `IsComplete`;
- a Go-implemented `ITypedEventHandler<PackageCatalog, PackageUninstallingEventArgs>`
  delegate: a `LocalAlloc`'d object holding the shared thunk vtable,
  `QueryInterface` answering every identity, refcounted `AddRef`/`Release`
  with memory release at zero, and `Invoke` mapping Go errors to HRESULTs;
- a dedicated multithreaded apartment thread that initializes once and
  uninitializes on `Close`, because the subscription outlives the call that
  created it (Rust initializes in `PackageLifecycle::new` and uninitializes in
  `Drop`). The subscription is opened under owner impersonation so it is the
  authenticated owner's catalog.

## Uninstall policy

`windowsandboxservice/uninstall_event_windows.go` ports
`registered::on_package_uninstalling`:

- a missing record means no retention, another owner's record means no decision
  and no event read;
- a retaining registration wakes the provisioning listener only once
  `IsComplete` reports the update finished;
- an owner without a managed package stores the pending-uninstall flag as
  `!IsComplete`, so an SCM stop initiated before the package is gone still
  cleans up;
- an unreadable ownership is logged as `SERVICE_FAILED` and leaves the flag
  alone.

## Lifecycle wiring

- `NewLifecycle` captures the running package's full name and fails without
  package identity; `NewPackagedProvisioningBroker` builds it when the SCM
  starts, so that failure is a startup failure.
- `RegisterOwner` subscribes on the first registered owner, keeps the stream
  when a restored watcher re-registers, and refuses the registration with
  `ServiceUnavailable` if the subscription fails, releasing the pinned home and
  guard so cleanup never runs against an unwatched installation.
- `Close` removes the registration, then the catalog and apartment, before
  releasing the pinned directories.

## Known gaps

The owner-removed admission loop (`runtime_lifecycle::run`, the
`wait_for_cleanup_retry` path and `ServiceStopReason::OwnerRemoved`), the
installer/MSIX required-resource wiring, and a caller for
`CleanUpRegisteredRuntime` remain open.

## Coverage

`uninstall_event_like_rust_test.go` covers the retention/wake policy, another
owner's event ignored without reading it, unreadable ownership logged, event
failures propagated, the first-owner subscription reused by a restored watcher
and released on `Close`, the refused registration on subscription failure, and
the delegate's `QueryInterface`/`AddRef`/`Release` bookkeeping with a real
vtable `Invoke` dispatch. The catalog probe against an unpackaged process
reaches `PackageUninstalling` and receives `CO_E_NOT_SUPPORTED`, which is the
expected WinRT answer outside a package.
