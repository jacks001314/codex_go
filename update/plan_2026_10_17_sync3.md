## 2. #54739：arg0 锁文件与 janitor（推翻上一轮 N/A）

Rust `527c5deb74` 的两点：

1. `Arg0PathEntryGuard` 字段 drop 顺序改为“先关锁、再删目录”，避免 NFS silly-rename 残留 `.nfs*`；
2. `janitor_cleanup` 用 `try_lock_dir` 判定目录是否仍被存活进程持有（拿不到锁就跳过），
   Unix 上先 rename 到 retired 目录再关锁删除。

Go 侧上一轮判 N/A 的理由是“Go 只用 `os.WriteFile` 写空 `.lock`，没有加锁”。本轮确认
`github.com/gofrs/flock` 已是依赖（`session/writer_lock.go` 等在用），载体成立，故落地：

- `cli/dispatch.go`
  - `DispatchAliasGuard` 新增 `lock *flock.Flock`；`PrepareArg0Aliases` 写完 `.lock` 后 `TryLock()`，
    锁随 guard 存活；`Cleanup()` 先 `removeArg0DirLocked`（内部先关锁）再兜底 `releaseLock`。
  - `CleanupStaleDirs` 改为 `flock.New(.lock).TryLock()`：拿不到锁 ⇒ 跳过（对应 Rust `try_lock_dir`）；
    拿到锁 ⇒ 删目录；`os.IsNotExist` 视为 TOCTOU 正常竞争。
  - `PrepareArg0Aliases` 启动时调用 `CleanupStaleDirs`（对应 Rust `janitor_cleanup`，失败只告警）。
  - `arg0TempRoot` 改为 `tmp/arg0-<GOOS>`，顺带补齐 Rust #53412（`16845bb8e8`）的按 OS 隔离，
    避免 Windows 与 WSL 共享 `CODEX_HOME` 时锁命名空间不一致。
- `cli/dispatch_dir_unix.go`（新增）：`removeArg0DirLocked` 先在父目录建 retired 目录，rename 后关锁再删。
- `cli/dispatch_dir_windows.go`（新增）：非 Unix 直接关锁后删除（Rust 的 rename 技巧仅 `cfg(unix)`）。
- `cli/dispatch_test.go`：新增 4 个用例 —— 持锁目录跳过、按 OS 根目录、第二个 guard 不删除活动会话目录、
  guard 生命周期内锁确实被持有；并扩展 `TestCleanupStaleDirs`（回收后根目录为空）与 `TestPrepareArg0Aliases`。

## 3. #54742：斜杠命令前缀改为 prompt 标记（TUI）

Rust `5009a99dfc` 的语义（`draft_state.rs` 的 `PromptPrefix{None,Shell,Slash}`）：

1. 首个 extended grapheme cluster 为 `/`（斜杠命令）或 `!`（shell）时，把它从可编辑文本移入 prompt 状态；
2. `current_text()` = prefix + textarea 文本，提交/排队/历史/外部编辑都保留前缀；
3. 正文起点 Backspace 删除前缀；Shell 模式下空正文按 Esc 退出；
4. `is_empty` 要求 prefix 为 None（裸前缀不算空）；
5. 渲染时 `/` 用 accent 色、`!` 用 light-red。

### 3.1 已知偏差（有明确技术原因，不可强行照搬）

- **composer-owned slash command element**：Rust textarea 把命令名注册成原子 text element，导出 draft 时剔除；
  Go 的 bubbles textarea 没有元素注册 API，`composerElements` 只承载 mention/attachment，命令名从未注册，
  因此“剔除”无载体（结果等价：导出元素里也不会出现命令名）。
- **Vim Replace recovery**：Rust 用 `replace_steps` 栈在删除前缀时恢复被覆盖字符；Go Vim 的
  `replaceVimCharAdvancing` 不保存恢复栈，故只做“删前缀、不动正文”，不回放恢复。

## 4. #54754：N/A 复核

（`jsonschema/jsonschema.go:31 jsonSchemaSubsetKeys`、`:59 SubsetSchema`），不存在可省的 inline 容量。
