# Round 1212: Authenticated provisioning pipe and client authorization (2026-10-31)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342, #42375, crate
windows-sandbox-service).

## Context

Round 1211 landed the service-side request validator and Codex home pinning, and
Round 1206 landed the client half of the protocol, but no Go process ever
created the pipe. This round adds the listener and the caller authentication that
must pass before a single request byte is dispatched.

## Pipe listener

`windowsandboxservice/pipe_windows.go` ports Rust `ipc::listener`:

- `PipeSecurityDescriptor` builds `D:P(D;;GA;;;<sandbox SID>)(A;;GA;;;SY)(A;;GA;;;BA)(A;;0x0012019b;;;IU)`,
  so the sandbox group is denied and only SYSTEM, administrators and interactive
  users may connect (Rust `pipe_security_descriptor`);
- `OpenProvisioningListener` resolves the pipe name for the active package
  family, takes the machine-wide `Global\CodexSandboxSetup` mutex, refuses an
  interrupted registered-Core cleanup (`runtime.retiring`), ensures
  `CodexSandboxUsers` exists and creates the pipe with
  `FILE_FLAG_FIRST_PIPE_INSTANCE`, byte mode, `PIPE_REJECT_REMOTE_CLIENTS`, one
  instance, a 1024-byte out buffer and the 4096-byte request bound as the in
  buffer, all under the converted SDDL DACL;
- `Refresh` re-resolves the group SID under the setup mutex and either
  `DisconnectNamedPipe`s the same instance (same generation) or closes the pipe
  and descriptor and rebuilds them, because a stale deny SID must never be used
  for dispatch;
- `AcceptPipeConnection` ports `accept_pipe_connection` (connected,
  disconnected wakeup, or error) and `WakeProvisioningPipe` ports `ipc::wake`
  (zero-byte client that retries 25 ms apart until the service stops).

The sandbox group SID is resolved through the existing setup helper package so
the service and the interactive helper share one implementation.

## Caller authorization

`windowsandboxservice/identity_windows.go` ports Rust `package_identity` and
`ipc::authentication`:

- `AuthorizeClientProcess` reads the connected client with
  `GetNamedPipeClientProcessId`, opens it with `PROCESS_QUERY_LIMITED_INFORMATION`
  and requires the client and service package families to be present and equal
  before any request is read;
- `AuthorizeClient` compares the client process token's user SID with the
  impersonated pipe token's user SID;
- `AuthorizeSetupRuntime` admits registered Core only from the service's own
  installed package family and image (`codex.exe` or
  `codex-code-mode-host.exe` beside the service binary), refuses legacy
  provisioning while a registered runtime owns the accounts, and treats a
  registration-only request as legacy without consulting the record;
- `AuthenticateClient` rechecks the sandbox group generation under the setup
  mutex (`sandbox group changed before authentication`), impersonates the pipe
  client on an OS-locked thread, opens the thread token, rejects session 0 and
  sandbox-group members, captures the user SID and `DOMAIN\name`, runs the
  runtime authorization above and pins the Codex home: `prepare_codex_home` for
  provisioning or the registration set (`OpenExisting` home with
  `FILE_ADD_FILE|FILE_ADD_SUBDIRECTORY|WRITE_DAC`, directory guard, probe and
  `GetFinalPathNameByHandleW`) for uninstall ownership. It also records the
  desktop installation (`.desktop-created` marker plus the owner's profile
  `.cache` root) and retains the impersonated token and every pin for the
  request.

`provisionservice.ProcessPackageFamily` is exported so the service can read the
family of an arbitrary process handle instead of only its own.

## Known gaps

The request read/dispatch loop, the response writer and error mapping, the SCM
service host (`EVENT_*`, `SetServiceStatus`), provisioning under a retained
impersonation, the managed-policy load that runs as the impersonated owner, and
the package-lifecycle/registered-runtime transactions are still missing, so
#42342/#42375 keep their service-side residuals.

## Coverage

`pipe_test.go` and `identity_policy_test.go` (SDDL shape and ordering,
`RequireRuntimePackageFamily` table, installed-service image matching),
`identity_windows_test.go` (a real named pipe: an unpackaged client is refused
before sending a request; a disconnected client does not block a later one;
legacy provisioning is refused while registered Core owns the accounts; a
registration-only request stays legacy; registered Core is refused without an
installed package family).
