# Round 1181: caller-owned Windows sandbox desktops and the runner startup flags (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

## Gap

The Windows sandbox stream still carried four `audit_pending` entries after the
TUI stream was handed to the parallel usealign agent.

- #44658 (`4caa5d615d`) keeps private desktops alive across helper exits. Go
  created every desktop inside `RunWindowsSandboxWrapperRequest`, and the
  filesystem helper runs that wrapper as a separate short-lived process, so each
  RPC paid for a fresh desktop and never reused it.
- #42801 (`89a4eec6da`) hides the command runner. Go already launched the
  elevated runner with `CREATE_NO_WINDOW` and pipes children through
  `ConsoleModeNoWindow`, but the runner's `STARTUPINFOW` never set
  `STARTF_FORCEOFFFEEDBACK`.
- #42596 (`f60dfe80b5`) recorded a `codex.windows_sandbox.private_desktop`
  counter. Rust deleted that counter together with the private-desktop opt-out
  in #46554, so the entry is superseded rather than portable.
- #49389 (`9212b3eca8`) only changes codex-rs nextest/Cargo test settings.

## Evidence

- `sandbox/windowssandbox/desktop_windows.go` now exposes
  `SharedLegacyPrivateDesktopName` (Rust `LaunchDesktop::shared_legacy_name`)
  and builds the desktop through `PrivateDesktop::create`'s security model, so
  USER32 processes in the restricted token stop failing with
  `STATUS_DLL_INIT_FAILED` (`0xC0000142`).
- `sandbox/windowssandbox/cap.go` ignores a `cap_sid` file whose JSON does not
  parse and rebuilds it, matching `load_or_create_cap_sids` (the damaged file
  otherwise fails every sandboxed launch).
- `sandbox/windowssandbox/wrapper.go` gained
  `--windows-sandbox-private-desktop-name`: `CreateWindowsSandboxCommandArgsForPermissionProfile`
  emits it when the caller opted into `PreparePrivateDesktop`,
  `ParseWindowsSandboxWrapperArgs` validates it,
  `wrapperCaptureRequest` forwards it, and `elevated_impl.go` plus `lib.go`
  open the parent-owned desktop instead of creating one.
- `sandbox/windowssandbox/wrapper_desktop_windows.go` ports the caller-side
  selection: restricted-token launches use the capability roots, elevated
  launches use `RequireLogonSandboxCredsForPermissions` plus
  `RootCapabilitySIDs` (Rust `require_sandbox_account` without the wrapper's ACL
  refresh), and both go through the process-wide desktop cache.
- `execserver/fs_helper.go` sets `PreparePrivateDesktop`, because filesystem
  helpers are exactly the short-lived-wrapper path Rust #44658 fixes.
- `sandbox/windowssandbox/elevated/runner_client_windows.go` sets
  `STARTF_FORCEOFFFEEDBACK` on the runner `STARTUPINFOW`.

Deliberate Go-only fallback: `RunWindowsSandboxWrapperRequest` is also the
in-process entry point for `codex sandbox`, where the desktop cache already
lives in the long-lived CLI process. An absent desktop name therefore keeps the
local selection path instead of failing the launch (Rust bails in
`parse_windows_sandbox_wrapper_args`). Because of that, #44658 stays `partial`.
