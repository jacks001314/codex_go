### sync140: Flex capacity failures are a distinct terminal error (#47967)

- `codexapi` gains `ErrorFlexUnavailable` with Rust's display text
  ("Flex capacity unavailable.") and the matching response-debug telemetry
  message.
- The model layer recognises `flex_unavailable` in HTTP 429 bodies, in a
  standalone streamed `error` event, and in `response.failed`, and treats it as
  non-retryable.
- The app-server maps it to `flexUnavailable` with `httpStatusCode: 429`
  (Rust `CodexErrorDetails::http_status_code_value`), and the rollout reader
  accepts the new classification.

### sync141: the cloud config table and cloud skills gate (#47074)

- `cloud` joins the recognized top-level config keys with strict sub-field
  validation mirroring `CloudToml` (`cloud.skills.enabled`).
- `Config.CloudSkillsEnabled()` reads `cloud.skills.enabled` defaulting to
  true; `orchestrator.skills` is retained as a legacy no-op, matching Rust's
  provider replacement. Go's gate therefore follows the cloud setting.
- `image_gen.imagegen` accepts the new `transparent_background` boolean and
  always sends an explicit `transparent`/`opaque` background, replacing the
  previous `auto` value (#47484); the vendored description gained the matching
  guideline.
- Guardian extra policy (#47125): the managed `guardian_extra_policy`
  requirement and `[auto_review] extra_policy` fill the template's
  `{{ extra_policy }}` slot, with Rust's two-pass substitution so
  placeholder-like text inside either policy stays literal.

### sync142: explicit gateway sign-in RPCs (#47170/#47207)

- `account/gatewayOAuth/read|login|cancel` are advertised in the JSON and
  TypeScript client surfaces with the `account/gatewayOAuth/changed`
  notification (`GatewayOAuthChangedNotification`).
- `auth.GatewayAuthManager` gained a per-CODEX_HOME login control: status
  (`notReady`/`started`/`succeeded`/`failed`), status subscriptions, the
  one-sign-in-at-a-time guard, and `LoginWithBrowser` with a caller-owned URL
  handoff. The read RPC reports provider policy and readiness without
  credentials; cancellation is bound to the initiating connection and is
  acknowledged only after the login releases its slot.

### sync144: the tool-suggestion app link validates its install URL (#48015)

- Static re-pin for the single new commit: the TUI snapshot total is 1321 and
  `tui/src/chatwidget/snapshots` grows to 314 with the new
  `declined_tool_suggestion` snapshot as a required entry.
- `bottompane` now parses the form-mode tool suggestion
  (`codex_approval_kind: tool_suggestion` with `tool_type`/`suggest_type`/
