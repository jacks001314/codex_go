## 2. 设计：怎么把「校验被拒」和「普通 discovery 失败」区分开

新增一个**类型化拒绝**（`mcp/oauth_discovery.go`）：

```go
// mcpOAuthIssuerBindingRejection marks a metadata document that parsed but was
// rejected by validateMCPOAuthAuthorizationServerEndpoints (#39935). Rust
// propagates that failure straight out of `perform_oauth_login`, so the
// interactive login hand-off treats it as fatal instead of falling back to the
// guessed `<server>/oauth/authorize` URL.
type mcpOAuthIssuerBindingRejection struct{ err error }
func (e *mcpOAuthIssuerBindingRejection) Error() string { return e.err.Error() }
func (e *mcpOAuthIssuerBindingRejection) Unwrap() error { return e.err }

func newMCPOAuthIssuerBindingRejection(message string) error { ... }
func mcpOAuthIssuerBindingRejected(err error) bool { var r *mcpOAuthIssuerBindingRejection; return errors.As(err, &r) }
```

`validateMCPOAuthAuthorizationServerEndpoints` 的 **7 处拒绝**全部改走 `newMCPOAuthIssuerBindingRejection(...)`（消息**逐字不变**，与 Rust 一致）；用 `errors.As` 判定 ⇒ 网络错误 / HTTP 状态错误 / JSON 解码错误**不**被误判为拒绝。

**这正是档 A 的边界**：网络类失败仍走原有兜底（实测 3 条既有测试依赖它），只有「metadata 成功解析但被绑定规则拒绝」才上抛。

## 3. 逐文件「改动前 → 改动后 + 理由」

### 3.1 `mcp/oauth_discovery.go`
| | 改动前 | 改动后 |
|---|---|---|
| validator 返回 | `return errors.New("OAuth token endpoint origin does not match …")` × 7 | `return newMCPOAuthIssuerBindingRejection("…")` × 7（文案不变） |
| `buildMCPOAuthURLWithDiscovery` | `func(...) string`；`err != nil` ⇒ 一律 `return buildMCPOAuthURL(config, scopes)` | `func(...) (string, error)`；**先**判 `mcpOAuthIssuerBindingRejected(err)` ⇒ `return "", err`，其余错误仍 `return buildMCPOAuthURL(config, scopes), nil` |
| `buildMCPOAuthURLForLogin` | `func(...) string`（nil-timeout 快捷路径直返） | `func(...) (string, error)`；快捷路径 `return buildMCPOAuthURL(config, scopes), nil`，否则透传 `buildMCPOAuthURLWithDiscovery` |

**理由**：Rust `perform_oauth_login.rs:875-876` 是把 `validate_authorization_server_endpoints(&metadata)?` 直接冒泡；Go 之前把该错误当普通失败吞掉并猜一个 `<server>/oauth/authorize`，属语义分叉。**注意**：nil-timeout 快捷路径（`buildMCPOAuthURLForLogin` 第一分支）**故意保留**——它就是既有 3 条测试依赖的兜底（`mcp/http_client_test.go:1953`、`app/mcp_cli_test.go:382`、`:772`），本单**不**删（那是被裁定的档 B）。

### 3.2 `mcp/api.go`
| | 改动前 | 改动后 |
|---|---|---|
| `startOAuthLoginServer` 签名 | `(string, bool)` | `(string, bool, error)` |
| discovery 出错 | 一律 `return "", false` | **先**判 `mcpOAuthIssuerBindingRejected(err)` ⇒ `return "", false, err`；其余 `return "", false, nil` |
| 其余 early-return | `return "", false` | `return "", false, nil`（语义不变） |
| `OauthLogin` 调用点 | `if loginURL, ok := ...; ok { url = loginURL } else if DCR… else { url = buildMCPOAuthURLForLogin(...) }` | `if loginURL, ok, loginErr := ...; loginErr != nil { return nil, loginErr } else if ok { … } else if DCR… else { `fallbackURL, fallbackErr := buildMCPOAuthURLForLogin(...); if fallbackErr != nil { return nil, fallbackErr }; url = fallbackURL }` |

**理由**：两处是 login URL 的**全部**产生点（`startOAuthLoginServer` 优先；失败后走 `buildMCPOAuthURLForLogin`）。两处都上抛，才能保证「被拒 AS ⇒ 绝不产出兜底 URL」。DCR 分支的既有错误**优先级不变**（只有「非绑定类」失败才会走到它——见 §5 实测）。
