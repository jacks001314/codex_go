## Newly discovered non-TUI core gap: reasoning-effort override runtime

While cross-checking the range, the reasoning-effort override cluster was found
unported and previously only referenced by the single `#44276` note in
plan_2026_09_11.md. It is non-TUI core, so it takes priority over the TUI pass.

Upstream commits (oldest -> newest):

- `56a8470aa0` #43110 Record reasoning effort changes in conversation history
  behind a flag: adds `reasoning_effort_override` (UnderDevelopment, off) for
  OpenAI models with `use_responses_lite`; appends a trusted
  `configuration_update` after accepted input when no effort is established in
  surviving history or the resolved effort changes; shares normalization via
  `ModelInfo::resolve_reasoning_effort` (ultra resolution, `persistent` ->
  `disabled`, custom values other than `disabled` excluded).
- `31ccaf40c2` #43795 Pin request reasoning effort while overrides are active:
  per-session `ReasoningEffortPin` (Unset / Active{model, effort}) establishes
  the request baseline for the current model, including during WebSocket
  prewarm; re-established after rollback/resume/model switch.
- `35d9e4bc4d` #43796 Preserve reasoning effort through compaction and reset it
  on success: local and remote compaction use the pinned request effort when it
  matches the model, fallback-model resolution must not mutate the live pin, and
  a successful compaction resets the pin so the next sampling request
  establishes the selection without a redundant `configuration_update`.
- `5d3f8752fc` #44285 Preserve prewarmed reasoning effort across replay and early
  rollback: history reconstruction keeps the pin while startup prewarm is
  retained; rollback clears it only after prewarm is consumed.
- `f5c5d9b2b0` #44276 Avoid duplicate reasoning effort updates during turn
  recovery: reuse a matching harness-authored `ConfigurationUpdate` at the end
  of history even when the runtime pin is unset.

Go current state (evidence):

- The feature key exists: `features/features.go` line 184
  (`reasoning_effort_override`, UnderDevelopment, default off).
- The trust/replay plumbing from sync30 already exists: `session.Item` with
  `harness_authored_configuration` metadata, `session.harnessAuthoredConfigurationUpdate`
  / `configurationUpdateInputItem` (session/history.go), and
  `appserver.trustedConfigurationUpdateSessionItems` (turn_runtime.go:4134)
  which persists internal `AdditionalInputItems` as trusted updates.
- Normalization exists privately as `model.reasoningEffortForRequest`
  (model/responses_agent.go:1081) for ultra resolution, with `persistent` ->
  `disabled` handled at the request-build call site.
- **Missing**: no producer that decides to append the update, no
  `ReasoningEffortPin` runtime state, no request-pin usage, and no
  compaction/prewarm/replay integration.

Integration points / hazards discovered:

- Selected effort is resolved by `appReasoningEffortForTurn`
  (turn_runtime.go:157) and flows as `appTurnRunConfig.ReasoningEffort`
  (turn_runtime.go:6303) into `turn.AgentLoopRequest.ReasoningEffort`.
- Request input assembly (turn_runtime.go:1354) appends
  `params.AdditionalInputItems` **before** the user message
  (`preparedUserMessageInputItem`/`Prompt`), whereas Rust appends the override
  **after** accepted input. A faithful port must place the trusted
  `configuration_update` after the accepted user message in both the request
  input and persisted session items (`sessionItemsForTurn` currently persists
  trusted updates at index 1, i.e. after the user message).
- Per-thread state lives in `RuntimeRouter` (`active`, `diffs`,
  `startupPrewarms`, ...); the pin would be a sibling per-thread map keyed by
  model slug, with reset hooks on rollback, resume, model switch, and
  successful compaction.
- Compaction paths to update: `compactThread` / `midTurnSamplingCompaction`
  (appserver) and `execMidTurnSamplingCompaction` (exec).

Status: **pending** - to be implemented as a dedicated non-TUI core batch
(`batch-reasoning-effort-override`) before the TUI pass. Because the feature is
disabled by default, this has no effect on default behavior until the key is
enabled, but it is required for parity.

Note: the parallel voice process is concurrently editing `turn_runtime.go`,
`runtime_router.go`, and other shared files, so this batch should be landed with
the same filtered-hunk staging discipline used for #44883.
