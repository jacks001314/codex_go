### 补丁内容（3 处改动，全部在 `config/cloud_config_policy_test.go`）

1. 新增 `runtime` import；
2. 新增纯函数 `cachePermMatchesPublishedMode(goos string, perm os.FileMode) bool`（Windows 接受平台回报，POSIX 严格断言 `0o600`）+ 其平台规则单测 `TestCachePermMatchesPublishedModeIsPlatformAware`；
3. 原断言改为调用该函数：

```go
-	if perm := info.Mode().Perm(); perm != 0o600 {
+	if perm := info.Mode().Perm(); !cachePermMatchesPublishedMode(runtime.GOOS, perm) {
 		t.Fatalf("published cache permissions = %o, want 600", perm)

```

**为什么不用裸 `if runtime.GOOS != "windows"`（我采用的替代形式的理由）**：行为与队长建议的写法**完全等价**，但把平台规则抽成纯函数后，**Windows 分支在 Linux 上可被单测覆盖**（`cachePermMatchesPublishedMode("windows", 0o666) == true`），并且能给出可复跑的**值级 RC**（见 §3）——裸 `if` 写法在 Linux 上无法被任何测试触达。Windows 分支的其余断言（目标文件存在、内容与已发布 payload 一致、staging 期间不被改写）**原样保留**，未削弱。

> 备选（如需最小 diff）：把 helper 换成 `if runtime.GOOS != "windows" { if perm := …; perm != 0o600 { t.Fatalf(…) } }`，功能等价、但失去 Linux 可跑的 RC。请队长择一。

## 4. `#49269` 本体其它 Windows 面风险（按 §4 要求说明）

队长的 Windows 门禁在 `cloud_config_policy_test.go:176` 就 `t.Fatalf` 中止了，**其后的步骤在 Windows 上从未被执行过**。加上 guard 后，Windows 会继续走到以下几处，请 batch five 的 Windows 门禁顺带确认：

1. **`config/cloud_config_storage.go:354 os.Rename(temporaryPath, destination)` 覆盖已存在目标**——测试里第二次 publish 会**覆盖**已发布的 cache 文件。Windows 下 `os.Rename` 走 `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`，能替换，但若目标被其它句柄占用会失败（POSIX 无此约束）。这正是 Windows 与 Linux 语义差异最大的一点，属**已实现但未在 Windows 上验证过**的路径。
2. `config/cloud_config_storage.go:331 temporary.Chmod(0o600)` 在 Windows 上是**空操作**（不改权限）；生产语义「cache 私有」在 Windows 依赖 `%LOCALAPPDATA%` 与用户 ACL，而**不是** 0600。若队长要求 Windows 上也表达「仅本人可读」，需要 ACL 方案——**这是新需求，不在本 PR 范围**，我未擅自扩展。
3. 测试里 `stagedCacheFiles` 依赖 `cloudConfigBundleCacheFilename+".tmp-"` 前缀计数（`os.CreateTemp` 的 pattern 在 Windows 上同样生效），以及 `errors.Is(err, os.ErrNotExist)` 的存在性断言——均为平台无关写法，预期安全，但同样未被 Windows 跑过。
