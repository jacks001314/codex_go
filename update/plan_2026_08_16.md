## Committed in this batch

1. #38767 Forward workload identity context during token exchange
   - `auth` reads `OPENAI_WORKLOAD_IDENTITY_CONTEXT`, forwards it unchanged as
     the `workload_identity_context` exchange field, and includes it in the
     workload identity session fingerprint so sessions with different values
     cannot share an exchange; `envutil` scrubs the variable from
     model-reachable child environments (Rust `NON_INHERITABLE_ENV_VARS`).
2. #38795 Add storage diagnostics to `codex doctor`
   - New `system.disk` check reports available space for `CODEX_HOME` and the
     active worktree (warning below 5 GiB, failure below 1 GiB, measured via
     `unix.Statfs` / `windows.GetDiskFreeSpaceEx`). New `git.worktree.dev_drive`
     check (Windows) reports whether the active Git worktree is on a trusted
     Dev Drive (IOCTL persistent-volume-state flags) with remediation.
     Feedback doctor-report workspace anchoring is N/A: Go has no feedback
     doctor attachment.
3. #38800 Route executor policy audits through log-only telemetry
   - Forwarded `codex.network_proxy.policy_decision` events carry
     `target=codex_otel.log_only`; the state `LogDBHandler` excludes that
     target from the persistent log while standard logging still receives it.
4. #38827 Add endpoint protection checks to `codex doctor`
   - New `security.endpoint` check detects CrowdStrike Falcon, BeyondTrust
     Privilege Management, Microsoft Defender and SentinelOne (Windows
     `sc.exe query`) plus Jamf Protect (macOS `systemextensionsctl list`),
     with product-specific exclusion remediation and
     complete/partial/unavailable inspection states.
5. #38840 Identify Mac mini hosts in remote control handshakes
   - Remote-control WebSocket handshakes send `x-codex-host-device-kind:
     mac_mini` on macOS when `system_profiler` reports a machine name of
     exactly `Mac mini` (2 s timeout, cached successful detection, header
     omitted on other platforms/failures).

## Follow-up batch (same window) — all four deferred commits closed

1. #38774 Use paginated history for persistent exec threads
   - Fresh persistent `codex exec` threads now persist `history_mode:
     paginated`. The paginated encoder maps non-command tool calls/outputs to
     canonical `DynamicToolCall` thread items (Rust's protocol `TurnItem` has
     no plain `function_call` variants) and command tools to `CommandExecution`
     via JSON-argument command extraction; exec session-item building carries
     arguments/input in item data so every exec item is paginated-compatible.
   - Verification: `go test ./exec ./rollout ./session ./appserver -count=1`.
2. #38743 Scope TUI app directory state to the active context
   - The tea apps directory flow tags fetches with a scope generation,
     discards stale results after account/workspace/thread changes, and
     dismisses an open apps view on invalidation (resume/fork/agent
     switch/delete). `AppListUpdated` revalidation is N/A: Go fetches fresh on
     every apps open, so there is no cached directory content to revalidate.
   - Verification: `go test ./tui/tea -run
     'TestApplyAppListResultIgnoresStaleScopeLikeRust|TestInvalidateAppsScopeDismissesOpenAppsView'
     -count=1`.
3. #38788 Show resume and fork status during TUI startup
   - Equivalent: Go's session-picker modal is the startup surface (entries
     labeled with the Resume/Fork action) and session actions resolve
     synchronously with outcome notices; Rust's `StartupDraft` loading line
     is a cosmetic status rendered during an async startup window Go does not
     have.
4. #38830 Isolate external editor buffers from sandbox-writable paths
   - `EditorDirectory` resolves a protected `<home>/editor` directory
     (configured home, default home, workspace fallback), rejecting
     candidates exposed as writable by the effective filesystem policy or
     resolving through symlinks; the tea external editor creates buffer files
     there and surfaces an editor error when no protected directory is
     available; the interactive app wires the effective permission profile's
     sandbox policy.
   - Verification: `go test ./tui/tea -run TestEditorDirectory -count=1`.
