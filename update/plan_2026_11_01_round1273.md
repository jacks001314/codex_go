## What changed

- `sandbox/windowssandbox/uninstall_prepared_stub.go` (build tag `!windows`)
  imported `golang.org/x/sys/windows` for its retained-token parameter, so
  every non-Windows build of `windowssandbox` — and therefore `execserver`,
  `tool` and `agent` — failed. The parameter is now the cross-platform
  `RetainedLogonToken` alias (`windows.Token` on Windows, an opaque struct off
  it); no caller changes.
- `execpolicy/dangerous_command_windows.go` held platform-independent string
  rules (they also classify a remote Windows executor from a POSIX host)
  behind the implicit `_windows.go` constraint, breaking linux/darwin builds.
  Renamed to `execpolicy/dangerous_command_winrules.go`; Windows behavior is
  unchanged.
- `.gitattributes` pins `prompt/collaboration_mode_plan.md` to `eol=lf` like
  the TUI copy. `//go:embed` kept the CRLF checkout, so on Windows
  `BuiltinPlanModeInstructions()` differed byte-for-byte from both the TUI
  preset and the Rust template, and Rust #41744 built-in-preset matching
  (`turn_runtime.go` collaborationModeInstructions) silently treated the
  built-in preset as custom text.
- New guard `parity/cross_platform_build_test.go` compiles `./...` for
  linux/amd64 and darwin/arm64 with `CGO_ENABLED=0` (skipped under `-short`).
