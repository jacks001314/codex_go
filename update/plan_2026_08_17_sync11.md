## Gap: session-startup prewarm

Rust schedules an asynchronous websocket prewarm at session spawn
(`Session::schedule_startup_prewarm`, session.rs) and the first regular turn
consumes it (`consume_startup_prewarm_for_regular_turn`, tasks/regular.rs):
the prewarmed ModelClientSession is used for the first model call, and a turn
that starts before the prewarm finishes proceeds without it (Unavailable).

Implemented in the appserver:

- `appserver/session_startup_prewarm.go`: `scheduleStartupPrewarm` runs an
  asynchronous token-free websocket prewarm (`ResponsesAgentRunner.Prewarm`,
  generate=false) when a thread is created, with a 15s timeout; the response
  id is stored per-thread. `takeStartupPrewarmResponseID` consumes it once.
- `appserver/runtime_router.go`: the trigger fires after ThreadStart
  (mirroring `startMemoriesStartupTask`).
- `appserver/turn_runtime.go`: the first regular turn's `previousResponseID`
  falls back to the prewarmed id when the thread has no prior response
  (Rust regular.rs consume semantics); a not-yet-finished prewarm is skipped.
- Agents that do not implement the prewarm interface are skipped (no-op).

## Dynamic verification (token-free)

- `TestRuntimeRouterSessionStartupPrewarmFeedsFirstTurnLikeRust`: ThreadStart
