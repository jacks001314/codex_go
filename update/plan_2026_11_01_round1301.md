## The gap

Rust #54432 (`1c5ca2a979`) does not trust text replacement alone. After
rendering a protected snapshot it re-virtualizes every decoded literal word
(`shell-command/src/shell_snapshot_literals.rs`, driven from
`prepare_snapshot_credentials`) and rejects the capture when a word still
carries a credential. That catches a secret an alias or function body rebuilds
from quoted fragments, for example

```
alias helper='printf %s token_ab'\''cdefghijklmnop'
```

which never contains the contiguous secret in the raw text. Go masked the text
and only checked the masked text itself, so such a capture would have been
written to disk and replayed.

## What changed

- `shell/snapshot_literals.go`: `SnapshotLiteralWords` decodes the words a POSIX
  shell rebuilds from a rendered snapshot: single quoting, double-quote escapes,
  backslash escapes, ANSI-C `$'...'`, quote concatenation, line continuations,
  and backtick / `$(...)` bodies as scripts of their own. A bash-backed `sh`
  snapshot keeps bash syntax, mirroring Rust's header promotion.
- `network/snapshot_credentials.go`: `SnapshotTextContainsUnmaskedCredential`
  reports whether a text still carries a real broker value after masking.
- `tool/shell_snapshot_builder.go`: the protected capture path now checks the
  decoded words through `CredentialTextUnsafe`, not just the raw rendered text.
- `execserver/shell_snapshot.go`: `validateMaskedShellSnapshot` rejects a
  capture that keeps a real broker value verbatim or reassembles one from
  quoting; the launch then keeps the existing fallback warning ("Credential
  masking is unavailable for this shell snapshot") and the unmasked
  environment.

The decoder is lexical, not tree-sitter based: heredoc bodies and
parameter-expansion operators stay opaque, so it can under-report but never
invents a word from unrelated fragments. That limit is recorded in
`parity.json`; the remaining gap on this line is native Unix Zsh end-to-end
coverage.

## Executor broker text check

Rust does not re-check the replay script against the mask pairs alone: it
re-runs `proxy.virtualize_brokered_text` over every literal word, so a
credential the broker recognizes by configured pattern — one that never appears
in the pairs — still disqualifies the capture. The executor already owns that
broker (`Server.credentialBrokers`), so `rewrite` now accepts the broker's
`SnapshotTextContainsCredential` predicate and `validateMaskedShellSnapshot`
consults it alongside the pairs, for both the whole text and each decoded
literal word. The standalone local snapshot executor passes nil.
