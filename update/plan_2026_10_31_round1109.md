## Goal

## Findings

- #47971 recognizes the raw plan value `promax` as `KnownPlan::ProMax` in
  login claims, account responses, and backend rate limits, and uses it for
  experimental context eligibility and usage-limit guidance. Go already
  classified `promax` in the usage-limit copy but had no named plan constant,
  no `planFromString` case, no backend mapping, and no TUI label support.
- Rust #49079 later moved TUI analytics labels onto the shared subscription
  mapping, so Pro tiers render as `Pro 100`, `Pro 200`, and `Pro 500` rather
  than the commit-local `Pro (More)`/`Pro`/`Pro (Max)` names. Go's legacy
  analytics labels (`Pro`, `Pro Lite`) are updated to the current mapping.
- #43355 lets the app server resolve omitted model and reasoning-effort
  settings for CLI forks, skipping the migration prompt and `config/read`.
  Go's fork paths never send those client defaults: local picker forks call
  `session.Store.Fork`, and remote forks send only `threadId`/`historyMode`.
  Go interactive startup also has no migration-prompt or `config/read` step,
  so the client override cannot occur.

## Implementation

- Added `auth.PlanProMax` and `chatgptapi.PlanProMax`, parsing `promax` in
  `planFromString`, and mapping it back to `auth.PlanProMax`.
- Added Pro Max to experimental-context plan eligibility via a small tested
  helper mirroring Rust's `experimental_context_is_eligible`.
- Removed the TUI-local Pro Max constant and reused `auth.PlanProMax` for the
  shared `Pro 500` subscription/status label.
- Updated analytics summary labels to the current subscription mapping and
  accepted `promax` in announcement plan targeting.
- Added tests for plan parsing, backend mapping, eligibility, analytics
  labels, status labels, and announcement targeting.
