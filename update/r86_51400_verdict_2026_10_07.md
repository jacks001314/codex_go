⇒ Go **没有** async scorer 模块、缓存分数（`CachedScore`）、`WrapperLag`、`cached_evidence`，也没有 `score_at_or_before_action`。

### 2.2 Go 自述「简化同步 reviewer」
`appserver/guardian_reviewer.go:99-105`：
```
// guardianScoreProgress tracks the latest tool call and the latest scored tool
// call per thread (Rust GuardianV2ScoreProgress, #39001): approval review is
// skipped when the score lags by more than max_tool_call_lag tool calls.
type guardianScoreProgress struct {
	latestToolCall       int
	latestScoredToolCall int
}
```
`appserver/guardian_reviewer.go:401-404`（`Review()` 内）：
```
	// Rust #39001: skip approval review when the latest risk score lags by more
	// than max_tool_call_lag tool calls. The Go simplified reviewer fails closed
	// (no stale-score auto-approval), mirroring the stale-data guard while
	// keeping the established refuse-approval convention.
	if lag := r.maxToolCallLagValue(threadID, turnID); lag > 0 && r.scoreLag(threadID) > lag {
		return state.DecisionDenied, "guardian review skipped: risk score lag exceeds max_tool_call_lag", nil
	}
```
⇒ Go 的 `guardianScoreProgress` **只镜像了 lag 计数器**（`latest_tool_call`−`latest_scored_tool_call`），用途是 #39001 的**失败关闭**（lag 超限 → 直接 Deny），**不是** #51400 的「缓存分数释放 pending review」。

### 2.3 Go 的 markScored 只在同步 Review 末尾触发
`appserver/guardian_reviewer.go:640-643`：
```
	r.emit(threadID, completed)
	decision := state.DecisionFromEvent(completed)
	r.recordDecision(threadID, turnID, decision)
	r.markScored(threadID)
```
`beginToolCall`（`:107`）/ `scoreLag`（`:125`）/ `markScored`（`:141`）的**唯一调用点**都在同步 `Review()` 内（`:405/:421/:643`），**没有任何异步评分器会在 review 进行中写入分数**。

### 2.4 Go 的 ReviewStore 无「pending 释放」概念
`state/guardian.go:423-506` 的 `ReviewStore` 只有 `Start` / `Complete` / `Timeout` / `Abort` / `FailClosed` / `finish` / `Get` —— **无 `updates` 订阅通道、无 pending 状态、无被外部分数释放的入口**。Rust 侧 `progress.updates.subscribe()`（approval.rs:133）在 Go 无对位。

### 2.5 Go 的 fast-decision 不含缓存分数原因
`appserver/guardian_reviewer.go:409-417` 的 `fastDecision` 只在两条**非缓存**路径触发（full-access、用户审批模式的 node_repl js），`telemetry/guardian_v2_event.go` 的 fast-decision 事件**无 reason 字段**（Rust 的 `record_fast_decision(..., "initial_cua_call"/"low_risk")` 无对位）。

## 3. 观测等价性结论

Rust #51400 修的 bug 需要**同时**存在：(a) 异步评分器（async_scorer）发布缓存分数；(b) 一个可被缓存分数释放的 **pending 同步 review**。Go 两侧**都不存在**：
- 无 async scorer（§2.1）；
- 同步 review 无 pending-release（§2.4），lag 超限一律 **fail-closed**（§2.2）。

⇒ Go 的行为是 **「从不依据缓存分数放行」**，是 Rust 修复目标的**超集（更严）**，非缺失。
