### 2.3 上游等价性钉（digest 与 Windows 工具链差异）

`metrics/tool_spec_metrics_test.go:TestToolSpecDescriptionBytesBoundariesMatchRust` 钉两条 digest：

- `2^20`（本 PR 的桶族） `sha256(LE float64 bits) = 4984e25980d77888eeb41e1f51ec7198338e307059c32b948f14a1d1f9de1648`
- `2^17`（telemetry 已入库并已对 Rust 钉过的族） `= 8cacf78cbe23be0158fb5fa8f4be5d8768684969b45c3f48b8841d8e42c80fea` —— 由**同一份** `contextLogBuckets` 复现 ⇒ 证明这份算法就是已被验证与 Rust 一致的实现。

本节点 **rustc 1.99.0 (MSVC)** 逐字照抄 `context_log_buckets` 编译后得到的是 `8a35317b...`(2^17) / `7922bcbb...`(2^20)，与上表不同：原因是 MSVC 的 `pow` 并非正确舍入，`2^17` 族正好有 **72/511** 个边界差 1 ULP（与 `telemetry/metric_buckets.go` 注释记录的 72 个完全吻合）；Go 的 `math.Pow` 在这一族同样差 72 个。因此本节点 rustc 的输出**不能**作为钉值来源，权威来源是「已被钉过的正确舍入语义」，即上表两条 digest。**标注：`metrics` 与 `telemetry` 目前各有一份该算法（telemetry 本轮不可改）；建议后续把 `contextLogBuckets` 下沉到 `metrics/` 由两边共用（backlog，需 pin/telemetry 车道配合）。**
