# Round 727: code-mode cancellation and exit semantics

Rust 依据：

- `c2617273706f142ea1cc7196a2d423893b0767e4` / `#52685`：输出序列化期间必须保留
  不可捕获的执行取消，不能被重入 V8 的 getter/异常替换。
- `165299214855c2e48facf9bb3bc3c0fc277ee639` / `#52748`：`exit()` 终止整个
  cell；`catch`、`finally`、微任务、并行 Promise 和后续 helper 调用都不能继续产生
  输出或状态变更。

Go 落地：

- `sobekExecutionState` 在每个 `Execute` 调用内记录终止 cause、终止标志和 exit
  标志；外部 context/宿主中断与 `exit()` 都先经过同一状态边界。
- `text`/`audio` 在序列化前后检查终止状态。输出追加与终止状态共用临界区，因此
  取消发生后不会漏出后产生的 content item；音频参数错误也不会在终止后替换为
  可捕获的 JavaScript `TypeError`。
- `exit()` 设置 cell 级 exit 标志并中断 Sobek。`RunString` 返回后优先完成成功
  结果，不再检查仍 pending 的 module Promise；rejected Promise 和异常格式化路径
  也会保留成功的 exit 结果。
- 回归覆盖同步无限循环、`catch`/`finally`、queued/unawaited/parallel Promise、
  async module、文本/音频 getter、异常格式化，以及输出序列化 getter 内的外部
  取消。

验证：

- `go test ./codemode -count=1`
- `go test -race ./codemode -run TestSobekEngine -count=1`
