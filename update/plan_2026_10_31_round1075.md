## Goal

Keep a standalone root fork's inherited user instructions in thread-owned
retained context for Guardian review, across compaction, resume and rollback.

## Findings

- Rust splits retained order into `RetainedContextOrder::Inherited` (prefix
  order) and `Local(acceptance counter)`, adopts copied parent instructions
  without sharing the owning thread's counter, marks recovered instructions and
  parent verified answers incomplete, and exposes
  `has_inherited_user_messages` so a root checkpoint is not adopted twice.
- Go's `retainedctx` already models this: `RetainedInputSource.Inherited`
  records copied instructions through `nextInheritedOrder`, keeps
  `Inherited` on each ordered entry, compares origin before order in
  `RetainedContextOrder.Less`, sets `verifiedAnswersIncomplete` for inherited
  evidence, repairs pre-adoption checkpoints that recorded an answer gap, and
  exposes `HasInheritedUserMessages`. Reconciliation and rollback keep the same
  inherited/local distinction.
- `TestAdoptedInstructionsPreserveLocalOrderAndRollbackScope` covers adopted
  prefixes, local-order collisions and rollback scope; `RecoverUserMessageExcerpts`
  tests cover bounded recovery without changing identity or order.
