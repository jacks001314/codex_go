### 0.1 gofmt 门禁的环境事实（重要，影响所有车道）

本 worktree 由 `git worktree add` 新建，而本机 Git **系统级** 配置 `core.autocrlf=true`

所以 **原始 `gofmt -l .` 在本 worktree 输出 3479 行（= 每个 .go 文件），这是换行符产物，不是格式化缺陷**。

证据（把 worktree 的 `.go` 全部按 CRLF→LF 归一化到临时镜像后跑 gofmt）：

```

```

## 7.2 C8 收尾结论：**无载体（Go 无 remote/executor stdio MCP 启动路径）**；Go 唯一 stdio 载体 **aligned**

三选一结论 = **无载体**（对 Rust 被改的那个函数而言）＋ Go 实际存在的载体已对齐。

- Rust 被改对象：`codex-rs/rmcp-client/src/stdio_server_launcher.rs:682-715`
  `ExecutorStdioServerLauncher::remote_env_policy(remote_env_vars, env)`；允许清单在 `:698` 额外补
  `["SYSTEMROOT","TEMP","TMP","SYSTEMDRIVE","LOCALAPPDATA"]`；`:713` `r#set: env.clone()`。
- **Go 无此载体**（正向证据）：
  1. Go 的 stdio MCP 只有**一条本地**启动路径：`mcp/stdio_client.go:414-437`
     （`mcpStdioLaunchConfig` → `createEnvForMCPServer` → `exec.CommandContext` 本地进程），
     **不看 `EnvironmentID`**；
  2. Go 的 local stdio 环境策略**显式拒绝** `source: remote`：`mcp/stdio_env.go:95-115`
     → `env_vars entry … uses source remote, which requires remote MCP stdio`；
  3. 全仓 `ExecutorStdio` / `remote_env_policy` **0 命中**；
  4. Go 的 executor（`execserver/`）只承载 **HTTP** 形态 MCP（`mcp/credential_policy.go:19-45` 的
     `executor_only`；`execserver/` 侧无 MCP stdio 启动器）。
  ⇒ Rust 的「remote stdio（executor 承载）+ 允许清单 + Windows-aware overlay」这一层在 Go 不存在，属**无载体**。
- **Go 实际存在的那个载体已对齐**（不是部分对齐）：
