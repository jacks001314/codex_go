## Verification

The Go implementation was already present under equivalent names:

- `app.runExecServer` parses only `-c features.prefer_mxc=<bool>` from startup
  overrides and ignores unrelated or invalid overrides.
- Local and remote exec-server paths pass the value through
  `SetPreferMXC` / `RemoteEnvironmentConfig.PreferMXC`.
- `execserver/hostconfig.Reader` emits it as a `session-flags` config layer above
  project config and below legacy managed/MDM config.
- No other startup override is retained in executor-local reads.
- Go's `sandbox.PermissionProfile` resolves MXC eligibility after the active
  profile, with managed `windows.allow_mxc = false` taking priority; the
  Rust-only helper name `windows_mxc_allowed_by_config` therefore has an
  equivalent Go carrier.

```text
go test ./app -run ExecServerPreferMXC -count=1                         # ok
go test ./execserver/hostconfig -run ReadEnvironmentConfigPreservesCLIPreferMXC -count=1  # ok
go test ./execserver -run 'MXC|EnvironmentConfig' -count=1              # ok
```

No source change was required; r109 is moved from implementation_pending to
complete on verified equivalent behavior.
