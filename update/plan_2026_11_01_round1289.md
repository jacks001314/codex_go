## Advanced this round

When `wait`/`terminate` names a cell the runtime no longer holds, Rust does not
raise a tool error. `InProcessCodeModeSession::terminate` and `begin_wait` map
`runtime::Error::MissingCell(_) | runtime::Error::ClosedCell(_)` to
`WaitOutcome::MissingCell(missing_cell_response(...))`, and that helper builds a
`RuntimeResponse::Result` with an empty content list and the error text
`exec cell <id> not found` (`code-mode-runtime/src/service.rs`):

```rust
fn missing_cell_response(
    cell_id: CellId,
    mode: CodeModeOutputTruncation,
    max_output_tokens: Option<usize>,
) -> Result<RuntimeResponse, String> {
    let error_text = format!("exec cell {cell_id} not found");
    let mut output = OutputCollector::new(mode);
    let event = take_completed_event(&mut output, Some(error_text));
    runtime_response(&cell_id, event, mode, max_output_tokens)
}
```

`handle_runtime_response` then appends `Script error:\n<error_text>` and reports
`success = false` with the `Script failed` status. Go's remote host path already
produced that shape (`codemode/session_runtime.go` returns
`Result(cellID, nil, "exec cell <id> not found")`), but the in-process executor
returned `RespondToModel("exec cell <id> not found")`, so the same stale cell id
rendered as a tool error without the code-mode header or the `Script error:`
block.

## What changed

- `tool/code_mode_exec.go`: `codeModeWaitExecutor.execute` returns Rust's
  failed observation for a missing cell (wait and terminate alike): an
  unsuccessful `Output` whose body is the code-mode header plus
  `Script error:\nexec cell <id> not found`, with `error_text` and `cell_id` in
  `Data`, truncated by the client policy when the host did not already bound it.
- `tool/code_mode_exec_test.go`: the two stale-cell assertions now check the
  observation instead of an error string.
- `tool/code_mode_missing_cell_like_rust_test.go`: new regression test for both
  `wait` and `terminate` on an unknown cell.
