## Goal

Close the macOS MCP stdio launcher stack and retire a tooling-only entry.

## Findings

- `#42192` adds a bare-command search to Rust's macOS `posix_spawn` path. Rust
  searches the *child's* configured `PATH` (an empty entry means the current
  directory, an unset `PATH` uses `/usr/bin:/bin`) because `posix_spawnp`
  searches the parent's `PATH`, and it preserves the configured spelling as
  `argv[0]` while the resolved executable drives the launch. Go already spawns
  MCP stdio servers with `os/exec` (no `posix_spawnp` wrapper), but
  `resolveMCPStdioCommand` performed that PATH search only on Windows, so a
  POSIX server whose config overrode `PATH` resolved against the parent instead
  of the child environment.
- `#42117` exists only because Tokio's `Command` falls back to `fork` for a
  relative executable combined with a working directory on macOS; the remainder
  of the commit folds the legacy and 2026-07-28 stdio transports into one local
  child wrapper with a bounded line size. Go has neither problem: `os/exec`
  resolves relative programs against `cmd.Dir`, and `stdioClient` already owns
  one process wrapper (`protocolMode` switch plus a per-launch `messageLimit`).
  This was documented in `update/plan_2026_09_05.md`.
- `#42109` only widens the Rust repository's Ruff pass and its
  formatter-coverage test; the Go repository has no `justfile`,
  `pyproject.toml`, or Ruff configuration.

## Implementation

- `mcp/stdio_client.go`: `resolveMCPStdioCommand` now resolves a bare command
  against the child's `PATH` on POSIX through `resolveBareCommandInChildPath`
  (empty entry = cwd, unset `PATH` = `/usr/bin:/bin`, non-executable files
  skipped, failed search keeps the bare spelling so the regular launcher's error
  behavior is unchanged). `preserveMCPStdioArgv0` keeps the configured spelling
  as `argv[0]` when a bare command was resolved, while `cmd.Path` still names the
  resolved executable; the Windows shim path is untouched.
- Tests: `mcp/stdio_command_child_path_test.go` covers child-PATH hits, misses,
  empty entries as the current directory, and the default search path;
  `mcp/stdio_command_posix_test.go` covers the POSIX `resolveMCPStdioCommand`
  contract plus `argv[0]` preservation.
