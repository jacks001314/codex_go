## The gap

Rust #54432 (`1c5ca2a979`) does not trust text replacement alone. After
rendering a protected snapshot it re-virtualizes every decoded literal word
(`shell-command/src/shell_snapshot_literals.rs`, driven from
`prepare_snapshot_credentials`) and rejects the capture when a word still
carries a credential. That catches a secret an alias or function body rebuilds
from quoted fragments, for example

```
alias helper='printf %s token_ab'\''cdefghijklmnop'
```

which never contains the contiguous secret in the raw text. Go masked the text
and only checked the masked text itself, so such a capture would have been
written to disk and replayed.

## What changed

- `shell/snapshot_literals.go`: `SnapshotLiteralWords` decodes the words a POSIX
  shell rebuilds from a rendered snapshot: single quoting, double-quote escapes,
  backslash escapes, ANSI-C `$'...'`, quote concatenation, line continuations,
  and backtick / `$(...)` bodies as scripts of their own. A bash-backed `sh`
  snapshot keeps bash syntax, mirroring Rust's header promotion.
- `network/snapshot_credentials.go`: `SnapshotTextContainsUnmaskedCredential`
  reports whether a text still carries a real broker value after masking.
- `tool/shell_snapshot_builder.go`: the protected capture path now checks the
  decoded words through `CredentialTextUnsafe`, not just the raw rendered text.
- `execserver/shell_snapshot.go`: `validateMaskedShellSnapshot` rejects a
  capture that keeps a real broker value verbatim or reassembles one from
  quoting; the launch then keeps the existing fallback warning ("Credential
  masking is unavailable for this shell snapshot") and the unmasked
  environment.

The decoder is lexical, not tree-sitter based: heredoc bodies and
parameter-expansion operators stay opaque, so it can under-report but never
invents a word from unrelated fragments. That limit is recorded in
`parity.json`; the remaining gap on this line is native Unix Zsh end-to-end
coverage.

## Executor broker text check

Rust does not re-check the replay script against the mask pairs alone: it
re-runs `proxy.virtualize_brokered_text` over every literal word, so a
credential the broker recognizes by configured pattern — one that never appears
in the pairs — still disqualifies the capture. The executor already owns that
broker (`Server.credentialBrokers`), so `rewrite` now accepts the broker's
`SnapshotTextContainsCredential` predicate and `validateMaskedShellSnapshot`
consults it alongside the pairs, for both the whole text and each decoded
literal word. The standalone local snapshot executor passes nil.

## Heredoc bodies

Rust decodes heredoc bodies as heredoc text rather than parsing them as shell
source. Go originally scanned them as ordinary script, so an unbalanced quote in
a quoted heredoc (for instance `cat <<'EOF'` followed by `it's a text`) could
swallow the rest of the snapshot and hide later words from the credential
check. `scanSnapshotHeredocBodies` now consumes each body after the line that
started the redirection, honors `<<-` tab stripping, keeps every byte for a
quoted delimiter, removes one escape layer for an unquoted one, and appends the
decoded body as its own word.

## zsh rcquotes

zsh snapshots are captured with rcquotes enabled, where a doubled single quote
inside a quoted region is one literal quote. Rust tracks `setopt rcquotes` and
`unsetopt rcquotes` across the script (`Quoting::ZshRcQuotes`), so an alias
value that contains a quote decodes with it. Go now follows the same directive
at statement boundaries and decodes the doubled quote, which keeps a credential
containing a quote visible to the check instead of silently losing the byte.

## Deferred assignment bodies

Rust parses an alias or assignment body again after quote removal, so a value
that is itself shell code is decoded twice. Go kept only the outer word, which
left a credential written as an ANSI-C string inside an alias body
(`alias helper='printf %s $'\''\x73k-real'\'''`) visible only as the escaped
text. `flush` now re-parses the value of a `NAME=value` word when it still
carries quoting, escapes, a substitution or a backtick, bounded by the same
nesting limit.

## Launch environment policy on the replay render

Rust's `parse_snapshot` filters the captured environment through
`params.env_policy` before it becomes the executor-owned snapshot: it converts
the wire policy with `shell_environment_policy`, forces `inherit` to `All`, and
then runs `create_env_from_vars` over the captured names. Go rendered with no
policy, so a launch that excluded a variable, or admitted only an allowlist,
still re-exported every captured declaration into the replay script.
`captureSnapshot` now renders through `shellSnapshotRenderPolicy`, which
converts the wire `ExecEnvPolicy` into an `execpolicy.EnvPolicy` with
`inherit=all` and preserves `ignore_default_excludes`, `exclude`,
`include_only`, and `set`. A name the policy sets explicitly keeps only the
command environment's value; the captured original is never persisted. A
launch without an environment policy keeps the previous unrestricted render.
