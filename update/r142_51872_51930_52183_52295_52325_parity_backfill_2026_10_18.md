# Parity backfill: projectless config, function prefixes, board descriptions, incremental notices, history metadata

Five ledger-complete entries were still pending in parity. Focused regressions
pass against the current tree.

## `#51872` Global app-server config and launch directory

`ConfigService.Read` without a CWD loads only user, managed, and runtime layers;
project layers require an explicit CWD. Global feature/marketplace/MCP reads use
the no-CWD path, while thread-scoped reads pass the thread CWD.

## `#51930` Model-specific function description prefixes

`ToolMessages` parses function namespace description prefixes. Registry
construction applies trimmed prefixes to available default-namespace direct,
freeform, and dynamic specs under the combined 256-byte boundary while leaving
namespaced/unavailable tools and search ranking text unchanged.

## `#52183` Agent-board channel descriptions

Channel summaries carry an optional description. Configuration validates the
512-byte UTF-8 limit, persists template descriptions, and migrates older local
channel tables by adding the nullable column before seeded inserts.

## `#52295` Incremental namespace update notices

The bundled hint uses the `tools.incremental_update` content kind and is emitted
once per changed/new namespace batch. Forked history retains it, while rebuilt
compaction prefixes stop before later batches.

## `#52325` History initialization in Responses metadata

Persisted/runtime provenance covers new, cleared, cold/warm/cold-fork, and
supplied-history cases. Start/resume/fork paths preserve live-runtime values and
turn metadata serializes the classification while reserving the client key.
