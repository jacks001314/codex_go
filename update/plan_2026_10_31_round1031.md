## Goal

Audit #41924 (record realtime conversation history in Core) and decide whether
Go already satisfies its observable contract.

## Findings

- Go's canonical realtime reducer lives in the shared `realtime` package
  (`realtime/history.go`), not in the app-server, so every host using the
  `Manager` gets the same segmentation, promotion, and session-boundary
  decisions. `realtime/history_wiring.go` derives the app-server item
  notifications from those same reducer effects.
- Go persists completed realtime transcript chunks and the transcript tail
  into the thread store (`appserver/realtime_runtime.go`
  `recordRealtimeTranscriptMessage`, Rust #58221/#50531), including in-memory
  ephemeral thread records and repeated sessions.
- The #41924 contract is broader: canonical `RealtimeItem` entries
  (`transcriptSegment`, `bemItemPromoted`, `realtimeSessionStarted`,
  `realtimeSessionClosed`) are appended to the live thread store as rollout
  items in event order, and hosts receive dedicated history lifecycle events.
  Rust persists `RolloutItem::RealtimeItem` and only then delivers
  `HistoryItemStarted`/`HistoryItemCompleted` (`core/src/session/realtime_history.rs`).
- Go does not persist canonical realtime items. Only flattened transcript
  messages reach the store; promotions and session boundaries exist only in
  the live notification stream. Resuming a paginated thread therefore replays
  transcript messages rather than the canonical item timeline, and artifact
  promotion is not durable.
- The structural blocker is representation, not the reducer: Go's session item
  model has no realtime-rollout variant, and paginated thread item conversion
  has no canonical-realtime mapping. Completing #41924 is a dedicated storage
  round rather than a local fix.

## Decision

- Mark `64c9cde458` as `partial` with the reducer, notification, and transcript
  persistence evidence above, and record the missing canonical-item
  persistence as the residual.

## Residuals

- Persist canonical realtime items through the thread store in event order,
  expose them on paginated history replay, and derive app-server item
  notifications from the persisted timeline instead of persisting transcript
  text twice.
- Add a realtime rollout item variant to the Go session model plus the
  thread-item conversion, then cover repeated sessions, ephemeral threads,
  accepted/rejected steering, typed input ordering, and artifact promotion.
