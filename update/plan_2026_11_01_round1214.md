# Round 1214: SCM service host and provisioning event log (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342, crate
windows-sandbox-service; `service.rs` and `main.rs`).

## Context

Rounds 1212/1213 made the pipe and the dispatcher usable, but nothing registered
the process with the Windows Service Control Manager or reported its state. This
round ports the SCM host scaffolding, the event-log writer and the argument
parser.

## SCM host

`windowsandboxservice/service_windows.go` ports Rust `service.rs`:

- `RunService` resolves the package-family service and pipe names, stores the
  process-wide `ServiceState` (refusing a second initialization), and blocks in
  `StartServiceCtrlDispatcherW`;
- `runServiceMain` registers `RegisterServiceCtrlHandlerExW`, reports
  `SERVICE_START_PENDING`, runs the injected `ServiceBroker`, and reports
  `SERVICE_STOPPED` after `EVENT_SERVICE_STOPPED`;
- the control handler records stop versus shutdown, reports
  `SERVICE_STOP_PENDING` once, logs `EVENT_SERVICE_STOP_REQUESTED` and wakes the
  listener for stop/shutdown, re-reports the current status for interrogate, and
  wakes the listener for session changes; everything else returns
  `ERROR_CALL_NOT_IMPLEMENTED`;
- `ReportStatus` accepts stop, shutdown and session-change controls only while
  running, sets checkpoint 1 and a 10 s wait hint only while pending, and flags a
  service-specific exit code by reporting 1;
- `WakeListener` spawns `WakeProvisioningPipe` so a blocked accept observes
  shutdown, and `FatalErrorHResult` maps a Win32 code from the error chain to an
  HRESULT without stringifying the error.

## Event log

`LogInformation`/`LogError` write the `EVENT_*` identifiers through
`RegisterEventSourceW`/`ReportEventW`/`DeregisterEventSourceW`. Messages are
scrubbed of control characters and bounded to 1024 UTF-16 units, counted in
UTF-16 rather than bytes so a non-BMP character cannot split the bound.

## Run mode

`runmode.go` ports `main::parse_mode`: no argument or `--service` selects the
SCM service, two arguments are refused, and `--foreground` is refused because
Rust only accepts it in debug builds and it enables the unpackaged-client
exemption.

## Known gaps

The provisioning broker itself (`provisioning.rs`, `provisioning/registered.rs`),
the managed-policy load as the impersonated owner, the package-lifecycle and
registered-runtime transactions, and the service diagnostics
(`ServiceStopReason::record`) are still missing, so #42342/#42375 keep their
service-side residuals.
