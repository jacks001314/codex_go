## Investigation notes (turn 53)

- #2 root cause: the world-state write in `turnEnvironmentContextInputItemForTurn` read the thread
  record before awaiting the host roster (`loadSubagents`), then saved that whole record afterwards.
  The test's `store.Save(&replaced)` landed during the await, so the save restored `u1/a1` and
  compaction's own re-read (and `TakeReady`) still saw the old generation. Patching only
  `Metadata.WorldState` keeps the replaced history. Ephemeral threads keep the whole-record save
  because they are single-writer and never touch the store.
- #3/#4: the failure text was `failed to save provider OAuth credentials`. A direct probe showed
  `safety`'s keyring `Save` returning `CredWriteW failed: Not enough memory resources are available`
  in this session while a plain keyring probe occasionally succeeded, so keyring-backed fixtures are
  not deterministic here. The app-server tests now pin `credentials_store = "file"`, which exercises
  the same sign-in/status/credential-visibility path.
- #8: `os.Environ()` on Windows keeps one entry per variable under its stored spelling, so the
  canonical `NO_PROXY` lookup missed a value set as `no_proxy`. `proxyEnvSummary` folds names on
  Windows only, which leaves the case-sensitive Linux list identical to Rust's `PROXY_ENV_VARS`
  (WS_PROXY/WSS_PROXY dropped from the websocket check to match Rust's list).
