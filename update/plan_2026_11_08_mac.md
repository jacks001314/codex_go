### 原生实现（Rust platform_macos 的 Go 对应）

- Key namespace：`com.openai.codex.user-verification.plugin-service.v1.` + base64url(sha256(account_user_id))，与 Rust `UserVerificationKeyNamespace::new` 完全一致。
- Keychain item：`kSecClassKey` + `kSecAttrApplicationLabel=label` + `kSecUseDataProtectionKeychain`，搜索时 `kSecReturnRef`；私有 key 为 P-256（`kSecAttrKeyTypeECSECPrimeRandom`，256 bit），`kSecAttrTokenIDSecureEnclave`，访问控制 `kSecAttrAccessibleWhenUnlockedThisDeviceOnly | kSecAccessControlBiometryAny | kSecAccessControlPrivateKeyUsage`。
- key 保护校验：`kSecAttrTokenID == SecureEnclave`、`kSecAttrKeyClass == Private`、`kSecAttrKeyType == ECSECPrimeRandom`、`kSecAttrKeySizeInBits == 256`；不匹配返回 `providerUnavailable` + Rust 原文 `the local credential has incompatible key protection; delete it before enrolling again`。
- 公钥与 credential id：`SecKeyCopyPublicKey` → `SecKeyCopyExternalRepresentation`（SEC1 65 字节）→ 手工拼 P-256 SubjectPublicKeyInfo DER；`credentialId = base64url(sha256(SPKI DER))`，`algorithm = "ecdsaP256Sha256X962"`，`publicKey = base64url(SPKI DER)`。与 Rust `UserVerificationKeyInfo::from_sec1_public_key`/`p256` 输出一致。
- `status`：先拿生命周期锁；无 key → `credentialMissing` + `no user-verification credential has been created`；有 key 但 `canEvaluatePolicy(DeviceOwnerAuthenticationWithBiometrics)` 失败 → 把 native unavailable reason/message 直接放进 status（Rust 行为）；正常 → 只返回 `credentialId`。
- `enroll`：锁内先查，已存在直接返回，不重复创建；不存在则创建 Secure Enclave key 并返回 metadata。
- `delete`：锁内 idempotent 删除该 label 下所有 key item（包含中断删除留下的公钥），`errSecItemNotFound` 视为成功。
- `verify`：
  1. provider 自身再校验 challenge/title/description 边界（Rust provider 的 `Failed{providerError}`）；
  2. 取跨进程锁；
  3. 用非交互 `LAContext` 读 key attributes + `kSecAttrAccessControl`，校验 key 保护；
  4. 新建交互 `LAContext`，`localizedFallbackTitle=""`、`localizedReason=title + "\n\n" + description`，`canEvaluatePolicy` 检查可用性；
  5. `evaluateAccessControl:operation:LAAccessControlOperationUseKeySign:localizedReason:reply:`；等待期间每 50 ms 检查取消，取消即 `invalidate` 并继续 drain 回调，再返回 `cancelled/interrupted`（对应 Rust `wait_with_cancellation` + guard）；
  6. 授权后对同一个 context `setInteractionNotAllowed:YES` 重新取 key，`SecKeyCreateSignature(kSecKeyAlgorithmECDSASignatureMessageX962SHA256, challenge)`；签名前再检查取消；
  7. 返回 `proof.credentialId` + base64url(DER ECDSA signature)。
- 错误映射：逐条照抄 Rust `platform_macos/error.rs`（NSOSStatus -128、LA -2/-3 → userCancelled；LA -4/-9 → interrupted；NSOSStatus -25293 / LA -1 → authenticationFailed；LA -5/-6/-7/-8/-12/-13 → biometricsUnavailable；LA -1004、NSOSStatus -34018、-25291/-25308 → providerUnavailable；其余 → providerError）。对外消息走 Rust adapter 的固定文案：`User verification was cancelled.` / `Local user verification is unavailable.` / `User verification failed.`；status 的 `unavailableMessage` 保留 provider 原文（如 `no user-verification credential has been created`）。
- 生命周期锁：`~/Library/Application Support/com.openai.codex/user-verification/<label>.lock`（目录 0700、文件 0600），`flock(LOCK_EX|LOCK_NB)` 每 50 ms 重试，60 s 超时 → `failed/timeout`；取消优先返回 `cancelled/interrupted`。
- `DeviceSupported()`：只按 `LAContext.biometryType == TouchID` 判断硬件，和 Rust 一样不受未录入/临时锁定影响；本机返回 false。

## 接管复核（mac-align-2，2026-11-08）

上一实例（mac-align / agent-32791ff849094dd77563f399）的结论未经核验，本节是重新核验后的更正与补充。**其上文「跑过的命令与结果」不能作为交付证据**：本机实际复现了 3 个它没有发现的问题（其中 1 个必崩、1 个编译失败）。

### 复核环境

- Rust 基线：`~/rust-baselines/55897425e8`（tar.zst 11153 条目，与预期一致），逐条对照源码，不再依赖 GitHub raw。

### 复现并修复的问题

1. **`darwin && !cgo` 编译失败（阻断）**：`user_verification_platform_other.go`（`!darwin || !cgo`）与 `user_verification_macos_nocgo.go`（`darwin && !cgo`）重复定义 `newUserVerificationPlatformProvider`。
   复现：`CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build ./appserver ./doctor` → `redeclared in this block`。
   修复：前者 tag 收紧为 `!darwin`。原 plan 只跑了 linux/windows 交叉构建，漏掉了 darwin 无 cgo。

2. **未 enroll 时 verify 触发进程崩溃（P0）**：`uv_access_control_for_label` 在 `errSecItemNotFound` 分支里对 `NULL` 执行 `CFRelease`，CoreFoundation 直接 abort。
   复现：`go test ./appserver -run TestZZAuthorizeAndSignMissingLabel` → `SIGILL: illegal instruction ... signal arrived during cgo execution`（栈顶 `uv_verify`）。
   修复：不再释放空指针，并把 `errSecItemNotFound` 写回 `uv_error`，使 Go 侧返回 Rust 的 `credentialMissing` + `no user-verification credential has been created`（对应 `user-verification/src/platform_macos/provider.rs:186-215`）。

3. **status 丢失 credentialId（wire 形状不符）**：key 存在但生物识别暂不可用时，Rust 同时返回 credential 与 unavailable 原因（`app-server/src/user_verification.rs:176-180`），旧实现只回 reason/message。
   修复：该分支同时回 `credentialId`。

4. **初始化激活门判断错了对象**：Rust 用 crate 级 `native::device_supported()` 探测硬件（`app-server/src/user_verification.rs:51`、`request_processors/initialize_processor.rs:110`），与注入的 provider 无关；Go 只看 `RuntimeServices.UserVerificationProvider`，生产环境该字段为 nil，于是真机永远不会激活。
   修复：`userVerificationDeviceSupported(nil)` 回落到平台探针（`userVerificationPlatformDeviceProbe`）。

5. **超时不取消原生操作**：Rust 在 RPC future 结束/超时时 drop `CancelOnDrop`（`app-server/src/user_verification.rs:143-146`），并在交付成功结果前再检查一次 guard（同文件 `:241`）。Go 超时后既不取消 token 也不复检，生物识别弹窗会留在屏幕上、取消后仍可能返回成功结果。
   修复：超时分支 `cancel.Cancel()`；成功结果返回前若已取消则返回 `cancelled/interrupted`。

6. **生物识别弹窗的 fallback 按钮**：Rust 设 `localized_fallback_title = ""`（`provider.rs:180`，空串＝隐藏「使用密码」），旧实现传 `nil`（＝恢复系统默认 fallback）。
   修复：传空 `CFString`。

7. **verify 的错误优先级**：Rust 先 `check_biometrics`（`provider.rs:183`）再读 key 属性（`provider.rs:186`）；旧实现先读属性，传感器不可用时会先报 key protection 错误。
   修复：调整为先 `canEvaluatePolicy` 再查 key。

8. **title 校验过度严格**：Rust 只拒绝空串（`app-server/src/user_verification_adapter.rs:21`、`provider.rs:168`），Go 用 `strings.TrimSpace` 把全空白 title 也拒了。
   修复：`user_verification.go` 与 `user_verification_macos.go` 均改为 `params.Title == ""`。

9. **SPKI 手工拼 DER → 改用 crypto/x509**：Rust 走 `from_sec1_public_key → to_public_key_der`（`user-verification/src/credential.rs:29-40`）；旧实现把 26 字节前缀硬编码在 C 里，无法测试。
   修复：C 只返回 SEC1 点（65 字节），Go 用 `elliptic.Unmarshal` + `x509.MarshalPKIXPublicKey` 生成 SPKI，再 sha256 出 credentialId（新增无需硬件的单测对照 RFC 前缀与 stdlib 输出）。

10. **doctor 两个探测串行**：Rust 用 `tokio::join!` 并发跑 spctl 与 `log show`（`cli/src/doctor/desktop/macos_security.rs:40`），旧实现串行，最坏 20 s。改为 goroutine + WaitGroup，最坏 10 s。

11. **macOS 日志路径回归测试缺位**：旧 plan 声称有回归测试，实际只有 `desktopLogRoot` 字符串断言，`inspectDesktopSession` 的 `root + "\" + …` 从未被覆盖。
    新增 `TestDesktopChecksFindDarwinSessionLogsOnDisk`：在临时 HOME 下按 macOS 真实布局落盘 `<identity>/<yyyy/mm/dd>/codex-desktop-<session>-<pid>-t<id>.log`，走完整 `desktopChecks()`。已验证把 `filepath.Join` 改回 `+ "\" +` 时该测试失败（`running: false`），恢复后通过。
