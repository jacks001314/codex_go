# Round 1160 update plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round closes the shell-snapshot credential cluster that the per-commit
audit had left `audit_pending`: `2e220af1` (#43909), `808b3411` (#43954),
`ec512d23` (#44040) and `38cbebaf` (#44072). The upstream work is one
behaviour: when managed-network credential brokerage is active, a shell
snapshot must never capture real credentials, must replay with broker dummy
values, and must be cached per command shape.

## Implementation

- `tool/shell_snapshot_builder.go`
  - `SnapshotCaptureRequest` gained `Protected`, `Env`, `SourceEnv`,
    `CredentialPairs`, `CredentialEnvKeys` and `CredentialTextUnsafe`;
    `SnapshotProviderRequest` gained `Protected`/`Env`;
    `SnapshotProviderResult` gained broker-prepared `Env`.
  - A protected capture runs in `brokeredSnapshotCaptureEnv` (only virtualized
    credential keys survive; unvirtualized provider keys and every
    `CODEX_NETWORK_PROXY_*` broker marker are stripped), masks rendered output
    with `network.MaskSnapshotText`, and is rejected through
    `CredentialTextUnsafe` when a real value or configured token pattern
    survives rendering.
  - `brokeredSnapshotLaunchEnv` builds the replay environment (dummy
    `..._BROKERED_VALUE_*` copies, markers unset, original `BASH_ENV`/`ENV`/
    `ZDOTDIR` preserved) and `ShellSnapshotFile.BrokeredEnv()` returns it.
  - `ShellSnapshotCacheKey` appends a `protected` suffix from
    `brokeredSnapshotKey` (prepared keys + login mode + permission profile +
    sandbox), so protected and unprotected captures never share a cache entry.
  - The validation run receives a read-only grant for the temp snapshot path
    through `sandbox.PermissionProfileWithAdditionalPermissionsForConvention`,
    mirroring Rust's `snapshot_read_permissions`.
- `tool/shell_snapshot.go`: the wrapper unsets
  `CODEX_NETWORK_PROXY_SNAPSHOT_BROKERED_PREPARED` before the user command;
  `brokeredSnapshotPrepared` recognises it.
- `tool/shell_executor.go`: `ManagedNetworkResolution.RestoreUnbrokeredEnvironment`
  restores the pre-virtualization environment for local PowerShell/Cmd
  launches; broker + `shell_zsh_fork` is rejected; a brokered POSIX launch
  without a protected snapshot fails with
  `credential brokerage could not create a protected shell snapshot`.
- `network/snapshot_credentials.go`: `CredentialMaskPair.Key`,
  `SnapshotCredentialEnvKeys`, `SnapshotTextContainsCredential`.
- `appserver/shell_snapshot.go` / `thread_shell_command.go` /
  `runtime_router.go`: the provider reads the thread's prepared proxy, capture
  only happens when that proxy is `Ready`, prepared keys are merged into the
  launch environment, and the broker restore hook is wired into the router.

## Residual

- Rust substitutes credentials at the word/span level (`CapturedArray`,
  `ExportValue`, `literal_word_bytes`); Go masks rendered text with the regexp
  helper in `network.MaskSnapshotText`, which is behaviourally equivalent for
  the exported environment but does not rewrite the script source.
- Rust's `CredentialBrokerEnvironment` and `SnapshotCredentialBrokerState`
  metadata types have no Go counterpart; the same information is carried by
  the prepared-key suffix and `BrokeredEnv()`.
- `#42137` (prewarm eligible turns) remains `partial`: the local v2 executor
  prewarm path still does not thread sandbox/permission context.
- TUI, Windows sandbox and usealign work is owned by the parallel agent
  tracks and is not touched here.
