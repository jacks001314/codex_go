# Round 1213: Provisioning request dispatch and response framing (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342, crate
windows-sandbox-service).

## Context

Round 1212 created the authenticated pipe and the caller identity, but nothing
read a request from the connection or answered it. This round ports the read
loop, the dispatch order and the response framing.

## Request read loop

`windowsandboxservice/ipc_windows.go` ports Rust `ipc::handle_request`'s
`PeekNamedPipe` accumulation:

- a 5 s idle deadline, a 25 ms poll and a shutdown check before every peek;
- the 4096-byte request bound is enforced twice: on the peeked byte count and on
  the frame's little-endian payload length;
- a read of zero bytes is "provisioning client sent an empty request";
- more than one frame in the buffer is refused instead of being ignored;
- the loop returns exactly the bytes of one frame.

## Dispatch order

`HandleRequest` follows Rust's order: read -> `ValidateRequest` ->
`AuthenticateClient` -> managed-policy validation -> provisioning handler. The
policy step is skipped for `register_installation_request` and for a registered
Core refresh, exactly like `machine_policy::validate_provisioning_request`, and
a missing validator is an error rather than a silent bypass. The provisioning
handler is an injected `AuthenticatedRequestHandler` so the worker can land
separately.

## Response framing

`WriteResponse` serializes one `provision_sandbox_response` frame at the shared
protocol version, writes it, and then peeks for up to one second so a following
`DisconnectNamedPipe` cannot truncate the reply (Rust `ipc::write_response`).

`ErrorMessage` ports `ipc::response_error_message`: wrapped causes stay in the
message (Go's `fmt` wrapping already embeds them), control characters become
spaces and the result is bounded to 512 bytes on a UTF-8 boundary. Mapping in
`failureResponse` turns `ServiceUnavailable` into the `unavailable` status that
lets the client fall back to its elevated helper and every other failure into a
bounded `error` message.

## Known gaps

The SCM service host (`EVENT_*`, `SetServiceStatus`, `main`), the provisioning
worker itself (`provisioning.rs`, `provisioning/registered.rs`), loading managed
configuration as the impersonated owner, and the package-lifecycle /
registered-runtime transactions are still missing, so #42342/#42375 keep their
service-side residuals.

## Coverage

`response_test.go` (wrapped-cause order, control characters, UTF-8-safe 512-byte
bound, nil error) and `ipc_windows_test.go` against a real named pipe (one frame
is returned byte-identical and validates as a registration request, a second
frame is refused, an oversized declared frame is refused, shutdown is reported
before reading, and a written response round-trips through
`provisionservice.ReadFrame`).
