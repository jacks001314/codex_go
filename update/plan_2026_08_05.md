## 一、上游变更概要（56b82e676c..30d99232f4）

### 1. EnvironmentConfig 携带权限配置快照
- `EnvironmentConfig` 新增 `permission_profile: PermissionProfileSnapshot`（原有 `allow_login_shell` 保留），
  由 `SessionConfiguration::environment_config()` 统一组装（`allow_login_shell` + 权限 profile 快照）。
- `PermissionProfileState::snapshot()` 新增，返回可克隆/比较的 `PermissionProfileSnapshot`。

### 2. 权限配置更新应用到未来 turn 环境
- `ThreadEnvironments::update_selections` 新增 `thread_environment_config` 参数；复用已解析环境时也会刷新 config。
- 新增 `ThreadEnvironments::update_environment_configs(&config)`：仅更新全部环境的 config，
  不重连、不重试失败解析（测试显式断言 failed resolution 不被重试）。
- Session 在 `update_settings`/turn start 两条路径中：环境选择变化时走 `update_selections(...)`；
  仅配置变化时走 `update_environment_configs(...)`；活动 turn 保持自己的旧配置。
- 内部重构：环境解析结果 `ResolvedEnvironment`（environment + shell + shell_snapshot task）
  与配置解耦，`TurnEnvironment` 在 `from_resolution` 时按 turn 组装。

### 3. ShellSnapshot 构建解耦
- `ShellSnapshot::build` 签名由接收整个 `TurnEnvironment` 改为
  `(Arc<Environment>, cwd: PathUri, shell: Option<Shell>)`，纯重构。

### 4. 核心行为测试
- `permission_profile_updates_apply_to_next_turn_environment`：通过 settings update 或 turn start
  应用新的 permission profile + profile workspace roots 后，下一 turn 的主环境 config 为更新后的快照，
  而活动 turn 的环境 config 保持原样。

## 四、风险与注意

1. Go 与 Rust 架构不同：Go 每 turn 重新加载有效配置，因此“权限更新应用到未来 turn”由构造保证；
   本轮补的是 settings 持久化/传递链，不改动活动 turn 参数快照语义。
2. `SettingsUpdateParams.RuntimeWorkspaceRoots` 仅在客户端显式携带时生效（`nil` 表示不修改，
   显式空数组表示清空），与既有 `CWD` 等指针字段语义一致。
3. 显式 turn 参数优先：turn start 自带 `permissions`/`sandboxPolicy`/`runtimeWorkspaceRoots` 时，
   不覆盖 settings 值。
4. Rust 其余改动（ResolvedEnvironment 解耦、ShellSnapshot::build 签名、连接事件监听）为内部重构，
   Go 无对应结构，标注 N/A。
5. parity 包两个“认证候选”测试（`TestAlignmentBaselineIsFrozenAndTraceable`、
   `TestParityManifestIsMachineReadableAndComplete`）自 08-04 起即与跟踪基线不一致：
   candidate/baseline/commits 仍指向 SDK 认证窗口 `bbbf396839`，需走 sdktests 认证工作流
   （3 次连续差分运行）后统一更新，非本日例行对齐范围。
