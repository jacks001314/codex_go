## 58404

Rust tracks the history boundary covered by the last usable usage report:

- `ContextManager::last_server_reported_usage_item_count` records how much
  history the saved count covers; items at or after it are estimated on top.
- `last_model_output_item_count` is the index just after the latest model
  output (failed responses included) and is the restored-history approximation.
- `update_token_info` covers `max(last_model_output_item_count, input_item_count)`,
  so a successful response covers the request input even with no output items.
- Spending-only updates preserve the boundary; failed or usage-less output stays
  estimated until a later usable report covers it.
- `items_since_last_usage`, `estimated_tokens_since_last_usage`, the
  `take(last_user_index.min(boundary))` truncation of non-last reasoning, the
  recomputed context count and remote-compaction estimate all use the boundary.

Go mirrors the parts that have carriers:

- `context.HistoryManager` keeps `lastServerReportedUsageItemCount` and
  `lastModelOutputItemCount`. `RecordItems` advances the model-output index for
  model-generated items (assistant messages, reasoning, web search, image
  generation, and call items the lossy history keeps as Other).
- `UpdateTokenInfoWithBoundary(usage, window, inputItemCount)` covers
  `max(model output, request input)`, mirroring `update_token_info`.
  `UpdateTokenInfo` (spending-only) leaves the boundary untouched.
- `SetUsageBoundary`, `ResetUsageBoundary`, `UsageBoundary`,
  `ItemsSinceLastUsage` and `EstimatedTokensSinceLastUsage` expose the boundary;
  `Replace`, `ReplaceCompacted` and `RemoveFirstItem` reset it through the
  last-model-output approximation, like `reset_last_usage_boundary`.
- `compact.ItemsSinceLastUsage` and
  `compact.EstimateActiveContextTokensWithUsageBoundary` port the boundary-aware
  estimate; a negative boundary is the restored-history approximation.
  `EstimateNonLastReasoningTokensSinceUsage` truncates reasoning at
  `min(user boundary, usage boundary)` so tail reasoning is not charged twice.
- `exec.execCompactStatus` passes the restored-history approximation explicitly,
  because persisted rollouts do not save the live boundary.

Residual (recorded rather than invented):

- The live in-turn boundary needs the sampling loop to pass the request input
  length when it records usage. That carrier is
  `appserver/turn_runtime.go` (`persistCompactTokenStatus` and
  `compactTokenStatusForTurnWithPolicy`), which a parallel agent owns; the Go
  runtime keeps using the restored-history approximation until that file is
  free. This is why the commit is recorded as partial.
