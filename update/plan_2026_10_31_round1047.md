## Goal

Log every failed MCP server startup attempt exactly once, including discovery
failures that never reach a startup notification, and keep the wrapped error
causes when a startup failure becomes a cloneable outcome.

## Findings

- Rust #42370 logs `MCP server startup failed` once per `ManagedClientStartup`
  attempt when the outcome is `Failed`, and stores `format!("{error:#}")` in
  `StartupOutcomeError::Failed` instead of `error.to_string()` so the whole
  anyhow chain survives conversion. `connection_manager/required.rs` and the
  startup update both surface that string, so the chain also reaches clients.
- Go equivalent boundaries: `MCPService.inventoryStatusForConfig` performs one
  inventory/startup attempt per call, `ListStatusCheckedWithObserver` applies
  each result once, and the non-blocking optional-grace path intentionally drops
  late results without notifying the observer. Logging at the observer would
  miss exactly those dropped attempts, so the attempt itself must log.
- Go previously formatted the failure with `err.Error()`, which keeps only the
  outermost message. `applyResult` rebuilds the observer error from that status
  string, so the chain was lost for both the wire status and the TUI warning.

## Implementation

- `mcp/api.go`: startup failures now use `mcpStartupErrorMessage`, which joins
  the `errors.Unwrap` chain (skipping causes already embedded by `fmt.Errorf`
  wrappers) to mirror anyhow's `{:#}` rendering. `status.Error`,
  `status.ToolsError`, and the observer error all carry that string.
- `inventoryStatusForConfig` emits one `slog.Warn("MCP server startup failed",
  "server_name", ..., "error", ...)` per failed attempt. Context cancellation is
  excluded to mirror Rust's `Cancelled` outcome, which is not logged as Failed.
- `mcp/startup_failure_logging_like_rust_test.go`: covers one log per attempt
  across repeated startup calls, a discovery failure whose optional-grace result
  is dropped before notification (slow-failing child process, no Failed
  observer callback), and the chain-rendering helper.
- `mcp/api.go` keeps the `errors.New(*result.Status.Error)` conversion; with the
  full-chain status message it now preserves the chain's text.
