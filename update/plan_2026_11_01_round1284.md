# Round 1284 — treat an explicit zero wait yield as an immediate poll

Rust target: `67f0994b532b8740f14b5b738af7b7b2a915b1d6` (anchor worktree
`D:\qax\reagent\dev\git\codex-anchor-67f0994b`, hash `67f0994b`).

## Advanced this round

Rust parses the wait tool's `yield_time_ms` as a plain `u64` with a serde
default:

```rust
struct ExecWaitArgs {
    cell_id: String,
    #[serde(default = "default_wait_yield_time_ms")]
    yield_time_ms: u64,
    ...
}
```

The 10 000 ms default therefore applies only when the field is **absent**. An
explicit `yield_time_ms: 0` travels unchanged through `WaitRequest` (also a
plain `u64` in `code-mode-protocol/src/runtime.rs`) into
`InProcessCodeModeSession::resolve_yield_timeout`, where it becomes
`YieldAfter(Duration::ZERO)`: the observation returns immediately with
whatever the cell has buffered.

Go collapsed the two cases twice over:

- `tool/codeModeWaitParams.YieldTimeMS` was an `int`, and both the remote and
  the local wait paths rewrote `<= 0` to `10000`, so a polling wait blocked
  for ten seconds;
- `codemode.SessionRuntime.Wait` mapped `WaitRequest.YieldTimeMS == 0` back to
  `ProtocolDefaultWaitYieldTimeMS`, so even a host that received an explicit
  zero waited the default.

`SessionRuntime.Execute` already modelled Rust's `YieldAfter(0)` correctly,
which made the inconsistency visible: exec could yield immediately while the
following wait could not.

## What changed

- `tool/code_mode_exec.go`: `codeModeWaitParams.YieldTimeMS` is now `*int`;
  `codeModeWaitYield` applies the 10 000 ms default only for `nil`; the remote
  path forwards the value verbatim and the local path uses it for its timer; a
  negative `yield_time_ms` is rejected with
  `yield_time_ms must be non-negative` (Rust's `u64` deserialization failure).
- `codemode/session_runtime.go`: `Wait` uses `WaitRequest.YieldTimeMS`
  directly, so a zero deadline observes the running cell immediately.
- Tests: `tool/code_mode_wait_yield_like_rust_test.go` records the forwarded
  yield (`0` for an explicit zero, `10000` when absent, an error for `-1`) and
  proves the in-process wait no longer blocks for an explicit zero;
  `codemode/session_wait_zero_yield_like_rust_test.go` asserts the runtime
  returns a yielded observation at once and still reports the released script's
  output on the next wait.
