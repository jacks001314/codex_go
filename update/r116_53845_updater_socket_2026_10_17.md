# Round 116 · #53845 daemon updater socket and bootstrap readiness

Rust source: `2f05c0a71f` (`Fix daemon updater socket binding and bootstrap readiness on Unix`).

## Landed

- `appserverdaemon/updater_socket.go`
  - Unix updater sockets bind inside a short private temporary directory and
    publish the advertised `CODEX_HOME` path as a symlink, avoiding `sun_path`
    length failures.
  - Startup removes only a stale socket or symlink. A regular file at the
    advertised path is preserved and bootstrap fails with a bind error.
  - Cleanup removes the advertised link only when it still points at this
    listener, then removes the physical socket and temporary directory.
  - Windows keeps the existing private-directory/direct-bind behavior.
- `appserverdaemon/lifecycle.go`
  - A supported automatic updater (`app-server daemon update --help`) must have
    a running process and a published Unix socket before bootstrap reports
    success.
  - Readiness never connects to the socket, so one-shot restore authority is not
    consumed by the probe. Failure includes updater stderr tail context.
