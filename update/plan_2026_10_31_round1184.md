# Round 1184: protect the Windows sandbox bin DACL and audit the setup env (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

## Gap

- #42330 (`f5990564`) protects the sandbox runner directory from inherited
  write access. Go's `lockSandboxDir` always set an unprotected DACL, so
  `codexHome/.sandbox-bin` — usually inside the writable workspace — inherited
  the workspace capability's WRITE/DELETE ACEs and the sandbox could replace
  its own runner.
- #42833 (`f1aac1e885`) added SYSTEMROOT to the wrapper-setup environment
  allowlist. Go has no curated wrapper environment, so the behaviour already
  held; the entry only needed evidence.

## Evidence

- `sandbox/windowssandbox/bin/setup_main/win/run_windows.go`
  `lockSandboxDir` now takes `protectDACL` and ORs
  `PROTECTED_DACL_SECURITY_INFORMATION` into the security information.
  `lockSandboxBinDir` passes `true`; the persistent sandbox and secrets dirs
  keep inherited ACEs, matching Rust `lock_persistent_sandbox_dirs`.
- Test `TestLockSandboxBinDirBlocksInheritedWriteForRunnerFilesLikeRust`
  (full and provision-only) grants the workspace capability SID inherited write
  on the workspace, locks the bin dir, then checks the capability SID loses
  WRITE/DELETE on the dir, an existing runner and a newly created runner while
  Authenticated Users keeps READ/EXECUTE. Removing the flag makes the test fail
  with `write/delete ... = true, want false`.
- SystemRoot: `cmd/internal/codexmain` runs the wrapper in-process and
  `setup_windows.go` elevates with `ShellExecuteExW` without an
  `lpEnvironment` override, so elevation inherits SystemRoot exactly like
  Rust's `std::env::vars_os()` copy; helper envs preserve SystemRoot via
  `fsHelperEnvironmentFrom` (`TestFSHelperEnvironmentPreservesWindowsSystemRootLikeRust`).
