### Implemented

1. **view_image decode validation** (`41ece455b7` + `7a18a5c528` +
   `260261ed8f`): `tool/view_image.go` now decode-validates file bytes with the
   stdlib `image` package (png/jpeg/gif) before producing any tool output,
   rejecting non-images with `unable to process image: invalid or unsupported
   image data`; valid bytes and metadata are preserved; the data URL uses
   `application/octet-stream` (Rust parity); history insertion owns preparation.

   `SessionIDEnvVar`; `ShellExecutorOptions.SessionID` injected into shell tool /
   unified-exec child env (authoritative over inherited values, case-insensitive
   stale-key removal); threaded from the thread record's SessionID in
   `toolRouterForTurnContext` via `turn.ToolRegistryOptions.SessionID`.

   patches whose hunks resolve to the same file
   (`multiple operations target <path>`); distinct files remain accepted.

   `safetyBufferingFromStreamMetadata` keeps a present top-level
   `safety_buffering` authoritative (including null/malformed) and falls back to
   typed `response.metadata` events where `metadata.type == "safety_buffering"`;
   unrelated metadata is ignored.
5. **MCP server status pluginId** (`78d3665d15`): `MCPServerStatus.PluginID`
   (`pluginId`) populated from plugin-contributed server registrations in
   `NewMCPService`, `null` for config/dynamic servers; marshaled and cloned.

   nullable wire shape) honored by `handleAppRead` through
   `appListConfigValues` so thread-level connector overrides apply.

   `PluginInstallParams.InstallAttemptID` (`installAttemptId`) accepted,

   `ClampProxyBindAddrs` and `ValidateProxyUnixSocketAllowlistPaths` are
   Windows-aware: Unix socket permissions no longer clamp listeners to loopback
   or fail validation on Windows; config values are preserved for state/remote
   launch.
9. **responses_api_metadata** (`9e301c8c9a`): `Config.ResponsesAPIMetadata()`
   accessor + project-local sanitize; `codexapi.ValidateResponsesAPIMetadata`
