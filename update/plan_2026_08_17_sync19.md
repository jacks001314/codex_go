1. `ea10ae7d0f` #38993 "Evaluate recent and character-routed skill selection"
   - Rust adds `LruPlusCharacterRoutingSkillSelector` (`lru_plus_character_routing_v1`)
     and `LruPlusLexicalCharacterRoutingSkillSelector`
     (`lru_plus_lexical_character_routing_v1`) to the shadow-selection experiment.
     Both fuse LRU recent-invocation history with the character routing-card selector
     (the lexical variant also fuses weighted lexical matches) via reciprocal rank
     fusion (`fuse_rankings_with_constant`, RRF_K=10, MAX_RESULTS=50).
   - Go `prompt/skill_shadow_selection.go` has the shadow experiment with
     weighted_lexical / fielded_bm25 / character_ngram / character_routing_card /
     multi_query_lexical / routing_card_exact / lru_v1 / lru_plus_lexical_v1 only.
     Gap = the two new fused selectors + wiring into `RunSkillShadowSelection`.
2. `3666a46ea3` #38994 "Remove the workspace settings gate for apps and plugins"
   - Rust deletes the ChatGPT workspace `enable_plugins` fetch and the
     `WorkspaceSettingsCache` gate; the effective feature configuration now controls
     app/plugin APIs, plugin skills/hooks, and experimental feature reporting.
   - Go has no workspace-settings fetch or gate (no `workspace_settings` equivalent;
     feature flags alone control the app/plugin surface). Gap = N/A (documented).
3. `4885eb6c52` #38997 "Retry transient Guardian sampling failures"
   - Rust `LunaSampler` retries transient transport/stream/rate-limit/server failures
     up to 2 times across the whole sampling flow, recovers from 401 through the
     auth manager (discarding pooled connections), and tolerates prewarm failures.
   - Go guardian samples through `model.AgentRunner` (no WebSocket pool, no
     prewarm-fail-fast path); transport/stream retry is owned by the Go model client.
     Gap = N/A (documented).
4. `8e89e98cf6` #39001 "Ignore stale Guardian tool risk scores"
   - Rust tracks per-thread `latest_tool_call` / `latest_scored_tool_call`, skips
     approval review when the lag exceeds configurable `max_tool_call_lag` (default 3,
     schema `uint`), and recovers once the scored call catches up.
   - Go `modelGuardianReviewer.Review` is called per tool action with no score-progress
     bookkeeping and no lag bound; `features.guardianv2.max_tool_call_lag` is not
     recognized. Gap = config key + per-thread score progress + lag skip.
5. `02e9bfaac7` #39005 "Disable Guardian V2 for managed automatic reviewers"
   - Rust forces `features.guardianv2` off when `allowed_approvals_reviewers` does not
     include `user` (both local requirements and cloud bundles), preserving Guardian V2
     when the user reviewer remains allowed; effective value surfaces via config/read.
   - Go `ConfigRequirements.AllowedApprovalsReviewers` exists but never affects
     `guardianv2` in `FeatureSettingsWithLegacyUsages` or loaded values. Gap = override.
6. `04caa22c82` #39006 "Emit API-key turn cost telemetry from app-server"
   - Rust spawns a `TurnCostWorker` (OTLP exporters + OpenAI provider only), observes
     turn lifecycle events for API-key sessions, polls `/v1/analytics/codex/turn-costs`
     (new `backend-client` `turn_usage` module) with bounded retries, and emits
     `codex.turn_cost` session-telemetry events.
   - Go has no OTLP session-telemetry log-event surface (`codex.turn_cost`), no backend
     turn-cost client, and no per-session SessionTelemetry object; Go telemetry is an
     HTTP analytics event pipeline. Gap = N/A (documented, architecture difference).
7. `def7ed5572` #39007 "Wait for Guardian score progress in approval tests"
   - Rust test-only change to the guardian-v2 approval test harness.
   - Go has no equivalent test harness. Gap = N/A (test-only).
8. `21cfd369ef` #39008 "Add task context to shadow skill selection"
   - Rust restructures `shadow_selection_experiment` into `mod.rs` +
     `task_context.rs`: a per-thread `ShadowTaskContext` retains up to 2 prior
     substantive requests (2 KiB request / 4 KiB augmented query, UTF-8-safe
     truncation) and up to 50 recently relevant skills; `begin_turn` snapshots the
     augmented query + recent skills for the `task_context_fusion_v1` selector

     builds the query from the single request. Gap = ShadowTaskContext +
     `task_context_fusion_v1` + explicit-intent/invocation recording + bounded
     augmented query.

## Gap implementation

### G1 (#38993 + #39008) shadow skill selection - fused + task-context selectors

- `prompt/skill_shadow_selection.go`:
  - `LruPlusCharacterRoutingSkillSelector` (method `lru_plus_character_routing_v1`) and
    `LruPlusLexicalCharacterRoutingSkillSelector` (method
    `lru_plus_lexical_character_routing_v1`): fuse the LRU selection, the weighted
    lexical selection (lexical variant only), and `SelectSkillsCharacterRoutingCard`
    through `fuseSkillRankingsWithConstant(..., skillSelectorRRFConstant)` capped at
    `SkillShadowSelectionMaxResults`; metadata = max of query term counts / OR of
    truncation flags.
  - `ShadowQuery{Text string, Truncated bool}`; `ShadowTaskContext` (per-thread,
    mutex-guarded) with `BeginTurn(turnID, current ShadowQuery, substantive bool)
    TaskContextSnapshot` and `Record(turnID, resource string)` mirroring Rust
    `task_context.rs` (MAX_PRIOR_REQUESTS=2, MAX_REQUEST_BYTES=2 KiB,
    MAX_QUERY_BYTES=4 KiB, MAX_RECENT_SKILLS=50, UTF-8 char-boundary truncation,
    pending-turn commit on the next turn, substantive dedup of prior requests).
  - `RunSkillShadowSelectionWithTaskContext(query ShadowQuery, documents,
    recentSkillIDs []int, snapshot *TaskContextSnapshot)`; the run list gains
    `lru_plus_character_routing_v1`, `lru_plus_lexical_character_routing_v1` and
    `task_context_fusion_v1` (the last runs the LRU-of-snapshot-recent-skills +
    character-routing fusion over the snapshot query). `RunSkillShadowSelection`
    stays as a context-free wrapper for tests/back-compat.
- `appserver/skill_shadow_selection.go`:
  - per-thread `skillShadowThreadState` gains `taskContext *promptctx.ShadowTaskContext`;
  - `runSkillShadowSelection` computes `ShadowQuery` + substantive flag from `params`,
    calls `BeginTurn(turnID, query, substantive)`, runs the experiment with the
    snapshot, and records explicit skill intent (host/orchestrator, model-visible)
    into the task context after predictions are frozen;
  - `recordSkillShadowInvocation` also records into the task context (future turns).
  - `skillShadowIsSubstantive(params)` mirrors Rust `is_substantive` (skill/mention
    input names + normalized-text ignore list).
- Tests: selector fusion cold-start/order/limits (mirror
  `lru_plus_character_routing_tests.rs`), continuation-prompt recovery
  (mirror `task_context_tests.rs`), explicit intent + turn isolation + bounded
  history, updated method-list test (8 -> 11 methods), appserver-level
  task-context integration.
