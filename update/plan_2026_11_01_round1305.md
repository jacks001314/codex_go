# Round 1305 — Linux portability sweep and snapshot-root hygiene

Rust target: `67f0994b532b8740f14b5b738af7b7b2a915b1d6`. `git fetch` on the
anchor repository reports no commits after the freeze point, so the ledger is
current as of 2026-11-01.

## Product fixes

- `cli/dispatch_dir_unix.go`: retiring an arg0 directory used `os.Rename`,
  which fails with `EEXIST` when the target exists; Rust calls `rename(2)`
  and lets the kernel merge directories, so the Go path now uses
  `unix.Rename`.
- `sandbox/integrity/contents.go`: a writable root that is a file must clear
  the default `ReadOnlySubpaths` carve-outs, and deny checks use the literal
  path for direct globs while resolving only directory globs, matching Rust.
- `sandbox/windowssandbox/registered_alias.go`: alias validation used host
  `filepath` semantics, which misjudges Windows state on a Unix host; it now
  rejects non-Windows absolute paths with `isWindowsSandboxAbs` and
  `windowsBase`.
- `execserver`: the descriptor replay probe now runs inside the capture
  sandbox, so the probe observes the same filesystem view as a real call.

## Snapshot-root hygiene

`parity/rust_snapshot_test.go` resolved the Rust tree from a sibling
`git/codex` checkout first. That checkout lags the freeze point here, so hash
and feature-registry snapshots reported drift that did not exist (for example
`deferred_tool_world_state` looked stale and
`suppress_model_change_announcements` looked Go-only). The resolver now
prefers `git/codex-anchor-<frozen sha>` worktrees derived from
`parity/commits.json` before falling back to a plain checkout, and logs the
root it picked. `parity/contracts/manifest.json` also pointed
`desktop-doctor-diagnostics` at three verifier names that no longer exist;
it now names the live desktop doctor tests.

## Concurrency sweep across the whole tree

Running `go test -race` one package at a time had hidden races that only appear
when packages run together and first-use initialization overlaps real work. A
whole-tree `go test -race ./...` on the Kali LF export reported 27 data races;
after the fixes below the same command reports none.

- `appserver/runtime_router.go`: `requireModels`, `requirePermissions`,
  `requireCollaboration`, `requireMCP`, `requireFeatures`, `requireApps`,
  `requireTurns`, `requireFS`, `requireRealtime`, `requireRemote`,
  `requireEnvironment`, `requireWindows`, `requireAccount`, `requireHooks`,
  `requireSkills`, `requirePlugins`, `requireReviews`, `requireMisc`,
  `requireCommandExec`, `requireProcesses`, `requireServerRequests` and
  `requireFeedback` created their singleton behind an unlocked nil check. Two
  turns starting at once could publish two instances, and a reader could clone
  the model catalog out of a half-published one. They now go through
  `requireServiceSlot`, which reads and publishes under `servicesMu` and builds
  outside the lock, because builders still touch other runtime services. The
  server-request broker keeps its sink wiring inside the builder: re-applying it
  on every call replaced the broker that callers inject via `RuntimeServices`.
- `realtime/history.go`: `StartSession`, `NoteHandoffRequested`,
  `SessionClosed`, `FinishStreamingAgentMessage`, `SealUserInput` and
  `SealUserInputForPrompt` inspected `activeSessionID` / `streamingAgent`
  before taking the mutex. The checks moved under the lock and
  `shouldSealUserInput` became `shouldSealUserInputLocked`.
- `config/api.go`: refreshing replaced the managed layer outside the lock, so a
  concurrent read could observe an empty managed layer; loading, warning and
  appending now happen in one critical section.
- `config/api.go`: managed-file reloads also raced each other. A reload reads
  the file outside `s.mu`, so one that started earlier could publish the older
  contents after a newer reload had already published. Reloads are serialized,
  which the whole-tree run showed was behind the `managed config fresh` flake.
- `execserver/server.go`: `startProcess` used `cmd.StdoutPipe()` with a
  concurrent `cmd.Wait()`, and Wait closes the pipes it created. A child that
  wrote and exited quickly could therefore lose its entire output (the stdio
  ordering test failed roughly once per 200 runs with only `process/exited` and
  `process/closed` on the wire). The server now owns both pipe ends, closes the
  parent writers after `Start`, and closes the readers when capture hits EOF.
- `execserver`, the realtime transport, `envutil.ScrubSlice`, the tool snapshot
  capture and the feedback snapshot were hardened earlier in this round.
- Test scaffolding: the screen-reader probe goroutine receives its probe and
  timeout by value instead of re-reading the package globals after a cleanup,
  and the updater install counter and rollout cancellation counter are atomics.

## Frozen-source resolution

Parity tests and `recordreplay.RustRoot` used to probe only
`git/codex/codex-rs`, a sibling clone at `b0f977c3`, while the ledger pins
`67f0994b`. That had two consequences: the app-server protocol schema tests
skipped (or compared stale fixtures), and real drift in
`app-server/tests/suite/v2` (2 files), `app-server-protocol/src` (3 files) and
`cli` (4 files) went unnoticed.

`internal/rustsrc` now resolves the checkout: it reads `rustToInclusive` from
`parity/commits.json`, prefers the `git/codex-anchor-<sha>` worktrees (pinned
commit first, then newest name), and falls back to the legacy sibling paths.
`appserver` (schema, protocol surface, v2 suite), `cli`, `memories`, `protocol`,
`sandbox`, `parity` and `recordreplay` all use it.

Verification: on Windows both app-server schema parity tests now run and pass
(`TestBuildProtocolSchemaMatchesRustStableFixtures`,
`TestBuildTypeScriptProtocolSchemaMatchesRustFixtures`), the v2 suite manifest
still covers every Rust module, and `go test` passes for `internal/rustsrc`,
`cli`, `memories`, `protocol`, `sandbox`, `parity` and `recordreplay`. On Kali
the same packages pass, including `-race`, against the anchor-less tree (where
the Rust-dependent tests skip as before).
