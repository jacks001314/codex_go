## L2 record-replay extended to core-level (dynamic verification infra)

The existing `recordreplay` facility only replayed the Rust recording through
the storage recorder (`rollout.Recorder`). This cycle added the dynamic half
of djalign method 2:

- `recordreplay.ReplayThroughCore` starts a paginated thread on
  `appserver.RuntimeRouter` and runs one turn per recorded task (3 tasks from
  `tui/tests/fixtures/oss-story.jsonl`) with a scripted agent reproducing the
  recording's per-task item surface (reasoning + agent_message presence;
  model text excluded per normalization rules).
- The observable contract is validated by `ValidateCoreReplayCrossCheck`:
  notification stream (turn/started, item/completed reasoning/agentMessage,
  turn/completed completed) plus the persisted paginated rollout (session_meta
  first, contiguous ordinals, task_started/item/task_complete lifecycle per
  turn), and `rollout.Resume` recoverability.
- Registered as verifier `TestReplayRustStoryRecordingThroughGoCore` on the
  `story-recording-replay` contract; token-free and CI-able.

## remote_sandbox_config shared-fixture differential (junction point 2)

Closed the last unwired config-requirements surface:

- Go parses `remote_sandbox_config` (hostname-pattern-scoped
  `allowed_sandbox_modes`) and applies the Rust
  `apply_remote_sandbox_config` semantics: hostname normalization
  (trim/trailing-dot/lowercase), first matching entry replaces the top-level
  modes, non-match preserves them, `WildMatchPattern` `*` / `?`
  case-insensitive matching.
- `ConfigRequirementsFromMapWithHostname` mirrors Rust's explicit hostname
  parameter (production paths keep the `os.Hostname()` fallback), so the
  differential is deterministic.
- `TestRustRemoteSandboxConfigSamplesRunInGo` drives the
  `config_requirements.rs` samples (`deserialize_remote_sandbox_config_requires_hostname_patterns_list`,
  `remote_sandbox_config_first_match_overrides_top_level`,
  `remote_sandbox_config_non_match_preserves_top_level`) with fn-name pinning;
  the fourth sample
  (`remote_sandbox_config_does_not_override_higher_precedence_sandbox_modes`)
  is pinned by name here and covered at the config unit level
  (`TestRemoteSandboxConfigDoesNotOverrideHigherPrecedenceModes`), which has
  access to `mergeConfigRequirements`.
- Registered as contract `remote-sandbox-config-shared-fixtures`.
