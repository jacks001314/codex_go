## 58444

Rust caps Guardian context entries before whole-entry elastic allocation.
Supporting text is capped once per entry, required and optional alike, while
exact planned-action JSON, images, audio and opaque native payloads stay
whole. Shortened sources are marked incomplete and their sizes recorded.

Go mirrors it with state.PrepareGuardianElasticEntries:

- Text entries are measured with the group max_section_entry_tokens plus the
  shared user-content framing; anything that already fits keeps its
  representation.
- guardianElasticTruncateTextToFit binary-searches GuardianTruncateText, so
  both ends and the omission marker survive and the marker is kept even when
  the cap cannot hold it.
- Exact entries, opaque media (ImageURL) and native sections are skipped.
- Shortened entries set Incomplete, clear their measured TokenCost so
  allocation charges the retained text, and append
  GuardianElasticTruncation{Component, OriginalBytes, RetainedBytes}.

Residual: prepare_sync_delivery(history) has no counterpart because Go
deduplicates retained instructions at composition time
(DeduplicateRetainedInstructions); revisit when the elastic pipeline is wired
into the guardian builder.

## 58454

Rust threads ContextBudgeting::{Fixed, Elastic} through root conversation and
Node REPL preparation. Fixed stays the default at every existing call site.

Go mirrors it with context.GuardianContextBudgeting:

- prepareGuardianRootContextWithBudgeting keeps every captured root candidate
  in elastic mode: no verified-answer filter, no message or handoff caps,
  full legacy text (deduplication still matches the stored excerpt), and
  retained-assistant stand-ins that only require the record to be complete.
- NodeReplReviewEvidence.SnapshotSinceWithBudgeting renders elastic snapshots
  with every admitted response and only the storage omission count.
- prepareGuardianRootContext and SnapshotSince keep the fixed policy.
