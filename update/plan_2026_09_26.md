## Why the model lives in its own package

Go's `history` package is the counterpart of Rust's **`message-history`** crate
(the append-only global `history.jsonl`: `history.go` / `message_history.go`
mirror `message-history/src/lib.rs`). Rust's **`codex-history`** crate
(`history/src/lib.rs` and its `retained_context` / `retained_source` /
`retained_assistant_messages` / `sender_user_messages` / `heartbeat` /
`reconciled_retained_context` modules) had no Go counterpart at all, so the port
lands as `codex_go/retainedctx` and the Go top-level directory inventory is
re-pinned (`parity/rust_inventory_test.go`).

Go also has no typed `CodexHarnessMetadata` (persisted items carry
`Metadata map[string]any`), so the package takes the typed view it needs
(`retainedctx.HarnessMetadata`: `user_input_order`, `inherited_user_message`,
`sender_user_messages`). Wiring the rollout/compacted-item wire to the typed
metadata is recorded below as the follow-up.

## sync215: the retained-context model (`codex-history`)

`retainedctx` ports the bounded, host-owned evidence families that live outside
the model's compaction contract, with Rust's admission rules intact:

- **`heartbeat.go`** - `HEARTBEAT_CONTENT_KIND`, `UserInputOrigin`
  (`FromTurnTrigger`, `FromMessage`, `IsUser`), and `Heartbeat`
  (`ParseHeartbeat`, `HeartbeatFromMessage`). `ParseHeartbeat` reproduces Rust's
  byte-budget guard (`len + lines*6 + 64 > 3600` with `str::lines()` counting),
  the single-trailing-newline strip, the exact envelope prefix/suffix, and the
  automation-id/timestamp byte-class limits. The Go zero value is normalized
  onto `User` so an unset origin never round-trips into a different stored value.
- **`retained_source.go`** - `ResponseItemID` (`NewResponseItemID("retained")`,
  UUIDv7), `RetainedSourceRole`, `RetainedSourceID`, `RetainedSource`, plus
  `RestoreSourceRevision` and `Source` (delivery proof requires both a message id
  and a recorded revision).
- **`retained_context.go`** - `VerifiedQuestionAnswer`, `VerifiedAnswer`,
  `RetainedUserMessage` (skips the ordinary-user origin on the wire, defaults it
  on decode), `RetainedInputSource` (`Local(order)` / `Inherited`),
  `RetainedContextOrder` (inherited prefixes order before local acceptance
  order), `RetainedContextEntry` / `OrderedEntry`, `RetainedContextEvent`
  (internally tagged `verified_answer`), and `RetainedContext` itself with
  Rust's serde layout: `verified_answers` + `incomplete`,
  `user_messages` + `user_messages_incomplete` (legacy default **true**),
  `assistant_messages` + `assistant_messages_incomplete`, `next_order`, and the
  empty-skipped `sender_deliveries`. Storage limits are `MAX_FAMILY_RECORDS = 8`,
  `MAX_RECORD_BYTES = 16_384`, `MAX_FAMILY_BYTES = 65_536`; `boundFamily` sorts
  by acceptance order (not persistence order) and evicts the oldest, marking the
  family incomplete; `RetainedUserMessage.bound` clears text/incompleteness and
  truncates ids at a char boundary; `RetainedContextEvent.Bound` clears an
  oversized answer's questions and truncates its ids.
- **`retained_messages.go`** - `RecordUserMessage` (heartbeat coalescing that
  compares only the latest version of the same automation, id-based replacement,
  inherited prefix order via `next_inherited_order`, revision minting,
  `verified_answers_incomplete |= inherited`), `RecoverUserMessageExcerpts`,
  `Record`, `Restore` (deep copy, re-bound every family, repair pre-adoption
  checkpoints, re-derive `next_order` from surviving item metadata), and
  `Rollback` (boundary by acceptance order or first removed message id; the
  legacy fallback by turn id, with inherited/local scoping).
- **`retained_assistant_messages.go`** - `RecordAssistantMessage`, including
  #48158's rules: an unsequenced `Local(None)` source is left to legacy
  transcript selection; a **complete, empty** assistant message is neither
  recorded nor a dedup hit (an id collision removes the stale record instead);
  an incomplete message keeps its omission notice; `HasOmittedAssistantMessages`
  reports storage loss or an undeliverable record.
- **`reconciled_retained_context.go`** - `LiveUserMessage`,
  `NewReconciledRetainedContext` (source-identity matching before ordering,
  conflicting/absent orders mark the result incomplete, latest ordered user turn
  tracking), `OrderedEntries` (with heartbeat-version coalescing after ordering,
  scoped per inherited/local prefix), and `UnmatchedUserMessages`.

Tests mirror Rust's suites: `retained_context_tests.rs` (order through recovery,
checkpoint and rollback; family storage limits without changing snapshots;
recovered excerpts obeying record/family limits; legacy checkpoints marking user
messages incomplete; surviving local sources advancing the counter; delayed
acceptance order across checkpoint replay plus `RestoreSourceRevision`; adopted
instructions preserving local order and rollback scope), the assistant rules
from #48158, `reconciled_retained_context_tests.rs` (source identity/acceptance
order/checkpoint gaps; missing and conflicting orders; heartbeat versions across
retention, restore and reconciliation), and `heartbeat_tests.rs` (exact
instruction body with and without a trailing newline, plus the rejection
matrix), with an added origin-classification and sender-budget matrix.
