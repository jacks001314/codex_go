## 0. 目标与口径

Rust `#51627`（`5b0b253035`）只把「assistant originals + omission notice 拆到独立
`RETAINED ASSISTANT CONTEXT` 段（置于 transcript 之后）」用于**异步独立快照**：

- 拆分动作 `retained_instructions.rs:201 deduplicate_transcript_instructions()`，
  **唯一生产调用点** `ext/guardian-v2/src/async_scorer/transcript.rs:95`（async scorer）；
- 同步/stateful reviewer 走 `retain_new_instructions`（`input_budget.rs:150` / `request_budget.rs:92`），
  `composition.rs:1-10` 头注释原文 **"Stateful reviewers retain their existing section order."**，
  且 `composition.rs:232` 的 `if session_id.is_some() { 2 } else { 9 }` 把 sync 的
  `retained_user_instructions` 放在 transcript **之前**（assistant 原文**同段**渲染）。

Go 之前（`e176a441`，我的 `#51627` 落地）在 `state/guardian.go` **无条件**拆分，
而 Go 唯一的 Guardian 生产消费者是 **stateful 同步 reviewer**（`guardianSessionRunner`
跨轮复用 `PreviousResponseID`，session kind 直译 `GuardianReviewSessionKind`）。
本补丁把拆分限定到异步 framing。

## 6. 仓内回归测试（硬门槛）

`state/guardian_retained_context_test.go:427`
`TestGuardianRetainedSnapshotSplitOnlyForAsyncPresentationLikeRust`：

1. **SyncFull / SyncDelta**（同步 framing）：无 `RETAINED ASSISTANT CONTEXT` 段；
   `retainedStart < assistantOriginal < retainedEnd < transcript`（assistant 原文留在 retained 段内、
   段在 transcript 之前）；两种同步 framing 的 retained→transcript 区间逐字节相同。
2. **Async**：`retainedStart < retainedEnd < transcript < assistantStart`；
   assistant 原文**不在**指令前缀内、**在** assistant 段内。
3. **证据守恒**：两段合并的 fragment 签名 == 未拆分渲染的签名（拆分只改框架，不改证据）。
4. 选择器直测：`RenderRetainedInstructionSectionsForPresentation(ctx, SyncFull).AssistantContext == nil`，
   `(…, Async).AssistantContext != nil`。

既有回归同步更新（原断言编码的是旧的无条件拆分）：
