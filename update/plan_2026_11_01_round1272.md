## What changed

Rust rejects uploaded audio *inside* the turn runner for steered input too:
`turn/steer` is accepted, the steered text is recorded, and the running turn
then fails with `UnsupportedOperation("Uploaded audio file inputs are not
enabled in this build.")`. Go refused the steer at admission, so the text was
never recorded and the client saw a JSON-RPC error.

- `turn/steer` accepts uploaded audio; the recorded steer drops the attachment
  (text and every other input preserved) and the queued item keeps the file
  reference.
- `AgentLoopRequest.ValidateSteerInput` + `drainSteerChecked` run at both steer
  drains, so a rejected steer fails the turn before inference and maps to
  `codexErrorInfo: badRequest` with the `unsupported_operation` analytics kind.
- Two transport gaps the steer path exposed are fixed: `inputContentFromTurnUserInputs`
  had no `AudioReference::File` arm and dropped file-backed audio, and
  `prepareUserMessageContentImages` rebuilt every non-image block as
  `input_text`, discarding `input_audio`. Image preparation now rewrites only
  `input_image` and copies the remaining blocks through, matching Rust
  `prepare_message_content`.
- `validateTurnUserInputAudioFiles` lost its last caller and is removed; the
  rejection now lives only in the turn runner, exactly like Rust.
- `valueContainsUploadedAudioFile` descends into typed `[]map[string]any`
  message content, which is what the steer queue actually stores.
