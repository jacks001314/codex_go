## `16537b20a5` #45248 - captured step settings for metadata and tool hooks

Rust now builds the Responses/MCP/extension request metadata and the pre/post
tool-use and permission-request hook payloads from the *issuing step's* captured
settings (`ExecutionMetadata::from_settings(step_context.settings)`) instead of
the turn context's initial settings, and it takes the Responses tool inventory
from the step's finalized tool router instead of a turn-scoped
`TurnMetadataState::tool_namespaces_info` write.

### What Go already has

- `turn.BuildResponsesClientMetadata` carries the lineage, sandbox, analytics,
  auto-review and Node REPL flags, and the app-server builds it per turn
  (`buildAppTurnRunConfig`), re-derives it for steer-issued requests
  (`steerClientMetadata`), and the standalone web-search and exec paths build
  their own copies.
- The hook runner serializes Rust's request shapes (`model`, `permission_mode`,
  `tool_use_id`, matcher aliases, ...).

### Divergences found in the same path (evidence)

1. **Tool-use hooks report no model.** `RuntimeRouter.turnHookAdapter` builds
   the adapter without `Model`, so `ToolHookAdapter.RunPreToolUse` /
   `RunPostToolUse` send `model: ""` in the hook input, and
   `PermissionMode` is the literal `"default"` instead of Rust's
   `hook_permission_mode(approval_policy)` (`Never` -> `bypassPermissions`).
   Rust has sent the turn's effective model here since before this commit.
2. **The turn metadata has no `model` / `reasoning_effort`.** Rust inserts both
   into the request metadata extra (`ExecutionMetadata::apply_to`); Go's
   `codexapi.ClientMetadata` has no such fields, so neither the Responses turn
   metadata nor the MCP/extension metadata carries them.
3. **The MCP/extension request metadata has no `x-codex-turn-metadata`.**
   Rust's `build_mcp_tool_call_request_meta` inserts the whole turn-metadata
   document; Go's `_meta` carries only `_codex_apps`, the plugin id, and the
   confirmation policies.
4. **PermissionRequest hooks are never invoked.** `HookRunner.RunPermissionRequest`
   and its parsing/analytics have no production caller, so Rust's
   `run_permission_request_hooks` step in the approval flow (`tools/approvals.rs`)
   has no Go counterpart.
5. **No step settings lane.** `step_model_switching` is registered in
   `features/features.go` but unimplemented: the agent loop copies the turn's
   model/effort once (`AgentLoopRequest`), so a mid-turn `turn/settings/update`
   never reaches a later sampling step. Rust's per-step capture
   (`session/step_settings.rs`, `session/step_context.rs`) is the prerequisite
   for the *step-scoped* half of #45248, and for the tool inventory
   (`tool_namespaces_info`) Go has no equivalent type at all.

### Landed in this pass

- `codexapi`: `ClientMetadata.Model` / `.ReasoningEffort` are emitted as the
  `model` and `reasoning_effort` turn-metadata keys when set (Rust's
  `ExecutionMetadata::apply_to` extra entries), and the captured pair overrides
  client-provided `responsesapi_client_metadata` / `responses_api_metadata`
  entries for those keys - Rust inserts them into the extra map after the client
  entries, and removes the effort key when the step has none. `turn.
  ResponsesClientMetadataOptions` forwards both.
- `appserver` / `exec`: the turn-config, steer, standalone web-search, and exec
  metadata sites now carry the model (and effort where the turn resolves one),
  so the request metadata describes the settings that issued the request.
- `appserver`: `turnHookAdapter` resolves the turn's effective model and
  Rust's `hook_permission_mode` mapping for the approval policy, so pre/post
  tool-use hooks report the issuing model and the correct permission mode; the
  interrupt hook uses the same mapping instead of `fmt.Sprint` of the raw
  policy.

Recorded divergence (step-scoped half): Go's metadata/hook attribution is
turn-scoped until the step-settings lane exists; a mid-turn
`turn/settings/update` is reflected in the next turn and in steer-issued
requests, not in the metadata of an already-running step.

## `516f2780fd` #45255 - command center opens sessions directly

Rust replaces the command center's inline task composer with a session list:
`n` opens a blank session in the selected checkout without sending an initial
turn, single-letter action shortcuts plus `Enter` open a session, `Esc` cancels
search/rename, `Ctrl+C` quits from the list, destination settings load while
explicit permission choices carry over, and blank sessions with drafts survive
navigation until the first turn.

Go's command center lives in `tui/agents_overview/*` (terminal-agnostic view),
`tui/tea/agents_overview.go` (in-session host), and `app/agents_dashboard.go`
(standalone `codex agents` host); all three still build the removed composer
(`State.Input` doubles as the rename field, `TypeChar`/`Backspace` type into it,
`Activate` returns `ActionDispatchTask`, `ClearNew` resets it, and the render
draws a "New task" prompt row). Disposition: **port (following slice)**; the
change list, verified against the Rust diff at `a505c71490`:

1. Keymap defaults (`tui/keymap.go`, mirrored in `tui/keymap_test.go`): the
   agents actions become plain single letters - `resume` `o` (Go has no
   resume-picker action, so this one has no Go target), `search` `f`,
   `new_task` `n`, `rename` `r`, `stop` `x`, `archive` `a`, `delete` unchanged,
   `hide` `h`, `toggle_grouping` `g` - and `new_task` describes opening a new
   session rather than composing a task. Rust also drops the printable-key
   reservation in `tui.keymap.agents.*` validation; that relaxation is what
   makes the single letters legal.
2. The composer leaves the view: `tui/agents_overview/overview.go` stops
   dispatching on `Enter` (`ActionDispatchTask` is removed), typing only edits
   the search or rename field (Rust `edit_input`), `Enter` renames when
   renaming and otherwise opens the selected row, and `Enter` clears an active
   search. `render.go` drops the "New task" prompt row, the attachment labels,
   and the composer cursor, and the footer hints become `new` / `open` /
   `ctrl+c quit` (Rust `agents_overview_render.rs`).
3. `n` starts a session instead of clearing input. Rust splits the new-session
   path into `agents_overview_new.rs::new_agents_overview_session` (start a
   thread with the destination's settings, no `turn/start`) plus
   `agents_overview_threads.rs` bookkeeping: `blank_sessions` keeps the started
   thread subscribed and reattachable, `selected_permission_profiles` carries
   an explicit profile choice into the new session, and `TurnStarted` /
   `ThreadClosed` / `ThreadArchived` / `ThreadDeleted` clear the blank entry.
   Go has no equivalent: `app/agents_dashboard.go` only starts a thread as the
   first half of `Dispatch` (always followed by `turn/start`), the in-session
   dashboard has no new-session callback at all, and
   `appserver/router.go::handleThreadResume` rejects an unmaterialized thread
   with "no rollout found for thread id X" - so opening a started-but-untouched
   session cannot go through the existing switch path and needs the Rust-style
   retained-started-session attach.

Verification for this slice: `go build ./...`; `gofmt -l` clean on touched
files; `go test ./tui/... ./app/... -count=1` green with the affected tests
updated (`overview_test.go`, `tui/tea/agents_overview*_test.go`,
`app/agents_dashboard_test.go`, `tui/keymap_test.go`).

## `a505c71490` #45262 - pastes route into the history search query

Rust appends sanitized pasted text to the active `Ctrl+R` history-search query,
restarts matching from the newest entry, ignores empty pastes (keeping the
selected match), renders `\n`/`\t` as `\u21b5`/`\u21e5` in the footer while
matching the raw query, and clamps the cursor for very large queries.

- `tui/history_cell/messages.go`: `SanitizeUserText` ports
  `sanitize_user_text` (CSI sequences and control characters dropped, tabs and
  newlines kept, an unterminated CSI sequence dropping the remainder) - the
  helper the composer applies to every paste.
- `tui/bottom_pane/chat_composer/history_search.go`: `AppendPastedQuery` mirrors
  the new paste branch (newline-normalize, sanitize, ignore an empty paste so
  the selected match survives, otherwise append and restart matching from the
  newest entry) and `DisplayQuery` renders the footer/cursor text with visible
  newline and tab markers while matching keeps the original query.
- Tests: Rust's `history_search_paste_tests.rs` matrix (append and accept, large
  paste cursor clamp, empty paste preserving the match, separator rendering,
  draft restoration on a miss and on cancel, image path and sanitized text) plus
  the `sanitize_user_text` cases.
- `parity`: the four new history-search snapshots and the moved app snapshots
  refreshed the TUI snapshot manifest counts and the recursive total.

Verification: `go build ./...`; `gofmt -l` clean on touched files;
`go test ./tui/history_cell/... ./tui/bottom_pane/... ./parity/... -count=1`
