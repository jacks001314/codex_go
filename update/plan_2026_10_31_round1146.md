## Findings

- Rust #44569 removes Guardian action truncation and the fixed synchronous
  action byte limit. Complete actions are admitted against the whole-request
  budget, long text is split losslessly into bounded transport parts with
  framing charged to the estimate, and cached asynchronous scores cannot cover
  an oversized action.
- When an optional review exhausts its local input budget, Rust completes the
  review as aborted with no decision and lets the caller ask the user. A
  policy-required review, and a strict auto review, stay closed. The exhausted
  review session is retired so the next review rebuilds its context.
- Go already rendered complete actions, deferred exec/apply_patch/write_stdin
  reviews to the user, and refused serving assessments for oversized actions.
  Two approval transports still returned a denial: MCP tool approvals and MCP
  elicitations. An exhausted reviewer session also stayed reusable in the
  thread's session map.
- Rust's native tool review explicitly has no user-approval fallback: it is a
  pre-dispatch gate for a required review, so Go's rejection there is not a
  missing prompt. Go has no asynchronous scorer, so the async action-budget
  overflow route is N/A, and its model layer has no per-part transport cap, so
  no lossless part splitting is needed.

## Changes

- `appserver/guardian_reviewer.go`: `discardExhaustedReviewerSession` resets a
  shared runner and drops the thread-owned reviewer after either an optional
  (`AskUser`) or required (`Denied`) input-budget exhaustion.
- `appserver/mcp_tool_approval.go`: `reviewViaGuardian` reports an `AskUser`
  outcome separately, and `approveMCPToolCall` falls through to the ordinary
  responder or elicitation instead of returning a denial.
- `appserver/mcp_elicitation.go`: a non-strict elicitation whose Guardian review
  returns `AskUser` is re-requested from the user; strict auto review keeps its
  decline path.
- Tests: `appserver/guardian_mcp_ask_user_fallback_like_rust_test.go` covers the
  MCP tool approval prompt, MCP elicitation user fallback and strict decline;
  the existing budget-exhaustion test now also asserts the reviewer session was
  dropped.
