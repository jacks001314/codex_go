# Parity backfill: step settings, worktree ownership, fork metadata, token budgets, tool search

These five non-TUI ledger entries were already marked `complete` but remained
`audit_pending` in `parity/commits.json`. Each was revalidated against the
current worktree with the focused commands below.

## `#40651` Snapshot resolved settings for each model step

`AgentStepSettings` carries model, effort, reasoning summary, service tier, and
request metadata. The agent loop applies captured values only to following
steps, while app-server resolution preserves config/model defaults and refilters
service tiers when the model changes.

## `#40716` Thread ownership metadata for managed worktrees

Worktree ownership validates the four-hex bucket layout, repository identity,
and linked-worktree common git directory before reading or writing
`codex-thread.json`. Binding is atomic and no-clobber, rejects
primary/nested/unmanaged checkouts, and preserves the versioned camelCase
schema.

## `#40987` Window and fork positions in turn metadata

Responses turn/client metadata carries `forked_from_ordinal_exclusive` only when
the logical history base names the direct fork parent. Ambiguous revert or
ancestor boundaries omit the cutoff, and window identity remains in turn and
prewarm metadata.

## `#41162` Resolve token budgets from each step's active model

`appTurnRunConfig` captures turn-start token-budget preferences and effective
configuration. Step input resolution evaluates them against each sampling
step's active model, rebuilds model/context-window world state, and emits
guidance changes once.

## `#51209` Ranked tool discovery in JavaScript code mode

`tool.ToolSearchHandler` indexes deferred specs, ranks deterministic token
coverage/frequency matches, honors the caller limit, and returns metadata for
the next model call. The `code_mode_tool_search` feature and direct-tool
fallback are wired.
