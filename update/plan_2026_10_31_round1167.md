## Rust behaviour

`codex-rs/core/src/tools/events.rs::emit_exec_command_begin` builds a
step-scoped telemetry clone before recording the artifact-operation counter and
histogram:

```rust
let session_telemetry = ctx
    .turn
    .session_telemetry
    .clone()
    .with_model(&ctx.model_info.slug, &ctx.model_info.slug);
session_telemetry.counter(ARTIFACT_OPERATION_STARTED_METRIC, 1, &metric_tags);
session_telemetry.histogram(
    ARTIFACT_OPERATION_EXPECTED_OUTPUT_COUNT_METRIC,
    operation.expected_output_count,
    &metric_tags,
);
```

`with_model` sets the `model` metadata tag used by every metric emitted from
that clone, so a mid-turn model change is visible on the artifact-operation
counter and expected-output histogram.

## Go change

`appserver.artifactOperationModelSlug` resolves the model captured for the
command item that produced the marker. The start-time context recorded by the
unified-exec begin path wins; the turn's resolved settings only stand in when no
start was observed, mirroring the attribution of the command's analytics event.
The lookup is a non-destructive `peekToolItemModelContext`, because the command
completion path consumes the same entry for its `model_slug` field.

`emitArtifactOperationForCommandItem` adds
`telemetry.MCPCallModelTag` (`model`) with the sanitized slug to both metric tag
sets.
