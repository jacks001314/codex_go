# Round 1245: require the applied configuration server to match the requirement (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6.

## Why

#56055 was still recorded as a plan-only N/A, but the audit showed a real gap:
Go parsed the local `[config_server]` managed requirement and fetched its
bundle, yet nothing verified that the bundle applied to a run came from the
server the effective requirements select, and a fetched enterprise-managed
policy could still supply `config_server` (the old test even pinned that drop
behaviour, which predates the anchor).

## What changed

- `config/config_server.go`: `ValidateAppliedConfigServer` (with
  `ErrConfigServerMismatch`) requires the applied bundle's server to equal the
  required one; a missing applied server is also a mismatch, and a trailing
  slash is normalised because both spell the same bundle route.
- `config/cloud_config.go`: an enterprise-managed (fetched) requirements
  fragment carrying `config_server` is rejected with
  `invalid cloud config`, matching the anchor's "config_server may only be
  configured in local managed requirements".
- `app/app.go`: `loadEffectiveWithAppliedConfigServer` wraps the effective
  load and is now used by the sandbox run config, exec-server registration and
  app-server startup paths, so a run whose applied server does not satisfy the
  effective requirement fails before it starts.

## Tests

- `config/config_server_like_rust_test.go`: `TestValidateAppliedConfigServerLikeRust`,
  `TestFetchedPolicyRejectsConfigServerLikeRust`, and the retargeted
  `TestCloudManagedConfigServerRejectedLikeRust`.
- `app/config_server_applied_mismatch_like_rust_test.go`:
  `TestEffectiveConfigRejectsAppliedConfigServerMismatchLikeRust` covers
  mismatched, missing and matching applied servers.
- `go test ./config ./app ./doctor -count=1` passes; the targeted app-server
  run still hits the pre-existing DNS-dependent skill MCP test.

## Residual

Rust also tracks the applied server through configuration snapshots, role
overrides and managed refreshes (`CloudConfigBundleSnapshot.config_server`,
`core/src/agent/role.rs`, `runtime_refresh.rs`). Go has one effective
requirements layer and loads the bundle once per run, so the refresh-time
rejection has no carrier yet; `CloudConfigLoader.ConfigServer()` plus
`ValidateAppliedConfigServer` are the hook for when it does.
