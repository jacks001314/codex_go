# Round 1187: harden Windows sandbox provisioning file handling (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

## Gap

- #42342 (`add870a4`) keeps privileged provisioning bound to the paths it
  validated: no-reparse directory opens, handle-relative atomic replacement,
  fresh or retained handles for provisioning logs, credentials, the setup
  marker and error reports, and service-side request validation.
- Go wrote provisioning outputs through caller-supplied pathnames with
  `os.WriteFile`, so a junction or hard link planted in the Codex home could
  redirect a privileged write.

## Evidence

- `sandbox/windowssandbox/no_reparse_dir_windows.go` ports
  `validate_local_directory_path` (absolute local-disk and verbatim-drive paths
  only; relative, device, UNC and alternate-data-stream components rejected),
  `open_directory_no_reparse` (`NtCreateFile` with `OBJ_DONT_REPARSE` and
  `FILE_DIRECTORY_FILE`) and `create_directory_guard` (delete-on-close guard
  file created relative to the pinned directory).
- `sandbox/windowssandbox/file_write_windows.go` ports
  `write_file_atomically`/`create_temporary_file`: a fresh `sandbox-<hex>.tmp`
  entry is created relative to the pinned parent, written, and renamed with
  `NtSetInformationFile` `FileRenameInformation` (`ReplaceIfExists` plus
  `RootDirectory`). A pre-existing hard link at the destination is replaced
  rather than written through, and failures delete only the temporary entry.
- ProvisionOnly now uses provisioning outputs: `OpenProvisioningSetupLog`
  creates a fresh `sandbox-<hex>.log` instead of appending to the daily log;
  `WriteSandboxUsersFileForProvisioning` and
  `WriteSetupErrorReportForProvisioning` replace their entries atomically;
  `PrepareProvisioningSetupMarker` creates the empty marker through the pinned
  `.sandbox` directory with a protected DACL (SYSTEM, Administrators, real
  user) and retains the exclusive handle until commit; `lockSandboxDir` applies
  the sandbox DACL through a reparse-free open-or-create handle.
- Legacy Full/ReadAclsOnly setup keeps the existing path-based writes.
