# 基本信息

1. rust版本的codex cli 源码路径："D:\qax\reagent\dev\git\codex"。
2. go版本的codex cli 源码路径："D:\qax\reagent\dev\codex_go"。

## 基本原则

- 不要进行如何git pull 操作，以当前仓库状态为准。


## 工作流

1. 构建rust版本的codex cli二进制文件,只要构建一次就可以，后续测试直接使用该二进制文件。

2. 构建go版本的codex cli二进制文件,每次修改后都需要重新构建。

3. 打开两个终端，分别运行rust版本和go版本的codex cli二进制文件。

4. 构造相同的测试场景（构造的测试用例，要根据系统的各种功能点进行设计，确保覆盖各种使用场景，而且应该优先核心功能点），分别在两个终端中执行相同的操作。

5. 通过截图或是其他手段采集事件，比较协议行为与工作区副作用。

6. 分析具体的session日志，定位差异。

7. 通过5,6步骤，明确go版本中的问题和差异，定位问题，修复问题，验证对齐。

8. 回到第2步，重新构建go版本的codex cli二进制文件，构造新的测试场景，直到所有功能点都对齐。
