## 2. 缺口分析

Go 的 Guardian transcript 由 `guardianReviewTranscript` 生成 `[]string`，
每条是 `role: text`，作者信息只存在于文本前缀里。Rust 的 JSON 模式要求
host 元数据（author/index/label）与文本分离，避免消息内容伪造角色或
transcript 边界。`#49038`（保留加密 agent message）也依赖同一套结构化记录。

## 3. 本轮落地

1. `state/guardian_transcript.go`
   - `GuardianTranscriptEntry{Author, Index, Label, LineRole, RetainedSourceOrder, Text}`；
   - `Render`：line 模式保持原有 `role: text`；json 模式输出
     `{"author","index","label?","retained_source_order?","text"}`，
     文本作为 JSON 字符串转义，`<`/`>`/`&` 与 serde_json 一样保持字面量；
   - `GuardianTranscriptJSONInstructions`（Rust `TRANSCRIPT_JSON_INSTRUCTIONS`
     原文）与 `ApplyGuardianTranscriptInstructions`。
2. `config.Config.GuardianV2TranscriptFormat()`
   - 读取 `[features.guardianv2].transcript_mode`，默认 `line`，仅 `json`
     选择 JSON（大小写/空白容忍）。
3. `appserver/guardian_reviewer.go`
   - `guardianReviewTranscriptEntries` 在收集条目时写入 host 归属：消息角色、
     tool 名称（JSON label）、顺序 index；`guardianReviewTranscript` 按线程
     配置渲染 line/json；
   - line 输出逐字保持不变，既有测试无需改写。
4. `appserver/agent_runtime.go`
   - `guardianReviewInstructions` 在 JSON 模式下把 provenance 指令放在
     policy 指令之前（Rust 语义：配置的 policy 不能移除 provenance 约束）。

## 5. `#49038` Preserve encrypted agent messages

Rust 依据：`368e5eae2f`。

- `appserver.guardianNativeAgentMessage` 从存储项
  （`metadata.rawResponseItem` / `raw` / `data`）中识别含非空
  `encrypted_content` part 的 `agent_message`，序列化完整原生 item，保留
  author、recipient、content 顺序与 ciphertext。
- `state.GuardianTranscriptEntry.Native` 承载原生项；文本渲染跳过它，
  `BuildPromptPartsWithOptions` 在 native 处切分 transcript 文本：第一个文本
  段作为 prompt，native item 与后续文本段按顺序进入 `InputItems`，planned
  action 仍位于最后。
- 序列化后超过 Rust sync 预算（`message_tokens=5_000` × 4 = 20,000 字节）的
  原生消息整条替换为宿主通知 `Some conversation entries were omitted.`，
  不截断 ciphertext。
- `guardianReviewContextChanged` 改为比较包含 native 字节的 entries，
  review 期间新增/变化的加密消息会触发 stale-context 刷新。

## 7. `#49796` Deduplicate retained-context omission notices

Rust 依据：`5ca55db09c`。

- `state.GuardianRetainedOmissions` 记录 reviewer 会话已投递的
  user-instruction / assistant-context omission 状态；`RetainedOmissionState`
  只把精确匹配的宿主 notice item 计入状态，工具输出里拼出的相同文本不算。
- `ApplyRetainedOmissionDeduplication`：
  - 缺失状态（首次审阅/未知）→ 照常投递；
  - 状态未变且 section 只剩 notice + marker → 整段抑制；

    availability-change notice；没有 retained originals 时补出 START/END。
- reviewer 在 `agent.Run` 返回成功后记录已投递状态；失败/重试不会误判为已投递。

## 9. `#41562` Preserve turn lineage across goal continuations

Rust 依据：`4210c08def`。

- `RuntimeRouter.goalLineage` 保存每线程的 `{RootTurnID, ParentTurnID}`。
- `create_goal` 成功：root 取活动 turn 的 `RootTurnID`（缺省为 turn 自身），
  parent 取创建 turn。
- 每个计入 goal 的 turn 完成时：保留 root，把 parent 推进到该 turn。
- `continueThreadGoalIfIdle` 启动自动续跑时写入
  `RootTurnID`/`ParentTurnID`。
- 外部 objective 编辑、清除 goal、以及活动 turn 上的
  `thread/injectItems` 会清除 lineage，避免陈旧归属。
- Go 的 async hook 结果按线程在接收 turn 中 drain，天然属于当前 turn，
  不需要额外的 source-turn 标记。
