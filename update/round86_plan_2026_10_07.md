## 3. 跨节点交付协议（本轮新增）

- **Windows 车道**：在 `D:\qax\reagent\dev\codex_go_wt\<lane>` 建 worktree，提交本地分支即可；队长在**同一台机器**的 `codex_go` 主仓里 `git cherry-pick -n` 合并。
- **Linux 车道**：队长看不到其本地仓库，因此车道必须把分支推到 GitHub：
  `git push git@github.com:jacks001314/codex_go.git <lane>:refs/heads/<lane>` 然后 `git ls-remote origin <lane>` 核对；
  队长侧 `git fetch origin <lane>` 后 cherry-pick。
  **阶梯回退**：push 失败时用 `git format-patch main..<lane> -o /tmp/<lane>_patches`，再用 `project_file_sync` 把补丁同步到项目镜像 `update/r86_patches/<lane>-<n>.patch`，队长取回后 `git am` / `git apply`。
- 车道**永不 push main**；main 的提交编号只由队长编排（车道自编号常撞号）。

## 4. 队长合并门禁（每条车道交付都做）

1. `git cherry-pick -n <lane-tip>` → 逐 blob `git diff` 判等 / `git patch-id --stable` 判等（对照车道提交）。
2. `gofmt -l` 空 → `go build ./...`（涉及 Windows 面加 `GOOS=windows`）→ `go vet`。
3. 受影响包**整包**测试对基线（新增失败必须 0；基线集见 `leader_runbook` R5，按平台调整）。
4. **队长自跑一条反向对照 RC**（撤修复 ⇒ 具体测试 FAIL 原文；恢复 ⇒ ok）。
5. `git commit`（编号 sync594 起）→ `git push git@github.com:jacks001314/codex_go.git main:main` → `git ls-remote origin main` 确认。
6. 车道回收前：`git log --oneline main..<lane>` + 逐 commit `git patch-id` 比对，确认**无未并入 commit** 再 `agent_admin_remove`（round85_8e 第 2 节的 #49100 孤儿教训）。
