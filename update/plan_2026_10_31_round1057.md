## Goal

Prevent a sandboxed child from injecting terminal input into the unsandboxed
shell that resumes after the Codex CLI exits.

## Findings

- Rust #42590 appends
  `(deny file-ioctl (ioctl-command TIOCSTI))` to the generated Seatbelt policy
  in `cli/src/debug_sandbox.rs`, after every shared policy allowance, and bails
  if the command is missing its `-p` policy.
- Go `app.runSandbox` inherits `stdin`/`stdout`/`stderr` for the
  `codex sandbox` command path and builds the same Seatbelt wrapper, but had no
  TIOCSTI deny. A sandboxed process could therefore queue input for the
  unsandboxed shell.

## Implementation

- `sandbox/seatbelt.go`: added
  `HardenSeatbeltArgsForInheritedTerminal(args)`, which locates the generated
  `-p` policy, appends the TIOCSTI deny last, preserves the remaining command
  tail, leaves the input slice untouched, and errors with
  `seatbelt command is missing its generated policy` when no policy exists.
- `app/app.go`: `runSandbox` applies the helper to
  `SandboxTypeMacosSeatbelt` plans right after `BuildCommandRunPlan`.
- `sandbox/seatbelt_tty_injection_like_rust_test.go`: asserts the deny ends the
  policy, the input policy is not mutated, the command tail is preserved, and
  args without a generated policy are rejected.
