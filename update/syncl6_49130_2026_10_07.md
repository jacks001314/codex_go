### 1.4 判定：**机制性 N/A（无 Go 载体）**

**正向陈述**（不是「暂不实现」）：
1. Rust 这一笔的**唯一结构性前提**是「存在一个被 Sampling 与 RemoteCompactionV2 共用的 handler」；
   Go **没有**这一层（§1.3 ① 的 0 命中），且 Go **没有** remote compaction v2 的发送路径（§1.3 ②），
   因此「把 guidance 记录从 sampling 环搬进共享 handler」在 Go 里**没有可搬迁的目标**。
2. Rust 改后要求的两条可观测语义，Go **现状即满足**：
   - **(a) 仅采样路径记录**：guidance 分支在 `responses_stream.go` 的采样环内，非采样路径（compaction 等）
     根本不经过它 ⇒「keep remote compaction excluded」在 Go 以「无此路径」天然成立；
   - **(b) 在重试判定之前记录**：`:264` 早于 `:278` 的预算判定，且覆盖 HTTP 层错误
     （`isContentFilterStreamError` 走 `errors.As`，`runStreamingOnce` 把 HTTP 层错误一并回抛到同一分支）。
3. Rust 换 `StepContext` 的动机是「handler 需要 `settings.model_info` 解析 **model 专属** guidance」；
   Go 的记录点在 `contentFilterGuidanceInputItem(request)`（`responses_stream.go:1343-1350`）里
   已从 catalog 的 `ModelMessages.ContentFilterGuidance` 解析 model 专属值（含 `ResolveContentFilterGuidance` 回退）。
⇒ **移植收益 = 0，且额外引入无行为收益的热路径重构**，故判 N/A，不落地。

**可复跑**：把 §1.3 的 5 条命令在 `6315c3a7` 上重跑即可复现（输出与上文逐字一致）。

### 1.5 披露（**另项**，需你裁定，不在本单改）

Go 的 **ws 采样路径**（`model/responses_agent.go:972 runWebSocket`，仅由 `appserver/guardian_reviewer.go:311` 触发）
在 content-filter 上**不记录 guidance、也没有 stream 重试预算**（§1.3 ④⑤）：`runWebSocket` 只在
「未收到任何事件前」做一次 transport 重试，其余失败直接返回，由 guardian 侧回落到 HTTP `Run`。
判读：这不是 `#49130` 引入的差（`#49130` 前后 Rust 的 ws 都走 turn.rs 的采样环 ⇒ 都已记录），
而是 **`#49119` Go 落点的残余面**，且修它需要先定「Go 的 ws 采样要不要有 stream 重试环」这一**架构问题**
（无重试环时单独记录 guidance 无可达消费者），**且落点在 `model/` + 触发面在 `appserver/`（避让面）**。
⇒ 建议登记为新项（需架构决策），本单不动、不扩范围。
