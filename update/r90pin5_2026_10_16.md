## ① 步骤 1：修好空跑的守卫（`appserver/schema_test.go`）

### 缺陷
`schema_test.go:833`（51fdcd03）的 `rustMethodsFromCommon` 用正则
```go
`Method[A-Za-z0-9_]+\s+Method\s+=\s+"([^"]+)"`
```
那是 **Go 风格常量** 的形式，而 `app-server-protocol/src/protocol/common.rs` 里的方法是宏变体 `Ident => "method"` ⇒ 实测在 common.rs 上命中 **0** ⇒ `TestRustProtocolMethodSurfaceIsCoveredByGoSchemas` 的 `rustMethods` 恒为空 ⇒ **永远 PASS**（空跑）。

### 修法（两处，均在 P-b5 授权面内）
1. `schema_test.go:828` `rustMethodsFromCommon` 改成正则
   ```go
   `(?m)^[ \t]*(?:#\[experimental\("[^"]+"\)\][ \t]*)?[A-Za-z0-9_]+[ \t]*=>[ \t]*"([^"]+)"`
   ```
   —— 同时认 `#[experimental("...")]` 前缀变体与 stable/notification/server 变体；**保留 `t.Fatalf` 报 missing（fail-closed），未降级为 `t.Logf`、未放宽为子集判断**。
   另加两条**加强**（非放宽）：
   - `if len(values) == 0 { t.Fatalf("parsed no Rust protocol methods from %s", path) }` —— 杜绝再次空跑；
   - `return dedupeSortedStrings(values)`（同 package 既有 helper，`rust_protocol_surface_test.go:340`）。
   精确性实测：该形态在 common.rs 全文件命中 **270** 条，其中位于四个 `*_definitions! { … }` 宏块 **外** 的 = **0** ⇒ 全文件匹配即精确，不会误报。
2. `schema_test.go:279-288` `covered` 追加 Go 的 **TypeScript-only** 两个面（`typeScriptLegacyClientRequestMethods()` / `typeScriptOnlyNotificationMethods()`）。
   依据：队长已判定 `getAuthStatus` / `getConversationSummary` / `gitDiffToRemote`「由 `typeScriptLegacyClientRequestMethods()` 覆盖，不是缺口」；同理 `rawResponse/completed` / `rawResponseItem/completed` 由 `typeScriptOnlyNotificationMethods()` 覆盖。守卫问的是「该 Rust 方法在 Go 有没有面」，故应计入——**不是放宽断言**，`missing` 仍走 `t.Fatalf`。
