# Round 1227: Prepared native cleanup and desktop home/cache removal (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#42342,
`package_lifecycle/cleanup.rs`; #42375; #45550).

## Context

Uninstall cleanup must delete owner-scoped desktop data while the sandbox
accounts stay disabled, and it must never delete a reinstalled app's home or
runtime cache. The decision needs the owner's impersonated token, the pinned
home, the package repository, and a prepared native cleanup phase that keeps
the machine-wide setup lock.

## Preparation

`sandbox/windowssandbox/uninstall_prepared_windows.go` exposes the two-phase
native cleanup Rust publishes as `PreparedWindowsSandboxCleanup`:

- `PrepareSandboxCleanup` takes the setup lock, disables both sandbox
  accounts, waits for their processes and logon tokens, and restores the
  original flags if preparation fails.
- `Finish` re-validates each captured account (same SID, still disabled),
  removes only the pinned sandbox directories, runs the desktop callback while
  the accounts remain disabled, and removes WFP/filter/firewall/hidden-user
  entries before the accounts and group.
- `Release` only drops the lock (Rust `Drop`); a failed `Finish` may be
  retried with the same identities.
- `ResolveAccountSID` exposes Rust `resolve_sid` so retained homes can drop
  the deleted sandbox group's ACEs.

## Cleanup orchestration

`windowsandboxservice/cleanup_windows.go` ports
`package_lifecycle::cleanup::clean_up`:

- Logs `EVENT_CLEANUP_STARTED`, removes the registered runtime metadata before
  native account deletion, then finishes native cleanup.
- Keeps the home and its ancestors pinned until the desktop callback starts;
  only a guarded home becomes the native `codexHome`.
- Skips every desktop directory when the owner reinstalled the app
  (`owner_allows_cleanup`), when no desktop installation record exists, or
  when the home was never pinned.
- Under owner impersonation, removes the desktop-created home only when the
  owner's `uninstall_codex_home` preference allows it; otherwise it preserves
  the home, revokes the sandbox group's ACEs, and prunes only an empty home
  after native retries.
- Pins the cache home only for cleanup, removes `codex-runtimes`, drops the
  cache root pin, and prunes the cache home only when empty.
- Collects independent desktop failures, reports each at
  `EVENT_CLEANUP_DETAIL`, and finishes with the Rust pending/finished event.

`windowsandboxservice/registered_uninstall_windows.go` adds
`ownerAllowsCleanup` (package repository, retaining registration, current
package full name), `RuntimeOwnerRemoved` and `runtimeOwnerHasPackage`.
`windowsandboxservice/package_identity_windows.go` captures the OEM preinstall
marker from the installed package location.

`Lifecycle` now keeps the uninstall flag, the captured preinstall default, and
the home guard separate from the ancestor pins, so releasing the guarded home
mirrors Rust's `directory_guard.take()` + `directory_handles.pop()`.
