# #41209 Align deny-read matching with executor path semantics

## Upstream change

Rust prepares deny roots and glob matchers from `PathUri` context, expands
executor-home patterns, folds Windows globs case-insensitively with normalized
separators, preserves byte-oriented POSIX matching, and fails closed for
malformed paths, incompatible conventions, unresolved home, or invalid globs.

## Go carriers

- `sandbox.ResolveFileSystemEntryAccess` materializes globs against cwd and
  lowercases both pattern and target on Windows while leaving POSIX byte
  comparisons intact.
- `sandbox/integrity.PreparePolicy` expands `~/` and `~\\` against the executor
  home and returns `ErrInvalidPolicy` when home/glob resolution fails.
- `ReadDenyMatcher.IsLocalPathReadDeniedWithCanonical` checks the alias and the
  canonical target so either spelling enforces the deny.
- Windows deny-read ACL discovery uses the lexical case-insensitive scan.

## Verification

- `go test ./sandbox/integrity ./sandbox ./sandbox/windowssandbox -run 'DenyRead|ReadDeny|PolicyHome|Glob' -count=1`
