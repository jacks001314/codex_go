## What changed

Rust's `ConfigManager` keeps the config server's managed-configuration loader
and its refresh worker for the app-server's lifetime, so `config/read` observes
a rewritten managed file or a refreshed fetched bundle without a restart. Go
loaded the bundle once per run and kept the startup snapshot forever.

- `Config` now remembers the `CloudConfigLoader` it was resolved from
  (`CloudConfigLoader()`), and `app` hands it to the runtime router, which
  installs it on its `ConfigService`.
- `ConfigService.Read`/`ReadDefaults` re-read `requirements.toml` and the
  app-server managed config path before computing the layer stack
  (`refreshManagedConfigFromFiles`). A host-installed `SetManagedLayers` stack
  wins over the file refresh.
- `readResponseForLayers` merges the loader's latest enterprise-managed bundle
  and requirements on every read (`applyCloudConfigBundle`) starting from the
  freshly reloaded file requirements, so repeated reads never compound policy.
- The refreshed bundle must still come from the configuration server the local
  requirements select; `ValidateAppliedConfigServer` rejects a swapped
  endpoint before any value is applied (Rust `runtime_refresh`).
