## The gap

Round 1294 hid the image-detail surface but left the preparation path on the
detail-based budget. Rust selects the mode per sampling model in
`Session::prepare_conversation_items_for_history`:

```rust
let image_preparation_mode =
    if unified_image_budget_enabled(&turn_context.config.features, model_info) {
        ImagePreparationMode::UnifiedBudget
    } else {
        ImagePreparationMode::DetailBased
    };
```

`resize_image` then ignores the per-image hint for `UnifiedBudget`, always loads
with `PromptImageMode::ORIGINAL_DETAIL` (6000 max dimension / 10000 patches),
never rejects `low`, and writes back `detail = Some(Original)` as a
compatibility hint that Responses Lite strips before sending.

Go prepared every request image with `HighDetailLimits` unless the image itself
asked for `original`, and rejected `low`, so a unified-budget model still got
2048/2500 resizing.

## What changed

- `eventmap/image_prep.go`: `ImagePrepMode` (`DetailBased` / `UnifiedBudget`)
  plus `PrepareImagePrepImageWithResultMode` and
  `PrepareImagePrepImageWithStoreResultMode`; the unified mode forces the
  original-detail budget and skips the low-detail rejection. Existing
  detail-based entry points delegate, so callers and tests keep their shape.
- `model/agent.go`, `model/responses_agent.go`: `AgentRequest.UnifiedImageBudget`
  selects the preparation mode, and a unified-budget image gets the
  `detail: original` compatibility hint (already stripped for models that
  cannot request original detail by #44249).
- `turn/runtime.go`, `turn/agent_loop.go`: the Code Mode visibility options are
  now the shared `UnifiedImageBudget` / `UnifiedImageBudgetForModel`; the runtime
  threads them onto `AgentLoopRequest` and every sampling step sets
  `AgentRequest.UnifiedImageBudget` from that model.
- `appserver/runtime_router.go`: one `resolveUnifiedImageBudget` feeds the Code
  Mode description, the view_image surface and the sampling request.
