## Context

Registering the app package for both managed accounts is the step that turns a
recorded owner into a launchable runtime. It runs inside the owner's logon
session, can outlive a client timeout, and fails for many distinct native
reasons, so the service must retain resources until Windows finishes and must
report the deployment phase, HRESULT and activity ID that explain a failure.

## Registration surface

`windowsandboxservice/winrt_async_windows.go` adds the asynchronous part of
the WinRT ABI: `IAsyncInfo` status and error code, `GetResults`, and the
`IDeploymentResult` diagnostic getters (extended error code and activity ID).
`Retain` drops every reference without releasing it, so a registration that is
still running when the service stops keeps its objects alive until the process
exits, mirroring Rust's `std::mem::forget`.

`registered_packages_register_windows.go` calls
`IPackageManager2.RegisterPackageByFullNameAsync` with
`DeploymentOptions::None` and no dependencies, and ports
`registration_result.rs`:
`registrationResult.check` keeps `GetResults` failure, a missing extended
error code and a failed getter distinct from a deployment failure, and reports
`status`, `async_error`, `activity_id` and the phase in one context.

## Provisioning transaction

`ProvisionRegisteredRuntime` ports `registered_runtime::provision`:

- Both accounts are logged on through the owner-pinned secrets directory,
  validated against the recorded SIDs and their profiles loaded.
- An account with no recorded SID may not already hold a package from this
  family.
- Both exact SIDs and their alias paths are persisted before either
  registration or metadata grant, and a still-valid launch receipt is kept when
  the accounts, alias paths and packages all match.
- Each missing package is registered as its own account, polled to a terminal
  status every 50 ms while honoring shutdown (returning
  `ErrRuntimeSetupInterrupted` with the operation and profile retained),
  checked through `registrationResult`, and verified by querying the package
  repository again.
- Metadata access is granted, the profile unloaded and the logon token closed
  per account, and the ready package is committed only after every account
  succeeds.

`CredentialsNeedRepair` ports `credentials_need_repair`: a credential
mismatch asks for full setup only after both recorded SIDs still match their
accounts and an unrecorded account has no foreign registration; every other
logon or validation error is returned unchanged.

## Known gaps

`provisioning/registered.rs::run` (setup lock, group-generation check,
refresh-only admission, `provision_sandbox_in_process`) is not wired into
`RunProvisioning` yet, so the registered path still answers "not available in
this build". `registered_runtime/removal.rs`, native packaged cleanup, uninstall
observation and the `OwnerRemoved`/`RegistrationInterrupted` stop reasons
remain open.
