### 2.1 附：相邻残项（**不是** `#50389` 的机制，需你裁定）

Go 唯一会「吞键」的导航路径有一个**既存**的相邻差异：`applyTranscriptNavigationKey`（`tui/tea/model.go:8328`）在派发链中位于 `composer.submit`(`:3063`)/`composer.queue`(`:3076`)/`chat.*`/`editor.*` **之前**，且不查 keymap ⇒ 用户把某个 active 动作**显式配置**到 `page-up/page-down/home/end` 时，Go 会去滚动 transcript 而不执行该动作。

值级探针（`-overlay`，测试只在 `/tmp/probe50389/`）：
```
default page-up: offset 155->151 composer="hello there"                       # 默认滚动 ✔ 与 Rust 一致

        # ⇒ Go 吞掉快捷键去滚动；Rust（#50389 前/后均如此）会交回 app ⇒ composer 提交 ⇒ 值级分歧
configured composer.submit=ctrl-space, pressed ctrl-space: offset 155->155 composer="hello there"
        # ⇒ 键位不可表示（ctrl-@ vs ctrl-space），既未提交也未滚动 ⇒ 另一处、另一条 PR 的缺口
```
- 最小落点（**若**立项）：`tui/tea/model.go` 的 `applyTranscriptNavigationKey` 或其调用点（`:3023` / `message_router.go:93`）——在消费导航键前，先判断该键是否被**显式配置**（`codextui.KeymapConfig.HasCustomBinding`/`Binding`，`tui/keymap_config.go:94/109`）给某个 active 非 pager 动作；若是则不消费、交回后续派发。
- 撞避让面检查：落点在 `tui/tea/model.go`，**不**在禁碰清单（`tui/state.go` 不涉及）⇒ 无撞面。
- 但它是**先于** `#50389` 就存在的 Go↔Rust 差异（Rust 该分支在 #50389 前后行为相同），因此**不建议**挂到 `#50389` 名下，请单独裁定是否立项。
