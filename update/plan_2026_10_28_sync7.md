## Landed this round

### `#55297` + `#55298` - responses API proxy federated authentication

Ported semantics from `responses-api-proxy` `auth.rs`, `github_oidc.rs`, and the
generalized stdin credential reader:

- `responsesProxySubjectTokenSource` supplies a fresh JWT for each exchange;
  `responsesProxyGithubOIDC` obtains one from the GitHub Actions OIDC endpoint.
- `responsesProxyFederatedAuth` exchanges a subject token for an OpenAI access
  token with the token-exchange grant, serializes concurrent exchanges with a
  mutex, caches the credential, and renews proactively (10% skew capped at 60
  seconds) while bounding both the relative and absolute lifetimes.
- The cached credential is discarded before a fallible exchange and is never
  reused after a failure.
- Token requests disable redirects, bound the connect timeout at 10 seconds and
  the request at 30 seconds, cap token and response sizes (16 KiB / 64 KiB) and
  the serialized exchange body (64 KiB), and keep diagnostics free of
  credentials, request URLs, and response bodies.
- GitHub OIDC request URLs must be HTTPS without user info or a fragment, and
  the audience parameter is replaced while other query parameters are
  preserved. The stdin request credential uses the RFC 6750 bearer alphabet
  (JWT periods allowed) and a bounded 16 KiB read.
- The proxy now resolves the `Authorization` header per request through
  `responsesProxyAuth`; API keys keep the default redirect policy and federated
  credentials disable redirects on the upstream client.

  primitives only.

## Blocked assessment: `#56000` + `#55994`

Rust adds a Windows-only proxy authentication tunnel built on libcurl
(`Easy2`, `gssnegotiate`/`ntlm`, SSPI), returning an authenticated connection
with buffered data preserved, plus named-pipe bridging into the route-aware
HTTP client pool and TLS configuration for HTTPS proxies.

Go's `net/http` exposes no hook that can replace the transport's `CONNECT`
tunnel after a `407`; `OnProxyConnectResponse` can only inspect the response,
and `DialTLSContext` is not used for proxied HTTPS requests. A faithful port
would require a new `RoundTripper` for every HTTP, HTTPS, streaming, and
WebSocket path plus a pure-Go Negotiate/NTLM/SSPI implementation. This is a
structural incompatibility, not a scheduling deferral, and is recorded here
instead of being silently skipped.
