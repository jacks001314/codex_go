## 4. 契约变更 vs 回归（显式标注）

**这是契约更新，不是回归。** 旧契约「tail flush ⇒ 路由成一个 turn（有活动轮则 steer）」在 Rust 侧由 #50531 明确废弃，Go 侧忠实跟随。

| | 旧行为（改动前） | 新行为（改动后） | 观测点 |
|---|---|---|---|
| 空闲线程收到 tail | `handleTurnStart(<ack prompt + transcript_delta>)` ⇒ 模型被调用、产生一个 running turn | 记入会话历史 + 一个**已完成**历史轮；**无** running turn、**无**模型调用 | 新增 `TestRealtimeTranscriptTailFlushRecordsHistoryWithoutInferenceLikeRust` |
| 活动轮收到 tail | `handleTurnSteer(...)` ⇒ 落一条 `metadata.steered=true` 的 steer item（会让活动轮多一次采样输入） | 以 `metadata.kind=realtime_transcript_tail`、`turnId=<活动轮>` 落入该轮历史；**无** steer item | 新增 `TestRealtimeTranscriptTailFlushJoinsActiveTurnWithoutSteeringLikeRust` |
| delegation 线格式 | tail 走 `<realtime_delegation><source>transcript_tail_flush</source>…` | 该 wire 形式**不再产生**（handoff 的 delegation 线格式不变） | 生产代码已无调用者 |

**你没有说错却也没有需要改的既有测试**：队长点名的 `TestV3BatchesCodexOutputRoutesBEMAndFlushesTranscriptTail` 位于 `realtime/realtime_test.go:948`（**realtime 包**），它只断言 realtime manager 会**发出** `transcript_tail.flush` 事件（`realtime/realtime_test.go:1042`），并不涉及 appserver 的路由决策。改动后它仍 PASS（`go test ./realtime/ -count=1` → ok 3.103s），**故未修改**。旧的「路由成轮」行为此前**没有任何 appserver 级断言**（`git grep -n 'transcript_tail' -- '*_test.go'` 在改动前仅命中 realtime 包两处、`git grep -n handleRealtimeEvent -- '*_test.go'` 仅命中 `handoff.requested`），新契约由本次新增的两条测试固化为唯一权威断言。
