## Goal

Audit Rust #49257 (`4f16bdc265`): allow Guardian cached approvals when retained
root context is incomplete. Missing retained root instructions must stay visible
to the classifier, but only the thread's own retained-context completeness may
veto a matching low-risk cached score.

## Finding

Go already implements the post-#49257 predicate:

- `appserver/guardian_serving_assessment.go` derives
  `ServingAuthorization.RetainedContextComplete` solely from the thread's own
  retained context (`VerifiedAnswersComplete`, `UserMessagesComplete`,
  `HasOmittedAssistantMessages`). Root evidence never enters the serving
  authorization.
- `state.ServingAssessment.AllowsSynchronousReviewSkip` therefore compares local
  completeness, the user-message revision, the environment/denied paths and the
  policy fingerprint - never root completeness.
- Root omissions are rendered into the review prompt as
  `RootMessageIncompleteRootInstructions`, so the classifier still sees them.

The audit therefore adds regression coverage rather than new behaviour.

## Tests

- `appserver/guardian_root_incomplete_cached_approval_like_rust_test.go` mirrors
  Rust's extended `confirmed_root_delivery_invalidates_root_and_worker_cached_approvals`:
  a matching low-risk assessment with complete local context approves even
  while the root authorization carries the omission notice, the notice text
  keeps its "do not treat the remaining root evidence as complete
  authorization" warning, and an incomplete local retained context still forces
  a fresh review.
