## Goal

Audit #42071 (detect Vite+-managed Codex installs) and close the remaining Go
gap in the published npm shim.

## Findings

- Go already modelled Vite+ installs before this audit:
  `install.InstallVitePlus`, `install.UpdateActionVitePlusGlobalLatest`
  (`vp install -g ...`), `install.Current`/`FromExe` reading
  `CODEX_MANAGED_BY_VITE_PLUS`, the `doctor` install rows, and the TUI update
  action all match Rust's observable behaviour and have tests
  (`install/context_test.go`, `install/update_test.go`, `doctor/doctor_test.go`,
  `tui/updates_parity_test.go`).
- The real gap was `npm/codex/bin/codex.js`: it only recognised pnpm, bun, and
  npm, so a Vite+-owned install was reported as npm and update hints suggested
  the wrong command.
- Vite+ owns a global install through
  `packages/@jacks001314/codex-go.json` and records the install ID either as a
  `#`-suffixed package directory (older layout) or as a subdirectory of the
  package prefix (newer layout). Ownership must be checked before pnpm because
  both layouts can expose the same package through ancestor `node_modules`
  directories.

## Implementation

- Added `npm/codex/bin/package-manager.js` as the shim's single source of truth:
  - `isVitePlusOwnedCodexInstall` verifies the metadata name and resolves both
    install-ID layouts against `lib/node_modules` and `node_modules`.
  - `detectPackageManager` searches ancestors of the canonical package root and
    lexical entrypoint, checks Vite+ before pnpm, then falls back to bun/npm
    user-agent heuristics.
  - `updateCommandFor` and `managedByEnvVarFor` centralise the `vp install -g`
    command and the `CODEX_MANAGED_BY_VITE_PLUS` marker.
- `npm/codex/bin/codex.js` now imports the module, uses `updateCommandFor` in
  the missing-optional-dependency error, and clears
  `CODEX_MANAGED_BY_VITE_PLUS` before setting the detected marker.
- `npm/codex/package.json` ships `bin/package-manager.js` in `files`.
- Publishing note: `.gitignore` ignores `bin/`, so shim files are added with
  `git add -f`, matching the existing `codex.js` entry.
