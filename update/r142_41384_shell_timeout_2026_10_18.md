# Rust #41384: configurable thread shell-command timeouts

Upstream commit: `e4d0ba4e927363f695bb8d0fef187fd229700657`

## Result

Implemented, with Rust-compatible expiry reporting added.

- `ShellCommandParams.timeoutMs` is optional; omitted or null keeps the
  one-hour default, zero requests an immediate timeout, larger values are
  allowed, and negative values are rejected before execution.
- The timeout is applied to the command context in a background goroutine, so
  the RPC acknowledgement is immediate.
- On expiry the command item now reports status `failed`, exit code `-1`, and
  `Timeout` in the aggregated output, matching Rust's user-shell task rather
  than command/exec's historical `124` code.
- A standalone timeout completes its own turn; an auxiliary timeout leaves the
  active turn running and emits no turn completion.
