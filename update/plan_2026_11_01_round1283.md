## Advanced this round

`codex-rs/core/src/code_mode_host.rs::LocalServerOutputProvider` is a thin
`CodeModeSessionProvider` wrapper that forces `output_truncation: Server` for
default sessions and passes explicit options through. It also forwards every
other provider capability, including `sample_process_metrics`:

```rust
fn sample_process_metrics(&self) -> ... {
    self.inner.sample_process_metrics()
}
```

Go's `codemode.LocalServerOutputProvider` forwarded availability, prewarm and
close but not `SampleProcessMetrics`. Because
`appserver/runtime_router.go:2000` discovers the capability with a type
assertion on `services.CodeModeProvider`, enabling
`code_mode_host_output_truncation` (#58159) silently downgraded #57841 host
observations from a real snapshot to `Unsupported` whenever the built-in
provider was a gRPC host:

- `code_mode_host_grpc` + `code_mode_host_output_truncation` on:
  `newRuntimeCodeModeProcessProvider` wraps `GrpcProcessProvider`, the router
  type-asserts the wrapper, fails, and answers `Unsupported`;
- `exec/exec.go:1555` builds the same wrapper for the non-router path.

Rust answers a snapshot in exactly that configuration (`ProcessOwnedGrpcCodeModeSessionProvider::sample_process_metrics`).

## What changed

- `codemode/local_server_output.go`: `LocalServerOutputProvider` implements
  `SampleProcessMetrics`, forwarding to the inner provider when it is a
  `tool.CodeModeProcessMetricsSampler` and answering `Unsupported` otherwise
  (Rust's trait default).
- Tests: `codemode/local_server_output_metrics_like_rust_test.go` asserts the
  sample is forwarded unchanged (one inner call, snapshot kind and process id)
  and that a provider without a sampler reports `Unsupported`.
- `parity/commits.json`: #57841 and #58159 carry the wrapper-evidence.
