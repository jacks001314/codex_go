## Feedback upload transport (#41569, #42096)

`appserver/feedback_upload.go` ports Rust's `codex-feedback` upload path:

- Envelopes are serialized as the Sentry wire format (header line, per-item
  header with `length`, payload, newline) and gzipped at `BestSpeed`; an envelope
  that does not shrink is sent raw with its decoded size still accounted for.
- `POST {dsn}/api/{project}/envelope/` carries `X-Sentry-Auth` and, for compressed
  bodies, `Content-Encoding: gzip`. Redirects are not followed and the transport
  never logs request bodies.
- Size limits: the event envelope stays under 1 MiB decoded, each attachment and
  its envelope under 200 MiB decoded, matching Rust's `MAX_EVENT_BYTES` and
  `MAX_DECODED_UPLOAD_BYTES`.
- `Retry-After` accepts integer seconds or an HTTP date, and
  `X-Sentry-Rate-Limits` only counts `error`/`attachment` categories (an empty
  category list applies to every item).
- The report event is accepted before any attachment is read; attachments are
  uploaded one whole envelope at a time, linked to the accepted event id. Any
  attachment failure surfaces as Rust's
  `feedback report was accepted, but some attachments failed to upload`.
- Events are never replayed; attachments retry at most twice (250 ms, 500 ms)
  with the exact same bytes, and everything shares one five-minute deadline.
  A quota, a deadline overflow, or a 429 without `Retry-After` marks the report
  rate-limited so later files are skipped rather than bypassing the limit.
- `feedback/upload` admits three concurrent uploads and answers a fourth with the
  overloaded code `-32001`; `feedback.enabled = false` is rejected with Rust's
  `sending feedback is disabled by configuration`. A permit is held for the whole
  upload, not just the RPC waiter.

Verification: `go test ./appserver -run 'Feedback' -count=1`. The full package
still reports only the four pre-existing file-change/analytics timeouts.

## exec fixtures on the HTTP transport

The `codex exec` tests that point the built-in OpenAI provider at a plain
`httptest` server were failing with `responses websocket handshake failed: HTTP
200`. Rust's own fixtures pin a mock provider with `supports_websockets = false`
because `[model_providers.openai]` only accepts `model_catalog_url`; Go has no
such switch for the built-in provider. The fixtures now answer a WebSocket
upgrade with `426 Upgrade Required`, which is the only handshake status both
implementations treat as "HTTP only" and fall back on, so the tests keep their
default-provider intent and exercise the real fallback. `go test ./exec
-count=1` passes in full.
