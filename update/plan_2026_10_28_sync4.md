### `#55653` (`87f3c3284e`) - code-mode cell lifecycle and result buffering

Ported semantics:

- `RuntimeResponse.Result` carries the buffering duration; `result_buffered_for_ns` is optional/default zero for older hosts, always emitted for `Result`, and never emitted for `Yielded`/`Terminated`.
- `WaitOutcome.ResultBufferedFor()` returns `(duration, true)` for a live `Result` (including zero) and `(0, false)` for `Yielded`, `Terminated`, `MissingCell`, and nil.
- Cells record `CompletedAt`; `CellStore` has a pluggable clock (`SetClock`/`Now`) so buffering is measurable with a paused clock.
- A wait that retrieves an already completed result reports the elapsed buffering time; immediate delivery reports zero.
- Termination that claims an already completed cell returns the buffered `Result` instead of `Terminated`.
- The stdio host, remote provider, and local/remote `exec` tool paths carry the measurement into tool output.

Files:

- `codemode/protocol_types.go`
- `codemode/codemode.go`
- `codemode/session_runtime.go`
- `codemode/stdio_host.go`
- `codemode/remote_provider.go`
- `tool/code_mode_exec.go`
- `codemode/observation_yield_test.go` (adjusted: termination of a completed cell may now report `Result`)

Tests:

- `codemode/result_buffered_like_rust_test.go`
- `tool/code_mode_result_buffered_like_rust_test.go`
- `codemode/cell_complete_terminated_like_rust_test.go` (race regression added this round)

Two Rust surfaces are intentionally not mirrored:

- **gRPC buffering metadata**: Rust adds `code-mode-result-buffered-for-ns` to gRPC response metadata. Go's remote code-mode transport is a JSON-framed stream over the generic transport, so the same field travels inside the response payload; there is no separate metadata RPC to extend.
- **`CodeModeCellTiming` contributor notifications**: Rust emits `ExecYielded`, `WaitFinished`, and `CellUnavailable` through its extension-contributor API. Go has no extension-contributor registry; the same lifecycle is observable through `CellStore` and the tool output `Data` map.

Race fix (this round): `CellStore.Complete` used to overwrite a cell that a concurrent termination had already marked terminated, so the termination caller saw `Terminated` while a later `Wait` saw `Result`. `CellStore.CompleteIfRunning` now performs the phase check and the completion under one store lock (Rust's single linearization point), and `completeCellFromEngine` uses it.

### `#56313` (`e103bbc06f`) - catalog overrides for history, notes, and context tools

Ported semantics:

- `ToolMessages` gains `history`, `notes`, and `context_management` entries (`HistoryToolMessages`, `NotesToolMessages`, `ContextManagementToolMessages`).
- History and notes support a catalog `namespace_description`, including explicit empty and whitespace values.
- Per-tool descriptions and parameter schemas apply independently. An invalid schema, or one that drops a bundled encrypted property, keeps the bundled schema.
- Tool identity, parallelism, namespace, and transport stay harness-owned.
- `new_context` and `get_context_remaining` read their catalog entries per turn, so switching models rebuilds the specs.
- Sparse catalog entries serialize without empty sub-objects.
