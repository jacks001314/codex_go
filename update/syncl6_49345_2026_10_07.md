## 9. ⚠️ 裁剪披露 2：GPT-6 家族的**基线缺口**（需队长裁定，非本补丁引入）

**事实**：Go 仓**不跟踪** `models-manager/models.json`（`git ls-tree -r origin/main | grep models.json → 空`），故 `BundledModelsResponse()` 恒走 `fallbackBundledModelsResponse()`（探针输出 `BUNDLED slugs=7`，只有 gpt-5.6-sol / gpt-5.6-terra / gpt-5.6-luna / gpt-5.5 / gpt-5.2 / gpt-5.4-mini / codex-auto-review）。

**后果**：Bedrock 目录里 `gpt-6.1-sol / gpt-6-astra / gpt-6-sol / gpt-6-luna` 四个 slug **在 bundled 里不存在** ⇒ `bundledModelBySlug` 走通用占位（`SupportedReasoningLevels=[]`）。

- 改动前：被 `normalizeBedrockCatalog` 强制成 `mav="v1"`（**遮住了缺口**）。
- 改动后：按 Rust 语义**保留**，这四个条目 ⇒ `mav=""`（Rust 是 `v2`）。

也就是说，**这 4 个 slug 的绝对版本值在 Go 侧本来就不等于 Rust**（改前 `v1` ≠ Rust `v2`，改后 `""` ≠ Rust `v2`），本补丁只是把「强制值」换成「保留值」这套 **Rust 结构**；真正要补齐绝对值得先把 GPT-6 家族补进 Go 的 bundled 目录 —— 那**属另一条工作**（`fallbackBundledModelsResponse` 目前有意「可能落后于 bundled slug」，见 `catalog.go:1217` 注释），本单**未动**以免扩范围 + 波及 `tui/`、`app/` 的模型选择器测试。

**建议**：新立一条「把 `models-manager/models.json` 的 GPT-6 家族（4 条）补进 Go fallback bundled 目录」的候选（那会让本补丁对 gpt-6* 直接等于 Rust 的 `v2`），**请队长裁定**。同时：

- `#49369`（1 文件，`Update Bedrock GPT-6 Sol catalog tests to expect multi-agent V2`，sha `2a34aef79484bf769b4b225f3f595755f2962170`，纯测试 4 行）判 **N/A（Go）**：它把 `gpt-6-sol` 的期望从 V1 提到 V2，但 **Go 的 bundled 里没有 `gpt-6-sol`**，无法产生 V2 ⇒ 无对位断言（和上面同一个缺口）。
