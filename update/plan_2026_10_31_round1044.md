## Goal

Recover a deferred environment after a provisioning failure while preserving
the same environment instance, and report failed provisioning without starting
a connection.

## Findings

- Rust #42388 makes a valid Ready report replace a deferred environment's
  provisioning failure, keeps the first failure until Ready, and prevents a
  late failure from replacing Ready. Invalid Ready information still fails a
  Pending environment only.
- Go's `appserver.ProvisioningState` already implements the same state machine.
  `applyReady` moves any valid report to Ready and clears the failure;
  `applyFailure` preserves the first error and rejects a failure after Ready.
- `EnvironmentManager.StatusContext` reports Pending without dialing, maps a
  failed provisioning state to `Disconnected` with
  `environment unavailable: <error>`, and only attempts a connection after
  Ready.
- Rust's retry of a stale startup failure has no Go counterpart to fix:
  `EnvironmentManager` keeps no cached initial-client result and re-dials on
  each request, so Ready cannot be shadowed by an older published attempt.
- Existing regression tests cover failure recovery on the same instance,
  invalid Ready preserving the first failure, late failure preserving Ready,
  the no-connection failed status, and capability-root refresh after recovery.
