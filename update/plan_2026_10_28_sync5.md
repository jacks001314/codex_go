### `#55724` - shared prepared MCP tool definitions

Ported semantics:

- One normalized definition per `(server, tool, agent plugin, schema budget)` key is shared across turns and sessions while a caller still holds the tool, using Go's `weak.Pointer` so the cache does not extend its lifetime.
- The shared definition snapshots the tool info, applies the JSON-schema budget once, and degrades oversized agent-plugin schemas to `{"type":"object","additionalProperties":true}` once.
- `ToolExecutor.Spec()` returns a clone of the cached parameters, so a caller cannot mutate shared state or force a re-normalization on every call.
- Matching metadata reuses the entry; different schema budgets, agent plugins, or tool metadata create distinct entries; dead weak entries are pruned on a miss.

### `#56295` + `#56314` - customer-hosted managed configuration server

The Go port introduces the source split from `#56295` in the shape the existing loader supports and adds the `config_server` feature from `#56314`:

- `config.ConfigServer` / `ConfigServerOAuth` validate trusted settings: HTTPS base and OAuth URLs, no userinfo, fragments, or query on the base URL, a non-empty client ID, and a nonzero redirect port when specified. `BundleURL()` resolves `<base_url>/codex/config/bundle`.
- `[config_server]` is parsed as a local managed requirement (`ConfigRequirementsToml.config_server`), survives local requirement merging and cloning, and is dropped from cloud-managed requirement layers. `Config.RequiresRemoteConfig()` reports whether local administration requires a remotely delivered bundle.
- The bundle loader and snapshot carry the selected config server (`CloudConfigBundleLoader.WithConfigServer` / `ConfigServer`), matching Rust's `CloudConfigBundleSnapshot.config_server`.
- `CloudConfigFetchOptions` accepts an explicit `EndpointURL` and `CacheNamespace`; namespaced caches use Rust's `managed-config-<namespace>.json` name and the existing ChatGPT cache path is preserved.
- The config-server source scopes the cache to `sha256(json((bundle_url, credential_id)))` and uses the current OAuth grant identity (`authorization_id`, or `anonymous` without OAuth) as the cache identity.
- Bundle requests use a no-redirect client; a `401` triggers exactly one credential recovery per fetch (`GatewayAuthManager.RefreshAccessToken`), and a second `401` is reported as an authentication failure.
- Bootstrap validation errors are generic (`invalid cloud config bundle: invalid TOML` / `invalid requirements`) so delivered fragment contents, names, and IDs are not exposed.
- `app` selects the config-server loader before ChatGPT plan eligibility in the CLI sandbox, remote exec-server, MCP managed config, and app-server startup paths. App-server managed requirements come from the fetched bundle when a config server is configured.

Deliberate deviations / N/A:

- Go's provider OAuth manager has no request-scoped `OAuthSessionRequest` API yet (`#56036`). The loader therefore resolves a token without interactive login, records the token that was sent, and performs one recovery on `401`; the grant identity is persisted in `GatewayAuthManager`.
- `device_authorization_url` is validated but unused: Go's provider OAuth manager has no device-flow configuration surface.
- Go has no `validate_model_providers` equivalent in `config`, so only TOML/requirements failures use the generic validation messages.
- The app-server startup path fetches the bundle but retains a single startup snapshot; Rust's runtime requirement reload for a config server is not modeled beyond that snapshot.
