## Goal

Mirror Rust #41666 (`cefa060695`): the first `js` execution from a Node
REPL-backed server proceeds without waiting for the synchronous Guardian
review while its asynchronous classification continues. Setup and reset tools
must not consume the allowance, and every later execution follows the normal
Guardian policy.

## Implementation

- `model/catalog.go`:
  - `GuardianModelPolicy.InitialCUACall` reads the catalog's
    `initial_cua_call`.
  - `AllowsInitialCUACall` mirrors Rust
    `GuardianModelPolicy::allows_initial_cua_call`: an explicit value wins and
    an omitted value keeps the allowance only while computer use is adaptive.
  - `ModelInfo.AllowsInitialCUACall` exposes the policy for a resolved model.
- `appserver/guardian_reviewer.go`:
  - `guardianScoreProgress.jsExecutions` counts `js` executions separately from
    the score-lag tool-call counter; `observeNodeReplJSExecution` dedupes review
    retries by call id so one invocation consumes the allowance once.
  - `guardianInitialCUAExecution` accepts `mcp_tool_call` actions named `js` or
    `browser_js` whose server or connector is Node REPL backed
    (`mcp.IsNodeReplBackedConnector`), so `js_reset` and
    `js_add_node_module_dir` never match.
  - `Review` fast-approves the first such execution when the model allows it,
    before the serving assessment and full review, and records
    `codex.guardian_v2.fast_decision{decision=approved, reason=initial_cua_call}`
    plus the Guardian v2 fast-decision analytics event.
- `appserver/agent_runtime.go`: `guardianAllowsInitialCUACallForTurn` resolves
  the reviewed turn's captured model metadata (falling back to the runtime
  catalog) and feeds the reviewer's `allowsInitialCUACall` hook.
- `telemetry/metric_names.go`: adds the `codex.guardian_v2.fast_decision`
  counter name.

## Residuals

- Rust's async scorer publishes a cached score that its approval path inspects;
  Go's reviewer is synchronous and has no cached-score auto-approval, so the
  first-execution allowance is evaluated directly against the per-thread `js`
  execution count. The observable contract - only the first execution skips the
  wait, setup/reset never count, later calls use the normal policy - is the same.
- Rust's later `GuardianPolicyLoader::resolve` overrides (node_repl auto-review
  requirement and administrator requirements) belong to separate upstream
  commits; the Go model catalog already carries
  `node_repl_auto_review_required` through
  `guardianReviewNodeReplAutoReviewRequiredForTurn`, and required models keep
  the allowance only through this catalog policy.
- A full `go test ./appserver -count=1` still reports the unrelated pre-existing
  failures recorded in Round 1022.
