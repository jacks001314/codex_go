## 44658

Rust keeps Windows sandbox private desktops alive across helper exits:

- The caller selects and caches the desktop (per permission set), and the
  wrapper opens that name instead of creating a desktop that dies with the
  wrapper.
- `parse_windows_sandbox_wrapper_args` requires the desktop-name flag on every
  sandboxed invocation; `create_windows_sandbox_command_args_for_permission_profile`
  computes it in the caller and propagates preparation errors.
- Desktop selection uses the sandbox account and capability SIDs without the
  wrapper's filesystem ACL refresh.

Go already ported the desktop cache, the `--windows-sandbox-private-desktop-name`
round trip, the restricted-token and elevated selection paths, and the
`execserver` opt-in (Round 1181). The remaining deviation was that a wrapper
command line could omit the name and fall back to local selection.

Round 1205 closes it:

- `ParseWindowsSandboxWrapperArgs` now rejects a non-disabled wrapper command
  line without `--windows-sandbox-private-desktop-name`, matching Rust's
  required-flag check. The disabled level stays exempt because it runs the
  command directly and never touches a desktop (Go-only level).
- `app.runWindowsSandboxPlan` (`codex sandbox`) now sets
  `PreparePrivateDesktop: true`, so the long-lived CLI selects and caches the
  desktop and hands its name to the wrapper; `execserver/fs_helper.go` already
  did this.
- Builder errors from desktop preparation still propagate to the launch path,
  as Rust maps them into `SandboxTransformError::WindowsSandboxPreparation`.

Coverage: `sandbox/windowssandbox/wrapper_desktop_name_required_like_rust_test.go`
(rejects a name-less sandboxed command line, keeps the disabled level exempt),
plus the updated `wrapper_test.go`, `wrapper_environment_transport_test.go`
and `smoke_windows_test.go` fixtures that now carry a name or opt into
selection. Existing desktop tests (cache survives a separate wrapper process,
caller-owned desktop e2e, name round trip, invalid-name rejection) still pass.

Verified with `go build ./...`, `go test ./sandbox/... -count=1`,
`go test ./execserver -count=1` and `go test ./parity -count=1`. The `app` test
binary currently fails to compile because of a parallel agent's in-flight
`config.OrderedTable` change (unrelated to this round); `go build ./...`
covers the `app` production code.
