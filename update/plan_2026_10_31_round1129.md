## Findings

- #43529 moved managed daemon updater startup out of `bootstrap` and into every
  managed `start`/`restart` path, made updater failures warning-only, and
  preserved a running updater while installer publication may be mid-flight.
- Go already implements the same lifecycle in `appserverdaemon`:
  `LifecycleRunner.startWithFeatureOverrides` calls `ensureManagedUpdater` on
  both the socket-probe reuse path and the pid-backend reuse path, fresh starts
  and restarts call it after `waitUntilReady`, and remote-control restarts
  re-ensure it. Every failure is reported through `daemon.Diagnostic` without
  failing the lifecycle command.
- `ensureManagedUpdater` stops the updater only when auto-update is disabled or
  the latest-channel marker is gone. With the marker present but a release,
  resolved binary, or updater-probe mismatch, it returns success without
  stopping the existing updater, matching Rust's preserve-during-install rule.
  Repeated `start` reuses the running server and still re-ensures the updater.
- The Go repository has no `app-server-daemon/README.md` counterpart, so the
  Rust documentation-only edits do not port.
