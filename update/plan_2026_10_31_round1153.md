## Findings

- Rust #47635 starts the startup prewarm's websocket handshake before tool
  capture finishes, then sends `generate=false` with the captured step tools and
  finalized request metadata. Round 982 had already ported the routing hints,
  guardian omission, 401 recovery, and 426 HTTP fallback, but the startup warmup
  still carried no discovered tools.
- Go's startup prewarm runs at `thread/start`, before any turn performs MCP
  discovery, so the warmup had no tool snapshot of its own.
- `turn.Runtime.ModelVisibleToolDefinitions` already produces the exact
  model-visible declaration set a turn sends (including MCP and plugin tools),
  and `ResponsesAgentRunner.Prewarm` already builds the warmup through
  `buildResponsesAgentRequest`, so only the capture and its ordering were
  missing.

## Changes

- `appserver/session_startup_prewarm.go`: add `startupPrewarmToolProvider`,
  which builds the thread's turn runtime (including MCP/plugin discovery) and
  returns `ModelVisibleToolDefinitions` for the effective tool mode, and pass it
  to the base startup prewarm as `AgentRequest.PrewarmTools`.
- `model/agent.go`: add the `PrewarmTools func(ctx) []any` hook.
- `model/responses_agent.go`: start the capture in a goroutine before dialing;
  after the socket is up, wait for the tools (or the context) and rebuild the
  finalized Responses request so legacy models send a top-level `tools` array
  and Responses Lite models send `additional_tools` declarations.
- Tests: `model/prewarm_tool_capture_overlap_like_rust_test.go` proves the
  handshake completes before the provider returns and that both wire shapes
  carry the captured tool; `appserver/startup_prewarm_tool_capture_like_rust_test.go`
  asserts the provider returns the thread's discovered inventory.
