# Round 1159 audit plan (2026-10-31)

Candidate target: `cbe16d525c2d7362fc3d4726143288e932905daa`.

Gate sweep after rounds 1151-1158. No new upstream commits were needed to find
these defects; each surfaced by running the existing suite on a clean checkout
of `main` at `40e3daf3` and comparing against the Rust tree at the pinned
commit `cbe16d525c`.

## Findings and fixes

- `appserver/schema_test.go` still carried the protocol-export SHA-256 values
  from the `e8e6a922c0` anchor, while `55854a7a` had already re-vendored both
  `appserver/schema/precomputed/*.json.zst` files. The vendored bytes now hash
  to `13c9fd8b...` (stable) and `bd796192...` (experimental), exactly matching
  `app-server-protocol/schema/precomputed/` at the pinned Rust commit. Updated
  the expectations and the anchor comment.
- `appserver/appserver_v2_suite_manifest_test.go` was missing the Rust v2 suite
  helper module `https_mock` (declared in `tests/suite/v2/mod.rs`, shared by the
  config-server and web-search-routing cases). Added its manifest entry.
- `appserver/router.go:preparePaginatedForkHistoryBase` passed
  `r.store.Root()` (the `sessions` directory) to
  `StateRuntime.PreparePaginatedFork`, which appends `sessions` and
  `archived_sessions` again when validating the managed rollout root. Rust
  passes `config.codex_home`, so paginated forks of Rust-written rollouts were
  rejected with "must be in Codex home directory" on every platform where the
  store root is the sessions directory. Switched the call to the existing
  `codexHomeFromSessionStore` helper, matching every other router call site.
