## Advanced this round

`codex_code_mode::parse_exec_source`
(`codex-rs/code-mode-protocol/src/description.rs`) parses the optional first-line
`// @exec: {...}` pragma and returns its rejections straight to the model —
`execute_handler.rs` maps them with `FunctionCallError::RespondToModel` and no
prefix. Go's `tool.parseCodeModeSource` diverged in six ways:

- every error was wrapped as `invalid exec pragma: ...`, a prefix Rust never
  emits;
- an empty input reported a truncated message without the "Provide JS only,
  optionally with first-line ..." guidance;
- a pragma line without a JavaScript body was silently treated as plain source
  instead of `exec pragma must be followed by JavaScript source on subsequent
  lines`;
- an empty pragma (`// @exec:`) was accepted, and non-object JSON fell through
  to a Go decode error instead of Rust's "must be a JSON object ..." message;
- an unknown key was reported with `%q` quoting instead of Rust's backticks,
  and non-JSON text skipped Rust's "must be valid JSON ...: {err}" wrapper;
- the field-level rejections (negative, wrong type, above the JavaScript safe
  integer) used Go-specific wording instead of Rust's
  "exec pragma fields `yield_time_ms` and `max_output_tokens` must be
  non-negative safe integers: {err}" wrapper and the per-field
  "exec pragma field ... must be a non-negative safe integer".

Both code paths accepted the same inputs and produced the same cell, so this is
a message-level gap — but these messages are model-facing tool output, and the
TUI/app-server show them verbatim.

## What changed

- `tool/code_mode_exec.go`: `parseCodeModeSource` follows Rust's control flow
  (trim the first line, require a body, parse JSON with `UseNumber`, check
  object-ness, then keys, then fields) and emits Rust's literals; the executor
  returns the message unchanged. A `null` field stays absent, and an explicit
  `0` stays an explicit zero.
- Tests: `tool/code_mode_exec_pragma_like_rust_test.go` covers every branch
  above, the `0`/`null` distinctions, and asserts the executor surfaces the
  message with no prefix.
- `parity/commits.json`: no in-range commit introduced `parse_exec_source`
  (it predates `rustFromExclusive`), so this round adds no entry there.
