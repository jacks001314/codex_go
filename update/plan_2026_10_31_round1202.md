# Round 1202: host-inherited execution policies (2026-10-31)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6 (#58406).

## 58406

Rust lets a trusted host transport a managed session snapshot:

- `StartThreadOptions::set_inherited_thread_instructions` makes the captured
  text replace the destination thread provider (empty text clears it).
- `StartThreadOptions::set_inherited_exec_policy` installs a point-in-time
  policy plus its source requirements, but only on a managed-only destination
  whose managed requirements match and are still preserved.
- `Policy::preserves_managed_requirements` checks managed rules verbatim, host
  executable mappings, absolute-path amendments that could weaken a basename
  restriction, and managed network denials.
- Isolated sessions reject inherited startup settings and a local manager cannot
  be combined with a transported policy.

Go mirrors the parts that have carriers:

- `execpolicy.PreservesManagedRequirements` ports the preservation check:
  identical host executable mappings, every managed prefix rule present
  verbatim for the same program, absolute-path amendments evaluated with
  `canWeakenFallback` against the managed basename rules (including the
  existing exact-denial overlap cases), and managed network denials present in
  the snapshot. `compiledNetworkDomains` mirrors the later-rule-wins domain
  compilation.
- `execpolicy.InheritedExecPolicy` + `InheritedExecPolicyDestination` +
  `InstallInheritedExecPolicy` mirror `ExecPolicyManager::from_inherited`: the
  managed-only destination gate, requirement compatibility (rule fingerprint,
  network rules, host executables), the preservation gate, and an independent
  `Policy.Clone` for the new manager.
- `RuntimeRouter.installInheritedChildExecPolicy` installs the prepared child
  context’s transported policy for the reserved child before the start, and
  `managedCommandPolicyForThread` uses it as that thread’s base policy (the
  destination requirement still applies to threads that inherit nothing).
  Environment attachments continue to tighten it. Teardown discards the
  installed policy.

Residuals (no Go carrier, recorded rather than invented):

- Go has no `StartThreadOptions`/`thread_extension_init`; the prepared child
  context and `SpawnAgentArgs.DeveloperInstructions` are the carriers. Captured
  user instructions replace the child contribution through
  `DeveloperInstructions` (nil inherits, empty clears), and the child start
  inherits the parent record’s applied instructions, so the live-provider
  replacement has the same effect without a provider abstraction.
- Go has no session isolation, so the isolated-session rejection cannot occur.
- Go never builds a local exec-policy manager alongside a transported snapshot,
  so the "cannot combine a local and a transported execution policy" error has
  no reachable state.

Coverage: `execpolicy/inheritance_like_rust_test.go` (Rust’s absolute-path
amendment cases, existing exact denials, weakened snapshots, install gates, deep
clone) and `appserver/inherited_exec_policy_like_rust_test.go` (child install,
destination isolation, independence from the snapshot, grandchild inheritance,
rejected incompatible and weakened snapshots).
