# Round 1170 audit plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round closes the residual recorded by `#47709`: the session-startup warmup
handshake now carries the startup turn's Responses metadata instead of dialing
with no client metadata at all.

## Rust behaviour

`codex-rs/core/src/session/startup_prewarm.rs` builds the handshake metadata from
the startup turn context before preconnecting:

```rust
let (window_id, window_number, context_window_id) = session.current_window().await;
let mut handshake_metadata = startup_turn_context.turn_metadata_state.to_responses_metadata(
    session.installation_id.clone(),
    window_id,
    CodexResponsesRequestKind::Prewarm,
);
ExecutionMetadata::from_settings(&startup_turn_context.initial_settings)
    .apply_to(&mut handshake_metadata);
let handshake_metadata = session.with_window_and_fork_metadata(
    &startup_turn_context, handshake_metadata, window_number, context_window_id,
);
client_session.preconnect_websocket(..., &handshake_metadata).await?;
```

So the prewarm carries installation/session/thread identity, the conversation
window and window number, fork/parent lineage, the executed model and reasoning
effort, and `request_kind: "prewarm"`.

## Go gap

`appserver/session_startup_prewarm.go::scheduleStartupPrewarm` sent
`model.AgentRequest` without `ClientMetadata`, so the websocket preconnect
handshake had no `x-codex-turn-metadata` (and no `x-codex-window-id`) while the
first turn that reuses the connection does send them.

## Change

`scheduleStartupPrewarm` now builds the metadata with
`turn.BuildResponsesClientMetadata` from `responsesMetadataLineage`,
`windowIDForThread`, `windowNumberForThread`, `contextWindowIDForThread`, the
installation id, the resolved model/reasoning effort and
`codexapi.ClientRequestPrewarm`, and passes it as the prewarm request's
`ClientMetadata`.
