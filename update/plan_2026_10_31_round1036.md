## Goal

Audit #42314 (`Preserve target-native cwd in permission approval requests`) and
close the convention gap in how Go materializes permission grants.

## Findings

- Rust replaced the host-native `cwd` of the request_permissions approval event
  with `LegacyAppPathString`, removed the core-side guard that rejected a cwd not
  native to the Codex host, and converts the preserved value back to a `PathUri`
  when materializing grants.
- Go's app-server protocol already carries `PermissionsRequestApprovalParams.CWD`
  as a plain string, and `activeTurnEnvironmentCWD` returns the environment
  selection's spelling verbatim, so the target-native cwd is preserved end to
  end; there is no host-native guard to remove.
- The remaining gap was materialization: `approvedRequestPermissionsDecision` and
  `intersectRequestedPermissions` normalized grants with the host `filepath`
  rules, and `permissionPathsWithin` compared them with host path semantics. For
  a foreign-convention cwd that dropped every grant (the request could reach the
  client but the approved access never unblocked later execution).

## Implementation

- `sandbox/permissions.go`: added
  `NormalizeAdditionalPermissionsForExecutor` (uses the cwd's path convention
  when the cwd is a path URI or a foreign convention, renders a URI-form cwd into
  its native spelling, and otherwise keeps the host resolver) and
  `NormalizeAdditionalPermissionsForConvention` (resolves relative grants under
  the executor convention and rejects a grant spelled with another convention
  instead of silently reinterpreting it).
- `appserver/request_permissions.go`: both grant materialization paths use the
  executor-aware normalizer, and `permissionPathsWithin` compares grants and
  requests as path URIs before falling back to host containment.
- Tests:
  - `sandbox/executor_cwd_permission_normalization_like_rust_test.go`: Windows
    and POSIX URI cwds, relative and absolute grants, read grants, cross
    convention rejection in both directions, and unchanged host behavior.
  - `appserver/request_permissions_target_native_cwd_like_rust_test.go`: the
    round trip keeps a target-native cwd, granted access under it is preserved,
    a cross-convention answer is dropped, and containment works for Windows and
    POSIX grants.

## Decision

- Mark `eb078b4f44` as `complete`: Go's protocol already preserves the
  target-native cwd (string-typed, no `AbsolutePathBuf` projection to remove and
  no schema/TypeScript regeneration to mirror), and materialization now follows
  the executor convention.
