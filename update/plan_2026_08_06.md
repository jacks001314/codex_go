## 四、风险与注意

1. Go 与 Rust 架构不同：Rust 的 skills crate 迁移、approvals 集中、unified exec 输出状态为内部重构，Go 侧无对应结构或已等价，标注 N/A，不强行模仿。
2. `transparentBackground` 为可空字段：仅 Images API 背景为 transparent/opaque 时设 true/false，自动或不可得时为 null；兼容旧 item 缺失该字段的反序列化。
3. `include_apps_usage_instructions` 默认 true（与 Rust 兼容旧元数据一致）；显式 opt-out 需可序列化。`modelSpecialty` 带 `serde(default)`，旧元数据缺失不报错。
4. Windows PathUri 大小写折叠仅针对推断为 Windows convention 的路径，POSIX 路径保持大小写敏感；Percent-encoded 原生分隔符仍 fail closed。
5. rollout→paginated 迁移为大型特性（Rust ~2500 行），涉及规范化、回滚回放、subagent 有界重放、归档/压缩、原子发布与日志恢复；建议独立批次实现并配回归，不并入本轮轻量项。
6. parity 包两个「认证候选」测试（TestAlignmentBaselineIsFrozenAndTraceable / TestParityManifestIsMachineReadableAndComplete）自 08-04 起与跟踪基线不一致：candidate/baseline/commits 仍指向 SDK 认证窗口 bbbf396839，需走 sdktests 认证工作流统一更新，非本日日例范围。
