## 1. `202b590e84` #60172 — answer moderation 携带 display 指令

### 1.2 Go 侧锚点

| 事实 | 证据 |
| --- | --- |

### 1.4 落地切入点

## 3. `358e464528` #60048 — 插件 `defaultPrompt` 上限 128 → 512

### 3.1 Rust 侧改动点

| 文件:行（提交后） | 在解决什么 |
| --- | --- |
| `core-plugins/src/manifest.rs:16-18` | `MAX_DEFAULT_PROMPT_LEN: 128 → 512`（条数上限仍是 3） |

| `app-server-protocol/src/protocol/v2/plugin.rs:882-886` 等 5 个 schema + TS/Python 绑定 | 文档与生成产物同步到 512 |

### 3.2 Go 侧锚点

| 事实 | 证据 |
| --- | --- |
| Go 有 `DefaultPrompt []string` 与多别名解析，但**看不到长度上限** | 【F:plugin/api.go†L101】`DefaultPrompt []string`；`:132-L168` 三种别名（`defaultPrompt` / `default_prompt` / `default_prompts`）解析 |
| 全树没有任何 prompt 长度校验 | `grep -rn --include='*.go' "len(.*prompt\|prompt.*len(" plugin/` → 仅 `plugin/api_test.go:366`（断言条数），生产 0 |
| 条数上限也不在 Go 侧强制 | 同上：只在测试里断言 |

### 3.3 判定：`partial`，但**不占契约位**

Go 现在是"完全不校验"，Rust 是"上限 512、超限拒"。这既不是"Go 更严"也不是"Go 更松到安全风险"——超长 prompt 只会污染 UI。理由：**这是一处常量+校验阈值，不改协议形状**；登记成长期 `partial` 契约会永久占一个 `missing`，收益远小于成本。建议做法：落地时随 `plugin/api.go` 的 manifest 校验一起改（加 `maxDefaultPromptLen = 512` + 3 条上限），并用一条单测覆盖 512/513 边界即可，不登记契约。
