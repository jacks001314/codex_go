### 3.2b ②b `move_path` 是否 gate 在 `Update` 上 — **CONFIRMED 但有分歧（不可达）**
Rust 只在 `AppliedPatchFileChange::Update { move_path, .. }` 读 move 目标；Go 版条件是 `change.MovePath != "" && change.MovePath != change.Path`，**不判断 `Kind`**。

### 3.3 ③ partial-failure 漏计 / 多计 — **CONFIRMED**
seam 层（`applypatch.Parse` + `Action.ApplyVerified`，第 1 个 hunk 提交成功、第 2 个失败）：

```
--- PASS: TestProbeFailureOnFirstChangeCountsNothing      # 首个 hunk 就失败 ⇒ 0 计数
```
端到端（真实 `Execute`，本地宿主 FS）：
```
zz_probe_agents_md_test.go:203: executor partial patch: out=<nil> err=apply_patch verification failed: failed to read file to update
  C:\Users\...\codex-apply-patch-preflight-293491605\paths\2: ... cannot find the file specified.
```
⇒ **本地宿主 FS 下 partial commit 不可达**：`Execute` 在提交前先跑 `action.Verify`（`apply_patch_executor.go:167`）→ `applypatch.preflight`（`:351-475`）在宿主临时目录做**影子 dry-run**，任何 hunk 失败即整体拒绝（`out=nil`、0 提交、0 计数、磁盘无改动）。
**可达条件**：环境 FS（exec-server / 远端）在真实提交时写失败、而本地影子 dry-run 成功。syncw1 自己的测试正是用这种虚拟环境 FS 覆盖的（`TestApplyPatchAgentsMdEditCountsCommittedPrefixOnFailureLikeRust`，`:180-224`，我复跑 **PASS**）。故「失败前已提交的前缀计数」= **能达且已覆盖**。
**无多计**：一次失败只计已提交的 change，未提交的不计。

### 3.6 ★ 新发现：Windows 原生路径**漏计** — **REFUTED**
```
--- FAIL: TestProbeWindowsSeparatorPathLikeRust (0.00s)
    zz_probe_agents_md_test.go:252: backslash patch: success=true body="Success. Updated the following files:\nA sub/AGENTS.md\n"
    zz_probe_agents_md_test.go:253: path.Base(raw) = "sub\\AGENTS.md"
    zz_probe_agents_md_test.go:254: filepath.Base(raw) = "AGENTS.md"
    zz_probe_agents_md_test.go:256: DIVERGENCE: Rust counts sub\\AGENTS.md under the Windows convention (display shows "A sub/AGENTS.md"); Go counted []
--- FAIL: TestProbeAbsoluteWindowsPathLikeRust (0.00s)
    zz_probe_agents_md_test.go:273: absolute patch: success=true body="...A C:/Users/.../AGENTS.md\n"
    zz_probe_agents_md_test.go:275: DIVERGENCE: Rust counts absolute C:\Users\...\AGENTS.md; Go counted []
```
**现象**：补丁路径写 `sub\AGENTS.md`（或绝对 `C:\...\AGENTS.md`）时，Windows 上**文件确实被创建**（摘要按 `filepath.ToSlash` 显示为 `A sub/AGENTS.md`），但 `codex.agents_md.edit` **0 次计数**。

**根因（已定位到行）**：
- 被计数的路径 = `AppliedChange.Path` = **补丁原文**（`applypatch.go:631/:634/:656/:659` 直接放 `change.Path`，不做归一），在 Windows 上可含 `\`。
- Rust 侧：delta 存的是**解析后、已归一**的 `PathUri`（`lib.rs:471 hunk.resolve_path(cwd)`，`path-uri/src/lib.rs:514-517` 在 Windows convention 下 `path.replace('\\', "/")` 后按 `/` 切段），故 `basename()` 得到 `AGENTS.md` ⇒ **会计数**。
- Go 侧：`path.Base` 只按 `/` 切（POSIX 语义）⇒ 得到 `sub\AGENTS.md`/整条绝对路径 ⇒ 不匹配。
- **内部不一致**：同一仓库展示摘要用的是 `filepath.ToSlash(file.Path)`（`applypatch.go:575`，承认原生路径），而指标取 basename 却用 POSIX-only 的 `path.Base`。

**最小修法（不越界，供队长裁）**：把 `tool/apply_patch_agents_md_metrics.go` 的 `path.Base` 换成 `filepath.Base`（Windows 上同时切 `\` 与 `/` ⇒ 两个用例都得到 `AGENTS.md`；POSIX 上仅切 `/`，与 Rust Posix convention 一致）。注释里那句「`path.Base`（not `filepath.Base`）mirrors PathUri::basename」的理由在 Windows 上不成立，因为 Go 侧在取 basename 之前**没有**做 Rust 那样的归一。

**影响面**：仅 Windows；仅补丁路径里出现 `\` 时（模型/用户在 Windows 上写 `src\file.ts` 是常见写法），属**漏计**而非误计。我**没有改补丁**。

## 6. 残留风险 / 边界

1. **§3.6 的 Windows 漏计**是本次唯一 REFUTED 项，属真缺口（可达、可复现），建议修 `path.Base → filepath.Base` 后重出补丁。
2. 我无法在此节点运行 Rust 二进制；Rust 侧结论来自 `C:\rw`（LF @ `5b0b253035`）源码逐行核对（`runtimes/apply_patch.rs` 的计数循环、`path-uri/src/lib.rs:273-282` 的 `basename`、`:514-517` 的 Windows 归一、`lib.rs:471/650` 的绝对 PathUri 存储）。
3. ③ 的 partial commit 在**本地宿主 FS** 上被 preflight 挡住（§3.3 原文），只有环境 FS 写入失败才可达；这不影响 Rust 语义对齐，但说明该分支的覆盖率依赖 syncw1 的虚拟 FS 测试。
4. `applypatch.go` 的 `return result, err` 是**共享契约变更**：非测试调用方共 3 处（`tool/apply_patch_executor.go:215`、`app/app.go:1043`、`applypatch/cli.go:35`），三处均**先判 `err` 再使用 `result`**（`cli.go:36-39`、`app.go:1044-1046`），`applypatch.go:474` 的 shadow 调用丢弃 `result` ⇒ **无调用方回归**；且 `Execute` 在本地路径下不会产生 partial commit（§3.3），故该 hunk 对指标本身非必需，仅用于远端/环境 FS 的对齐。
