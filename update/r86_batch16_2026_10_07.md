## New finding recorded this batch — real bug in handed-in `sync638`

lane `syncw4` (independent adversarial verification of `syncw1_51652.patch`) **REFUTED** one property:

- A patch path written with Windows-native separators (`sub\AGENTS.md`) or an absolute Windows path
  (`C:\...\AGENTS.md`) **does land the file** (summary shows `A sub/AGENTS.md` via `filepath.ToSlash`) but
  `codex.agents_md.edit` counts **0** → *undercount*.
- Root cause located: the counter takes the basename with **POSIX-only `path.Base`** while
  `AppliedChange.Path` holds the **raw patch text, not normalized**; Rust's delta stores an already-normalized
  absolute `PathUri` (`path-uri/src/lib.rs:514-517` replaces `\` with `/` under the Windows convention), so
  Rust's `basename()` resolves. The same file prints its summary through `filepath.ToSlash` — internally inconsistent.
- Minimal fix: `tool/apply_patch_agents_md_metrics.go`: `path.Base` → `filepath.Base` (Windows splits both
  separators; POSIX behaviour unchanged).
- Also noted (syncw4 ②b): Go does not gate `move_path` on `Kind==Update` (`delete+MovePath=AGENTS.md` counts 1
  vs Rust 0), but `parseAdd/parseDelete` and `applyAdd/applyDelete` never produce `MovePath` ⇒ **production unreachable**.

Dispatched to `syncw1` (patch author) as the `sync642` candidate:
`update/r86_patches/syncw1_51652_windows_path.patch` + in-repo Windows-path regressions promoted from syncw4's
