## Findings surfaced by the differential

1. **Test bug (identity marker).** `TestSystemCodexSlashParityWithConPTY`
   waited for the single marker `gcode` on both binaries and asserted it on
   both, but the Rust release brands itself `OpenAI Codex` - a documented
   allowed identity mapping (parity/domains.json: rust `codex` <-> go `gcode`).
   Fixed: each side waits for and asserts its own identity marker; the shared
   `/status` + `/mcp` surface markers (model, approval, permissions, reasoning
   low, read only, collaboration mode, session) are asserted on both.
2. **Real Go divergence (Windows sandbox NUX).** With the cwd already trusted
   in the effective config, Go still opened the Windows sandbox startup
   enable prompt, while Rust gates it on
   `onboarding_result.directory_trust_persisted` (a fresh/untrusted cwd
   produces a session trust decision; elevated-required bypasses the gate).
   The Go comment admitted the missing bit. Fixed in
   `interactiveWindowsSandboxStartupPrompt`: the prompt now mirrors Rust
   `should_prompt = (trust_decision_was_made && level == Disabled) ||
   elevatedSetupRequired`, with `trustDecisionContext =
   !config.ProjectConfigEnabled(values, cwd)` (exported trust check; a cwd
   already trusted produces no session trust decision) and the cwd resolved
   from `root.Shared.CWD` or `os.Getwd()` (the binary runs without `--cd`, so
   `Shared.CWD` is empty).
