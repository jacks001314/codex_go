## Goal

Keep plugin-backed skill listings fresh after another process sharing
`CODEX_HOME` replaces an installed plugin version, and bound the retained
configuration-based skill snapshot cache.

## Findings

- Rust #42284 rejects a cached `LoadedPluginsCache` entry when any cached
  plugin root no longer equals `PluginStore.active_plugin_root` (falling back to
  the plugin base root), so upgrades and rollbacks reload skills. It also turns
  `HostSkillsService::cache_by_config` into a 32-entry LRU (`VecDeque`), while
  callers holding an evicted snapshot keep using it.
- Go has no `PluginsManager`/`LoadedPluginsCache`: per-turn plugin capabilities
  are derived synchronously, and `appserver` re-discovers plugin skill roots on
  every `skills/list` (`pluginSkillEntriesAndErrorsForRuntime` walks
  `Plugins.EnabledSkillRoots()` and rescans each root). A warm `skills/list`
  therefore cannot pin a stale plugin skill path. `PluginService` details use
  stable materialization roots (`plugins/<marketplace>/<plugin>`) rather than
  the versioned `PluginStore` layout, whose `ActivePluginRoot` only feeds remote
  sync and script attribution. The owned `manifestCache` re-reads manifest
  revisions on every call, so an out-of-process replacement is observed too.
- `appserver.SkillsService.cache` was an unbounded `map[string]skillsCacheEntry`
  keyed by CWDs, extra roots, config fingerprint, and bundled-skill flags. It is
  the Go carrier for Rust's configuration-based snapshot cache, but it never
  evicted, so parallel sessions/configs could retain snapshots indefinitely.

## Implementation

- `appserver/skills.go`: added `cacheOrder` (MRU-first keys) and
  `skillsConfigCacheCapacity = 32`. Cache hits move the key to the front;
  inserts do the same and evict the least recently used map entry. Every full
  reset (`ClearCache`, extra-root changes, config writes, persistent-config
  drift) clears both the map and the order. Responses are clones, so a caller
  keeps a usable snapshot after eviction.
- `appserver/skills_test.go`: added
  `TestSkillsServiceBoundsConfigCacheLikeRust` (33+ generations keep exactly 32
  entries, the oldest is evicted, the held response survives, and a re-request
  reloads it as the most recent key) and
  `TestRuntimeRouterSkillsListRefreshesExternallyChangedPluginSkillLikeRust`
  (plugin skill content changes are visible on cold and warm `skills/list` reads
  across simulated upgrade/rollback versions).
