## Findings

- #43912 closed a reviewer-session inheritance gap in Rust: Guardian clones the
  parent config, so a parent turn that enabled token-budget mode could push the
  reviewer into context rollover instead of summary-based compaction. Rust now
  clears the inherited startup activation, installs an explicit default
  `TokenBudgetConfig`, and disables `Feature::TokenBudget` and
  `Feature::ContextManagement` for reviewer sessions.
- Go's reviewer isolation already disabled `token_budget` explicitly (so model
  defaults cannot reactivate it) but still enabled `context_management`, and the
  rollover check read the parent turn's captured
  `RunConfig.TokenBudgetFeatureEnabled` instead of the reviewer's own feature
  gate. A parent token budget could therefore start a fresh reviewer chain.
- Rust's rollover gate in `guardian/review_session.rs` is
  `spawn_config.features.enabled(Feature::TokenBudget)`, where `spawn_config` is
  the isolated reviewer config. Go now applies the same gate before consulting
  the #41221 parent-preference resolution.

## Changes

- `appserver/guardian_reviewer_config.go` disables `context_management` together
  with the rest of Rust's reviewer feature set, and adds
  `guardianReviewerTokenBudgetEnabled` for the reviewer-owned feature gate.
- `appserver/guardian_reviewer.go` only calls the #41221 rollover resolver when
  that reviewer gate is on, so a parent's token-budget activation no longer
  resets the reviewer response chain.
- Coverage: reviewer isolation test now includes `context_management`; the new
  regression test checks both features are disabled, that model defaults cannot
  reactivate token-budget mode, and that a parent token budget never consults
  the rollover resolver for the isolated reviewer.
