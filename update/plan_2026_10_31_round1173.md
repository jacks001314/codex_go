# Round 1173 audit plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round closes the `#42137` residual named in round 1172: a turn now
speculates the v2 executor shell snapshot instead of paying for the first
capture on its first `exec_command`.

## Rust behaviour

`codex-rs/core/src/unified_exec/shell_snapshot.rs:32-152`
`Session::prewarm_shell_snapshots` returns `None` unless `Feature::ShellSnapshotV2`
is enabled, `exec_command` is registered for the step, the project is trusted,
the approval policy is not `UnlessTrusted`, the turn carries no network, and the
configured network proxy is off. It then spawns one task that, for every turn
environment, skips remote environments, environments without the v2 capability,
`allow_login_shell = false` and managed networking, and for bash/zsh/sh captures
the login shell's empty script through the executor with the environment's cwd,
environment policy and sandbox context. The session stores the handle in
`state.shell_snapshot_prewarm`, so it runs once per session and is aborted when
the session shuts down (session/handlers.rs:322-325).

## Go gap

Round 1172 taught local unified-exec launches to restore the executor snapshot,
but nothing warmed it: the first launch captured synchronously. Rust's v1
`PrewarmSnapshot` only covers the session file snapshot.

## Change

- `tool.PrewarmLocalShellSnapshot`: builds the executor request from a launch
  shape (shell login invocation with an empty script, cwd, environment policy,
  explicit `CODEX_THREAD_ID`) and calls the local executor's `Prewarm`.
- `appserver.prewarmShellSnapshotV2`: applies Rust's gate (feature, registered
  `exec_command`, local capability, `allow_login_shell`, project trust,
  approval policy, managed networking), resolves the thread's POSIX shell, and
  starts the capture once per session; the marker is cleared with the thread's
  snapshot state on unload.
- The prewarm scope, shell, cwd and policy are the same values the launch
  provider returns, so the executor cache lookup hits.

## Residual

Go's local unified-exec path still has no filesystem sandbox context, so both
the prewarm and the launch carry an empty sandbox entry; when the local path
gains a sandbox, the helper both use must produce the same value or the cache
stops matching.
