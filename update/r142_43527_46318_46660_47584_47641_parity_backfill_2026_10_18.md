# Parity backfill: Guardian score lag, gateway OAuth, MCP launch, retained order, Retry-After

These entries were already `complete` in the ledger but remained
`audit_pending` in parity. Focused tests were rerun against the current tree.

## `#43527` Guardian wrapper-lag discount

Guardian score freshness records bounded tool-start provenance per thread.
Direct custom `exec` calls carry their origin item as wrapper identity, and
nested code-mode calls inherit it, so a review discounts only its own newer
unscored wrapper.

## `#46318` Gateway OAuth credentials

The auth package retains the provider-gateway OAuth surface: encrypted storage
with a cross-process lock, token rotation/refresh-skew handling, reuse and
rejection paths, and a single-shot loopback callback listener with state
validation.

## `#46660` Explicit local MCP launch settings

The local MCP launcher owns explicit environment/argv, pipe setup, process-group
containment on Unix, and suspended/Job-Object containment on Windows. Rust's
`ChildKind`/`NativeChild` are backend wrappers rather than separate Go behavior.

## `#47584` Streamed assistant order in retained context

`RetainedContext` reserves an assistant message's order when stream output
starts, then consumes that reservation when the completed message is recorded.
A user reply accepted mid-stream therefore keeps a later order.

## `#47641` Server Retry-After deadlines

`codexapi` captures `Retry-After` as a monotonic deadline at header receipt.
The deadline survives wrapping and retry state, and `RetryDelay` returns the
remaining duration. `TestResponsesHTTPErrorPreservesRetryAfterMetadata` was
updated to assert the captured deadline and the `(0, 17s]` remaining-delay
bound instead of a restartable fixed duration.
