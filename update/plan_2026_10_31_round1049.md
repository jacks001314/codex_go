## Goal

Cancel remote-control enrollment when the stdio connection closes so a blocked
enrollment cannot keep the app server (and its thread writers) alive, while
still allowing cached or persisted enrollments to be enabled and durably saved.

## Findings

- Rust #42668 gives remote control a child shutdown token, cancels it in the
  stdio single-client branch before RPC drain, and races `enroll_pairing_server`
  against that token. Network enrollment returns `Interrupted` ("remote control
  is shutting down"), but a reused in-memory or persisted enrollment still
  enables, persists `remote_control_enabled = true`, and never contacts the
  backend.
- Go performed remote-control RPCs with `context.Background()` and drained
  in-flight stdio requests (`requests.Wait()`) without cancelling them. A
  `remoteControl/enable` blocked on the enroll request therefore held the
  process open after EOF, exactly the Rust bug.
- `Manager.EnableContext` runs the whole durable enable synchronously (unlike
  Rust's background controller), so both the persisted-enrollment read and the
  preference write must survive the shutdown cancellation. Local store work is
  bounded by the existing `remoteControlPersistenceWriteTimeout`.

## Implementation

- `remotecontrol`: added `ErrRemoteControlShuttingDown`. `enableDurable` loads
  persisted enrollments and writes the enabled preference through a bounded
  `context.WithoutCancel` store context, rejects an already-cancelled context
  before network enrollment, and maps a cancellation observed during
  `EnrollRemoteControlServer` to the shutdown sentinel.
- `appserver/runtime_router.go`: added a router-lifetime
  `remoteControlOpsCtx` (cancelled by `Close()`), a `remoteControlContext()`
  helper, and `CancelRemoteControlOperations()`. Enable/disable/pairing RPCs and
  the remote client-management paths that perform network work use that context.
- `appserver/stdio.go`: cancels remote-control operations right after the read
  loop ends (EOF or signal) and before `requests.Wait()`.
- Tests: `remotecontrol/shutdown_enable_like_rust_test.go` covers in-memory,
  persisted, and missing enrollments after shutdown (durable enable with zero
  backend calls, and the interrupted sentinel). 
  `appserver/remote_control_stdio_shutdown_like_rust_test.go` drives a real
  JSON-line stdio connection with a blocked enroll backend and proves EOF
  returns promptly with the shutdown error.
