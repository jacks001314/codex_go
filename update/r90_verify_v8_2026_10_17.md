## 3. 发现③（本轮新增）：Go 的实验门也没盖住 `project/*`

Rust 侧门控是**宏机制**，不是手写清单：

- `app-server-protocol/src/protocol/common.rs:89-99` `macro_rules! experimental_reason_expr`：`(variant ..., #[experimental($reason:expr)] ...) => { Some($reason) }`；
- `common.rs:404` `EXPERIMENTAL_CLIENT_METHODS` 亦由同一属性生成（`export.rs:273` 用它裁剪 stable `ClientRequest.ts`）；
- 消费点 `app-server/src/message_processor.rs:984`：`if let Some(reason) = codex_request.experimental_reason()` ⇒ 无 experimentalApi 能力时报 `"{reason} requires experimentalApi capability"`（同族用例：`app-server/tests/suite/v2/server_diagnostics.rs:107`、`.../experimental_api.rs:460`）。
  ⇒ 客户端若不开 experimentalApi，Rust 的 `project/list` **必须被拒**。

Go 侧对应物是手写清单 `experimentalAPIMethod`（`runtime_router.go:2710+`）：

```
$ git -C D:\qax\reagent\dev\codex_go grep -n "MethodProject" -- appserver/runtime_router.go
(无输出)
```

该清单包含 `MethodServerDiagnostics`，但 **0 条 `MethodProject*`**；全仓 `MethodProjectList` 仅出现在 `projects.go:20/179/192` 与测试里 ⇒ Go 的 `RuntimeRouter` **不会**因缺 experimentalApi 能力拒绝 `project/*`。

**这就是双向不对称**：Rust =（进 experimental 面 + 受 experimentalApi 门控）；Go（sync692 前）=（出面 + 无门控）；sync692 后 =（进面 + **仍无门控**）。是否要补门控请队长裁决（本车道只报事实，不写实现）。
