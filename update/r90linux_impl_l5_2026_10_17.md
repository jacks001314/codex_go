## 1. Step 0 · 先证伪：上游到底在哪些布局挂设备树

上游 builder 把设备树挂在**四个**位置（不是“特定组合”，而是**所有布局都挂**），函数 `create_filesystem_args`（`bwrap.rs:409`）与 `create_bwrap_flags_full_filesystem`（`:268`）：

| # | 布局条件 | Rust file:line | 挂载序列 |
|---|---|---|---|
| R1 | `has_full_disk_read_access()`（含“restricted 但显式读 `/`”） | `bwrap.rs:500-516`（字符串 `:510-513`） | `--ro-bind / /` + **`--dev /dev`** |
| R2 | restricted 且显式可读 `/` | `bwrap.rs:546-556`（字符串 `:550-553`） | `--ro-bind / /` + **`--dev /dev`** |
| R3 | restricted 且没有可读 `/`（scoped read roots） | `bwrap.rs:517-523`（字符串 `:519-522`） | `--tmpfs /` + **`--dev /dev`**（上游用例 `restricted_read_only_uses_scoped_read_roots_instead_of_erroring`，断言 `:2436` `args.args[0..4] == ["--tmpfs","/","--dev","/dev"]`） |
| R4 | full-disk-write（`create_bwrap_flags_full_filesystem`）+ 写入根为 `/` 的重绑 | `bwrap.rs:275-281`、`:648-657` | `--bind / /` + **`--dev /dev`** + `--bind-try /dev/shm /dev/shm`；重绑 `/` 时再补一次（注释：“Preserve nodev on the root bind while exposing only standard devices”） |

结论（写进实现）：**不存在“只有 full-disk-write 才挂”的条件**——Go 只在 `hasFullDiskWriteAccess()` 分支挂是**缺口**；且 `--dev /dev` 在这些布局里都与 `/` 的读/写根绑定**位置相关**（必须早于写入根绑定，见 `:505-508` 注释）。

**第二个（更隐蔽的）上游条件**：设备树会被之后的挂载遮蔽。`append_read_only_subpath_args`（`bwrap.rs:1243-1257`）只在 `is_within_allowed_write_paths(subpath, allowed_write_paths)` 成立时（即该 subpath 落在某个写入根**之内**）才重新 `--ro-bind`。上游从不把**读基线 `/`** 再绑一次；`bwrap.rs:396-408` 的挂载顺序注释也把“ro-bind subpaths”列为应用在写入根**之下**的第 5 步。

## 3. 实现（生产 argv 变更，最小面）
`sandbox/linuxsandbox/linux.go`（`execBubblewrap` restricted 分支）：
1. `--ro-bind / /` 之后追加 `--dev /dev`（D1）。
2. 写入根为 `/` 的重绑之后追加 `--dev /dev --bind-try /dev/shm /dev/shm`（D2）。
3. 只读 carveout 循环改为只处理“落在写入根之内”的路径；写入根含 `/` 时全部保留（D3）。

根因链（本批实测，非推断）：restricted 布局原先产出的 argv 是
`--ro-bind / / … --bind <cwd> <cwd> --ro-bind / / …`——最后那条 `--ro-bind / /` 来自把 read entry `/` 当成 carveout，它把宿主根（含 `/dev`）重新盖到设备树与写入根之上，于是沙箱内 `open("/dev/null")` 得 `EACCES`，managed-proxy 的 local bridge（Go `os/exec` 会为子进程 stdin 打开 `/dev/null`，`linux.go:1270-1293`）无法启动：`codex-linux-sandbox: error activating Linux proxy routing bridge: open /dev/null: permission denied`。
修复后同一策略的 argv（真机抓取，经假 launcher 打印）：
```
--ro-bind / / --dev /dev --bind <cwd> <cwd> --chdir <cwd> …
```
