## Goal

Remove the duplicate legacy Guardian approval review paths (extension
`fast_decision` / `full_review` hooks, `ApprovalAssessment`, the duplicate
Guardian V2 fast-approval implementation and `StrictReviewReason`) and require
an explicit `GuardianReviewReason` for synchronous reviews.

## Findings

- Go has no `ApprovalReviewContributor` extension registry, so it never had the
  two legacy hooks or `ApprovalAssessment`. `appserver/guardian_reviewer.go`
  documents this at the `fastDecision` field and keeps one synchronous review
  policy (full access, initial computer-use call, serving assessment, user-mode
  node-REPL fast path, then the shared model review).
- Go also never had a duplicate Guardian V2 fast-approval implementation:
  `appserver/agent_runtime.go` injects one `emitGuardianV2FastDecision` hook and
  `appserver/guardian_reviewer.go` fires it from those single fast paths.
- Upstream kept the Guardian V2 fast-decision event and metric
  (`codex_guardian_v2_fast_decision`); Go mirrors both through
  `telemetry.NewGuardianV2FastDecisionEvent` and `GuardianV2FastDecisionMetric`,
  so no telemetry had to be deleted.
- Gap: Go models no `GuardianReviewReason`. `state.Event` exposes no
  `review_reason`, `modelGuardianReviewer.Review` takes no reason, and the
  synchronous review only labels its route counter `policy` or
  `fresh_required`. Rust now requires the reason on every synchronous review
  assessment event.
