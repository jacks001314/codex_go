### #57586 host-reserved V2 child creation — Go shape

- `agent.InvocationRegistry` is the opt-in live-call registry. `turn.ToolDispatcher`
  reserves `(turnID, callID)` before admission, publishes only after pre-tool
  hooks, rejects duplicates with Rust's model-facing message, and revokes the
  guard when dispatch ends.
- `RuntimeRouter` installs one registry per V2 thread (`turnInvocationRegistry`),
  exposes `ToolInvocation`, and implements `CreateChild`, `PrepareChild` and
  `StartPreparedChild` with `agent.HostThreadSpawnReservation`.
- `runtimeAgentController.SpawnReservedAgent` spawns under the host ID while
  reusing the ordinary spawn body, so registry, spawn-graph, provisional-cleanup
  and telemetry behavior stay identical.
- Detached preparation rejects managed application network policy, cloud config
  binding, EMA-authenticated MCP servers and pending environment configuration.
  Go has no thread-attachment store and no inherited-instruction providers, so
  those two Rust rejections have no Go equivalent.

### #57569 queue semantics — not applicable

The Rust change also reworks the `tokio::mpsc` event queue in
`exec-server/in_process.rs`. Go's exec-server/app-server process bridge is a
synchronous writer with per-stream drain deadlines (`outputDrainTimedOut`,
`CapSatisfied`), and has no equivalent queue or control-reply coalescing path.
Only the `outputDrainTimedOut` protocol surface applies and is landed.

### #57598 empty-result cache — executor half landed, appserver cache not applicable

The exec-server protocol, Linux `fs/watchMissing` implementation, client watch
registration/invalidation and `fs/missingChanged` handling are landed.

The Rust cache lives in `ext/skills/src/host_roots.rs` and is keyed by a
long-lived `Arc<dyn ExecutorFileSystem>`, working directory and project-root
markers, reusing only after the executor acknowledges watch coverage. Go's
equivalent discovery (`appserver/skills_remote.go`) has a different shape:

- it probes each selected capability root directly and does not walk ancestor
  directories looking for `.agents/skills` or project-root markers;
- it dials a fresh exec-server connection per discovery and closes it when the
  walk returns, so no connection survives to carry `fs/missingChanged`;
- it already caches each root's result per thread through
  `selectedCapabilitySkillCatalog` (`sync.Once`), so repeated scans within a
  thread do not re-request metadata.

A Rust-equivalent reuse cache would therefore need a new long-lived per-
environment connection lifecycle inside the app-server, which is outside this
commit's scope and would change Go's connection architecture rather than mirror
it. The executor capability is available for a future appserver redesign.
