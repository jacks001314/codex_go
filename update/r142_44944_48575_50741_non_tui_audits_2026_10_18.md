# Non-TUI audits: managed provider threads, provisioned executors, readiness-stable tools

## `#44944` Managed provider requirements on existing threads

Existing threads retain the model-provider route they were admitted with, and
later requirements changes that no longer match reject retained-thread entry
points while unrelated changes keep the thread usable. App-server provider
requirement tests pass.

## `#48575` Provisioned executor startup window

Provisioned executors use a separate fixed readiness window and retry until
the longer `environment_offline` deadline, while already-ready executors do not
pay the extra wait. Exec-server provisioned-connect tests pass.

## `#50741` Environment tools across readiness changes

Environment-backed tools stay advertised as readiness changes, with waiting
and legacy failure messages split at execution time. Tool environment-readiness
tests pass.
