# Parity backfill: heartbeat overrides, Guardian OTLP, console suppression, streamed writes, snapshot cleanup

Five ledger-complete non-TUI entries were still marked pending in parity.
Focused regressions pass against the current tree.

## `#47851` Human overrides across heartbeat instructions

Heartbeat provenance comes from the exact `user.heartbeat` content kind.
Bounded scheduler envelopes coalesce only unchanged instructions per automation;
new heartbeat versions and ordinary human messages retain acceptance order, so a
human override is not hidden by repeated heartbeat replay.

## `#47870` Opt-in Guardian assessment logs

`otel.log_guardian_assessments` remains disabled unless an OTLP HTTP/gRPC log
exporter is configured. Completed assessments emit the bounded
`codex.guardian_assessment` record with rationale capped at 64 KiB on a UTF-8
boundary; fail-closed, timeout, and in-progress events omit model outcome.

## `#49164` Windows console suppression

`envutil.SuppressConsoleWindow` ORs `CREATE_NO_WINDOW` into existing flags,
preserving `CREATE_SUSPENDED` for Job Object containment. Shared background
launches and hook/MCP containment paths use the helper.

## `#49778` Streamed exec-server writes

The exec-server protocol defines `fs/writeBlock`, handle/offset/base64 chunk
params, 1 MiB chunk size, and open mode types.

## `#49782` Failed shell-snapshot process cleanup

Each snapshot capture owns its process group. Failure, timeout, or cancellation
terminates that group, while successful captures preserve startup helpers.
