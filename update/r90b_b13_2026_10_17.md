## 5. 未决 / 未覆盖（如实）

1. **运行中包识别用的是"字节摘要"而不是 Rust 的路径摘要**：Rust 从 pid 记录取 `path_digest`（blake3 of canonical path，`managed_install.rs:225`）区分"字节相同但目录不同"的两代 release。Go 的 `install.ExecutableIdentity` 只有 `Digest`（`install/context.go:80-82`），pid 记录里没有路径摘要（`appserverdaemon/pid.go:61-68`），而 `install/**` 不在本批授权写面 ⇒ 本实现退化为「候选 entrypoint 的字节摘要 ∈ 运行中摘要集合 ⇒ 保留」。方向是**保守**的：绝不会删在用的 release，最坏情况是多留一个字节相同的旧 release。**未验证 + 原因**：需要一个真跑起来、且 pid 记录携带路径摘要的 daemon 才能端到端验证真正的路径级判定，本批无此环境。
2. **updater handoff（`backend/pid.rs:573-585`）未单独落地**：Go 侧未改 `pid.go`（Rust 那处是"记录里的 pid == 自身 pid 时改用自身 exe 身份"）。本批的等价护栏是 `pathWithin(caller, path)`（自身 exe 所在 release 保留），已由 §3 用例覆盖路径维度；pid==self 的"记录可能滞后于 handoff"这一层未做，记为缺口。
3. **USN 身份（Windows `selection_identity` 的 USN 部分）未实现**：Go stdlib 无 `FSCTL_READ_FILE_USN_DATA`；本实现用卷序列号 + 文件 id（`GetFileInformationByHandle`）。**未验证 + 原因**：文件 id 被回收（删除后立即重建同 id）时无法像 Rust 那样察觉；写入与校验在同一次安装的 installer lock 内完成，窗口即为安装本身。Linux 分支按 Rust 原义实现（`mnt_id`）。
4. **Linux / macOS 分支未在本节点验证**：`release_pruning_linux.go`（`/proc/self/fdinfo` mnt_id）与 `release_pruning_other.go`（dev + ino + mtime）**只做了 `gofmt` 与语法审查**：`GOOS=linux go build ./appserverdaemon/` 因跨平台依赖（`sandbox/linuxsandbox` 需要 `go-seccomp-bpf`/`go-landlock`，本节点无法访问 proxy.golang.org）**失败于下载**，不是编译错误 ⇒ **未验证 + 原因 = 依赖不可下载**。Windows 分支（本批主要面）已真机验证。
5. **运行中 worker 的"路径级"保留没有独立用例**：本批用例覆盖 selected / previous / 调用者 / 非受管名 / 无 manifest；"server 或 updater 真在跑"这一支需要起真进程，记为未覆盖（由 §5-1 的保守实现兜底）。

## 7. `#53853` 定档（只判定，未改码）

- 上游 `e342df7b66`（"Reuse staged file digests when preparing daemon installs"），Rust 全 hunk：
  - `prepare_install.rs:232-245`：`package_tree(source, Some(stage.path()), &mut staged_digests)` 现在在拷贝阶段顺带收集 `相对路径 → blake3` 映射；staged 可执行文件的一致性检查由 `managed_install::executable_identity(&staged_exe)`（**重新读一遍并哈希 staged 文件**）改为 `staged_digests.get(staged_exe)`。

- **定档 = `already_implemented`（正确性等价）+ 增量是纯性能优化**：Rust 改动不改变任何判定结果，只是把"已经算过的文件摘要"复用，省掉一次 staged 入口的全量读取/哈希；Go 的等价语义（staged 入口摘要 == 运行中身份）在 `:548` 已实现，仍保留 Rust 改动前的那次额外读取。若要追平这份**性能**增量，需要给 `walkPackageTree` 增加 `map[string]string` 出参并让 `ensurePackageUnchanged` 复用之（并发面：`copyPackageTree`（`:629`）与 `packageTreeDigest`（`:633`）共用同一 walk，签名变更会牵动 publish/copy 路径）⇒ 属**可实施但不阻塞对齐**的性能项，本批未改码。
