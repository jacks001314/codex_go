# Round 1166 audit plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round finishes the `#44242` view_image registration alignment for
`codex exec`, completing what Round 1165 did for the app server.

## exec view_image is feature-gated, not model-gated

`exec.execViewImageOptions` used to return nil for a text-only turn model, which
removed `view_image` from the exec model-visible tool surface. Rust's plan adds
`ViewImageHandler` whenever `features.view_image` is enabled
(`codex-rs/core/src/tools/spec_plan.rs`), and
`codex-rs/core/src/tools/handlers/view_image.rs` decides at call time from the
step's captured `model_info.input_modalities`:

```
view_image is not allowed because you do not support image inputs
```

Go's exec runner now takes the turn's feature settings, so a disabled
`view_image` feature hides the tool and every other model keeps it. The handler
installs `StepSettings` with the exec model's image modalities and
original-detail support, so a text-only model receives Rust's rejection instead
of a produced image, and an image-capable model can request
`detail: original`. The options no longer nil-dereference an unknown model.

## Tests

`TestToolRouterRegistersViewImageForImageCapableModel` now covers the disabled
feature (nil options), the text-only model (options present, call rejected with
Rust's message) and the image-capable model (tool present, original detail
allowed). Verified with `go test ./exec -count=1` (package green).

## Residual

`#44242` stays `partial` for the remaining model-dependent registrations that Go
still resolves once per turn: `apply_patch_tool_type`, the resolved tool mode,
clock/sleep support, web-search image content types, and the artifact-operation
metrics model tag (emission lives in `appserver/turn_runtime.go`). `view_image`
presence and its per-step schema are now aligned in both the app server (Round
1165) and exec.
