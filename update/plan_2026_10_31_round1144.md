## Findings

- #44255 made every supported provider use streamed remote compaction and added
  `trim_function_call_history_to_fit_context_window`
  (`codex-rs/core/src/compact_remote_history.rs`). At the streamed boundary the
  snapshot is never shortened by dropping items: while
  `history + base_instructions` exceeds the captured usable window, the newest
  tool outputs are rewritten in place, and the pass stops at the first item that
  cannot be rewritten so older turns stay whole.
- Rewritten forms differ per item: function and custom tool outputs become the
  placeholder `Output exceeded the available model context and was truncated`,
  while a `tool_search_output` keeps `call_id`/`status`/`execution` and reports
  an empty `tools` array. Feature-enabled retained client tool outputs
  (`client_authored`, `function_call_output`, no `call_id`, named) are a
  boundary like user/developer messages.
- The estimate used for that pass charges JSON payloads that are themselves
  arguments: `ToolSearchCall.arguments` and `ToolSearchOutput.tools` count their
  serialized bytes, and the session base instructions are added to the total.
- Go still called `TrimHistoryToContextWindow`, which fell back to
  `TrimHistoryToTokenBudget` and could drop whole messages, ignored
  `tool_search_call`/`tool_search_output` in `EstimateItemTokens`, and lost
  tool-search identity when compaction items crossed the session bridge.

## Changes

- `compact/compact.go`: `TrimHistoryToContextWindow` is replaced by
  `TrimFunctionCallHistoryToFitContextWindow(items, contextWindow, baseInstructions, retainClientToolOutputs)`,
  a new-to-old in-place rewrite that keeps every item, charges the base
  instructions, honours `RetainClientToolOutputs` as a boundary, and returns the
  rewritten-output count. `rewrittenOutputForContextWindow` produces the
  placeholder for function/custom outputs and an empty `tools` array for
  `tool_search_output`. `EstimateItemTokens` now charges `tool_search_call`
  arguments and `tool_search_output` tools as JSON bytes
  (`estimateToolSearchOutputTokens`).
- `appserver/async_compaction.go`: `captureBackgroundCompactionInput` uses the
  new trim and passes the `retain_client_tool_outputs` feature flag from the
  run config.
- `appserver/router.go`: `sessionItemsFromCompactItems` copies
  `Name`/`Namespace`/`CallID`/`Status` (status from the item payload), so a
  trimmed tool-search output keeps its identity when it is serialized back into
  the compaction request.
