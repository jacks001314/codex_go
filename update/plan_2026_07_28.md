## Contract rules

1. Rust canonical names, order, descriptions, inline-argument support, feature gates, task gates and side-conversation gates are authoritative.
2. Compatibility aliases may remain directly dispatchable, but they do not appear in the default popup or participate in popup matching unless Rust does so.
3. Go-only compatibility commands remain directly dispatchable while hidden from the Rust-aligned popup until an explicit removal decision is made.
4. TUI behavior is verified primarily through Windows PTY scenarios. SDK differential tests are secondary and only apply where a slash action crosses session, config or app-server protocol boundaries.
5. Destructive actions use isolated `CODEX_HOME` directories and disposable session fixtures. Feedback is never submitted to the real service during parity tests.

## Delivery slices

1. Entry contract: canonical names, compatibility aliases, popup inventory/order/filtering, feature/platform/task/side gates, inline args.
2. Read-only commands: copy/raw/diff/status/usage/debug-config/mcp/ps/stop/rollout.
3. Settings and modals: model/permissions/keymap/vim/experimental/memories/title/statusline/theme/pets/personality.
4. Session lifecycle: new/clear/rename/resume/fork/archive/delete/logout/exit/app.
5. Prompt and integrations: init/compact/plan/goal/agent/subagents/side/btw/review/skills/import/hooks/plugins/feedback.
6. Go compatibility extensions: verify direct dispatch remains stable while excluded from the Rust popup.
7. Windows PTY differential suite, focused Go tests, full `go test ./...`, report and formal baseline decision.

## Latest import evidence

- `/import` now detects Claude Code and Cursor independently. When both contain importable setup, Go presents Rust's source chooser before the existing customize checklist; when only one has data, it opens that checklist directly. Detection and import carry the selected `migrationSource` through the embedded app-server path.
- Cursor migration covers home and repository config, sandbox policy, MCP servers, hooks and hook files, skills, commands, subagents, `.cursorrules`, cached plugins and recent sessions. Cursor path/text rewriting and command-description fallback follow the Rust source rules; macOS-only path handling remains outside scope.
- Claude and Cursor session detection apply Rust's age/count defaults, transcript validation, title selection and source-specific parsing. Completed imports are content-hash ledgered, unchanged transcripts are suppressed, changed transcripts are detected again, and a ledger write failure preserves session successes while adding `session_ledger_update / failed_to_update_session_ledger`.
- Deterministic coverage passed in `config`, `plugin`, `rollout`, `appserver`, `tui/tea` and `app`. The remaining observable difference is architectural: Rust returns `externalAgentConfig/import` before session/plugin background work finishes and emits completion later; the embedded Go callback currently executes the migration synchronously and returns the response with its completion result.
