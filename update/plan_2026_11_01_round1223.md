## Context

A registered Core runs as two managed accounts that must read the owner's
packaged Known Folder metadata. The service therefore has to grant exactly one
`FILE_READ_ATTRIBUTES` ACE on each owner AppData root, record the root before
touching permissions so cleanup still owns it, and take that ACE back before
the accounts are deleted. It also needs to log those accounts on again to repair
a registration, which it must do from the owner-pinned credential directory.

## Metadata roots

`windowsandboxservice/runtime_metadata_windows.go` ports
`registered_runtime/metadata.rs`:

- `GrantRuntimeMetadata` requires the SID to be a recorded runtime account,
  resolves `FOLDERID_LocalAppData` and `FOLDERID_RoamingAppData` for the owner
  token, records each root in `metadata_roots` and persists it before any ACE
  mutation, then inserts one explicit ACE granting only `FILE_READ_ATTRIBUTES`
  (no listing, contents or inheritance) ahead of the inherited entries.
- `RemoveRuntimeMetadata` deletes every matching ACE for every recorded
  account from every recorded root, skips roots that no longer exist and
  reports all other failures as one summary, matching Rust.
- The ACL editor keeps Rust's shape: it copies the DACL out of the retained
  directory handle, rejects an unexpected revision or oversized DACL, edits the
  raw ACL, and writes it back with `NtSetSecurityObject` so inheritable ACEs are
  not reapplied to children. `SE_DACL_PROTECTED` and
  `SE_DACL_AUTO_INHERITED` are preserved and a null DACL is never replaced.

`windowsandboxservice/known_folder_windows.go` ports
`registered_runtime/known_folder.rs`: `SHGetKnownFolderPath` for an explicit
token with `KF_FLAG_DONT_VERIFY | KF_FLAG_NO_PACKAGE_REDIRECTION`, a bounded
UTF-16 read and an unconditional `CoTaskMemFree`.

## Existing-account logon

`sandbox/windowssandbox/identity_logon_existing_windows.go` ports
`logon_existing_sandbox_account`: read the setup marker (a missing marker keeps
its not-found error so cleanup can distinguish it), require a matching marker
version, read and version-check the account records, refuse a record that names
another account, decode the DPAPI-protected password and call `LogonUserW` with
`LOGON32_LOGON_INTERACTIVE`. A rejected password keeps the existing
`SandboxAccountCredentialMismatch` classification.
