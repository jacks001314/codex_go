### #38907 Edit queued messages with Vim history-up

Rust (`tui/src/chatwidget/interaction.rs`): the chat `edit_queued_message`
action restores the latest queued follow-up into the composer for editing and
removes it from the queue (so re-submitting replaces it instead of creating a
duplicate). The new commit makes an empty composer's Vim-normal history-up
binding (`vim_normal.move_up`, default k/up) trigger the same restore, keeps
normal history navigation when the composer has text, honors remapped Vim
bindings, and adds tests covering repeated edit-and-requeue cycles plus a
remapped binding.

Go's tea TUI lacked the entire feature. Implemented in the tea Model:

- `applyEditQueuedMessageKey` (routed before input-history navigation in
  Update): the chat `edit_queued_message` binding (default alt-up /
  shift-left) restores whenever queued follow-ups exist and no modal or popup
  is active; the Vim path is gated on Vim mode + an empty composer +
  `vim_normal.move_up` (Go's Vim mode is a model-level flag; the empty-composer
  gate mirrors Rust's VimNormal context for the history-up behavior). Remapped
  bindings are honored through the resolved keymap
  (`keyMatches("vim_normal", "move_up", keySpec)` etc.).
- The restored submission is removed from `m.queued` (last entry) and its
  prompt/attachments/mention-bindings are restored into the composer, so
  submitting the edited version replaces it.
