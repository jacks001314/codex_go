## Result

Not applicable by architecture.

- Rust's async binding can wait for one MCP server while another connection
  updates a shared tool catalog; the change rechecks the current catalog before
  falling back to the pre-wait capture.
- Go's `MCPService.CaptureBinding` snapshots the statuses passed at the
  model-step capture synchronously. There is no cross-server wait or captured
  fallback window to refresh.
- Cache opt-out and eligibility are still enforced by
  `retainedToolCatalogUsable` and `mcpToolCatalogCacheEligible`.
