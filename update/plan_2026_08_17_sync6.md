## Gap: update command does not normalize paths for WSL (P2)

Rust `cli/src/wsl_paths.rs` provides `win_path_to_wsl` (`C:\foo\bar` /
`C:/foo/bar` -> `/mnt/c/foo/bar`, drive lowercased, backslashes to slashes) and
`normalize_for_wsl` (maps only under WSL). Rust `cli/src/main.rs` `run_update`
applies it on non-Windows to the update command path and every argument.

Go already had `shell.WinPathToWSL` / `shell.NormalizeForWSL` (exact Rust
mirrors, with tests) and `utils.IsWSL` detection, but `install.ExecCommandRunner`
did not apply the normalization. Implemented:

- `install/update.go`: `updateCommandAndArgs` mirrors Rust's run_update split -
  Windows runs non-PowerShell commands via `cmd.exe /C` (PATHEXT semantics,
  PowerShell direct), non-Windows normalizes the command path and every
  argument via `normalizedUpdateCommand` (shell.NormalizeForWSL, injectable for
  tests). `Run` now uses the resolved command/args.
