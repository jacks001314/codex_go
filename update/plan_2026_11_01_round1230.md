# Round 1230: Owner-aware admission and the OwnerRemoved stop reason (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6
(`service/runtime_lifecycle.rs::run`, #42375).

## Context

Shutdown means "SCM stop until cleanup finishes": the broker must retire the
sandbox before admitting another client once the recorded owner's package is
gone, and it must never replay a retirement fence from stored intent.

## Lifecycle cleanup entry

`Lifecycle.CleanUp` ports `PackageLifecycle::clean_up`: it holds the sandbox
setup lock for the whole teardown, runs `CleanUpRegisteredRuntime` when a
runtime record exists, and otherwise retires the legacy installation record
before preparing native cleanup. The registered transaction re-acquires the
setup mutex while preparing managed logons, so the entry pins one OS thread to
make that recursion legal.

## Admission loop

`windowsandboxservice/runtime_admission_windows.go` ports
`runtime_lifecycle::run`'s admission closure:

- `restoreOwner` restores durable temporary-enable intent (fatal on failure)
  and the recorded owner (logged, because other clients can still use elevated
  setup);
- `check` runs between admissions: while the owner still has a package it
  clears the remembered cleanup error and admits; once
  `runtime_owner_removed` is true it retires the sandbox, stops the listener
  and reports `SERVICE_STOP_PENDING`; a failed teardown is fatal when the
  runtime record is gone or already retiring, and otherwise logged once and
  retried during the pre-fence backoff;
- `finish` repeats the owner-aware teardown for an SCM stop that arrives after
  the listener closed, and records `ServiceStopReason::OwnerRemoved` when the
  loop retired the sandbox.

The broker now restores the owner in `OnReady` before publishing
`SERVICE_RUNNING`, runs `check` on every session change, and computes the stop
reason from `ownerRemoved` / `stopRequested` in `runServiceMain`.

## Known gaps

Installer/MSIX required-resource wiring for the service binary and its assets
is the remaining non-TUI gap; `CleanUpRegisteredRuntime` now has both callers
(the admission loop and the post-broker stop path).
