## Goal

Mirror Rust #41660 (`0a12b855a0`): preserve Guardian authorization across
history compaction. Compaction and host-injected context rewrite the
model-visible conversation without changing what the user authorized, so they
must not invalidate a retained Guardian decision. Genuine user input and history
resets must still invalidate it.

## Implementation

- `context/user_authorization.go` (new): `IsUserAuthorizationMessage` mirrors
  Rust's `context::is_user_authorization_message`. It reads the host annotation
  (`internal_chat_message_metadata_passthrough.content_item_kinds`) instead of
  text markers, and stays conservative: missing, empty, length-mismatched, and
  legacy metadata, plus `""`/`unknown`/`images.preparation_error`/
  `images.unsupported`/`audio.unsupported` and any `user.*` kind, count as user
  authorization.
- `context/history.go`:
  - `HistoryManager.userMessageRevision` mirrors Rust's
    `ContextManager::user_message_revision`; `RecordItems` advances it for each
    genuine user message.
  - `Replace` is Rust's `HistoryReplacement::Reset`: it advances both the
    history generation and the user-message revision.
  - `ReplaceCompacted` is Rust's `HistoryReplacement::Compaction`: it advances
    the history generation while preserving the revision.
  - `DropLastUserTurns` (rollback) advances the revision even when no user turn
    survives the trim, matching Rust's `replace_annotated` call on that path.
  - `UserMessageRevision()` exposes the snapshot value.
- `appserver/guardian_user_message_revision.go` (new): thread-owned revision
  beside the independent Guardian review history. Every append classifies its
  items through the same predicate, so goal/environment context never counts as
  authorization.
- `appserver/guardian_review_history.go`: appends advance the revision; the
  rollback entry point (`truncateGuardianReviewHistoryBefore`) and thread
  forgetting reset/advance it. Compaction (`captureGuardianReviewHistory`) keeps
  it unchanged.
- `appserver/guardian_reviewer.go`, `appserver/runtime_router.go`: a cold resume
  and a fork replay history into a fresh runtime, so
  `resetGuardianAfterParentHistoryReset` now takes the thread id and advances
  that thread's revision alongside resetting the reusable reviewer.
- `state/guardian_serving_assessment.go`,
  `appserver/guardian_serving_assessment.go`: `ServingAuthorization` carries the
  thread's user-message revision and includes it in `Matches`, so a retained
  low-risk serving assessment survives compaction but is rejected once new user
  input or a reset/rollback arrives.
