## Goal

Keep a paginated thread's resolved multi-agent version across `thread/revert`
and later reloads or cold resumes.

## Findings

- Rust's revert rebuilds the thread's rollout from a replacement recorder. It
  copies the source session metadata line and overwrites `multi_agent_version`
  with the live thread's resolved version, falling back to the persisted value
  when the live thread has none.
- Go's `session.Store.Revert` truncates items and turn snapshots in place and
  saves the same record under the same thread id; it never rebuilds a rollout
  from session metadata, so `Metadata.MultiAgentVersion` (and the other session
  metadata fields) is carried through unchanged.
- Turn-time version resolution already prefers a persisted
  `MultiAgentVersion` on the record and otherwise re-resolves from the model's
  catalog entry (`runtimeMultiAgentVersionForTurn`), so a model-selected V2
  thread keeps its collaboration tools after a revert and reload.

## Implementation

- Added `TestStoreRevertPreservesMultiAgentVersionLikeRust` in
  `session/store_test.go`: it reverts a paginated thread twice for `v1`, `v2`
  and `disabled`, asserts the in-memory result keeps the version, and reads the
  record back to cover the persisted metadata.
- No production code change was needed; the Rust behavior is the "retain the
  existing metadata value" branch of this commit, and Go has no replacement
  rollout to copy session metadata from.
