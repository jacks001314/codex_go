## What changed

Rust maps `CodexErrorDetails::InvalidAudioInput` to `CodexErrorInfo::BadRequest`
(`protocol/src/error.rs`), keeps the `invalid_audio_input` analytics kind, and
reports no HTTP status because `http_status_code_value` returns `None` for that
detail. Go already rejected uploaded audio at admission and kept the provider
error terminal, but `turnAnalyticsErrorFieldsFromAPIError` fell through to the
empty default, so a turn that failed on audio validation reported
`other`/`nil` instead of `badRequest`/`invalid_audio_input`.

The new arm closes that residual:

```go
case codexapi.ErrorInvalidAudioInput:
    return fields("badRequest", "invalid_audio_input")
```

The router-level test drives a real turn through `turn/start`, asserts the
completed turn carries `badRequest`, and checks the analytics event keeps
`invalid_audio_input` with no HTTP status.
