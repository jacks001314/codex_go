## Goal

Name the SQLite databases whose integrity checks fail in `codex doctor`, and
harden detail redaction so Windows drive letters are not treated as labels.

## Findings

- Rust #47330 replaced the generic state-check remediation with a structured
  issue listing every failed database path and moved the recovery text onto the
  issue. Go's `stateCheck` only kept the generic summary and check-level
  remediation, so users could not tell which file was damaged.
- Go's `redactDoctorDetail` split sensitive details on the first `:` and used
  the prefix as a label. A Windows path such as `C:\...\logs_2.sqlite database
  failed integrity check` was therefore redacted as `C: <redacted>` instead of
  hiding the path; Rust now splits on `": "` and fully redacts unlabeled
  details.
- Rust #49415 bounds derived `Debug` previews of protocol input text. Go has no
  derived `Debug` rendering for `TurnUserInput` and does not log request or
  params payloads in model/appserver, so there is no formatter to bound.

## Implementation

- `doctor/doctor.go`: collect failed database paths in `stateCheck`, attach
  `<paths> database(s) failed integrity check` as an issue with the recovery
  remedy, and stop setting the check-level remediation for this case.
- `doctor/doctor.go`: `redactDoctorDetail` now cuts on `": "` and returns
  `<redacted>` when no label separator exists.
- `doctor/doctor_test.go`: add single/multiple failed database coverage (status,
  summary, issue cause and remedy, JSON projection, preserved damaged bytes)
  and path-versus-label redaction coverage.
