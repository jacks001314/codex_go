### Safety recourse implementation notes

- Protocol embedding stays internal: `ThreadEvent.InternalTurnID`,
  `ThreadEvent.Metadata`, `ThreadEvent.TurnFailed`, and `ThreadError.Kind` are
  `json:"-"`, so the exec JSON contract is unchanged. The embedded exec runner
  also emits an internal-only `turn.moderation_metadata` event.
- The app-server emits `error` before `turn/completed`. Remote `turn/completed`
  now carries the server's failed status internally, so a failed turn never
  reports a successful completion, and the deferred error is still available
  when the completion arrives.
- Old or non-primary servers cannot trigger the picker: without a
  `turn/moderationMetadata` notification there is no pending recourse, and the
  picker is only opened from a validated pending result. Active side
  conversations, read-only threads, and unavailable threads are rejected, and
  one pending block owns the turn (Rust #57365's `supports_server` / primary
  thread checks are therefore satisfied by construction in the single-backend
  Go TUI).
- Cyber guidance now carries Rust's `Notice::Disabled`/`Notice::Enabled` states.
  The picker offers "Enable Daybreak" only when the active model advertises
  Daybreak and the account currently has it off, matching `render_failure`.
- Queued submissions while a block is pending keep the full `SubmitRequest`,
  including composer attachment paths. Go has no prepared-image byte cache, so
  this is the equivalent of Rust's prepared input at the Go carrier boundary;
  it is not byte-level parity.
- The in-process TUI reads the workspace display from the local account record
  (`interactiveAccountWorkspaceDisplay`). Workspace discovery and caching live in
  the auth/app-server layers, so a local account without a discovered name keeps
  the row hidden, exactly like Rust's `workspace_display(None, None)`.
- `account/read` always serializes `workspaceName` for ChatGPT accounts and emits
  `null` when unknown, matching Rust's required nullable field in
  `app-server-protocol/v2/account.rs`.

### Safety block rendering and rewrite recovery

- `SafetyAccessBlockCell.DisplayLines` matches Rust's `safety_recourse`
  snapshot at width 80. The body wraps at `width - 4` and keeps the two-space
  first-row prefix on every row, mirroring Rust's `"  " + message` line with a
  `"  "` hanging indent. Action rows use a local textwrap-compatible FirstFit
  wrapper that keeps leading spaces and breaks at the standard hyphen/slash
  opportunities, so `enterprise-trusted-access-for-` / `cyber/` splits exactly
  like Rust. `tui/history_cell/safety_access_snapshot_like_rust_test.go` locks
  both the plain and the turn-explained cyber blocks.
- `applySafetyRecourseRewriteReady` mirrors `continue_with_rewrite`'s recovery:
  the source thread keeps its draft, the fork attaches with an empty composer,
  and a rewrite whose turn never starts (for example the fork's cyber access
  program is unavailable) is restored to the fork composer instead of being
  lost in the reset.
- A rejected rewrite reports only `Couldn’t start a new chat for this rewrite.`
  plus the sanitized prompt, and `restoreSafetyRecoursePrompt` merges the
  rewrite ahead of any unsent draft, matching
  `restore_user_message_to_composer` / `merge_user_messages`.

## Mouse wheel scrolls the transcript (2026-10-27)

Problem: Go resolved `tui.alternate_screen = "auto"` to an inline screen and
left terminal mouse reporting off, so the terminal translated the wheel into
scrollback movement. Rust resolves `tui.fullscreen_transcript` (default true)
and `tui.alternate_screen = "auto"` to `TranscriptMode::Owned`, enters the
alternate screen, and captures the wheel in `TranscriptView`.

Change:

- `Options.usesOwnedScreen` now owns the screen for the default, `auto`, and
  `always` modes, and stays inline only for `--no-alt-screen`,
  `tui.fullscreen_transcript = false`, or `tui.alternate_screen = "never"`
  (`TranscriptMode::resolve`).
- `NewProgram` enters the alternate screen and enables cell-motion mouse
  reporting for owned launches; `Init` disables DEC 1007 so terminals cannot
  rewrite the wheel into Up/Down keys. The transcript wheel path then moves
  only `TranscriptYOffset`. Inline launches still leave wheel, selection/copy,
  and native paste to the terminal.
- Regression tests cover the default owned launch capturing the wheel, every
  inline configuration leaving mouse reporting off, and both PTY restore smokes
  asserting alternate-screen entry plus mouse reporting. The old "auto stays
  inline" expectation was replaced with Rust ownership semantics.
- `tui/tea/program_mouse_wheel_like_rust_test.go` drives the real Bubble Tea
  program over a pipe: the owned launch must emit `\x1b[?1049h`, `\x1b[?1002h`,
  and `\x1b[?1007l`, and an SGR wheel escape (`\x1b[<64;5;3M`) must move the
  transcript off its bottom row instead of reaching the composer. The inline
  launch must emit none of those sequences.

Verification (clean worktree at `2b1114d5` plus this patch): `gofmt -l` is clean,
`go vet ./tui/... ./app ./auth ./protocol ./exec ./model`, `go test -p 1
./tui/... ./app ./auth ./protocol ./exec ./model -count=1`, and `go build ./...`
all pass. The shared worktree also passed `./tui/tea` and `./app` before the
parallel appserver WIP broke compilation there.

Known gap: Rust also keeps `auto` inline for Terminal.app over SSH, which it
identifies from the startup DA1/DA2 device-attribute replies. Go now issues DA1
at startup for the exit drain (below), but it never queries DA2 and does not
feed the reply into terminal identity, so an SSH session to Terminal.app owns
the screen here. `--no-alt-screen`,
`tui.fullscreen_transcript = false`, and `tui.alternate_screen = "never"` keep
the terminal-owned inline screen for those users. `parity/commits.json` records
`#47417` as partial for this reason; the entry had previously claimed a
whole-terminal inline `auto` mode that the wheel fix removed.

## Math: integral limits and parenthesized matrices (2026-10-27)

Rust `#57393` (`d0f33fab36`) adds two display-math layouts to
`codex-rs/tui/src/markdown_render/math.rs`: `\int` now joins `\sum` and
`\bigwedge` as a stacking operator whose limits sit above and below the sign,
and a new `pmatrix` environment renders a centered grid inside scalable
parentheses. Both are display-only; nested display math (lists and blockquotes)
keeps compact operator limits and rejects spatial layouts in favor of the
verbatim source, and a layout only renders when its required width fits
`width - 4`.

- `tui/markdown/math_render.go` adds `mathMode` (inline / display /
nested display), `mathRendered{text, requiredWidth, hasRequiredWidth}`, and
reports a required width for matrices and any multi-row layout. `\int` stacks
only in top-level display mode; `\frac` stacks in display and nested display.
- `tui/markdown/math_render_structured.go` replaces `aligned` with `grid`, which
parses `{aligned}` and `{pmatrix}`, rejects empty cells and ragged rows, treats
an adjacent `*` or `[2pt]` after `\\` as a row-break option, centers matrix
cells, and wraps rows in `( )`, `⎛ ⎞`, `⎜ ⎟`, and `⎝ ⎠`.
- `tui/markdown/math_spans.go` selects the mode from the Markdown container and
applies the spatial-layout width gate through `mathRenderFits`.

Regression coverage lives in `tui/markdown/math_integral_matrix_like_rust_test.go`
(integrals in all three modes, matrix geometry, `\\*` and `\\ [2pt]`, ragged and
mismatched environments, the narrow-width fallback, and nested list behavior).
Verified with `go test ./tui/markdown -count=1` and `gofmt -l`.

## Drain pending terminal reports on exit (2026-10-27)

Rust `#57391` (`d30fe145fc`) pauses event polling on shutdown, asks the terminal
for a DA1 reply on Unix (two-second timeout, only when startup saw DA1 support),
flushes queued input, and only then restores cooked mode. Without it, mouse and
focus reports generated while reporting was still enabled can be read by the
parent shell after Codex exits. Go now mirrors that in its Bubble Tea runtime:

- `tui/terminal_exit_drain.go` owns the DA1 query, the split-reply buffer, the
two-second deadline, and the remembered `TerminalDA1Supported` state.
- The Unix startup probe (`tui/terminal_default_colors_unix.go`) now sends
`\x1b[c` alongside the OSC 10/11 colors and enables raw mode for the probe
window, matching Rust's `set_modes()`-before-probe order; a canonical terminal
otherwise withholds the unterminated replies. It records whether DA1 answered.
- `tui/tea.Run` calls `DrainPendingTerminalReports` after the program returns.
Unix makes the tty raw again, duplicates stdin non-blockingly, waits for DA1
when supported, and drains the queue; Windows calls
`FlushConsoleInputBuffer`. Panic unwinding and non-terminal input skip the DA1
wait and never block shutdown.

Regression coverage lives in `tui/terminal_exit_drain_test.go` (DA1 parsing,
reply-before-deadline, bounded timeout, and non-terminal no-op) and the existing
`tui/tea` program tests still pass with pipes. Verified with `go test ./tui/...
-count=1`, `GOOS=linux go vet ./tui/...`, and `GOOS=linux`/`GOOS=darwin`
`go build ./tui/...`.
