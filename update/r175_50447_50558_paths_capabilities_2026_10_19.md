# Round 732: absolute-path and provider capability audits

## `#50558` absolute paths without current-directory lookup

Rust 依据：`19e554bb70103b17aa7dca6bbd0dbf1c8b2eddb6`。

Go 无 `AbsolutePathBuf::relative_to_current_dir` 载体，直接使用标准库
`filepath.Abs`。Go 1.26 的 Unix 实现先判断 `filepath.IsAbs`，绝对路径直接
`filepath.Clean`，不会调用 `os.Getwd`；只有相对路径才读取当前目录。因此
Rust 的 deleted-CWD 回归在 Go 标准库层已满足，记为 `not_applicable`。

验证：

- `go test ./utils -count=1`

## `#50447` provider capability gate for tool namespaces

Rust 依据：`fd75aa116c4a6d1db0fa1e0a0f896e3368349649`。

Go 现状已对齐：

- `ProviderCapabilitiesReadResponse` 仅包含 `imageGeneration` / `webSearch`，
  没有 `namespaceTools`。
- `model.ProviderCapabilities` and provider config overrides contain no
  namespace-tool capability.
- Tool namespace specs are serialized by `model.ResponsesToolsFromSpecs`
  without a provider capability check; Responses Lite requests use that
  namespace-aware serialization.
- Tool-search availability follows model/search settings rather than a namespace
  capability.

验证：

- `go test ./model -run TestProviderCapabilities -count=1`
- `go test ./appserver -run TestRuntimeRouterModelProviderCapabilitiesReadMatchesRust -count=1`
- `go test ./appserver -run TestRuntimeRouterModelProviderCapabilitiesReadUsesConfiguredProviderLikeRust -count=1`
