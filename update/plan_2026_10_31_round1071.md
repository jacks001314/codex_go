## Goal

Make exec-server shell-snapshot metrics distinguish capture purpose, retry
attempt, shell, and sandbox, and report a bounded failure reason on both the
counter and the duration sample.

## Findings

- Rust's exec-server snapshot cache records `purpose` (`execution`/`prewarm`),
  `attempt`, `shell` and `sandbox` on the v2 `codex.shell_snapshot` counter and
  duration, and maps each capture error to a bounded reason (`spawn_failed`,
  `timeout`, `nonzero_exit`, `too_large`, `unsupported_shell`, ...). The
  duration sample also carries `failure_reason`.
- Go's host-side v2 observation mirrored exec-server telemetry but emitted only
  `version`/`success`, collapsed every failure into `capture_failed`, and put the
  reason only on the counter.
- Go's host builder has no exec-server retry loop: `Snapshot`/`PrewarmSnapshot`
  capture once per purpose under the builder lock, so the attempt label is `1`.
  Local captures run without a sandbox, which Rust tags `none`.

## Implementation

- `appserver/shell_snapshot.go`: `recordShellSnapshot` takes the capture purpose
  and shell name; `shellSnapshotCaptured` now tags the v2 counter and duration
  with `purpose`, `attempt=1`, `shell`, `sandbox=none` and the bounded
  `tool.SnapshotFailureReason` (`write_failed`/`validation_failed`), and adds
  `failure_reason` to the duration sample. Prewarm passes `prewarm` plus the
  session shell; command-driven captures pass `execution` plus the launch shell.
- `telemetry/metric_names.go`: document the v2 diagnostic labels.
- `appserver/shell_snapshot_test.go`: assert the new labels on success, and on
  failure assert `purpose=execution`, `attempt=1`, `shell=bash`, `sandbox=none`,
  `failure_reason=validation_failed` on both the counter and the duration.
