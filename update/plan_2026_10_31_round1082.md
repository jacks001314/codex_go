## Goal

Use `127.0.0.1` instead of `localhost` for the local login server redirect URI
and success-page redirects, so loopback sign-in does not depend on the
`localhost` hostname resolving.

## Findings

- Go binds the browser-login listener on `127.0.0.1` but advertised
  `http://localhost:<port>/auth/callback` as the OAuth redirect URI and
  redirected to `http://localhost:<port>/success` afterwards.
- `composeOAuthSuccessURL` (the success page carrying `id_token` and
  `plan_type`) had the same `localhost` host.
- Rust #47927 changes the login server redirect URI and success page to
  `127.0.0.1`; the CLI start message intentionally still shows `localhost`.

## Implementation

- `auth/oauth.go`: redirect URI, fallback success redirect and
  `composeOAuthSuccessURL` now use `http://127.0.0.1:<port>`.
- `auth/oauth_test.go`: `TestStartBrowserLoginRedirectsToSuccessPage` now
  asserts the authorize URL carries
  `redirect_uri=http%3A%2F%2F127.0.0.1%3A<port>%2Fauth%2Fcallback` and that the
  callback redirect targets `http://127.0.0.1:<port>/success`.
