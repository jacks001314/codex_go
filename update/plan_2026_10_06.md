1. `gofmt -l <改动文件>` 为空；`go build ./<改动包>/...` 通过。

5. 无法落地项：写明技术理由 + 证据（Rust 源码位置 / Go 侧阻塞点），保留在“遗留”章节。

## 遗留与差异

- **tcp-tunnel `draining` 分类（Go-only）**：`sync337` 的 JSON 诊断里，Rust 区分 `Code::Draining`（收到 GOAWAY 后重建）与 `Code::Closed`；Go 使用 quic-go/http3 的传输层，没有可观测的 draining 事件，因此丢失一律记为 `closed`（已在 `serve` 注释与测试中固定）。
- **`additional_tools` 历史项生产者（Go-only）**：Rust 的 `ResponseItem::AdditionalTools` 既用于 Responses Lite 的 prompt-only 前缀（每请求重建，`client.rs`），也用于 world-state/guardian 等会进入历史的路径，`#50435` 让后者可持久化。Go 的 `responsesLiteInputItems` 同样每请求重建该前缀，且当前无把 `additional_tools` 写入 session 历史的生产者；本次已按 Rust 语义补齐持久化谓词与写路径（`rollout/additional_tools.go` + 往返测试）以保证一旦产生即可无损落盘。
- ~~**截断标记字形不一致**~~：已由 `sync320` 消除。
- **MCP 结果截断的序列化键序（Go-only）**：`sync324` 已移植 `truncate_mcp_tool_result` 的算法与结构（保留 `isError`、丢弃 `structuredContent`/`_meta`、预算收缩）。Rust 以 struct 字段序序列化（`content, structuredContent, isError, _meta`），Go 的 `result` 是 `map[string]any`，`json.Marshal` 按字典序输出，因此**预览文本里的 JSON 片段键序不同**（长度一致，算法与预算一致）。属 Go 存储层（map）限制，已由 `TestTruncateMCPResultValueLikeRust` 冻结行为。
- **`browser_use` 空表判定的边角（Go-only）**：`sync325` 的 `browserUseRequirementsIsEmpty` 覆盖了 `extension`（无 headers 视为空）与各标量字段，但未实现 Rust `BrowserUseOriginPolicyToml::is_empty`——即 `[browser_use.default_origin_policy]`/`[browser_use.origins.*]` 存在但**所有字段皆空**时，Rust 视为空表、Go 仍视为已设置。此差异在 Go 侧先于本轮存在，未被 #51194 触及，记录待后续单独对齐。
- **`resolve_web_search_mode_for_turn` 的降级次序（Go-only）**：`sync330` 在 hosted web search 的两个调用点用 `WebSearchMode.RestrictToProviderWebAccess` 实现「provider 禁用 external web access → live/indexed 降为 cached」。Rust 的等价逻辑在 `core/src/config/mod.rs::resolve_web_search_mode_for_turn` 内合并了 permission-profile-Disabled 的分支与 `can_set` 约束回退；Go 的 permission/requirements 约束另行处理（`resolveRequirementConstrainedWebSearchMode`），未与该 provider 降级合并进单一解析器，属结构差异，行为在既有 Go 语义下保持一致。
