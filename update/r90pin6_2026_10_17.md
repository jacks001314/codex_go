### 2.2 item 2 = (c) 测试与宿主时钟/Rust 契约不同源

- 夹具时序 `appserver/multi_agent_wait_metrics_test.go:32-44`：**先** `router.notifyRuntimeAgentActivity(...)`（消息已入 mailbox），**再** `WaitForActivity`。产品 `appserver/agent_controller.go:772-777` 的 `select` 里 `case message := <-mailbox` 立即就绪 ⇒ 从 `started := time.Now()`（`:761`）到 `time.Since(started)`（`:768`）相隔约 0。
- 探针原文（临时 `appserver/zz_pb6_probe_test.go`，跑完已删）：
  ```
  clock: time.Since(time.Now()) == 0 in 2000/2000 calls
  mailbox: activity=&{Message:child finished TimedOut:false} err=<nil>
  timeout: activity=&{Message:Wait timed out. TimedOut:true} err=<nil>
  ```

  ⇒ mailbox 记录**必然** 0ms（与本机时钟分辨率无关地趋 0，本例到采样精度直接为 0），断言 `:66 if record.DurationMS <= 0` 因此必红。

- **顺带发现一条真缺口（不在本条修复范围内，需裁决）**：Rust 对 timeout 做钳制 `wait.rs:53,57-65`（`Some(ms) => ms.max(min_wait_timeout_ms)`，默认 `DEFAULT_MULTI_AGENT_V2_MIN_WAIT_TIMEOUT_MS = 10_000`，`config\mod.rs:258`；`None => default_wait_timeout_ms`），而 Go `agent_controller.go:750-754` 只有「args 给定则用 args，否则 `agent.MultiAgentV2DefaultWait`(30s)」，**无 min/max clamp、无 default/max 配置**。这是真实的 parity 欠账，但**实现它需要 config 的 `multi_agent_v2` 面**（本次授权面外）。

> **夹具不得硬编码 POSIX 字面量 / POSIX 形状的 URI；宿主相关的路径与 URI 一律「宿主感知」构造。**

具体展开（本轮两条红正是栽在这里）：
1. **路径**：不要在测试里写 `"/tmp/..."`、`"/abs/path"` 这类 POSIX 字面量并期望它在本机可用。用 `filepath.Join(t.TempDir(), ...)` / `os.TempDir()` / `filepath.FromSlash` 等宿主感知构造；若必须表达「上游 POSIX 夹具」，照 Rust 的 `test_path_buf()`（`utils/absolute-path/src/lib.rs:258-271`，`cfg!(windows)` ⇒ `/tmp/x` → `C:\tmp\x`）做等价映射，或按 `runtime.GOOS` 分支。
2. **URI**：`file://` + 宿主路径 = 非法（`file://C:\Users\...`；URL 会把 `C:` 当 authority/端口）。文件 URI 用 `"file:///" + filepath.ToSlash(宿主绝对路径)`，或直接走 `utils.FromHostNativePath` 生成。
3. **时限/时钟**：断言「时长 > 0」前，先确认被测路径真的经历过等待——先把事件投递进去再等，会让分支在时钟分辨率内返回并记录 0（本机实测 `time.Since(time.Now()) == 0` 出现 2000/2000 次）。
4. 判据（与 A 车道先例一致）：若同一根因在**下层包**（`utils/` 等宿主感知夹具的包）不报错，只是某一处夹具绕过宿主构造层，则判**夹具缺陷**而非产品缺陷。
