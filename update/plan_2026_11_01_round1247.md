# Round 1247: inherit the invoking step's environment snapshot (2026-11-01)

Target: Rust main at 67f0994b532b8740f14b5b738af7b7b2a915b1d6.

## Why

#55327/#55331 were still plan-only N/As and the Go tree carried both modes:
spawned agents inherited the invoking step's attachments unless the
`subagent_thread_environments` feature was enabled, in which case only
configured thread environments were inherited. The anchor removed that
configured-only mode (#55331 deleted the flag and the separate configured
bindings; only the orphaned feature key remains in
`codex-rs/features/src/lib.rs:1618` and nothing reads it), so the opt-in mode
was a divergence.

## What changed

- `appserver/environment_inheritance.go`: `inheritableEnvironmentSelections`
  lost its `configuredOnly` parameter and always keeps ready, still-starting and
  thread-derived attachments while dropping a failed one.
- `appserver/agent_controller.go`: removed the
  `inheritConfiguredThreadEnvironments` field and the feature lookup, so spawn
  inherits the invoking step's environment snapshot unconditionally.

## Tests

- `appserver/environment_inheritance_test.go`: a temporary attachment is now
  inherited with the rest of the snapshot, and enabling the vestigial
  `subagent_thread_environments` key in `config.toml` no longer narrows the
  child's environments (renamed to
  `TestRuntimeAgentControllerIgnoresRemovedEnvironmentInheritanceFeatureLikeRust`).
  Child/grandchild inheritance, owner propagation and configuration ownership
  stay covered.
- `go test ./appserver -run 'AgentController|Spawn|Environment|Subagent'` passes.
