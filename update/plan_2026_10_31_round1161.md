# Round 1161 update plan (2026-10-31)

Target: Rust `main` at `cbe16d525c2d7362fc3d4726143288e932905daa`.

This round closes the stdio drain-admission gap left open by earlier rounds:
`go test ./appserver -run TestStdioServerHandlesConcurrentTurnStarts` failed
with `Server is draining; retry after reconnecting` for `turn/start` requests
the server had already read from the wire.

## Upstream behaviour

Rust `app-server/src/message_processor.rs` takes a `TurnAdmission::admit()`
permit in `dispatch_initialized_client_request` for every mutating request
(`thread/start`, `thread/fork`, `thread/resume`, `thread/revert`,
`thread/settings/update`, `turn/settings/update`, `thread/delete`,
`thread/archive`, and the turn-work family: `thread/sample`,
`thread/guardianReview`, `turn/start`, `turn/steer`, `review/start`,
`thread/compact/start`, `thread/shellCommand`, `thread/queue/start`,
`thread/realtime/start`). A request admitted before a drain therefore keeps
running, while requests dispatched after `begin_drain` get the structured
`serverShuttingDown` error. Go only checked the gate inside `ReserveTurn`, so
work read before EOF but reserved afterwards was rejected.

## Implementation

- `appserver/thread_manager.go`
  - New `TurnAdmissionPermit` plus `AdmitTurnWork()`, mirroring Rust's
    `TurnAdmission::admit`: rejected once the drain gate closed
    (`ErrServerDraining`) or while admission is paused.
  - `ReserveTurnAdmitted(threadID, permit)` keeps the permit on the
    reservation, and `registerTurn` lets that reservation register even when
    `closing` became true after dispatch. `ReserveTurn` clears any retained
    permit so a fresh reservation always observes the live gate.
  - `PauseTurnAdmission` now also waits for outstanding permits
    (`admittedWork`), mirroring Rust's `subscribe_active` watch, so a workspace
    switch cannot start while a dispatched request is still preparing a turn.
- `appserver/turn_admission.go` (new) carries the method table, the
  `admitDispatchedRequest` helper and the JSON-RPC draining response Rust sends
  to the connection that dispatched too late.
- `appserver/stdio.go` and `appserver/websocket.go` admit each request
  synchronously when it is read and release the permit when its handler
  returns; rejected requests get the draining error instead of being run.
- `appserver/runtime_router.go` reserves the turn through
  `reserveRuntimeThreadForRequest`, which passes the request's permit.
- `appserver/protocol.go` carries the permit on `Request` (never serialized).

## Residual

- Rust re-checks `admit()` right before a queued turn request runs so work
  still waiting in the per-thread serialization queue observes a drain that
  started meanwhile. Go has no such queue for turn requests (each dispatched
  request runs in its own goroutine), so the dispatch permit is the only gate.
- The `Request`-scoped permit is only taken by the stdio and WebSocket
  transports; in-process callers keep the immediate gate behaviour Rust gives
  automatic continuations.
- `TestRuntimeRouterFileChangeEmitsAnalyticsLikeRust` and its neighbours still
  time out; `appserver/turn_runtime.go` is under active parallel work (the
  model-metadata warning added there appears in those traces), so the fix stays
  with that track.
